# Windows 轻量安装器

推荐 EXE 安装真正不含可选 EPL 媒体的 Core，然后通过同一 Resource Store 完成首次资源缓存。Qualification 从同次已完整核验的 Full 候选分离 Core，生成独立 Core ZIP/NSIS、清单和摘要，并在签名前验证实际安装与桌面启动。原 Full ZIP 保留既有离线行为；旧客户端仍使用原 Full NSIS 更新。开发 core-only 保持不可发布，readiness 仍须真实首次安装证据。

## 构建与晋级

在 main Release Qualification 内消费原 ZIP、NSIS 和已核验的解压 Core：

```powershell
./scripts/web-installer/build.ps1 -ProductDirectory <产品目录> -CoreDirectory <解压Core目录> -OutputDirectory <产物目录> -Qualification
```

入口复用既有 Qualification 身份检查、更新清单和完整载荷验证，拒绝其它工作流、源码不一致、缺少安装桥和改变的原资产。它只编译原生引导器，不重建 Core。签发后显式传入最终已核验的 Core 解压目录，使用部署内 SDK 和依赖做隔离客户端验证，不依赖签发 job 的 checkout node_modules。Qualification 同时证明原 EXE 和构建身份；Promotion 验证这些原字节后发布，拒绝同名不同内容。构建报告保持未发布、未取得生产安装证据的状态，不能把已有自动化当成新版本实机验收。

## 下载与验证

Native 匿名读取固定 GitHub Release 的 `machine-metadata.json`，核对原 v2 更新信封与 Qualification 内嵌的版本、源码、更新清单摘要及发布确认；不调用 Releases API，不需要 Token。元数据直连运输失败后可经 GH-Proxy 读取同一固定资产，每来源最多 15 秒、整体最多 30 秒；格式、编码或发布身份核对失败不切源。随后从同一版本原 GitHub 资产下载 NSIS，直连失败可使用同一受限代理，全部字节必须符合内嵌大小和 SHA-256，执行前再次验证。代理请求与重定向只允许当前固定资产及 GitHub 发行 CDN，不发送 Token；跨来源不续用 partial。元数据和下载均限制 HTTPS 地址、重定向、大小和时长，连接响应最多等待 15 秒。此步骤核对公开状态和固定资格身份，不能替代安装后原 SDK 的来源签名认证。

原生后端下载在既有摘要命名的缓存和独占锁内保存 `.part` 与有界运输记录。记录绑定内嵌资格计划的版本、源码、清单摘要、载荷名称、完整 SHA-256 和长度，以及请求来源、最终允许地址和强 ETag；不保存只读 Token。取消与超时同时关闭响应以中断停滞读取；取消、超时或截断等待文件关闭并保留合格 partial，重开同一计划时使用 `Range` / `If-Range` 续传。无强 ETag、损坏记录或不同计划／镜像重新完整下载；最终地址变化、206 范围或 ETag 不匹配、416 清空后有界重试，200 从零覆盖。运输记录与 ETag 只保证续传条件，不能授予来源信任；完整原字节仍须通过固定资格摘要，执行前沿用原锁定文件复验，资源与签名验证继续由原 SDK / Store 负责。

安装后使用已核验 Core 自带的 Node 和原 SDK。StableSource 从固定 GitHub 版本的机器元数据解出该版本原更新清单与正式发布确认，并验证双签名；官方资源元数据与 ZIP 同样读取 GitHub，运输失败可用受控代理，认证失败不切源。运输载体有名称白名单、大小、重复条目和规范编码边界；原目录/出版/归档签名仍交同一 SDK 验证，不建立第二根。现代客户端验证同次 Qualification 对 Full/Core 四份原始清单的精确 subject，并核对版本、源码、派生摘要和 Windows x64 安装包身份后选择 Core；旧 1.1 继续消费原 Full 更新清单。仅 Core 与同一 Store 的官方资源通过验证才显示完成，先验证资源小元数据及缓存原 receipt 和实际内容，缓存不可用时再验证原资源声明与归档的精确签名 subject，之后才请求 ZIP。更新工具在提交 Core 升级前完成同一安装桥；资源准备失败时旧程序尚未替换，Store 保留原可用缓存。轻量安装器不再提前完整扫描旧程序，也不因安装目录有额外文件要求用户备份；程序核验、文件保留与恢复统一由更新工具负责。安装桥在导入产品代码前完整核验一次 Core，随后直接使用原 Store，不再经第二层包装重复扫描。Full 保留随包来源，Core 只使用已授权缓存。

Box 过渡期只新增原始 latest 与每版机器元数据；旧 WebInstaller 依赖的历史元数据、后端与资源路径原位保留。新安装器两阶段均不依赖 Box，旧安装器不能通过这项源码修改远程修补。旧版链路与实际安装证据在发行验收中分别核对，见[发布流程](../../docs/development/release-readiness.md#分发镜像与应用内更新)。

## 界面与取消

安装前没有进度条或内部 Core/EPL 术语。全新安装可输入、粘贴或浏览安装位置；提交时统一规范化与验证，输入过程中不报错。使用含盘符的绝对本机路径，忽略首尾空白，支持中文和路径中的空格，不展开环境变量，不接受相对路径、网络目录或既有非空目录。已有安装和 pending 恢复锁定原目录；安装开始后位置不可编辑。下载显示真实字节进度；安装和资源准备的未知阶段显示不定进度。完成后默认勾选启动，只在点击完成时启动，取消勾选或关闭 X 不启动。取消等待实际写入进程安全停止；错误按安装、权限、恢复或资源阶段准确报告。

确认网络下载失败或下载超时后，提示可点击「下载完整离线包」，从 [GitHub 正式发布页](https://github.com/Starfie1d1272/Mizar/releases/latest)选择完整 Setup 或离线 ZIP；首屏不显示此提示。文件验证、权限、发布验证超时与用户取消不显示网络下载指引，多个来源的聚合错误也保留这些区别。入口只打开固定的可信下载页，不执行下载或安装，也不改变验证约束。

首次安装与覆盖更新共用同一目录切换事务；原生引导器仅负责下载、固定计划和父子进程交接，不另行扫描程序、执行卸载回滚或隔离部分安装。执行器先在同卷候选目录准备完整 Core 与资源，再切换程序目录和登记。首次安装要求空目录，不建立旧版备份；覆盖更新只重命名原程序作为唯一回退目录，不复制用户数据。取消等待写入停止后由原执行器撤回，首次安装撤回后不显示“旧版已恢复”。成功结束回滚窗口后清理本事务载荷，首次安装补建缺失的开始菜单入口，既有链接不改写。

父进程记录仅绑定固定计划、脚本、目标与真实 PID/创建时间。NSIS 子进程接过同一文件锁的实际句柄，父进程退出也不释放子写入者。重新打开同一安装器由原执行器核对并恢复中断事务：已提交的完整安装直接完成清理，不重新安装；未提交的事务恢复原目录或首次安装前的空目标。无法确认写入者结束或目标已被后继安装接管时保留现场。已发布旧安装器的恢复仍由它携带的原脚本负责，新执行器不维护第二套旧式复制恢复流程。

资源目录 v2 将当前 Core 的 Qualification/Promotion 授权与原 Pack Qualification、原发行声明 Promotion 与原发布版本/规范地址分开；v1 保持原严格绑定。跨兼容 Core 复用保存原主 catalog，并在同一 receipt 附加当前 Core 授权，旧 Core 回滚仍可使用原主 catalog。Qualification 可选 `resource_source_run` 和可选精确 `resource_source_artifact`（默认从成功 Promotion 任务唯一的资源 artifact 选择；后续资格 artifact 必须保留原发行证明，旧的仅 Qualification 资源 artifact 会拒绝），先验证原始 Qualification/Promotion 签名与实际内容再复制原 ZIP/证明，只签发新 Core 描述符，不改写 Pack 原始 SHA 或重打包。

## 验证边界

常规 CI 在相关改动时编译 WebInstaller C# 源码，不运行真实安装器，也不证明 Windows 进程、注册表、快捷方式或 UI 生命周期通过。正式安装与恢复仍须独立 Windows 验收，见[开发验证](../../docs/development/development-validation.md)。

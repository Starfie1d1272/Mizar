# 节目编排与展示

本文维护节目顺序、展示范围与预览含义。组件视觉见 [Mizar Pulse](mizar-pulse.md)，控制接口见[协议](../protocol.md#制作控制与场景)，决策理由见 [ADR-0017](../decisions/0017-program-direction-and-presentation.md)。

## 自动流程

已观测到同图实时比赛、当前仍在自动 Gameplay 且可信单图结果成立时，Director 保留游戏画面 3 秒，并在比分栏正中心显示使用 Barlow Condensed 的 GG，然后进入原有单图大比分和图间/整场数据面板。时长由 Director 维护，五套 HUD 共用顶栏行为；浏览器重载读取当前剩余时长，不重新计时。迟到接入已结束地图不补播 GG，手动接管、过期/恢复与执行变更不能重播旧 cue。编辑器使用 EPL 单图结果样例；GG 过渡由真实回放触发，不改变比赛事实。

| 比赛阶段 | 节目行为 |
| --- | --- |
| 准备 | 检查与预览，不自动切正式场景 |
| 热身 | BP 就绪时完整揭示一次，之后回到等待 |
| 首回合冻结期 | 按剩余时间安排 BP 最终板、完整/短开场或直接 HUD，开打前稳定画面 |
| 常规半场 | 展示半场数据，在可信比赛进展下返回 HUD；加时换边不冒充常规半场 |
| 单图结束 | 展示结果，再进入图间或整场结果 |
| 暂停、数据过期或冲突 | 保持安全画面，停止不具备条件的自动推进 |
| 手动接管 | 保持人工选择，显式恢复自动后重新判断当前比赛 |

工作台的下一节目由 Director 预测，与满足安全与计时门槛的实际切场目标分开。比赛上半场预告半场，下半场及加时预告单图结果；半场预告回到比赛。单图结果预告图间，系列完成时直接预告整场结果。图间依据下一图计划预告 BP 或开场，实际冻结期预算仍可缩短或跳过开场。赛果确认中仍预告单图结果；热身结束仍预告开场。同一执行来源、地图与当前场景的短暂遥测中断沿用最近预告并标明等待恢复，不允许自动切场；来源变化不沿用旧预告。仅缺少阶段、下一图计划或有效比赛归属等必要资料时显示等待原因。暂停和手动保持仍可展示可靠预告，但不因此发出切场命令。预告复用注册场景与真实资料，不制造未来赛果，也不新增工作台比赛阶段状态机或高频订阅。

精确时长只在 [ProgramDirector](../../apps/companion/src/program-scenes/director.ts) 的配置维护。已经开打不补播开场，失败不循环重试，排练阶段仍由排练控制器推进。

普通自动切场短淡化，回比赛更快；开场衔接 HUD、人工切场和紧急返回直接切入。转场类型与时长由[场景注册表](../../packages/protocol/src/program-scenes.ts)维护。OBS 确认完成才提交场景；BP 跨场景淡出共用该转场，成功后清理会话。

## 画面信息

- 等待页以赛事与双方为主，计划时间不生成倒计时；有相邻赛程才展示。
- 开场透明叠加真实游戏，队标落位使用当前 HUD 实际位置；缺目标槽或媒体时安全退场。
- 半场、图间和整场结果复用统计板，仅展示单图 K/D。整场结果标明最后一图，不伪装为系列合计。
- 单图结束摘要来自同一时刻已确认的赛果与公开选手数据，缺失为 `—`；跨图保留，换比赛清除。已确认比分不依赖选手统计是否完整，统计缺失显示不可用提示，不留下空画面。
- 已绑定比赛可手动打开半场、单图结果、图间和整场结果，缺少摘要显示等待内容；手动切场不确认赛果，自动编排保留阶段门槛。已有冻结摘要可在遥测停止后回看，整场未完成时显示等待结果标签。
- 画面缺媒体时收拢或保留稳定槽位，不生成虚构队标、头像或赛果。

## 预览

`/preview` 使用生产渲染器，提供场景、赛制、长名称、缺媒体与开场演示。普通场景选择和连续演示只读，不发正式切场命令；静态背景不是同步 CS2 录像。

BP 标签复用真实 `BpSession`，播放、收起、演示与填写会影响 BP 播出，必须明确提示。切换预览标签不丢弃 BP 草稿；旧 `/operator/bp` 保留重定向。

测试样例、比赛资料与局内遥测来源分开记录，不为了好看修改真实游戏事实。截图来源见[图集](../screenshots/README.md)；Windows 画面与 OBS 转场由 RC 实机验收补齐。

# HUD 风格与展示规则

HUD 的结构、组件设置、布局、外观与比赛数据分离；技术归属见[架构](../reference/architecture.md#雷达与展示配置)，操作见[预设使用](../guide/quick-start.md#hud-预设与文件分享)。

## 内置风格

| 风格 | 主要表达 | 定义入口 |
| --- | --- | --- |
| Mizar 默认 | [Mizar Pulse](mizar-pulse.md) 的深壳、冷白读数与蓝色强调 | `default-theme.ts` 与默认布局 |
| 类 EWC | 斜切构图与分层战斗信息 | `presets/ewc.ts` |
| 类 IEM | 深色卡片、方形外侧头像与紧凑信息 | `presets/iem.ts` |

定义位于 [packages/hud-config/src](../../packages/hud-config/src)，对应渲染样式位于 [apps/web/src/program/designs](../../apps/web/src/program/designs)。四套参考是 HUD 风格，完整默认节目包装由 Pulse 提供。参考来源与取舍见[历史审查](https://github.com/Starfie1d1272/Mizar/tree/70ec10084c13e2b634f0c12749a8ebe4c1c25c5f/docs/archive/design)，许可见[第三方说明](../../THIRD-PARTY-NOTICES.md)。

## 共同规则

- 阵营色和物理左右分离，换边只改变事实对应关系。
- 头像缺失、死亡、状态切换不挤动五人槽位；队名保留完整来源，不擅自生成简称。
- 组件描述符声明设置、方案与尺寸；编辑框、解析布局和播出使用同一结果。换方案不随意重写用户锚点和偏移。
- 当前观察选手显示真实持有物与可用统计；道具高亮直接跟随当前数据，不滞留动画旧值。
- 赛事身份优先于播出品牌，素材缺失不伪造。展示接口可接受的媒体不等同于编辑器已经提供全部编辑入口。
- 雷达地图、楼层、坐标、烟火与目标进度沿用既有数据语义，风格适配不移植另一套游戏状态或计时器。

## 暂停、历史与目标状态

战术和技术暂停在同一 HUD 画布组织紧凑名单、经济与赛事信息，不为该展示另切 OBS 场景。战术暂停跟随实际参赛方位置；归属未知时中性显示，技术暂停不猜结束时间。

剩余暂停数字来自游戏，格子容量是展示约定，不能当成游戏提供的总次数。回合历史保留缺失和未知胜因，不从比分补造；暂停竖向历史与冻结期横向历史分别管理展示，实战及时收起。

C4 目标动作、爆炸计时与伤害估算各消费自己的投影。最后十秒内，包括仍处于已安放状态的零秒帧，显示当前合格估算。连续收到爆炸帧而生命尚未变化时，五套 HUD 共用爆炸前估算的视觉衔接，最多保留半秒；爆炸帧中的回合计数保持或推进一位均允许衔接，之后再变化立即清除。这段残影不是当前预测，不更新估算、血量、计时或回合事实。生命变化、选手/地图/展示边界、缺段、断流、暂停与拆弹完成立即清除。动画不回写血量、不补猜行动时长；能力边界见[数据源说明](../guide/data-source-capabilities.md#c4-爆炸伤害估算)。

选手 K/D 使用固定图标列与等宽数字列，给两位数预留位置；总宽跟随实际字号，不保留旧的固定宽度，不因数字变化移动相邻统计。回合击杀另行表达：EWC 使用三片切口组成、上下交错的三角，IEM 使用带深色外轮廓的独立星星，ESL 保留原始 overlay4 的星形字形及生死位置差异，默认与 Perfect World 保留圆形徽标；跨卡片上缘的标记不受主体裁剪。

C4 预计损失区间使用琥珀色斜纹，与低生命的红色实心填充分开；预测、扣血残影和当前生命共用同一几何区间，EWC 保留斜切，Perfect World 保留直边。IEM 的区间排除外侧头像和观察编号，缺失头像时收回媒体宽度，左右镜像。

EWC 存活卡在文字下保留按参考周期和连接关系拟合的 60° 矢量线纹，左右镜像，死亡卡不显示该纹理；比分条只在队标翼保留紧凑半透明深底，暂停队标不额外铺黑色方块。EWC 与 IEM 的 K/D 使用实心骷髅，IEM 正常生命底色向内侧提亮，低生命仍使用统一警示色。ESL 的回合和时间在中央区域垂直居中；Focus 适配方形 Steam 头像，收紧媒体及其状态效果区域，默认与 Perfect World Focus 保留各自结构。队标加载失败仅对失败地址生效，更新地址后重新尝试；缺少真实素材时仍使用已有队名回退，不伪造标识。

## 配置与扩展

通用外观工作区尚未开放，只有已实现组件的受控设置可供编辑。独立目标和回合结果槽位未实现时不伪装成可用组件。

预设文件只组合已注册的设置、布局与外观。新增组件结构或赛事造型仍需实现渲染器并注册，完整模板包和第三方 HUD 接入属于[后续方向](../roadmap.md)。

维护时检查五套方案的生死、残血、目标状态、长名称、头像失效后恢复、满库存、跳转重放与减少动效。布局与样式变更不改变比赛事实。展示与复核直接使用 HUD 编辑器中的实际渲染器。

## 共享展示行为

五套 HUD 通过同一组件和节目事实表达选手状态、C4 与装备；风格差异不建立独立状态机。减员人数仅在完整十人名单的连续当前观测下降时短时显示，继续减员更新同一个面板并延长窗口；初次接入、过期恢复、回合或数据源边界不补播。Perfect World 沿用关闭人数面板的预设策略。

选手卡在当前存活且护甲可信时显示低甲数值，零甲、高甲、未知或死亡不残留数字；阈值由共享 [presentation](../../apps/web/src/program/widgets/player-rails/presentation.ts) 维护。数字放在原装备槽内，不改变卡片外框；左右镜像由物理侧决定。Perfect World 的 C4 辅助条必须有明确阵营到参赛方映射，未知时不默认归到右队。

雷达飞行轨迹保留最早可信观测到当前观测的完整已发生路径，所有外观使用连续虚线。共享雷达按固定点数预算优先压缩直线中间点，保留首尾和主要折返点；不补造出手点或落点。数据不连续、缺失位置、楼层切换或生命周期结束时清理，地图坐标、裁剪与缩放仍由原有几何负责。

# Gameplay HUD 播出预设

内置预设包括升级后的 Mizar 默认版，以及「类 EWC」「类 IEM」「类 Perfect World」「类ESL」。用户在原有预设工作区切换、另存并启用；保存不会直接上屏。所有预设共享 Runtime、Program/Radar、真实回放、组件 renderer 与 Companion 持久化，不建立第二条数据通道。

通用默认资源显示为「Mizar 默认预设」「Mizar 默认布局」「Mizar 默认外观」，不绑定赛事上下文提供方。赛事风格只在预设与组件方案中选择，不保留另一套“HUD 设计”选择器或旧试验风格。

## Mizar 原生转播包装

升级现有 `builtin:mizar-default`，仍为五套预设，不新增第六套或永久旧/新默认分支。组件继续使用现有 `default` variant；尺寸在 descriptor / builtin layout 中声明，外观限制于 `designs/native.css` 的 `data-hud-design="current"`。四套赛事布局、设置和美术不变；EWC 显式固定原有 surface 数值，避免继承默认材质的后续调整。

- 从 EWC 吸收深浅主次、死亡态减重和 Focus 去重，从 IEM 吸收紧凑对齐、五人固定行位，从上海吸收完整身份、装备/真实生命/预测的分工；不复用其整套轮廓。
- 比赛内以平直网格为主，冷黑两翼与冰白时间核心形成稳定读数；不在比分区使用向内凹的弧切。品牌弧面用于全屏包装、开场揭示和 Focus/暂停的非关键边缘。`broadcast.brand` 取自既有标志，CT/T 只表达当前阵营，品牌蓝不代表左队。辅助经济使用近白，不沿用荧光绿作为品牌色。
- 比分和短标题使用已有 Barlow Condensed；昵称与双语队名使用 Inter / 中文系统回退，数字用 tabular-nums。顶部队名固定 19px、允许换行；长昵称保留现有省略策略，Focus 提供较宽的完整名称区。
- 默认比分 envelope 800×152，实际主条 800×80，位于 (560,24)。两侧身份各 256px，比分各 84px，中间 120px；时间/目标在同一个区域切换，不改变两翼位置。
- 侧栏 envelope 保持 440×478，放在 (20,492) 与右侧对称位置；可见卡宽 400、高 76、间隔 8，外侧 76 方形头像、内侧 HP 与武器。无头像仅收拢本卡到 20px 槽位；死亡不移动五行和姓名。观察者白色细框/编号，扣血残影近白，C4 预测沿用斜纹叠层、真实 HP 使用 7px 直条。
- 四套共用 `PlayerStatusEffects` 的播出烟雾云形、强度与渐隐；默认烟雾在头像之上、姓名/HP/装备之下。蓝灰身份层与深色战斗层来自默认 recipe；不通过产品全局 CSS 加色。
- Focus envelope 480×176、可见主体 480×96，默认收起重复统计。弹药使用冰白弧切端部与深色数字；死亡或无弹药读数时收起端部。打开统计后主体 120px，仍在原 envelope 内；其它可选字段与开关全部保留。
- 默认启用既有 720×84 冻结历史，以及同 Gameplay 画布内的战术/技术暂停编排。事实、胜因、剩余次数和时钟仍来自已有 projection；没有新 OBS 场景。
- 地图条保留图片/选图方/开局阵营/地图名/状态的结构，60px 可见高度，当前图用短蓝线。雷达继续使用共享 RadarView 原有地图亮度、轮廓和实体，不更换坐标或数据通道。

已保存的 current-version 默认 snapshot 可以继续使用原 480×152 / 360×176 / 560×56 envelope，校验只额外接受这些精确旧尺寸，拒绝任意错配；读取不修改位置、主题、开关或 snapshot。它们使用同一新版 renderer 的窄尺寸排版；重新选择组件方案时才由既有 resolver 解析当前尺寸。统一回合历史窗口也适用于旧尺寸，不保留另一套旧默认 renderer。

## 三层组合

- Layout：复用 1920×1080 组件外框与物理侧锚点。选手卡可见宽度可不同，死亡不推动其他卡位。
- Theme：recipe 管理受控配色；原版与四套赛事风格均在 `hud-config` 注册。recipe 随外观副本保存，resolved snapshot 冻结语义值。
- Preset：引用布局、主题及组件 variants；造型作用域落在每一个 widget，不依赖全局 A/B 开关，允许已有编辑器保存组件组合。

内置资源只读，另存为创建自定义副本；启用仍使用 editor revision CAS。内置激活引用重启时按代码解析，自定义激活保存完整 snapshot；未知 style/recipe 拒绝。HUD 上的固定文案保持英文，编辑器保持简洁中文。

## 参考与适配

**EWC**：浅色中央倒梯形、完整深色队标翼、宽体比分、同向斜边卡片与斜向残血分界，独立三角观察位。死亡态采用缩短的半透明底板与低透明度骷髅，保留姓名、K/D、经济；隐藏 DEAD 与 ADR/DMG。左右底板只镜像一次，不继承旧渐变的 `scaleX(-1)`。观察目标边框在头像上。

EWC 的真实生命、扣血残影与整块 C4 预测共用 44/76 的斜率；残影只淡出，避免横向缩放改变斜率。致命预测覆盖现有 HP，不留下虚假的剩余生命。拆弹采用浅底上的深色图标与圆环，没有行动时长时只显示轨道。Focus 默认隐藏重复统计，突出生命、当前装备与弹药；已有统计开关及已保存设置继续有效。普通比分的暂停附加面板仍对齐队标翼；完整赛事预设启用新的同画布暂停编排。地图条保持既有信息结构与几何。

**IEM**：深蓝比分底板、竖排局数标记、直边选手卡、姓名/统计在外侧、正方形 Steam 头像在最外侧、武器和 HP 在内侧。死亡态可见宽度缩短，保留头像与灰色骷髅；局数和姓名保持各自安全区。Series Strip 为紧凑横条。

**Perfect World**：深灰比分条同时显示队标、队名与比分；卡片上部显示姓名、经济、K/D 和道具，下部为生命与武器带。死亡时收起头像、缩短卡面，保留经济、ADR 和 K/D；编号保留在外侧圆形位。Series Strip 为紧凑横条。

**ESL**：以用户提供的 `HUD/overlay4.vue` 和 `overlay4.zip` 为展示参考。深灰纹理直边底板、荧光绿标题/60px 比分、竖排系列胜图标记和阵营色下划线；440×184 外框内使用 28px 标题与 80px 主比分。五行选手卡宽 308px、高 76px、间隔 8px，外侧 12px 编号条；160×76 头像叠在生命色底层上，姓名/KD/经济在外侧，武器/生命/库存在内侧。死亡底板缩至 216px，头像变灰并保留骷髅。观战卡使用 240px 方形头像、36px 姓名/生命带，统计默认隐藏，可启用显示在下方；外框固定 296×316。雷达保留地图原色、阵营色黑字编号、观察位放大、参考方向/开火图案、低透明度死亡标记、白色烟雾圆与燃烧区颗粒；400×28 系列地图条放在雷达上方。

`类ESL` 是独立 `esl` recipe/variant，支持另存、启用、重载及预设文件导入导出，主题副本保留荧光绿 brandColor。ESL 官网可公开获取的 Legend 字体和 Adobe 思源黑体本地加载，仅用于该展示方案；来源及权利说明见仓库 THIRD-PARTY-NOTICES。参考缺少 `text2.png`，当前使用新绘制的近似 SVG 纹理。未提供视频摄像头素材，使用现有头像/观察位回退；未提供暂停/历史参考，复用既有赛事组件与事实，并统一适配 ESL 字体、纹理和强调色；战术/技术暂停、双方经济名单、竖向与冻结期回合历史均有专门样式。可选地图详情也支持同一风格。BLAST 描述是旧复刻残留，不作为新预设名称。地图资源、坐标校准、楼层、烟火生命周期、C4 进度仍由现有 Program/Radar 事实驱动；不移植 LexoRadar 适配器、固定 C4 时长、浏览器游戏倒计时或原始 GSI WebSocket。详见 [ESL 视觉复核](reviews/esl.md)。

## 几何读数

EWC 截图为 1988×1248，游戏画面约位于 y=65–1182；黑边不计入。压缩与抗锯齿导致约 1–3px 读数误差，以下是比例校准，不是逐像素一致的声明。

| 项目       | 参考截图                    | 1920 画布实现                   |
| ---------- | --------------------------- | ------------------------------- |
| 比分外框   | 约 473×77px                 | 456×74px，居中放在原 480px 外框 |
| 比分中心   | 外框宽度约 32.5% / 67.5%    | 148 / 308px                     |
| 原摄像头区 | 约 145px 宽                 | 改为 76×76px Steam 头像         |
| 卡片主体   | 约 310px 宽                 | 300px；总宽 376px               |
| 主斜边     | 水平退让约 48px / 高约 83px | 44 / 76px                       |

IEM 使用 360px 卡宽，76px 方形头像位于外侧；Perfect World 使用 300px 卡宽、84px 卡高、28px 下部战斗带，死亡正文 180px。三者共享既有卡位与回放；这些素材适配后的尺寸不是对摄像头版的机械缩放。

## 同画布暂停与两种回合历史

五套内置预设共享五行阵容和经济/比分横栏，分别保留各自配色、直边或斜切边。1920 画布底部预留 110px；左右阵容各 620px，中间赛事区 640px。每行外侧头像 32px，姓名占剩余空间，装备区 296px，金钱区 88px。装备内按头甲/钳/C4/Zeus 64px、投掷物 80px、副武器 40px、主武器 88px 和三段 8px 间距划分；内容朝画面中心对齐，空库存保留栏位。队名采用已有测量与双侧统一字号，不伪造简称。

战术暂停方的倒计时在本方外侧，另一侧显示竖向历史；换边通过 entrant A/B 的已解析 entryId 连接，禁止假设 CT 永远在左。暂停小卡片显示剩余次数数字，经济栏使用格子而非再次显示数字；填色数直接读取游戏的 `timeouts_remaining`。按用户定义的 MR12 播出惯例，常规三格、加时一格；实际计数更大时扩展格数，未知阶段或异常大计数回退数值，缺失时显示占位。游戏未发布总次数，格子容量是明确的展示约定，不是新造的比赛事实。无法解析暂停归属时，提示置于中间；技术暂停没有猜测的倒计时。可见性、头像、经济、库存、队伍汇总和暂停设置继续生效。

暂停历史采用 Shanghai06 的竖向格子，显示最近半场（12 回合）或一次加时（6 回合），CT 原历史胜方图标在左、T 在右。冻结历史是独立 720×84 横条，放在比分下方；每 3 个已结束回合显示 5 秒，开局剩余 3 秒、LIVE、数据过期立即隐藏。窗口由 accepted source/map cursor 与 seek revision 重置，浏览器计时只控制展示时长，不递减游戏时钟。胜因保留 Program 的 elimination/bomb/defuse/time/unknown；缺失回合、中性归属和未来格不补猜。颜色使用当回合历史 side，不根据当前半场重新归属队伍。

烟雾从外侧头像向卡片正文扩散，位于图像上方、姓名/HP/库存下方，降低一点透明度。IEM 稍带阵营色，EWC 使用冷灰与卡片斜切，上海使用柔和中性灰；默认版烟雾同样位于文字/战斗信息下层，所有闪光事实规则不变，减少动效关闭烟雾漂移。

`GameplayHud.broadcastBranding` 保留赛事 Logo、播出品牌 Logo/名称、平台 Logo 和最多三个赞助 Logo 的展示接口；赛事名称/阶段仍来自既有 MatchContext。当前不新增编辑器设置或持久化资产字段，也不伪造赛事、赞助商与教练资料。提供赛事 Logo 时作为中心主视觉；未提供时突出赛事名称，播出品牌居于次级位置。

## C4 与事实边界

保留既有居中 C4 图标、安放密码格 1→4、已安放后变红及拆弹环形进度。剩余时间条保持两侧向中心收缩；安装完成只做短淡入；上海已下包图标补充 1400ms 的轻微透明度呼吸，减少动态效果时关闭，不增加 JS 计时或改写游戏时钟。动效和进度由既有 accepted samples 驱动，跳转/重播使旧瞬态失效。缺少时长证据时不补猜进度。

上海粉色斜纹段已接入 #52：`cs2-c4-damage@0.1.0`。Companion 加载并校验官方随包地图资源，Core 使用站立预测器，Program v8 发布有界逐人结果。只在同代、同地图、当前完整名单、fresh 且已安放/拆弹时计算；姿态、遮挡等未知条件保留在结果中。HUD 仅在 accepted 爆炸倒计时 `0 < remainingSeconds <= 10` 时显示，不在浏览器建立另一个游戏时钟；结束、暂停或过期立即隐藏。预测仅叠在真实 HP 条，不改写生命或死亡事实。组件设置「C4 伤害预测」可持久化关闭；资源、身份、位置缺失时隐藏。雷达保留预设去色和地图描边，删除额外的 brightness 压暗。详见 ADR 0019。

## 验证与设计系统

- 真回放使用 Ancient 第 3 回合（完整）及第 11 回合拆弹片段；静态地图仅作预览背景，不伪装同步游戏视频。
- 每套检查左右、生存/残血/死亡、C4、头像缺失、长名、满库存、回放跳转和 reduced motion。
- 持久化测试覆盖内置启用重载、自定义副本/主题复制、保存不改变已启用画面；浏览器覆盖预设选择→另存→启用→磁盘重载→Program 同一 renderer。
- 属于播出画面，固定几何位于 `apps/web/src/program/designs/`，共用规则与各赛事风格分开，上海按组件拆分；配色来自 schema 校验的 Theme recipe，字体通常来自 canonical tokens；ESL 的局部展示字体按参考单独随包加载。复用产品控件，未增加共享基础组件或旧样式额度。
- Windows/CS2/OBS 真实验收与本地浏览器检查分开；参考不完整的状态沿用已有组件行为，不宣称赛事动画已经逐帧复刻。

## 上海状态与实测

参考原图约 1988×1248，去上下黑边后按 1920/1988 换算。live 比分 570×58、冻结比分 800×58，顶部 y=6；冻结结束收回居中紧凑外框。左上阶段/三图横条 364×34，右上独立地图详情 340px 宽，仅 freezetime 显示。布局为比分预留 800×210 固定容器，不由动画改写持久化坐标。

### 队名边界

当前 RivalHub 公共入口和 Mizar entrant 只有 `name`，没有正式 `shortName`。本轮保留完整名称并按可用宽度适配字号，禁止省略号；未把 G2.Esports 擅自裁为 G2。后续可联合增加可选 `shortName`：RivalHub 队伍编辑/存储及公开 manifest → adapter → Core entrant → Program → 比分 presentation。冻结用 name，live 用 shortName ?? name。此为展示元数据扩展，不需要改变 GSI 或 Runtime 事件架构；不得将按比赛变化的队名写入全局主题预设。

## 维护与分享

- 暂停实现集中在 `widgets/broadcast-pause/`：`BroadcastPause` 只组合比分经济栏、选手行、暂停小卡片和赛事品牌，各组件拥有对应 CSS。左右共用 DOM，命名 grid area 镜像内部栏位；physical side 与阵营颜色分离。普通选手卡与暂停选手行共用 `player-equipment/EquipmentIcon`，仅素材叶节点处理枪械朝向。验收直接测量暂停小卡片、装备列与翻转次数，避免只检查组件外框位置。
- 公共 API：`packages/hud-config/src/index.ts`；schema/type、descriptor/registry、geometry、校验、资源目录与 resolver 分别独立。四套风格各放在 `src/presets/ewc.ts`、`iem.ts`、`perfectworld.ts`、`esl.ts`，共同目录在 `catalog.ts`；同一文件管理该风格的 recipe 和内置布局组合。
- 组件方案的 envelope 由 descriptor 声明。换成上海比分或 Focus 时，即便引用默认布局，也分别解析为 800×210 和 342×192；换回其他方案使用它自己的尺寸。锚点和偏移沿用布局，越界时在解析阶段约束到画布。布局编辑、拖动和播出消费同一尺寸。Radar 保持独立的正方形 resize。冻结 snapshot 尺寸不匹配时拒绝；精确旧默认尺寸按上文兼容，不在读取时重排。
- 上海不展示实际不渲染的“队名”“系列赛胜图”“存活对比”控件；已有 schema 字段继续可读，避免改写已启用的当前版本快照。左右主体镜像内侧圆角，死亡与不显示头像的主体维持四角圆角；文字与头像保持原方向，枪械素材单独朝向画面中心。

用户在预设工作区保存更改后点击“导出预设文件”；文件完整包含组件方案、布局与外观。可以分享文件，也可以编辑其中的已声明设置和布局偏移，再点击“导入预设文件”。导入创建完整的新副本，用户从预设列表选择它预览，再显式启用。文件不依赖导出机器的自定义 ID，重复导入也不会覆盖已有资源。

格式为 `format: "mizar-hud-preset"`、`formatVersion: 1`，顶层仅有 `format`、`formatVersion`、`preset`、`layout`、`theme`；三个资源仍使用各自 `schemaVersion: 1`。内部 `preset.layoutId/themeId` 必须指向文件内的资源，导入后重写为本机的新 ID。UTF-8 文件上限 256 KiB。完整可编辑示例见 [Perfect World 预设文件](../examples/perfectworld.mizar-hud.json)。

新增现有组件方案的组合只需一份通过 `parseHudPresetPack` 的配置文件，可作为用户文件、未来内置数据或社区下载内容复用。新增组件结构或赛事造型仍需实现并注册 renderer/variant/recipe 和对应 CSS，再更新受控枚举；文件不会执行任意代码。未来社区可在这个格式上增加分发、预览和作者信息；当前实现只负责文件交换与本地持久化。

## PR 120 最后一轮状态修复与展示分享

IEM Focus 默认不显示统计；手动启用 K/A/D/ADR 时使用同一 176px envelope 内的 136px 主体与 40px 顶部留白，统计不被裁切。已保存的启用设置继续有效。道具 presence 只保留动画阶段与退出项，当前持有状态每次渲染读取新 presentation，换持有物不重启动画。选手头像失败使用声明式回退，换 URL 后可恢复。

上海安放/拆弹附加面板只在同类动作剩余时间有限且大于零时显示；完成、计时失效、状态切换或取消时同帧撤掉，不显示占位时间，也不等待退出计时器。语义 C4 图标仍由 Program bomb 状态控制，后端未启动导致的数据缺失不作为图标资源 bug 处理。

`node scripts/hud-reference/build-perfectworld.mjs` 从实际 renderer 生成离线展示 ZIP，包含预览、DOM 样本、展示数据、样式、源码、素材和许可。用途是给 Vue 项目参考移植；它不建立公共 SDK、插件协议或第二个 Runtime。说明见 [参考包 README](../../scripts/hud-reference/README.md)。

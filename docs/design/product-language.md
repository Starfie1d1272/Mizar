# 产品文案

本文是用户界面文案的唯一规范。数据格式、开发者术语和状态证据边界由 [术语文档](../development/terminology.md) 维护；界面文案不能改变其含义。

## 中文优先与事实表达

页面标题、字段名称、提示、状态、错误、操作、空状态和加载说明均使用自然中文。说清“发生了什么、可以做什么”，表达当前有证据的事实。代码字段、协议值、路径、环境变量，以及 OBS、CS2、HTTP 等标准名称保留原文。

## 正式播出标签

默认节目包和 HUD 的固定广播标签保留常规英文，例如 COMING UP、SCHEDULED、UP NEXT、HALFTIME、CURRENT、MAP STATS、FINAL MAP STATS、DECIDER。赛事名、队名、昵称和赛事提供的阶段名称保留来源文本。制作控制、预览说明与诊断仍使用简洁中文。默认节目包计划开赛时间使用 Asia/Shanghai，展示日期、时间与 UTC+8 时区；上一场卡片使用 PREVIOUS MATCH。资料的展示语义见[节目规范](program-direction-v1.md)。预览场景只标注「示例画面」。

## 桌面制作中心

| 场景 | 统一写法 |
| --- | --- |
| 一级导航 | 总览、比赛资料、播出画面；连接设置为游戏设置、OBS 连接、赛事平台、高级设置 |
| 比赛分区 | 比赛资料、队伍与名单、地图与 BP |
| 现场操作 | 启动游戏并打开工作台（桌面首次启动）、打开直播工作台、隐藏工作区、退出工作台 |
| 当前 5v5 名单识别 | 从当前服务器识别首发；无法证明双方时提示确认 CT 对应队伍 |
| OBS 当前画面缩略图 | OBS 画面确认；不称实时监看 |
| 本机覆盖设置 | 本机 HUD；两个操作为「雷达」「其他 HUD」，说明只控制本机 CS2 上方画面 |
| 应用更新 | 高级设置中的「应用更新」；版本、更新日志与「一键更新」默认展开；「更新设置」只折叠「自动检查更新」开关 |
| 更新提醒 | 空闲时显示「发现新版 v版本号」与「查看更新」「稍后」；关闭提醒不下载或安装 |
| 更新操作与状态 | 「检查更新」「一键更新」为操作；「正在更新…」为忙碌状态，下载时显示「取消」「稍后」；便携版显示「下载新版」 |

| 类型 | 写法 |
| --- | --- |
| 字段名称 | 简短名词，如“赛事名称”“比赛顺序”；一个字段对应一个清晰含义 |
| 操作 | 动词加对象，如“选择比赛”“保存资料”“收起 BP”；高影响操作明确目标 |
| 辅助提示 | 补充用途、条件或后果，不作为唯一无障碍名称或唯一错误说明 |
| 状态 | 当前事实，如“等待比赛数据”“资料已保存”；同时提供文字，不只着色 |
| 错误 | 已知问题加可行恢复，如“连接失败，请检查本地服务后重试。” |
| 加载 | 明确正在执行的动作，控件保留清晰名称、禁用与忙碌状态 |
| 空状态 | 解释当前缺失与下一步，如“尚未选择比赛”“选择比赛后可检查播出画面。” |

普通界面不直接展示内部枚举。诊断页面可以在中文解释之后显示原始标识符和协议值。`stale` 只说明数据过期，CS2 是否退出由独立证据确认。缺失的精度、状态、时间和结果保持缺失，不用文案补成确定事实。

模式名称遵循产品文档，操作名称在本表维护；新增名称必须有明确产品依据，组件样例不能自行创造业务模式或流程。涉及赛事资料时优先复用带来源记录的真实数据；状态测试只证明控件行为。

供开发者和维护者使用的命令行保留必要的代码术语与机器状态；面向现场人员的提示使用中文。

## 资源管理

「播出内容」用于预览、制作与使用；「工具与素材」用于查看依赖与维护。「方案」是 HUD、场景、音乐和运镜的组合。「当前使用」「已修改，尚未使用」沿用播出配置的版本事实；当前版本的显式重试写作「重新使用」，不把已保存草稿称为已应用。依赖更新失败与实际可用性分别表达，状态未知时不宣称已安装或可用。

## 简洁与信息层级

默认界面只展示当前状态、必要操作和下一步。优先使用简短、正向的中文；解释仅在影响用户判断或操作时出现，紧贴相关控件。以适用条件和下一步操作说明边界，每条规则集中维护。数据来源、协议、实现机制放入高级信息或诊断，预览用「示例画面」标识即可。

现场比赛卡片直接显示已知原因及对应操作：地图不一致时核对地图与 BP，上场账号与名单不一致时核对名单，比赛数据中断时检查游戏连接，启动时恢复缓存是正常状态，只有真实刷新失败才显示网络、授权或格式原因及对应操作。单项原因可展开详情，多项问题逐项处理。名单不完整、Steam64 缺失或重复身份时先补全或修正资料，不能将同时出现的未知账号直接判为不匹配。只保留异常状态而缺少具体原因时使用中性待核对提示，不推断名单或阵营冲突；不能将地图执行待确认一律称为错图，也不能将身份冲突一律称为 Steam64 不匹配。运行诊断保留技术原因，不代替已知问题的处理入口。

直播状态采用紧凑文字：OBS 正常／未推流／需检查／无法确认；Bilibili 正常／未开播／未设置／无法确认。状态有文字标签，颜色仅作辅助。预览中的 BP 操作区保留「操作将同步到 BP 播出画面」，其余说明按需展示。

本地 BP 使用「先禁图方／后禁图方」表示禁选角色，下拉项优先显示实际队名，缺少队名时才显示队伍 A／B 占位。选定先禁图方后，后续步骤由赛制和所选规则确定；先禁图方影响整套 BP 顺序，不只是第一张禁图。BO3 的最后禁图顺序与决胜图选边按当前规则显示，不能将默认规则说明泛化到所有规则。用户界面不暴露内部 `vetoA` 角色名。

本地独立比赛的名单恢复使用「从当前服务器识别首发」，须取得完整、新鲜且同一执行的 5v5 候选并确认双方；不按昵称合并账号。网站比赛与本地 BP 叠加比赛的名单由网站管理，提供「核对网站名单」与真实刷新操作，不提供本地名单写入。未关联 Steam64 的记录由身份核验模块按预期首发标记影响范围；未上场替补不会因错图、缺少观测或不完整帧变成当前名单故障，不按昵称关联账号。

地图执行有合法未完成位置时提供「确认当前图」，确认前展示实际地图与场次；切场、换图或核验变化须重新核对。没有合法位置或缺少最终比分时说明当前能力限制，保留已有资料并导出诊断反馈；确认地图位置不补录赛果。


在线比赛的完整当前 5v5 与完整网站首发存在明确人员差异时，工作台自动显示醒目提醒，分列游戏中额外出现的账号和网站首发中未观测到的账号，以昵称与可用头像展示，不按昵称猜测账号对应关系。相同比赛与差异只提醒一次；关闭后保留警告与核对网站名单入口，差异变化或完整首发恢复后重新提醒。临时资料读取失败不清除已关闭的提醒。同步状态依据实际认领、资格和网站接收状态显示：同一当前授权、生产者、会话、输入代际与地图执行已接受 LIVE 才称仍在同步；新执行等待可靠开局或网站拒绝开局时明确说明，不能沿用上一执行的 accepted 状态；未就绪、待确认或接收失败分别说明。只有资料未齐全时继续使用资料待核对提示。桌面端使用居中并请求焦点的独立核对窗口，浏览器预览使用页面对话框；提醒不控制 OBS。核对入口沿用网站本场工作台与返回刷新流程，关闭核对窗口后可返回游戏。

正式现场已关联在线比赛、预期本机同步且观测到已绑定地图的正式比赛后，网站同步状态给予短暂宽限；未认领、开局确认等待或接收中断持续存在时，工作台主动显示核对提醒；桌面端使用独立核对窗口，浏览器预览使用页面对话框。正常时仅显示简短状态；本机认领和可靠开局回执都不能代替网站接受当前执行的新实时数据。关闭后保留「网站同步需处理」入口，同一异常不重复弹窗，明确恢复后出现的新异常可以再次提醒。准备、示例试播、热身、未绑定练习和主动停用不触发；已知由其他设备供数时显示归属，接管必须明确确认。

同步异常按已知原因提供重试、重新连接网站、刷新比赛资料或检查游戏连接；未知拒收保持中性，不推断人员差异或网络根因。网站本场工作台与诊断导出放在处理入口内，人工补分不表示实时同步恢复。

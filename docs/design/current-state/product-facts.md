# Mizar 产品事实

本文描述 `Starfie1d1272/Mizar` 在 **`12d785a8b2cba7dc72cb7f15bc1f1def02a0d31b`**（本轮启动时远端 main）的产品现状。它是独立重设计的事实输入，不是新方案、未来页面清单或发布验收报告。关键结论通过 `E` 编号链接至[独立证据索引](source-index.md)；阅读正文无需阅读源码。

## 1. 产品、用户与使用情境

### P01 定位及责任范围

Mizar 是面向校园与社区 CS2 赛事的开源制播系统。现有产品覆盖赛前等待、地图禁选（BP）、对阵开场、局内 HUD、半场、单图结果、图间及整场结果，围绕真实观战画面提供比赛信息与制作控制。基础制播组合是 Windows x64、CS2 观战客户端及 OBS；游戏状态集成（GSI）提供局内观测。本地比赛资料可独立使用，连接 RivalHub 可扩展赛事资料和网站实时输出。[E01](source-index.md#e01)

赛事平台负责官方资料与正式结果，Mizar 负责本地观测及现场呈现，DAK 被定位为赛后分析的相邻工具。不能据此声称 Mizar 已提供完整报名、裁判、赛后分析或跨产品自动闭环。自动节目编排负责画面切换；游戏视角选择、推流及录像启停仍由人控制。[E01](source-index.md#e01) [E11](source-index.md#e11) [E13](source-index.md#e13)

### P05 事实的来源及冲突处理

| 信息 | 主要来源 | 缺失、矛盾及越权边界 |
| --- | --- | --- |
| 官方赛事身份、计划、登记名单、终局结论 | 本地人工资料，或经验证的 RivalHub 比赛资料 | 平台拥有官方数据；本地覆盖不能获得平台权限。同场刷新失败可保留并标过期，切到另一场失败不得把旧场当新场 |

| 单图／系列结果 | 已证明的执行、身份、比分与冻结结果；上游明确终局资料 | 已冻结本地结果不被普通刷新覆盖；未知结果只在明确兼容上游完成证据下补入；冲突保留并提示核对 |
| 精确事件特效 | 可选正式节目事件源 | 缺失时仍提供基础 GSI HUD；过期、错图或身份不符的提示不补播 |
| 提前时间轴 | 仅私有观察辅助的隔离边界 | 不能作为正式节目备用输入；存在类型和通道不证明可用 Lookahead 产品 |
| OBS 状态／缩略图／B 站直播状态 | OBS 控制接口、周期截图、解说资料中的直播间查询 | 分别只证明相应状态；均不能替代实际节目、音轨、录制试听与观众端检查 |

## 4. 现有任务流程

下面按用户任务组织，而非按页面组织。流程中的操作名用于辨认现产品，不要求未来保留相同按钮或步骤数量。

### F01 准备并完成一场本地转播

1. 创建或选择本地比赛，填写双方、赛制；按需要逐步补名单、时间、地图及 BP。空名单可以保存，不等于现场身份已满足。
2. 检查 CS2 安装与 GSI；安装／修复后重新启动游戏加载配置。核对 OBS WebSocket、场景、视频设置和音频。第一次启用 Mizar 场景集合需明确操作。
3. 请求启动游戏并进入工作台。正常路径由桌面管理本次 CS2；外部已经启动的游戏需先自行退出。工作台可以等待观战数据，不把“进入工作台”当作“比赛已开始”。
4. 在 CS2 连接赛事方提供的 GOTV；核对实际双方、首发及地图。必要时捕获本地首发、确认 CT 对应队伍或当前地图位置；复制并在游戏中执行隐藏原生 HUD 命令。
5. 核对 OBS 实际游戏、HUD 和音频，录制试听；操作者开始直播／录像。节目按条件自动推进，需要时人工接管。
6. 赛后核对结果，执行安全结束制作与游戏配置恢复。OBS 输出是否停止单独处理；结束制作不会隐式停止直播或录像。

**完成证据**：所选比赛与观测相符、实际节目及音画已人工检查；安全退出完成后回到准备状态。任何配置、身份或输出状态未知都不自动升级为“已就绪”。[E02](source-index.md#e02) [E03](source-index.md#e03) [E10](source-index.md#e10) [E12](source-index.md#e12) [E13](source-index.md#e13)

### F02 连接 RivalHub 并向网站提供现场状态

1. 通过授权流程配对，选择网站比赛并核对资料；有效本场资料自动刷新，也可以手动刷新。
2. 本地 BP 与网站冲突时保留当前 BP，其他兼容资料可更新；网站候选需明确确认，不能静默覆盖。正在进行的新选择优先于旧后台刷新。
3. 进入现场并满足绑定、名单、权限及新鲜度条件后认领数据源；LIVE 还需当前授权及执行的可靠开局被接收确认。认领成功本身不代表网站正在收到现场帧。
4. 接收端持续明确接受当前 LIVE 才可确认同步恢复。重试使用新的有效输入；不补发旧实时画面。
5. 人工停止数据源后本地立即禁发；远端释放失败也不能继续发送。明确重新认领才解除该停止；切场或重新进入工作台会重新检查认领条件。

**异常与结果**：同场失联可保留最近有效资料并标过期；换场失败不能显示旧场为新场。其他设备归属、权限失效、等待开局、网站未接收分别处理。无赛事比赛不具备当前赛事级在线输出资格。[E04](source-index.md#e04) [E14](source-index.md#e14)

### F03 补齐名单、地图及结果归属

本地首发捕获先取得当前完整可信 5v5 候选，操作者预览双方并确认阵营归属，再保存；候选或比赛变化后旧确认失效。网站比赛及本地 BP 叠加的在线比赛仍由网站提供名单。手动地图绑定只能选身份已验证、同名、未完成的计划位置，不能通过它改比分、覆盖已完成地图或新增计划。[E03](source-index.md#e03) [E07](source-index.md#e07)

已有计划严格按顺序推进；实际地图不符、上一图结果缺失等情况进入待核对。没有赛事关联且没有地图计划的比赛可按观测追加允许图池内地图，但须上一图完成、未重复、未超赛制上限；有赛事关联但等待地图计划的比赛不能靠 GSI 自建计划，本地赛事也遵循这一点。仅名单差异的在线例外可以展示实时状态并观察图结束，但不确认正式比分、胜者或系列胜场。上游兼容完成结果补入与冲突处理另有门槛。[E07](source-index.md#e07) [E14](source-index.md#e14)

### F04 编写、演示和播放 BP

选择真实资料来源，填写规则与禁选／选边，校验保存后回到隐藏态；本地比赛可编辑完整本场资料，平台绑定只能本地补 BP，不能顺带改平台身份或名单。赛事默认变化不重写已有 BP，本场规则变化也不顺带修改赛事默认。[E05](source-index.md#e05)

播放／收起是正式 BP 控制；普通节目预览的场景切换不是。BP 内置演示须在隐藏态开始或退出，不入正式资料；退出恢复真实来源，重启不恢复演示及播放。编辑断线保留草稿；冲突由用户核对后重新保存或确认网站候选。[E05](source-index.md#e05) [E16](source-index.md#e16)

### F05 自动编排及临场人工接管

| 阶段／触发 | 当前推进逻辑 | 受阻或人工操作后的结果 |
| --- | --- | --- |
| 准备阶段 | 检查和预览，不自动切正式节目 | 等待进入制作及可用资料 |
| 热身 | 有就绪 BP 时完整揭示一次，再接等待或操作者选择的游戏画面 | 不猜测缺少信号的热身结束时机 |
| 首回合冻结期 | 使用 BP 最终板，按真实剩余时间决定完整／短开场或直接 HUD | 不固定假设冻结期时长；来不及时跳过，开打不补播 |
| 实战 | HUD 与当前观战；可靠下一节目可预告 | 预告不是切场命令 |
| 常规半场 | 单图统计板，按可信进展和时间预算返回比赛 | 加时换边不当作常规半场 |
| 单图结束 | 已经观察同图实战、仍在自动 Gameplay 且结果可信时先短暂保留游戏及 GG，再结果板、图间或整场结果 | 迟到接入、重连或恢复自动不补播旧 GG；统计缺失明确显示 |
| 手动选择场景 | 保持人工选择；同场景重选也核对实际 OBS | 显式恢复自动后按当前证据重新判断，不重放错过流程 |
| 数据过期、身份／地图冲突、OBS 切场失败 | 停止不满足条件的推进并显示原因 | 处理原因并恢复；不靠前端自行推测成功 |

切场先准备，OBS 确认后才提交当前节目。人工意图使过时自动请求失效。手动 Gameplay 只需新鲜正式输入，可以以中立身份展示未绑定的 Demo；这不建立赛事归属。结果类手动场景可显示已有冻结摘要或等待内容，不确认比赛结束或赛果。[E11](source-index.md#e11)

### F06 编辑和分享 HUD

选择内置风格与样例，另存自己的副本，编辑组件／布局并预览；保存后显式启用才改变正式播出。内置资源只读，未保存编辑、已保存但未启用、已启用是三个结果。导出前处理未保存修改和引用；导入生成新副本，仍需选中、预览、启用。导入失败保留原配置；多窗口版本冲突保留草稿，不能自动覆盖。[E15](source-index.md#e15)

样例录像、样例投影和静态展示有各自来源；真实同步回放的 HUD 与雷达同游标。素材失败可切静态样例继续编辑，不应把样例当成现场数据。预设文件包含受控外观，不包含比赛、图片或代码；当前界面不提供完整外观工作区。[E15](source-index.md#e15) [E16](source-index.md#e16)

### F07 检查 OBS 并控制输出

保存并测试连接后核对 Mizar 场景集合与来源；当前集合为 Mizar 时可自动恢复安全可修复项，其他集合不会被自动切换，自定义来源保留。配置修复需停止直播／录制。显式添加默认桌面音频与麦克风会实际采集这两种声音，之后仍需检查设备、静音和音轨。[E13](source-index.md#e13)

直播／录像独立人工启停，停止有确认，操作中或状态未知禁用相关按钮。命令超时只能表示结果未确认，不能推断已停止。OBS 场景外部变化后可重新选择节目核实恢复；缩略图、来源启用、捕获活动或 GSI 正常不证明游戏帧和声音正常。OBS 配置结束保留实例并提示手动关闭，不自动关闭用户或本次启动的空闲 OBS。[E13](source-index.md#e13)

### F08 配置和控制节目音乐

为等待、战术暂停、技术暂停、中场、单图胜利、整场胜利、开场音效选择本地音频并保存，或验证 ZIP 后一次性替换七组。空组静音；等待与技术暂停支持顺序循环或随机，其余固定主题。背景音乐与一次性开场音效由两层自有 OBS 媒体源输出，不替代游戏和麦克风。[E18](source-index.md#e18)

单图主题可跨图间自然播完再接等待，实际比赛恢复优先停音；最终图只播整场主题，结束静音。操作者可停止、下一首、调音量、恢复自动；在 OBS 直接停／暂停／静音／调音量也形成音乐人工保持。重连先核对实际来源和播放状态，不盲目重播。断连时媒体可能仍播放，需在 OBS 核对。文件不上传或分享，授权由使用者提供。[E18](source-index.md#e18)

### F09 Demo 试播与恢复正式制作

准备试播，选择 HUD 与本地 Demo；OBS 需连接且停止推流，既有受管游戏先结束恢复，外部游戏自行关闭。启动前记录试播隔离，临时资料不进入比赛库，暂停正式检查点、资料修改、采集和网站输出。游戏运行、有效观战数据、选定 Demo 实际加载是不同事实。[E17](source-index.md#e17)

结束时先隔离输入并确认等待画面，再关闭本次游戏及恢复配置，最后解除试播事务。失败或重启保留隔离与恢复记录；成功恢复原正式资料、清除试播动态状态，明确重新进入正式制作后才接受正式输入。用户选用的 HUD 保留。Demo 暂停／拖动由 CS2 控制，拖动后累计统计不保证正确。[E17](source-index.md#e17)

### F10 隐藏、退出、恢复及回收比赛

隐藏只收起制作窗口，服务与游戏继续；恢复布局和返回游戏是不同操作。结束制作先核对 OBS 等待画面，再释放平台数据源，再由桌面关闭归属已确认的受管游戏、恢复临时配置。不能因断流、无窗口或关闭消息已发送就认定游戏退出。任一步失败保留具体原因、恢复记录与重试入口，不能进入“已完成”。[E10](source-index.md#e10) [E12](source-index.md#e12)

配置恢复只处理受管理字段；保留用户其他改动。原配置接管失败且无待恢复事务等阻断时，可明确保持原设置继续，但没有自动画质、帧率、游戏布局和本机 HUD 覆盖；已有恢复未完成不能借此绕过。数字键观战备份和恢复独立失败时保留对应待处理信息。[E12](source-index.md#e12)

回收比赛前核对对阵；现场或隐藏状态的当前比赛不能删除。准备／等待下从未收数据且未启动游戏的新选择可明确解除并回收；已有数据或重启恢复的选择，需桌面完成游戏收尾并确认全机 CS2 已退出。资格随新的游戏、输入、制作或绑定变化失效。恢复保持比赛身份、名单、地图、BP 与结果，采用当前赛事展示资料，不自动选中或重启比赛。回收站满／存储失败保留资料并报错。[E02](source-index.md#e02) [E03](source-index.md#e03)

### F11 排障、更新及素材维护

故障时可标记问题时间，查看当前与历史状态，主动导出保留范围内的诊断包；可选时间范围。包内有操作、阶段、原因、配置和完整性说明，含路径、业务／选手标识等非匿名内容，凭据替换后私下交付。已轮转、未采集、尚在内存、损坏或写入失败等缺口必须显示，不能从“导出成功”推断完整复现。服务打不开时桌面启动恢复入口仅按已有保护检查和恢复。[E20](source-index.md#e20)

自动诊断发送默认无同意、无接收端；未配置不能启用。若配置并获明确同意，只处理同意后的允许记录，不上传音视频或聊天。暂停保留队列；撤回停止并清待传正文，远端删除需收到确认，离线时保持待同步。本基线没有云接收服务已部署的证据。[E21](source-index.md#e21)

安装版可检查更新、读日志并明确发起一键更新，验证后下载、备份、安全退出、安装并重开；保留下载不表示获准自动安装。制作中（包括隐藏）、输出中、编辑工具未关闭或状态未确认会阻止安装。失败／取消恢复旧程序并保留资料；恢复未完成需继续处理。便携版提供下载入口，不自动执行安装迁移。当前新安装后台检查默认开启、启动及每六小时检查，已保存关闭值保持；旧手册有冲突，见 U02。[E22](source-index.md#e22)

官方示例素材状态区分下载、验证、准备、激活及失败；验证完成不等于已启用，失败也可能仍有旧活动版本。现场只准备，不切换素材；无活动缓存时可有 Full 随包素材。当前素材设置只查询状态，没有应用内重新下载操作。[E23](source-index.md#e23)

### P07 状态维度

各行是独立维度，不能合成一个笼统的“就绪／异常”。括号中的机器值只为精确辨识，不是界面文案要求。

| 编排 | 准备、自动、手动、受阻；下一节目预测／等待／结束；切场准备与已提交 | 预测不保证马上切换；人工恢复与自动条件满足分别成立 | [E11](source-index.md#e11) |
| BP | 隐藏、揭示、完整展示及收起过程；真实／演示来源；草稿／网站候选 | 预览标签不消除播出副作用；换来源需遵守隐藏及修订条件 | [E05](source-index.md#e05) |
| OBS | 连接、场景对齐、配置就绪、直播／录像各自状态与待确认 | 已连接不代表在推流；已推流不代表观众音画正常；停止请求不等于停止完成 | [E13](source-index.md#e13) |
| 平台同步 | 未启用、人工停止、其他设备归属、等待、接收中、需处理 | 授权、开局确认与新 LIVE 接受是三种证据 | [E14](source-index.md#e14) |
| HUD | 未保存草稿、已保存、已启用、版本冲突／配置读取失败 | 保存／导入不启用；故障保持最近有效配置，不改比赛事实 | [E15](source-index.md#e15) |
| Demo | 空闲、启动中、播放中、停止中、待恢复（`idle/starting/playing/stopping/recovery`） | 进程在运行和数据可用分开；待恢复时仍隔离正式数据 | [E17](source-index.md#e17) |
| 音乐 | 自动意图、人工停止／保持、播放／结束／失败及待核对 | 音乐恢复不等于画面恢复；OBS 断线不保证静音 | [E18](source-index.md#e18) |
| 更新／素材 | 更新检查、下载、准备安装、失败／恢复；素材缺失／下载／验证／就绪／失败／不兼容及活动版本 | 下载不等于安装，验证不等于激活；后台检查不授权安装 | [E22](source-index.md#e22)、[E23](source-index.md#e23) |
| 诊断／发送 | 本机持久化及缺口；未同意／启用／暂停／撤回待同步；待传／已确认 | 队列成功不等于全链日志完整；撤回不表示已经收回远端字节 | [E20](source-index.md#e20)、[E21](source-index.md#e21) |

### P08 保存、重启和失败时的连续性

| 信息／意图 | 当前保留及恢复行为 | 不能宣称 |
| --- | --- | --- |
| 本地比赛、回收站、HUD 已启用配置、本机偏好 | 持久保存；读取／写入失败按原保护保留资料或最近有效配置 | 保存请求已发送即成功 |
| 网站资料及赛程 | 最近有效缓存恢复时重新验证；与当前比赛、赛事、窗口匹配 | 缓存等于网站最新状态或新授权 |
| 系列进展 | 兼容比赛、参赛方、赛制、冻结计划的检查点恢复已知事实 | 重启恢复旧遥测、目标时钟或所有实时统计 |
| 网页实时连接 | 重连取当前基线，过期短时事件不补播 | 断线期间的每帧与动画均重放 |
| 可靠发送队列 | 保留幂等身份与回执；损坏时只恢复可证明同次完整提交，否则隔离旧事件并提示核对 | 自动补齐未知送达结果，或用新授权重发不兼容旧事件 |
| 游戏配置及试播隔离 | 有待恢复记录就继续核实进程、配置、隔离，失败保留重试 | 新开一次工作台即可覆盖旧恢复事务 |
| 音乐人工停止 | 持久保留；重连核对实际媒体，显式恢复 | 刷新自动解除人工意图 |
| 日志／采集 | 有界日志会轮转；采集当前不自动到期清理；异常退出可留下不完整记录 | 无限历史、必然零丢失或普通支持包等于全部原始采集 |

## 6. 明确要求与当前实现选择

### R 明确的产品及业务要求

此表提炼基线已经明确的要求，不新增愿景、商业目标或验收承诺。后续是否改变产品范围是独立决策，不能仅依据当前 UI 作答。

| 编号 | 现产品应满足的要求 | 依据／边界 |
| --- | --- | --- |
| R01 | 核心本地制播不依赖赛事平台或可选增强；缺失增强应明确降级 | [E01](source-index.md#e01)、[E09](source-index.md#e09)；基础环境仍需要 CS2、GSI、OBS |
| R02 | 比赛为主，中文优先；状态有可理解的文字、原因和下一步，不能只靠颜色 | [E01](source-index.md#e01)、[E25](source-index.md#e25)；不固定当前色板、字号和排布 |
| R03 | 显示真实来源和未知，不凭缺失数据制造身份、赛果、位置、暂停、时钟或统计 | [E06](source-index.md#e06)–[E08](source-index.md#e08)；结果待补和不提交必须保留区别 |
| R04 | HUD、雷达、节目及公开输出对同一比赛事实保持一致；比赛、地图执行、阵营和选手身份不能混用 | [E06](source-index.md#e06)、[E07](source-index.md#e07)、[E14](source-index.md#e14) |
| R05 | 人工接管优先，显式交回自动；过期自动请求不能夺回控制或重播旧动作 | [E11](source-index.md#e11)、[E18](source-index.md#e18)；画面、音乐和网站发送的人工意图分别处理 |
| R06 | 编辑／预览与正式启用分开，具有播出效果的操作明确说明；保存冲突不覆盖用户草稿 | [E15](source-index.md#e15)、[E16](source-index.md#e16)；BP 是有实际控制作用的预览工具例外 |
| R07 | 官方资料与本地观测分责，输出需符合授权、身份及连续性条件，不越权改平台结果 | [E04](source-index.md#e04)、[E07](source-index.md#e07)、[E14](source-index.md#e14) |
| R08 | 未来时间轴、凭据和私有诊断不能混入公开节目；本机写操作与原生高影响操作受控 | [E09](source-index.md#e09)、[E24](source-index.md#e24)；界面隐藏不能代替数据隔离 |
| R09 | 退出与恢复以实际安全条件为准，只管理已确认归属的游戏及字段；异常可重试，不伪报完成 | [E10](source-index.md#e10)、[E12](source-index.md#e12)、[E17](source-index.md#e17) |
| R10 | 删除、导入、资料保存、素材激活和更新不因部分失败丢失已有有效资料；现场状态受到保护 | [E02](source-index.md#e02)、[E15](source-index.md#e15)、[E22](source-index.md#e22)、[E23](source-index.md#e23) |
| R11 | 诊断有来源、时间、操作关联、具体原因及完整性边界；凭据精确脱敏，自动回传须明确同意且可暂停／撤回 | [E20](source-index.md#e20)、[E21](source-index.md#e21)；不能承诺匿名或完整无损 |
| R12 | 有效键盘、可见焦点、可理解错误、减少动效及拖动替代操作；样例、自动化与实机证据分开 | [E25](source-index.md#e25)、[E26](source-index.md#e26)；本轮没有作无障碍或实机通过认证 |

### I 当前选择，不是独立重设计的既定答案

| 当前选择 | 可以证明的范围 | 不能因此固化的未来要求 |
| --- | --- | --- |
| 准备中心、独立工具、左右／底栏、八个可见场景按钮、多个桌面窗口 | 当前任务入口及窗口组织 | 相同导航、页数、栏目位置、不可滚动布局或多窗口结构 |
| Pulse、四套赛事参考 HUD、Graphite Instrument、字体、蓝色、1920×1080 画布 | 当前视觉和播出适配约定 | 唯一品牌表达、组件几何、交互密度或固定视觉风格 |
| 三秒 GG、开场／淡化时长、轮询间隔、数据阈值、缓存上限、默认 60 帧／秒 | 当前实现的可观察参数 | 参数数值本身是用户需求、所有设备均可达到该性能 |
| Windows x64 桌面、CS2 + OBS、RivalHub 适配、当前 BO 赛制及支持地图 | 当前交付与兼容边界 | 已支持其它平台、其它游戏或任意赛制；也不据此推断未来必须永久排除 |
| 本地服务单一运行状态、投影、文件持久化、HTTP／WebSocket、桌面私有命令 | 当前如何实现事实一致性与隔离 | 下一产品必须照搬技术栈、目录、接口路径或内部状态机结构 |
| 文件格式、字段、协议版本与输入上限 | 现系统兼容性约束；继续互通时需履行 | 没有互通目标时也必须复制所有字段、存储格式和编辑步骤 |

以上来自 [E01](source-index.md#e01)、[E11](source-index.md#e11)、[E12](source-index.md#e12)、[E15](source-index.md#e15)、[E24](source-index.md#e24)、[E25](source-index.md#e25)。当前功能范围与兼容契约仍需如实承认；“不是未来固定答案”不表示可以在现产品中无视它们。

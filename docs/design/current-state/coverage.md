# 现状文档覆盖核对

基线：**`12d785a8b2cba7dc72cb7f15bc1f1def02a0d31b`**。本页记录本轮文档核对，不作为产品测试报告或未来功能清单。交付由[产品事实](product-facts.md)、[源码索引](source-index.md)及[基线说明](README.md)组成。

## 核对方法

1. 首次读取远端 main 的 SHA，fetch 后核实相同提交；工作区干净，快进到该基线后开始梳理。
2. 从产品定位、操作手册、数据能力、架构、协议、遥测、音乐、更新、诊断、视觉规范和路线图建立任务与约束清单。
3. 反查 Web 实际路由、Companion 服务注册、桌面启动／退出／恢复与领域类型，区分“规范要求”“实际入口”“只有底层模型／接口”。
4. 对核心风险读取实现门槛和既有测试断言：制作状态、人工接管、资料与确认修订、地图计划、输出授权、HUD 保存／启用、试播隔离、更新默认值。
5. 按能力、流程、状态、异常、持久化、权限、验证范围逐项核对；对未知和矛盾独立编号，不用猜测补齐。
6. 检查交付文档的本地链接、锚点、固定提交路径／行号、证据编号及差异范围。实际检查结果见本页末尾。

范围是可影响用户任务及业务边界的现有能力，不声称逐行审计所有程序。资源导入、CI、发布脚本、样例生成、组件样式及测试工具按所属能力登记；未把每条内部参数、每个错误码或每个脚本写成产品需求。

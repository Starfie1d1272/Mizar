# 后续方向

当前产品范围见[产品定位](product.md)，发布进度由 [#90](https://github.com/Starfie1d1272/Mizar/issues/90) 追踪。本文只维护未来方向及依赖，不重复功能完成清单或承诺日期。

| 方向 | 目标 | 前提 |
| --- | --- | --- |
| 视觉包与更多 HUD | 将成套模板、风格和资源打包，降低新赛事视觉适配成本 | 保持现有组件、布局、外观与比赛数据分离；明确资源许可和版本边界 |
| 第三方 HUD 适配 | 复用既有比赛信息与节目能力，减少每套 HUD 自建后端 | 以真实接入对象验证需求，再定义共享展示接口 |
| 更多赛事平台 | 接入赛事资料，并向网站等消费者提供局内状态 | 复用 Mizar 输入与公开输出契约；各平台自行管理官方赛事事实 |
| 分发与维护体验 | 完善安装、更新、签名和现场恢复 | 基于 RC 实机使用反馈收敛，不先建设通用插件平台 |
| 观察辅助 | 探索较早时间轴、对齐与私有观察提示 | 独立数据源可用并验证时间轴；未来信息始终与正式节目隔离 |

1.0 之后的视觉包和第三方 HUD 接入，不等于当前预设文件已经能安装任意代码。现有文件交换范围见[操作手册](quick-start.md#hud-预设与文件分享)。

观察辅助研究见 [RFC-0001](rfcs/0001-lookahead-observer.md)。AI 叙事、通用插件市场和跨项目一键部署不属于当前承诺。

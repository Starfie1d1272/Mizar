# 后续方向

当前产品范围见[产品定位](guide/product.md)，发布进度由 [#90](https://github.com/Starfie1d1272/Mizar/issues/90) 追踪。本文维护未来方向及其交付前提。

| 方向 | 目标 | 前提 |
| --- | --- | --- |
| 视觉包与更多 HUD | 将成套模板、风格和资源打包，降低新赛事视觉适配成本 | 保持现有组件、布局、外观与比赛数据分离；明确资源许可和版本边界 |
| 第三方 HUD 适配 | 复用既有比赛信息与节目能力，减少每套 HUD 自建后端 | 以真实接入对象验证需求，再定义共享展示接口 |
| 更多赛事平台 | 接入赛事资料，并向网站等消费者提供局内状态 | 复用 Mizar 输入与公开输出契约；各平台自行管理官方赛事事实 |
| 界面与操作体验 | 优化准备、比赛资料、播出画面与现场工具的组织，见 [体验讨论 #204](https://github.com/Starfie1d1272/Mizar/issues/204) | 结合实际制作反馈拆分交付 |
| 分发与维护体验 | 完善安装、更新、签名和现场恢复 | 基于实机使用反馈逐项完善 |
| 观察辅助 | 探索较早时间轴、对齐与私有观察提示 | 独立数据源可用并验证时间轴；未来信息始终与正式节目隔离 |

当前预设文件分享已有组件、布局与外观，完整视觉包与第三方 HUD 接入按后续计划推进。现有文件交换范围见[操作手册](guide/quick-start.md#hud-预设与文件分享)。

观察辅助研究见 [RFC-0001](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/rfcs/0001-lookahead-observer.md)。具体交付范围以已确定的产品任务为准。

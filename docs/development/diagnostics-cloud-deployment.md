## 权限与密钥

临时部署凭据使用账户范围 API Token，不使用 Global API Key。需要的权限组为 `Workers Scripts Write`（Worker、绑定、secret 与 Cron）、`D1 Write`（仅拟执行诊断 schema）、`Workers R2 Storage Write`（读取/修改目标桶生命周期）。这些管理 API 权限属于账户范围，不能将它描述成只具有单桶或单库能力；执行程序必须额外核对上述准确账户、名称、数据库 ID 和前缀。部署结束后可撤回临时管理 Token。

Worker 运行时只持有上述 R2/D1 绑定，不持有管理 API Token、R2 S3 凭据或其他服务绑定。运行时需要的 secret 名称为：

- `INGEST_SIGNING_KEY`：签发/校验安装身份的短期接收令牌。
- `IP_HASH_KEY`：对用于短时滥用限流的网络地址生成键，不在诊断索引中保存原始地址。
- `ADMIN_KEY`：维护检索、有限读取与接收器健康接口；不得进入客户端、公开页面、日志或诊断包。

父会话在本机安全生成并写入 secret；仓库、PR 和执行证据只记录名称及是否设置，不记录值。客户端使用每安装独立登记证明，不嵌入上述共享密钥。此部署不申请 DNS、KV、Durable Objects、Queues、RivalHub、用户电脑或其他生产数据权限。

## 验收与保留的准确含义

审批前交付真实客户端到本地 Worker/R2/D1 模拟运行时的完整链路：同意、原始记录、gzip 批次、持久确认、重启、幂等重试、索引检索、实际包读取及撤回；另外验证来源/摘要/大小/认证拒绝，写入或索引失败不能确认，撤回与进行中上传竞争，以及到期清理。不得只断言 HTTP 400 或生成文件。

正文截止时间从服务端为该批次签发接收许可起计算，最长七天；离线等待会消耗这段时间，不承诺接收后重新获得完整七天。客户端首次 PUT 前把公开签名许可封入标准 gzip FEXTRA 并落盘、原子保存新 SHA，后续重试沿用同一包。许可仅绑定安装、原始 gzip 摘要与截止时间，不是鉴权凭据；仍须独立 Bearer。服务端先验签、核对原始及封装 SHA，再判断截止时间；即使批次定位行已删除，同 SHA 旧包也只能收到 410，不能重建正文或重复累计索引。签发接口不存逐批墓碑，但每批增加一次 HTTP 请求和安装鉴权查询；最终容量核算必须计入。签名密钥更换需保留有效七天许可的验证能力或明确拒收影响，不可悄悄重新签发旧包。

正文在七天到期后拒绝读取并请求物理删除。Cron 清理和 R2 生命周期是实际删除机制，不能把到期不可读说成物理删除已完成；Cloudflare 的生命周期删除通常在到期后二十四小时内执行，已有对象规则变更或故障可能延迟。撤回只有完成确认的删除才清除客户端待同步意图。[R2 生命周期行为与所需权限](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)

九十天索引只保留可识别的安装/会话、时间、版本、事件计数与故障计数等检索信息，不保留原始日志正文、路径、错误堆栈或全部逐操作详情；七天正文定位与九十天会话索引分开过期。首次同意必须明确说明索引也可识别且保留九十天，不能只写正文七天让人误认为全部删除。

配额数值在最终采集器量测后确定，部署默认拒绝接收，审批记录再填准确预算并启用。须量测正常多场、异常突发及 10/30/100 安装，包含离线恢复、PUT 次数、D1 表与索引大小以及 `rows_read` / `rows_written`；不能沿用旧的每日 12 MiB/256 云批或用截去原因缩减数据。D1 索引更新也计写入量，账户共享额度与应用预算不能冒充全账户零元硬封顶。[D1 计费与索引写入](https://developers.cloudflare.com/d1/platform/pricing/)

真实批准只覆盖审查记录中的 Worker、绑定、secret 名称、schema、限流/配额、保留规则和接收器启用。部署不等于发版；本任务不发布客户端或操作用户机器。

## 当前可审查实现

`apps/diagnostics-worker` 使用原生 Worker、R2 与 D1 绑定，没有新增服务框架。`wrangler.jsonc` 的入口及所有接收预算默认关闭，尚无真实部署。schema 只创建诊断所需表；body 定位与安装身份、会话索引分开，七天清理不保留九十天的逐批正文定位。每次上传先原子预留 D1 预算与身份，再按摘要写私有 gzip；原始保留时钟不因重试重置。正文确认只在 R2 与索引都已持久之后发送，真实 SQLite 索引失败保留重试状态；重试不重复计数。

D1 维护已登记写入者数量。并发撤回先封禁身份，再删除正文和索引；仍进行中或无法确认结束的写入者会令删除状态保持 pending。正常写入者在异步写入停止后关闭计数并再次检查撤回，后续请求才能确认 complete。接收器进程在计数关闭前崩溃属于客观不确定性：重试可以恢复完整正文接收，但不能伪造旧写入者已退出。到期/撤回持续清理正文，过期后去掉该不确定记录的检索元数据，只保留最小隔离定位和计数直至其真正关闭或经独立证据修复；不得以清理了当前可见对象冒充完整删除。隔离记录不参与维护者检索，不允许重新登记使旧身份复活。撤回立即用安装撤回标记屏蔽两种列表和正文，即使后续 SQLite 删除失败也不可见；Cron 会继续清理撤回索引。撤回后的最小认证围栏（随机安装 ID、登记证明摘要、登记/撤回时间及配额计数）不含会话或诊断内容，持续保留以拒绝旧登记证明复活，受同一 D1 分配预算硬停止保护；这项持续保留与七天正文、九十天会话索引须分别列入父会话最终审批，不能先行部署。

清理使用分页、批量 R2 删除与 D1 删除前的 deleting 状态，避免清理和重试互相越过。完整性读取在到期时立即拒绝，物理删除另有真实结果；未知写入者不阻挡健康过期正文清理。原始 IP 只用于当天加盐限流键，不写 D1。维护读取须独立 ADMIN_KEY，拒绝浏览器 Origin；原始诊断不提供公开链接。接收端不解压或重新筛选完整正文，维护读取器必须验证 SHA 与实际展开上限。

复现：`pnpm exec vitest run tests/diagnostics/cloud-ingest.test.ts`。它运行真实 workerd HTTP 服务和持久化本地 R2/SQLite D1：真实客户端队列写入、原始 cause/参数/前后状态读回、双端重启、丢失 ACK、幂等与原始 TTL、索引检索、正文到期拒读和实际删除、进行中 R2 写入与撤回、真实 SQLite trigger 注入索引故障、超限/错误元数据拒绝，以及未知写入者崩溃的重试与待同步状态。它不连接 Cloudflare 账户，不证明线上 CPU/共享免费额度或真实 Windows/CS2 表现。

源码、schema 与预算仍在准备中；本段不是部署批准记录。最终采集器量测、准确 head/schema 摘要、最终 HTTPS URL 与批准预算必须补齐后才可启用。

维护接口使用相同私有 ADMIN_KEY：`GET /admin/health` 返回本应用当天预留计数、开放写入者与 D1 分配体积，不代表 R2 账户实际总用量；`GET /admin/sessions` 可按安装/会话、版本、原始 UTC 范围及是否有错误筛选；`GET /admin/batches?installation=...` 返回七天正文定位。两种列表均有最多一百行与明确 nextCursor，时间相同也可完整分页；正文使用 `GET /admin/bodies/<installation>/<sha256>` 私下读取并校验。`POST /admin/cleanup` 与定时器执行相同有界清理。维护鉴权不放 URL 参数，原始包没有公共链接。Cloudflare 账户实际资源用量仍须父会话通过管理界面或额外获批的只读管理能力核实。

接收器还有 D1 分配体积停收阈值 `DATABASE_BYTES`，以实际 D1 `meta.size_after` 检查表、索引及分配空间；默认零，只有审批后才填值。它是保守的应用停收阈值，并发会有少量在途预留，不是账户零元硬封顶。阈值留出撤回/清理空间，不会自动 VACUUM、变更套餐或改其他库；分配空间未回收时需维护者核实后再恢复接收。完整容量模型需把该阈值、未知写入者隔离状态及所有索引计入。[D1 返回的大小与行统计](https://developers.cloudflare.com/d1/worker-api/return-object/)

故障索引按实际来源 envelope 解析，而不是按阶段名子串猜测：浏览器 failure/任务终态、Host 原始失败结果、性能窗口中的原始异常、遥测、业务原始错误和结构化服务错误共用分类。`failures` 为“含故障证据的记录数”，不声称独立事故数或现场根因；`failure_kinds` 为精简类别集合，正常取消和仅输入静默不等于故障。跨批次累计类别和计数，健康后续批次不能清除已有证据。源范围取浏览器自身 UTC、每条 Host 原始 UTC、恢复窗口源记录/原始异常/样本 UTC；已知延迟来源时钟未知时明确计数，不拿收集时间冒充发生时间。索引只是会话范围，精确事件仍以七天完整正文为准。延迟浏览器异常同样按真实发生时间检查同意，不能借延迟写盘补传同意前证据。

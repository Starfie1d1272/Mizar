# 产品介绍

Mizar 面向校园与社区 CS2 赛事，让规模有限的制作团队也能呈现完整的赛事转播。解说、观察者与制作人员可以由同一人兼任，也可以分工协作。

## 核心体验

| 能力 | 使用体验 |
| --- | --- |
| 自动节目编排 | 结合游戏进展与赛事资料，衔接赛前等待、BP、对阵、比赛中、半场、单图结果、图间和整场结果 |
| 制播工作台 | 围绕真实 CS2 画面查看大雷达、比赛资料、制作提示和播出状态，支持远程制作 |
| 赛事视觉 | Mizar Pulse 提供完整节目包装，另有四套 HUD 风格；预设可编辑、预览与分享 |
| 赛事连接 | 从 RivalHub 复用赛事资料，向网站提供局内状态与公共雷达 |
| 持续制作 | 通过连接恢复、配置备份、明确的异常提示与诊断，帮助制作人员应对现场变化 |

## 两种使用方式

**本地制作**：在本机管理赛事、队伍、比赛与 BP，独立完成转播。

**连接 RivalHub**：授权后选择网站已有比赛，核对资料并进入现场。网站管理官方资料与结果，Mizar 提供现场游戏观测；两种方式共享本地制作能力。

RivalHub、Mizar 与 DAK 分别服务赛事运营、现场制播和赛后分析。其他赛事平台通过[公开协议](../reference/protocol.md)适配接入。

## 产品原则

1. **比赛是主角。** 赛事、队伍与选手身份贯穿节目，产品品牌保持次级位置。
2. **自动推进，人工掌控。** 常规场景随比赛推进；人工接管后，由制作人员决定何时恢复自动。
3. **先预览，再播出。** 保存编辑结果后，显式启用预设；具有播出效果的操作清楚标示。
4. **本地优先。** 核心转播在本机运行，平台连接扩展资料与输出能力。
5. **信息有据可查。** 已知数据按来源展示，缺失信息提供明确提示。
6. **中文优先。** 面向制作人员说明当前情况与下一步操作。
7. **共用比赛信息。** HUD、雷达、节目和公开输出使用同一份比赛事实。

## 能力边界

节目编排负责场景切换，游戏观察视角和推流启停由制作人员控制。OBS 缩略图用于定期核对画面，直播状态用于确认连接；实际音画在 OBS 和观众端检查。

半场与结果数据页使用单图统计，整场结果的选手表展示最后一图。预设文件分享已有组件、布局与外观；视觉包、第三方 HUD 与观察辅助的后续方向见[路线图](../roadmap.md)。

具体数据条件见[数据源能力](data-source-capabilities.md)，安装与制作步骤见[操作手册](quick-start.md)。

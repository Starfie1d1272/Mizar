# 快速开始与操作手册

适用于 Windows x64 安装版与便携版。下载使用 [GitHub Releases](https://github.com/Starfie1d1272/Mizar/releases/latest)，功能条件见[数据源说明](data-source-capabilities.md)。首次制作按下方步骤操作；故障时先保留现场，使用[问题处理](#出现问题时)和[诊断导出](#导出诊断包与退出)。

## 安装与升级

### OBS 支持范围

Mizar 跟随 OBS 当前稳定主版本维护支持范围；本版支持 **OBS 33 稳定版**。请从 [OBS 官方网站](https://obsproject.com/download)安装或升级。Mizar 更新不会更新 OBS 内置浏览器，旧版 OBS 可能无法正确显示播出画面。

准备阶段会核对实际连接的 OBS 版本。旧版提示升级，预发布版或尚未适配的新主版本不放行；无法读取版本时须重新检查连接。版本不受支持时不开始视频或场景准备，已有制作的退出、停止输出和恢复仍可使用。支持基线随 Mizar 版本维护，不在现场联网改变。

### Mizar 安装与更新

- **首次安装**：下载 `-WebInstaller.exe` 轻量安装器，按向导安装到当前用户目录。国内下载目录仅提供轻量安装器；需要离线使用时，从 GitHub 下载完整离线包。
- **安装版数据**：比赛、配置和日志位于 `%LOCALAPPDATA%/Mizar`，卸载保留数据。升级前正常退出并备份该目录。
- **便携版**：完整解压到可写目录，运行 `Mizar.exe`，数据在同目录 `state/`。升级时保留旧包和备份，新版解压到新目录，按发布说明迁移。转安装版时分别导出/核对预设、比赛资料及连接设置。
- **应用内更新**：在「高级设置 → 应用更新」阅读说明并点击「一键更新」。安装前保存并关闭编辑器、结束制作、停止 OBS 输出；下载可留待稍后。后台检查不自动安装，来源验证失败时保留旧版并使用正式发布入口。

旧更新器不再由国内镜像提供完整安装后端。旧版用户应保存资料、正常退出后手动运行当前安装器，不删除资料或绕过目录校验。若启动提示同一运行目录仍有其他版本服务，先用原版本完成制作、游戏和托盘退出，再启动新版。

更新中断时保留备份和恢复记录，按「应用更新」中的恢复提示处理；程序无法打开时，在用户数据 `updates/install-*/` 查找对应工具。运行 `Restore-Mizar.cmd` 前关闭 Mizar 与残留安装向导，核对它确实属于本次安装。历史旧工具不会因安装新版自动升级，不要用旧恢复记录覆盖后来重新安装的程序。详细边界见[应用内更新](../reference/updates.md)。自定义数据目录位于安装目录内时，先手动备份再更新。

遇到 Windows 来源提示时，先核对正式下载地址和文件名。PowerShell 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath '.\<下载的文件名>'`，对照同一 GitHub Release 资产的摘要。用 [GitHub CLI](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) 核对正式安装器的构建来源：

```powershell
gh attestation verify '.\<下载的文件名>' --repo Starfie1d1272/Mizar --signer-workflow Starfie1d1272/Mizar/.github/workflows/release-qualification.yml@refs/heads/main
```

核对结果里的源码摘要与该版本标签；Windows 发布者信息在文件属性中单独查看。

## 制作第一场比赛

1. 在「比赛资料」创建或选择本地比赛，至少填写双方队名和赛制；使用 RivalHub 时先在「赛事平台」授权，再选择比赛。
2. 在「设置 → 游戏与观战」选择标准启动或 MulNX，并保存下次启动设置。自行打开的 CS2 请先退出，再由 Mizar 启动。
3. 在 OBS「工具 → WebSocket 服务器设置」启用服务器并保留身份验证。在 Mizar「设置 → OBS」填写对应端口与密码，点击「保存并测试」。
4. 停止直播、录像、回放缓冲与虚拟摄像头后，点击「打开工作台」。面板先打开，游戏、GSI 与 OBS 分别准备；有失败可按提示重试未完成步骤。配置写入或临时捕获检查未收尾时，等待完成再开播。
5. 在「GoTV 连接」提交本场地址。标准启动按提示复制到 CS2 控制台执行；MulNX 自动连接可用时由 Mizar 提交，仍须检查实际观战画面。
6. 核对当前比赛、双方首发、CT 对应队伍与地图。需要时使用「识别服务器首发」或「确认当前图」。
7. 在 OBS 检查实际节目、HUD、混音器、静音和直播音轨，录制一段试听，再开始直播。请求受理不代表平台已收到画面，开播后继续核对平台端。

没有比赛或 GoTV 也能先进入工作台准备音画。OBS 可由 Mizar 尝试打开；非标准安装位置在设置中选择 `obs64.exe`。推流地址、密钥、编码器和录制格式仍在 OBS 配置。

### 准备中的下一步

连接或重连 OBS 只检查现状。全部视频输出停止后，显式打开工作台或点击「配置 Mizar 场景」才准备专用的「Mizar 制播」集合，核对 1920×1080 画布/输出与 60 帧／秒。此集合的视觉场景、浏览器和画面结构由 Mizar 管理，额外视觉内容可能在下次准备时被修复；个人制作内容应放在其他集合。音频恢复责任保留，视觉修复不代替音频核对。

已有但归属不明的同名集合不会被自动接管。旧「Mizar」集合中明确保存的音频选择可按提示迁入，原集合保留；未完成事务或绑定冲突须先核对，不靠删除来源或记录解决。失败不会自动停止 OBS 输出。

### OBS 连接页

按页面当前动作处理：未找到程序时选择 OBS；确认未运行时打开；未监听时到 OBS 启用 WebSocket；需要认证时填写密码。未监听不等于程序没运行，改密码也不会开启服务器。

「结束本次配置会话」只结束配置任务，不表示音画验收通过，也不会停止输出。当前配置会话结束后 OBS 可能继续运行，需要时在 OBS 手动关闭。

### CS2 游戏捕获

场景可提前准备，捕获目标必须是实际 `cs2.exe` 窗口。Mizar 为本次启动传入工作台窗口参数及 `-console -allow_third_party_software -worldwide`；不修改 Steam 持久启动选项。国际服需要对应账号许可，[第三方软件选项](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)也可能影响信任系数。冲突按设置提示处理，不靠反复改启动参数排查黑屏。

正式输出使用游戏捕获与节目 Browser Source。显示器或制作窗口捕获会包含控制页面和提前信息，不应替代正式来源。黑屏排查见[出现问题时](#出现问题时)。

## 游戏与观战

**标准启动**沿用 Steam 与 Mizar 管理。**MulNX 官方启动器**需具备受支持的启动接口；Full 包提供随包版本，首次进入自动核验准备，之后保留已选版本。检查/更新 MulNX 在「资源管理」进行，不会启动游戏；标准路线不依赖 MulNX。

MulNX 可分别启用自动连接 GoTV 与自动隐藏原生 HUD。自动隐藏需要本机控制台记录，`console.log` 可能含聊天并持续增长；不希望启用时关闭该偏好并保存。ALL 公共聊天上屏的开关也在游戏与观战设置中，关闭后停止读取，下次启动停止对应记录。

### 提交与切换 GoTV

1. 在工作台打开「GoTV 连接」，粘贴赛事方提供的命令，如 `connect IP:27025; password 密码`。若赛事明确同时提供 27025/27026，填写节目用的 27025；其他情况按赛事说明设置，不推断通用端口规则。
2. 首次连接选择「连接或重新连接游戏」；已在观战、仅需辅助时选择「我已在观战，只开启提前提示」。核对选项后提交。标准路线使用「复制并前往游戏」，在 CS2 中执行。
3. 下一图使用同一工具提交新的连接意图。服务器无缝换图时选择保留已有连接，避免重复 connect。失败重试沿用原意图；接收器重试不会重发已接受的节目连接。
4. 若结果未知，先在游戏核对，再按提示处理。复制成功、命令入队或辅助接收成功都不能证明节目游戏已连接。

重新打开工具保留草稿，但服务重启或切场后须按当前状态重新确认。提交新地址会清理旧提示和时间校准，工作台、OBS 与游戏继续运行。

### 解说快捷键

标准、MulNX 和 Demo 都请求加载同一解说 CFG：数字键 1–9、0 用于原生观战选择，H 切换 CS2 原生 HUD。键身份不明、文件冲突或加载失败时按设置提示处理，不能以启动请求成功当作按键已生效。

Mizar 先备份涉及的键位与个人启动 CFG，退出或取消后恢复受管字段；后续人工修改保留，不要求删除个人配置。MulNX HUD 原值待恢复时，使用「恢复游戏 HUD」，它不重新连接或停止辅助。实际键位加载与 Steam Cloud 写回仍须实机核对。

### CS2 启动与原设置恢复

新安装默认中画质、60 帧／秒和适配工作台的无边框窗口，升级保留已保存偏好。「下次启动设置」只影响下一次启动。希望保留现有画质与帧率时，可直接选择对应的“保留画质与帧率”启动入口，无需先尝试失败；仍会备份并临时应用工作台窗口布局。

- **恢复配置备份**只恢复设置；**退出 CS2 并恢复设置**还会关闭本次受管游戏。制作尚未结束时先结束制作。
- 恢复只改仍属于本次管理的字段，保留人工新值和冲突备份。未完成恢复或未知启动不能用新启动覆盖。
- Steam 启动待确认时，先取消 Steam 请求并确认 CS2 已关闭，再按恢复提示勾选确认并恢复。
- 游戏关闭失败时，择机在 CS2 内正常退出，再重试收尾。不删除恢复记录、不自动强杀游戏。

本机 HUD 跟随实际游戏客户区，不以目标布局代替真实画面。运行中可在 CS2 视频设置调整；工具有当前帧率读回时可使用提供的选项。连接服务器时 CS2 可能拒绝更改 `fps_max`，请等不影响比赛的时机返回主菜单设置并读回，不为调帧率强行中断比赛。参见 [Valve 更新说明](https://www.counter-strike.net/newsentry/657081807721726196)。

### 游戏设置中的检查与维护

「CS2 与 GSI」分别显示配置文件、窗口与实时数据。未确定安装时，可选择安装目录、`game/bin/win64` 或 `cs2.exe`。已安装 GSI 不等于已收到游戏数据，新配置须重新启动游戏加载。

配置缺失、变化或重复时使用「修复 GSI」；显式修复先保存原件，保留首次备份及原令牌。自动准备不覆盖未知文件。需要撤销时使用「恢复原 GSI 配置」，更换安装位置前先完成游戏收尾和原 GSI 恢复。读取失败可点击「重新检查 CS2 与 GSI」，不要把读取失败当作未安装。

## 比赛资料与工作台

### 比赛库与现场首发

本地比赛只需双方队名和赛制，赛事归属可选；队标、名单和 BP 可后补，也可复用已保存队伍。进入观战并看到完整十人后，在左栏「识别服务器首发」，预览 CT/T 队伍与选手，再确认保存。上下文或名单变化后重新识别；网站比赛仍回网站维护官方名单。

RivalHub 比赛库定期刷新授权赛程，详情按选择加载；离线保留已浏览资料，但载入本场仍须联网核对和确认。浏览另一场不切换当前制作。当前比赛的资料刷新、BP 冲突和同步恢复见[网站资料更新与恢复](#网站资料更新与恢复)。

在「地图与 BP」确认地图顺序、当前图及禁选。只记录地图结果时可以不填起始边，不会补造 BP 动画；完整有效 BP 才用于动画。已有比分或完成时间的地图受保护，不能由编辑裁剪覆盖。

### 回收本地比赛

在「切换比赛 → 管理本地比赛」确认对阵后移入回收站，恢复不自动切换本场。当前比赛先结束制作；接收过游戏数据或重启恢复的选择，需用「关闭游戏并允许删除」完成游戏收尾，外部 CS2 自行关闭后重试。尚未接收数据、未启动游戏的准备期新选择可按确认直接解除。数据过期不等于游戏已退出。

回收保留比赛文档，共享队伍、HUD 和其他比赛不受影响。资料库读取失败时保留文件及草稿，修复权限或文件后使用「重新加载资料库」；不要建空文件覆盖未知资料。

### 常用现场操作

| 操作 | 作用 |
| --- | --- |
| 隐藏工作区 / 返回设置 | 收起界面，保留游戏、制作与网站同步 |
| 返回游戏 | 显式请求把输入交给 CS2；Windows 拒绝时手动选择窗口 |
| 恢复布局 | 重新排列本机窗口，保留当前输入焦点 |
| 恢复本机 HUD | 仅重建本机覆盖层，不改变播出预设 |
| 雷达 / 其他 HUD | 控制自己的游戏覆盖层，不关闭 OBS 中的 HUD |
| 开始/停止直播、录像 | 控制对应 OBS 输出，停止需确认；平台与音轨仍在 OBS 配置 |
| 结束本次制作 | 关闭本次游戏、恢复配置，分别显示本地与远端收尾结果 |

首次进入只有限尝试聚焦游戏，普通面板操作和切节目不会抢焦点。窗口化/无边框受管 CS2 可与面板联动恢复，但 Alt-Tab 仍是多个窗口；隐藏、模态窗口或独占全屏不强制展开。OBS 画面确认是定期缩略图，含义见[工作台状态边界](data-source-capabilities.md#工作台的状态边界)。

## 赛前核对与异常提醒

热身时检查实际 OBS 画面、更新时间、音轨和录制试听。完整首发差异按提醒核对；换边时暂时不完整不直接判为冲突。关闭提醒只收起窗口，不清除故障；正常等待和成功检查不要求逐项点击确认。

网站同步通过固定「比赛同步」入口核对。热身等待正式数据不一定是故障；认领成功、开局可靠回执和实时接收分别显示。缺资料、游戏数据、身份或首发时处理具体原因，不用反复重连代替核对。准备完成后由制作人员按赛事流程通知选手，Mizar 不发送选手准备命令。

## 节目编排与现场控制

新制作会话默认自动衔接 BP、对阵、比赛、半场与结果。点击场景或在 OBS 手动切场即接管，需要时点击「恢复自动」；隐藏再返回保留原状态。自动暂停时先处理当前数据、比赛归属或 OBS 提示，再恢复。画面、音乐与运镜的人工接管分别控制。

BP 编辑不直接播出，未保存草稿不影响节目。工作台按有效比赛资料编排 BP；没有完整禁选记录时只显示已知地图，不造动画或选边徽标。

### 节目音乐

1. 在「设置 → 声音 → 音乐」配置等待、战术暂停、技术暂停、中场、单图胜利、整场胜利和开场音效。选择音频、音量及选段后，点击「保存并应用音乐配置」；资源库中“保存”仅保存草稿，另点“使用”才应用。
2. 音乐来源尚未准备时，停止全部视频输出并点击「配置 Mizar 场景」；播放或试听不会自行补建来源。准备后用曲目旁「试听」，最长 15 秒。试听也通过 OBS，可能进入直播/录制；输出活动或状态未知时须明确确认。不要把“播放所选”当作私下试听，它是正式手动播放。
3. 现场可播放已保存曲目、暂停、继续、停止、下一首及恢复自动。人工播放独立于自动场景，离开页面不会停；恢复自动后重新按节目阶段控制。OBS 直接暂停、停止、静音或改音量同样保留人工控制。
4. 自动音乐的单图胜利可跨图间播完再接等待，真实比赛恢复优先停音；最终图仅播整场主题。开场音效只跟随实际开场，不因刷新重放。

首次使用会加载内置节目音乐。在「导入音乐包」中可以查看内置音乐，或导入 ZIP 替换七组配置。导入失败时保留原配置。支持 WAV、MP3、OGG、FLAC、M4A，单首最多 32 MiB，实际解码以 OBS 为准。空组静音。内容制作与素材来源见[音乐契约](../reference/music.md)。

试听可在音路安全时临时开启本机监听，结束后恢复借用字段，不改变长期偏好。若提示监听未开启或恢复未确认，在 OBS 核对设备与音路；OBS 断连时媒体可能仍在播放，直接检查「音乐」「音效」来源。监听听到的是 OBS 所在机器，电平与播放回执都不证明观众端有声。

### 核对桌面混音的播放设备

首次准备默认桌面混音，需要分别控制游戏和远端解说时选择独立分路。已准备的模式可在输出期间切换，但新增来源和结构修复仍须停止全部视频输出，建议赛前完成。

设备和应用在 Mizar 保存。停止全部视频输出后，可直接选择桌面或麦克风设备；若提示监听关系未知或会改变回采路径，先在 OBS 核对相关音源的监听与节目输出，再重试，不必为换设备反复切模式。未完成模式切换仍须用「核对并恢复音频」处理，不删恢复记录。

检查实际播放设备与直播音轨，避免音乐既直接输出又经桌面监听重复收音。OBS 33、同设备或关系不明时可能暂缓监听，应选择未被桌面采集的监听设备。Sonar Chat/Gaming 等不同设备不会自动互含；耳机同时听见不代表 OBS 已采全。分别播放游戏、音乐并让解说说话，录制核对完整性与重复声音。

### 短时输入电平检查

在声音设置「音源」页点击「检查两秒输入电平」，同时说话或播放声音。显示的是本次采样在静音和音量调整前的输入峰值，不是持续电平；没有数据表示无法判断。检查不改配置，也不能替代输出音轨和录制/平台试听。

### 地图运镜与开场音效

在「设置 → 运镜」选择、编辑或导入预设，保存草稿后显式启用。需要筛选镜头时，在 Demo 试播选择“运镜筛选（MulNX）”，等待游戏数据及地图包准备后逐条播放、停止和重播，核对实际游戏画面。人工接管后，核对当前地图和包再恢复自动。制作与交付见[地图自动编排](../reference/orchestration.md)。

## 开播前 Demo 试播

1. 在桌面准备中心选择「准备 Demo 试播」，选择 HUD 和本地 `.dem`，无需先创建赛事、名单或 BP。
2. 停止 OBS 推流，完成既有游戏与恢复任务，再启动试播。配置受阻时可按提示保留画质与帧率，仍须完成备份与窗口准备。
3. 核对游戏确实加载选定 Demo，并收到有效观战数据，再检查 HUD、雷达和 OBS 音画。暂停/拖动用 CS2 自身界面；拖动后累计统计不保证正确，需要整段验证时重新开始。
4. 「结束试播并恢复设置」完成等待画面、数据隔离、游戏退出与恢复。失败保留备份，按提示重试；结束后重新核对正式比赛并明确进入正式制作。

试播保持手动编排，不写比赛库、不回传网站；所选 HUD 保留。它不能替代正式 GoTV、完整系列赛或真实推流验收。

## HUD 预设与文件分享

在「HUD 与画面 → 画面预览」选择预设，点击「应用」才改变播出。调整内置预设时先另存副本，在编辑器保存，再「启用当前预设」。预览、草稿和当前活动配置分开；HUD 预设只作用于比赛中画面，不替换其他节目主题。

编辑器的 EPL 实景与静态样例供预览，实际输出仍须在 OBS 核对。分享前保存修改，再导出 `.mizar-hud.json`；接收方导入为新副本，预览后启用。文件含组件、布局与受控外观，图片及比赛资料另行管理。多窗口冲突时保留需要的修改并重新读取版本。

C4 伤害预测可在左右选手栏分别开启，条件见[数据源说明](data-source-capabilities.md#c4-爆炸伤害估算)。

### 官方示例素材缓存

「资源管理」管理 HUD、场景、音乐、运镜和播出方案。保存、复制与导入只更新草稿，使用才切换活动配置。缺失某个模块的资源不阻止其他可用模块；失败时可能保留上次活动版本，仍须检查实际输出。

音乐原文件丢失或损坏时，在原资源详情「恢复原音频」，选择相同原音频，完成后再“使用”。修复不改选段、音量和顺序，也不自动播放。MulNX 内容依赖已验证的发行来源；没有活动素材缓存时 Full 包仍可尝试随包来源。安装未完成回安装器处理，应用内暂不提供素材重新下载。

## 网站资料更新与恢复

当前在线比赛定期刷新名单、BP 和解说，也可手动刷新。与本地 BP 冲突时先核对候选，再「确认加载网站版本」；断线编辑保留草稿，按修订提示处理。

现场资格就绪后可自动首次认领来源，具体状态在「比赛同步」核对。「停止作为数据源」保留人工停止，继续时明确「恢复网站同步」，先核对旧交付和当前所有权，不默认接管其他设备。返回设置或重新显示工作台不会重认领。已落盘不代表网站已接收；有未确认队列或来源时保留记录并导出诊断，不手动删库或重发旧事件。

网站队列容量报警时，先导出诊断并按原比赛核对来源是否完成，结束制作后正常退出 Mizar。备份整个数据目录：安装版为 `%LOCALAPPDATA%/Mizar`，便携版为 `state/`。其中 `data/reliable-outbox.json.sqlite` 及仍存在的 `-wal`、`-shm`，须与同次备份的来源账本一起保存。需要离线排查时在副本上用 SQLite 只读执行 `PRAGMA quick_check;`。恢复前保留当前整套目录，并核对备份以后是否还有网站已收事实、撤权或来源变更；有变化时先由维护者对账，再决定恢复。

## 出现问题时

| 现象 | 下一步 |
| --- | --- |
| 启动无窗口 | 查看启动提示和日志，核对完整解压、可写目录及 WebView2 |
| 没有比赛数据 | 核对真实观战、GSI、游戏是否重启加载配置，再查看接收状态 |
| 队伍、首发或地图不符 | 核对本场、CT 对应关系和地图绑定，网站名单回网站维护 |
| HUD 修改未生效 | 核对已保存、已启用以及当前活动预设 |
| 自动编排暂停 | 处理具体数据/归属/OBS 原因，再恢复自动 |
| 工作台布局异常 | 核对窗口模式、分辨率和显示器，再“恢复布局” |
| 资料库不可用 | 保留文件及草稿，修复权限或已核实文件，再“重新加载资料库” |
| 退出或恢复失败 | 正常退出 CS2，保留事务和备份，按当前阶段重试并导出诊断 |

缺少或损坏 WebView2 时，从[微软官方下载页](https://developer.microsoft.com/microsoft-edge/webview2/)安装/修复 Evergreen Runtime。

### OBS 黑屏或节目不一致

1. 保持 OBS 与 CS2 现场，先导出诊断，再打开来源投影，避免检查动作改变原故障。
2. 工作室模式以右侧“节目”为实际输出。若来源投影有游戏而节目没有，检查节目选择、图层、启用、裁剪和遮挡；可重新播出目标场景，同场景重对齐不会重新播放动画。
3. 来源投影也无画面时检查实际窗口与捕获日志。错误 5 表示访问拒绝；错误 32 表示文件占用但不能确定占用者。择机保存工作、正常退出相关程序和 OBS 后重试，不按错误码猜测并强杀进程。
4. 必要时保留原游戏捕获，在比赛中场景增加不同名称的“窗口捕获”，仅选 CS2，置于游戏捕获上方、节目 Browser Source 下方。此临时来源会在下次配置专用集合时被清理，使用前核对观众端音画；已试失败则保留结果反馈，不反复重启全部程序。

GSI 正常、来源活动、尺寸非零或配置检查通过都不能证明像素正常。来源投影可能激活原本不活动的捕获，若打开后恢复请记录该动作。参考 [OBS 游戏捕获排查](https://obsproject.com/kb/game-capture-troubleshooting)。

## 导出诊断包与退出

在「高级设置 → 运行诊断 / 导出诊断包」保存 ZIP。默认导出当前版本全部保留证据，可选时间范围；普通单包交付一个 ZIP，多卷须一并交付全部 ZIP 和总清单。读取缺失会说明覆盖缺口，保存失败可重试同一份，重新生成才重新取快照。

反馈时说明版本、时间、步骤和实际结果。诊断含操作、技术路径、相关配置及比赛账号，**请私下交付维护者**；凭据会替换，但不能因此公开整包。导出不会自动上传。服务正常而页面打不开时，可访问 `http://127.0.0.1:3000/debug`；服务启动失败则用原生「启动与配置恢复」查看日志和重试。

安装版日志在 `%LOCALAPPDATA%/Mizar/logs`，持久资料在 `data`；便携版对应 `state/logs` 和 `state/data`。需要完整备份时正常退出后复制整个资料目录，运行中仅复制 SQLite 主文件可能遗漏 WAL。不要删除未知来源、队列、恢复记录或 `.partial` 采集来消除错误。旧版日志/JSON 包保留原位，当前导出不迁移它们。

“返回设置”与“隐藏工作区”保留制作；“结束本次制作”关闭本次游戏并恢复设置，分别显示本机、OBS 和网站收尾。“关闭主窗口”、工作台 Alt+F4 或托盘“退出 Mizar”会执行安全收尾并停止服务；工具窗口关闭只收起工具。失败保留原因和恢复入口，不以游戏窗口消失代替全部完成，OBS 输出也不会被自动停止。

## 从旧备份恢复游戏设置

在游戏设置的「游戏设置备份」选择视频备份。先退出 CS2 并完成既有恢复，核对 Steam 昵称、头像和目标，再确认。单个 `.bak` 恢复画质，含 `cs2_video.txt` 与 `cs2_machine_convars.vcfg` 的备份也可恢复帧率。Mizar 先保存当前原件，只改识别的字段；文件变化或中断时保留现场，从原恢复入口继续。取消选择不改配置。

## 私有观察辅助

在「设置 → 提前提示」保存启用、提前时间和昵称偏好，再按[GoTV 流程](#提交与切换-gotv)确认本图。偏好保存不确认新地址。提示依据两路同回合时钟校准，缺证时等待；倒计时是估计，不能保证与实际画面完全同步。

“停止提前提示接收”只暂停辅助，保留当前连接与已接受游戏命令；“恢复/重试提前提示接收”由 Host 重新核对，不重复游戏 connect。换地址使用 GoTV 工具。普通暂停与同图重连保留适用缓冲，比赛或执行变化隔离旧事件；已经显示/退休的提示不因重校准补播。

返回设置保留辅助；结束制作、游戏退出或宿主异常退出会回收观察器。私有提示不进入正式 HUD、雷达、OBS 或网站，不要用含提前信息的制作窗口作为正式输出。结束 MulNX 工作台与普通结束制作共用收尾，不因更换入口重复停止请求。

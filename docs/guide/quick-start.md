# 快速开始与操作手册

适用于 Windows x64 安装版与便携版。[南大云盘](https://box.nju.edu.cn/d/91dec4c27e5d47f38fcf/?p=/Downloads)提供国内下载，[GitHub Releases](https://github.com/Starfie1d1272/Mizar/releases)提供已发布版本、便携包与校验文件。功能适用范围见[数据源说明](data-source-capabilities.md)。

## 安装与升级

首次使用请选择名称以 `-WebInstaller.exe` 结尾的轻量安装器，按向导安装到当前用户目录。国内下载目录仅提供轻量安装器；完整离线 ZIP 从 GitHub Releases 获取，适合解压后运行、自行管理程序目录。GitHub 发布页还保留程序使用的更新与资源文件。旧更新器不再由国内镜像提供完整安装后端，旧版用户请保存资料、正常退出后手动运行当前轻量安装器。安装后双击 Mizar 打开准备中心。

安装版将比赛、配置与日志保存在 `%LOCALAPPDATA%/Mizar`。升级前正常退出 Mizar 并备份该目录，再运行新版安装包。卸载会保留用户数据。

在「高级设置 → 应用更新」阅读更新日志，点击「一键更新」。程序完成验证、备份和安装后自动重新打开。制作期间请先保存并关闭编辑工具，结束制作并停止 OBS 推流或录制；下载可以保留到稍后安装。后台检查默认关闭，开启后最多每日一次，安装始终由你主动发起。无法完成来源验证时通过正式发布页手动更新。

安装取消或失败时恢复旧程序并保留用户资料。意外中断后，下次登录 Windows 尝试恢复；仍提示需要恢复时，在「应用更新」打开恢复目录，运行 `Restore-Mizar.cmd`。如果程序无法打开，可在用户数据目录的 `updates/install-*/` 找到同一恢复工具和备份；先关闭残留的 Mizar 与安装向导，再恢复。自定义用户数据目录位于安装目录内时请手动备份、更新。

便携版完整解压到可写目录后运行 `Mizar.exe`，数据位于同目录的 `state/`。升级时保留旧包与数据备份，将新版解压到新目录，按对应发布说明迁移数据。转用安装版时，先导出所需 HUD 预设，再在安装版中核对或导入比赛资料与连接设置。

1.0 使用未签名安装包。遇到 Windows 来源提示时，核对下载地址、文件名称和发布页校验值，再决定是否继续。

## 游戏与观战

1. 在 **设置 → 游戏与观战** 选择 **标准启动（Mizar 管理）** 或 **MulNX 官方启动器**，保存启动设置。新安装默认使用标准启动；升级保留已保存的启动选择，旧设置未记录启动方式时也使用标准启动。标准启动沿用 Steam 与 Mizar 的游戏管理；支持启动协议 1 的 MulNX 可自动一键启动并执行官方环境检查；未提供此协议的当前安装版本，请按提示打开「设置 → 运镜」的手动启动与游戏交接，在官方启动器完成环境检查后启动游戏，检查实际程序路径、PID 与创建标识，再明确借用此游戏进入工作台。
2. MulNX 路线可分别选择自动连接节目源和自动隐藏游戏内 HUD。进入前核对本机版本与自动启动能力；可通过「更新 MulNX」独立准备最新发行版，不启动游戏；更新不保证获得自动启动协议，启动仍以当前安装版本的实际能力为准。自动隐藏需要允许本机控制台记录，并以该设置启动游戏；游戏生成的 `console.log` 可能包含聊天并持续增长。依赖缺失时按提示启用记录并重新启动游戏，或在游戏与观战设置关闭自动隐藏并保存。
3. 需要提前提示时，在 **设置 → 观察辅助** 独立开启功能，保存预期延迟差和提前时间，默认 120 秒与 5 秒。两种游戏启动方式都可使用观察辅助。只改提前时间会保留缓冲与测量历史并立即更新提示；改预期延迟差会清空缓冲，从新收到的事件计时。连接条件不变时，同值保存和返回现场不会重复连接节目游戏。
4. 点击 **打开直播工作台**，照常按已选方式启动或接入 CS2 并打开工作台；没有地址时游戏可先停在主菜单，不启动早源或连接旧地址。之后在工作台 **本图连接** 填写地址：粘贴 `connect IP:27025;password 密码` 或同场 `27026` 连接均可。默认将 27025 分给早源观察器、27026 分给游戏；自定义端点在高级设置分别填写。输入作为草稿，取消不会连接；点击「确认本图连接」才更新共享连接并执行。每张图使用各自的授权地址与密码，换图时重新填写并确认；不自动沿用旧密码。
5. 标准启动后在游戏控制台执行弹窗提供的节目源命令。换图保留工作台、OBS 与 CS2，提交新地址会停止旧早源并清空旧提示与时间对齐；标准模式手动执行新的节目命令，MulNX 对新地址提交一次节目连接。同地址早源失败重试不表示已换图，也不重复已接受的节目连接。确认本场连接时，MulNX 自动连接开启且当前借用实例实际拥有网关时，由 Mizar 提交节目源命令；入队不代表游戏已连接。标准与 MulNX 路线均按观察辅助开关独立启动早源观察器。
6. 左侧雷达下方显示估算状态、槽位、昵称和击杀倒计时，归零移除。地址变化时，从工作台 **本图连接** 填写并确认新地址。结束时退出工作台；服务重启后重新填写本场连接。HUD 原值待恢复时，在游戏与观战设置点击「恢复游戏 HUD」，此操作只恢复 HUD，不停止辅助或重新连接节目游戏。

音乐和运镜在设置中各有独立入口，内容制作与交付见[音乐步骤](../reference/music.md#内容制作与交付)和[运镜步骤](../reference/orchestration.md#内容制作与交付)。音乐使用 OBS；运镜使用 MulNX。正式 HUD、OBS 与网站继续使用节目时间轴。开启观察辅助后的制作窗口包含提前信息，正式 OBS 输出使用独立游戏捕获和播出 Browser Source。

## 制作第一场比赛

1. 在「比赛资料」创建或选择本地比赛，填写队伍、名单、地图与 BP。使用 RivalHub 时，先在「赛事平台」完成授权，再选择比赛。
2. 在「设置 → 游戏与观战」检查 CS2 与 GSI。准备中心会自动发现安装并配置 GSI；有多个安装或配置冲突时，选择本场使用的位置并按提示修复。安装目录、`game/bin/win64` 和 `cs2.exe` 均可用于定位。配置完成后重新启动游戏以加载。
3. 在 OBS「工具 → WebSocket 服务器设置」启用服务器并保留身份验证，再在 Mizar「设置 → OBS」填写相同端口与密码，点击「保存并测试」。连接成功且推流、录制已停止时，Mizar 会准备播出场景；有冲突时按提示检查与修复。
4. 点击顶部「打开直播工作台」。启动前完成 GSI、OBS 连接与场景检查；已经自行打开 CS2 时，按界面提示处理现有游戏。工作台可以在等待观战数据时打开。
5. 按上节确认本场观战连接。标准启动或未开启自动连接时，在 CS2 开发者控制台执行本场节目源命令；MulNX 自动连接开启时，核对游戏确实已连接。核对游戏数据、队伍、名单与地图；识别需要确认时，按制作提示选择 CT 对应队伍和实际地图。
6. MulNX 自动隐藏开启且已完成原值读取与应用时，直接核对游戏原生 HUD；标准启动或未开启自动隐藏时，点击「复制隐藏命令」，回到 CS2 控制台粘贴并执行。复制或命令入队都不代表已生效。
7. 核对 OBS 的游戏画面、HUD、混音器、静音与音轨分配，录制一段试听，再在 OBS 或工作台点击「开始直播」。

Mizar 会尝试打开已安装的 OBS，并复用正在运行的实例。非标准路径可在设置中选择 `obs64.exe`。直播平台推流地址和密钥在 OBS 中配置。连接成功且停止输出后，Mizar 自动准备场景；没有音频来源时自动添加默认桌面音频与麦克风，采集系统声音和默认麦克风。已有自定义或游戏捕获音频时保留，避免重复采集；实际设备与音轨仍需在 OBS 核对并试听。

### CS2 游戏捕获

Mizar 通过 OBS 识别 `cs2.exe` 的实际窗口。场景可以提前准备，开播前通过 OBS 预览确认游戏捕获、HUD 和声音。

本次游戏使用 `-console -allow_third_party_software -worldwide`，并传入工作台所需的窗口模式、宽高与帧率。`-worldwide` 选择国际服，需要账号具有对应许可，见 [Steam 官方说明](https://help.steampowered.com/en/faqs/view/0653-C465-7FC1-44C1)。第三方软件选项用于 OBS 捕获兼容，可能影响信任系数，见 [Valve 受信任模式说明](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)。Steam 原有启动项保持原样，冲突时按设置提示处理。

## 比赛资料与工作台

本场卡片的原因文字可打开详情，旁边操作进入对应任务。本地名单待补时，在现场工作台点击「识别服务器首发」，从当前服务器识别完整 5v5 首发，预览并确认双方后保存；网站比赛及本地 BP 叠加比赛先核对网站名单，再刷新资料。地图位置待确认时，在「地图与 BP」确认当前属于第几图；切场或换图后重新核对，已有赛果保留。没有可用位置或缺失最终结果时，保留记录并导出诊断反馈。

本地赛事可以复用队伍、安排多场比赛并查看前后场。先创建最小比赛资料，再逐步补齐时间、名单和 BP。在「比赛资料 → 地图与 BP」设置 BO3 禁图顺序和决胜图选边方式。网站比赛沿用平台提供的规则。

在「比赛资料 → 切换比赛 → 管理本地比赛」可删除不再使用的本地比赛。确认对阵后，比赛移入回收站并从赛程移除；在同一区域恢复比赛，不会自动切换当前比赛。当前比赛需先结束制作；已有游戏数据或重启恢复的选择，在桌面点击「关闭游戏并允许删除」，由 Host 完成游戏收尾并确认 CS2 已退出后，可在删除确认时解除选择并回收，包括最后一场比赛。外部启动的 CS2 需自行关闭后重试。尚未接收游戏数据且未启动游戏、处于准备状态和等待画面的新本地选择，也可直接确认回收。新的游戏启动、游戏数据、进入现场或切换比赛会使退出确认失效；数据过期不能证明游戏退出。共享队伍、HUD、网站比赛及其他比赛不受影响。回收站达到容量上限时先恢复其中的比赛；存储失败时保留资料，按提示检查磁盘空间、目录权限及诊断。

制播工作台将游戏、雷达、比赛资料和制作控制放在同一屏幕。左侧提供比赛概况与画面确认，底栏控制节目、BP 和本机 HUD，右侧提供制作工具。常用操作如下：

首次进入工作台时，Mizar 会尝试一次将输入交给 CS2；如果你已经切到其他窗口，则尊重当前选择。点击面板后，普通操作和「比赛中／BP」节目切换会保留面板焦点，需要回到游戏时点击「返回游戏」。

在 Windows 现场工作台中，从其他应用切回 CS2、左栏或底栏任一窗口，Mizar 会尝试同时恢复另外两块窗口，并保留所选窗口的键盘焦点。此联动适用于由 Mizar 启动的窗口化／无边框 CS2，不改变窗口位置和缩放；Alt-Tab 中仍可能显示多个窗口。明确隐藏工作区后不会自动展开，游戏使用独占全屏、窗口置顶或存在模态弹窗时不执行联动。

- 「隐藏工作区」：暂时收起制作页面，保留游戏和制作服务。
- 「恢复布局」：重新排列本机窗口，保留当前输入焦点。
- 「返回游戏」：尝试将键盘输入交给 CS2；若 Windows 未允许切换，按提示手动选择游戏窗口。
- 「退出工作台」：安全收起节目、释放数据源并返回准备中心。标准启动关闭本次受管理游戏并恢复配置；MulNX 启动或显式借用的外部游戏保留，恢复本场由 Mizar 修改的 HUD 原值与解除借用分别核对。

「雷达」「其他 HUD」控制自己 CS2 画面上的覆盖层，OBS 持续使用已启用的播出预设。工作台的「开始直播／开始录像」可分别控制 OBS 输出；停止时需确认，状态不明或操作进行中时按钮不可用。推流地址、密钥、录制格式和音轨仍在 OBS 中配置，也可直接在 OBS 启停。退出 Mizar 后 OBS 可继续运行。

正式 OBS 场景使用游戏捕获与播出网页源；显示器捕获会包含制作页面，适合工作台展示和远程制作。OBS 画面确认是定期更新的缩略图，直播状态的含义见[工作台状态说明](data-source-capabilities.md#工作台的状态边界)。

捕获失败时，OBS 连接页显示当前原因，自动展开「处理捕获问题」。错误 5 表示访问拒绝；无错误码的进程打开失败保持原因未知。错误 32 表示捕获文件被占用，占用者无法确认时显示未知。先保存工作、正常退出可能使用捕获功能的程序、正常退出并重开 OBS，再重新检测并核对画面。仍无画面可在 OBS 临时添加「窗口采集」并选择 CS2，核对画面与音频后再播出。挂钩未就绪本身不能证明权限或占用问题；核对捕获文件应比较版本或哈希，不能仅凭日期判断损坏。诊断包保留历史错误与相关技术事件，日志报告恢复后清除当前故障提示。

## 赛前核对与异常提醒

赛前核对可选择「本场比赛不再自动弹出」；本场静默后仍可从工作台手动打开，并选择「恢复本场自动提醒」。未关闭本场自动提醒时，新的名单或身份问题仍可自动提示；普通收起后，同一提示不会因实时通道短暂错位或数据暂缺而再次自动打开。地图变化不会覆盖本场静默偏好；切换比赛后，按新比赛的提醒偏好处理。

当前比赛热身期间，首次取得新鲜、完整且属于本场的双方五人数据后，打开「赛前核对」。正常的名单和网站检查简短显示，详情可展开；异常提供核对资料或连接入口。确认节目已恢复自动，选择热身画面。自动隐藏路线显示实际画面核对说明，无需复制命令；启用开关或存在 HUD 待恢复记录都不能证明当前画面已隐藏。需要手动隐藏时，点击「复制隐藏命令并返回游戏」，复制成功并获准切换焦点后关闭核对窗口，在游戏控制台粘贴执行，再核对 OBS 画面和试听声音；不要求在弹窗中勾选已执行。若 Windows 未允许切换，保留提示并可用 Alt-Tab 返回游戏。完成核对后，通过语音通知选手在游戏输入 `.r`。软件不会代替选手发送准备命令，也不会把复制成功当成执行成功。

网站比赛赛前检查本场绑定与本机数据源就绪，正式开始后依据网站对当前执行的数据接收确认显示同步健康；赛前「等待正式比赛数据」不是故障。网站未连接、状态不可用或正式比赛同步异常都会提醒。名单、地图和自动编排等核对依据变化后，原完成摘要不再作为当前就绪依据；同一提醒关闭后可以从工作台重新打开。

Windows 中的赛前核对、名单差异、网站同步异常和本场问题使用独立的「本场核对」原生窗口，在工作台所在屏幕居中并主动请求焦点。关闭只收起核对窗口，不停止比赛或 OBS。窗口创建失败会在工作台显示重试入口。浏览器预览使用屏幕居中的模态弹窗；Windows 前台激活和 CS2／OBS 捕获仍需实机验证。

## 节目编排与现场控制

进入工作台后默认自动编排：赛前衔接 BP 与对阵，开局切入 HUD，半场和地图结束展示统计，随后进入图间或整场结果。临近开打会缩短或跳过开场。

点击场景按钮即可手动接管，点击「恢复自动」交回控制。手动保持时，下一场景区域显示「自动推进已暂停」，恢复自动后再显示下一场景及推进原因。运镜接管后突出「确认运镜包并恢复自动」，恢复前仍需连接正常、地图与隔离包检查通过；自动运镜时提供「接管运镜」与「跳过本次」。自动暂停时，先处理数据过期、比赛归属或 OBS 切场提示，再恢复自动。观察视角、推流和录制继续由操作者控制。

工作台的「紧凑 BP 底栏」先展示完整 BP 的预览；选择「Take 底栏」才开始同一 BP 播放，关闭或切换节目场景会收起。该底栏只叠在受管比赛画面上，不代替全屏 BP。Take 时临时隐藏受管比赛 HUD；关闭底栏后，若来源身份和原状态仍可确认且期间无人修改，则恢复原可见性。底栏播出期间不要重新开启 HUD，以免画面重叠。人工更改会保留；连接中断后不自动恢复旧状态，提示待核对时请在 OBS 检查。

舞台和采访等自定义场景可手动添加浏览器源，地址为 `http://127.0.0.1:3000/program/bp-compact`（端口按本机服务地址调整），尺寸 1920×1080、透明背景。在工作台的底栏输出选择「自定义场景浏览器源」并点击「播放底栏源」；不需要切换受管比赛场景。自定义场景的图层、可见性与播出由制作人员在 OBS 中核对。关闭底栏后源恢复透明。Mizar 不自动修改自定义场景。

比赛详情中的「地图与禁选」显示地图顺序，可展开核对禁选过程。网站比赛由网站同步，正常开播无需修改；需要更正时回网站操作。准备页不控制播出，进入工作台后由自动编排安排 BP 与对阵画面。

本地比赛可选择「只记录地图结果」或「填写完整 BP」。只有地图顺序时，起始边可留空，不会生成虚构的禁选记录或 BP 动画；HUD 仍显示地图名称和顺序，未知的选图方、起始边不显示对应徽标。完整且有效的 BP 才可用于动画。编辑在弹窗完成，保存后回到同一份比赛详情；未保存的编辑不影响播出。

### 节目音乐

在「设置 → 声音 → 音乐」为等待、战术暂停、技术暂停、中场、单图胜利、整场胜利和开场短音效选择本地音频，然后保存。默认启用，空组静音。等待曲库在赛前、BP、热身与图间连续播放；等待和技术暂停支持顺序循环或随机不连续重复，其余组使用一首固定主题。曲目音量独立，未单独设置时使用所属组音量；选段和淡化在高级设置中调整。 曲目以列表显示，可逐首移除；重新选择本地文件会替换本组列表。场景配置修改后，点击列表上方的「保存音乐配置」生效。顶部混音的音乐总音量与静音独立于曲目设置；播放操作立即生效，有未保存配置时先保存，再选择正式播放曲目。整包导入在「导入音乐包」中展开，成功后直接保存，无需再点保存。

正式制作时，Companion 使用 OBS 的两个自有媒体源播放背景音乐和开场音效，保留原游戏声、环境声和麦克风。单图胜利跨图间自然播完再接等待，真实比赛恢复优先停音；最终图只播整场胜利，播完静音。开场音效绑定实际 Take，不因刷新或重连补播。现场可停止、下一首、调音量和恢复自动音乐；音乐停止与画面手动保持分开。在 OBS 直接停止、暂停、静音或调整自有音乐源，也会保留人工控制。

支持 WAV、MP3、OGG、FLAC、M4A，单文件最大 32 MiB；以 OBS 实际解码能力为准，不能播放的曲目跳过，整组无有效曲目时静音。ZIP 音乐包先验证再一次性替换七组配置，失败保留原配置，格式见[本机音乐契约](../reference/music.md)。本机文件只传给本机 Companion 保存，不联网下载或分享，也不进入比赛文档；诊断包只包含文件元信息和相关配置，不包含音频正文。请使用有权直播／录制的音乐；Mizar 不提供歌曲或音乐授权。

OBS 控制断连时，现有媒体可能继续播放；请在 OBS 混音器核对并按需停止 Mizar 的 BGM／Stinger。连接恢复后会先核对来源身份、媒体文件、状态与人工控制，再决定恢复；不以检查通过代替实际音轨和观众端试听。

### CS2 启动与原设置恢复

配置无法接管时，Mizar 先在本机备份原始文件，并说明重复字段、格式或 `fps_max` 数值问题。可选择「保持原游戏设置继续」打开工作台：本次不应用自动画质、帧率和游戏窗口布局，本机 HUD 覆盖停用；退出时保留游戏运行期间的新设置。原始备份可从「打开备份目录」查看，不会自动用它覆盖当前设置。上次恢复未完成或进程归属待确认时，先完成恢复，不能通过此入口跳过保护。

默认以无边框窗口、适配工作台的分辨率、最高画质和 60 帧／秒启动。在「游戏设置 → CS2 启动设置」选择画质与帧率并保存，下次启动生效。同一卡片的「配置与恢复」显示当前恢复状态；「恢复配置备份」只恢复设置，「退出 CS2 并恢复设置」会关闭本次游戏后恢复，制作尚未结束时按钮会说明先结束制作。中画质包含 FSR 缩放；「保留原画质」沿用自己的设置。60 帧／秒便于为雷达与 OBS 留出资源，30 帧／秒适合资源紧张或 30 帧播出。

游戏保持 16:9。1920×1080 屏幕对应 1440×810 游戏窗口，2560×1440 屏幕对应 1920×1080。更改屏幕分辨率后，若提示游戏未接受尺寸，退出工作台再重新进入；显示缩放变化由工作台自动适配。

Mizar 在启动前备份本账号视频与帧率设置，正常退出后恢复受管理字段，包括启动脚本中的直接 `fps_max` 赋值。受管理期间保留启动配置原样；外部改动或动态帧率命令需要按提示核对。默认继续使用自己的键位。

可在同一卡片为当前 Steam 账号明确启用完整解说键位，下次标准启动时生效。Mizar 会检查账号、安装位置、本地槽位、安装自带的默认资源和个人启动脚本；无法唯一确认或发现冲突时会说明原因并使用基础观战模式。退出游戏后按启动前的本机持久配置恢复；如果受管理键位已被其他程序修改，保留当前文件和备份供核对。此设置不保证脚本执行后的即时键位或 Steam Cloud 状态，Demo 试播与 MulNX 不使用此选项。

连接服务器时，当前 CS2 会拒绝更改 `fps_max`，控制台提示“现在不能更改”表示命令没有生效。按 [Valve 更新说明](https://www.counter-strike.net/newsentry/657081807721726196)，需要等到不影响当前比赛的时机断开到主菜单，再设置上限并查询 `fps_max` 确认，之后重新连接。Mizar 的启动设置保存后只影响下次启动；不要为了调整帧率中断当前比赛或强行重启 Mizar。

异常退出后，到总览或「游戏设置」查看恢复提示。先确认 CS2 已关闭，再「恢复配置备份」。Steam 启动超时时保留待确认状态与备份；取消 Steam 启动请求并确认游戏退出后，勾选确认恢复。备份可通过「打开备份目录」查阅，保留待恢复记录供重试。

工作台窗口的 Alt+F4 只隐藏工作区；结束本次制作使用红色「退出工作台」，关闭 Mizar 使用托盘「退出」。如果提示 Windows 拒绝关闭请求、未找到游戏窗口或关闭等待超时，请在不影响比赛的时机通过 CS2 自身正常退出，再到准备中心「重试退出工作台」或「恢复配置备份」，完成后重试托盘退出。权限拒绝不代表游戏已关闭；不要删除待恢复记录或用新的启动覆盖它。再次失败时保留具体错误，在运行诊断中导出诊断包；窗口定位正常、OBS 画面恢复都不能证明退出收尾已完成。

## 开播前 Demo 试播

在桌面准备中心总览选择「准备 Demo 试播」。双方名称默认队伍 A／B、赛制 BO1，不必创建赛事、名单或 BP；选择喜欢的 HUD，再选择一份本地 CS2 `.dem` 文件。开始时启用所选 HUD，结束后保留这一选择。

先在 OBS 停止推流，完成现有 GSI、OBS 连接与场景检查，再「启动 Demo 试播」。外部打开的 CS2 请自行退出；已有受管游戏先结束并恢复设置。试播使用同一个工作台，分别显示游戏启动与观战数据状态；游戏已运行不证明选定 Demo 已加载。收到有效、新鲜观战数据后检查 HUD、雷达及 OBS 实际音画。缺少玩家数据时不补造名单，试播保持手动编排。

配置接管失败时，可显式选择「保持原设置启动试播」，继续使用同一 Demo；此时不应用自动画质、帧率、窗口布局和本机 HUD 覆盖。

暂停和拖动使用 CS2 自身 Demo 界面；拖动后不保证累计统计正确，要重新检查整段顺播时请结束并重新开始试播。Demo 试播不代替正式 GOTV 连接、完整系列赛或真实推流验收。

「结束试播并恢复设置」先切等待画面并隔离试播数据，再关闭本次受管 CS2、恢复配置；失败保留隔离和备份，处理提示后重试。Steam 启动尚未确认时，先取消 Steam 请求并确认游戏已关闭，在已有恢复提示中勾选确认、恢复备份，再重试结束试播。结束成功后核对正式比赛，重新启动或接入正式观战数据；试播不会保存到比赛库或回传网站。

## HUD 预设与文件分享

沿用已启用配置时，直接从本场进入工作台，无需经过画面页。需要更换时，在「HUD 与画面 → 画面预览」选择预设，大画面显示该预设的实际组件、布局与外观；点击「应用」才更新播出配置，单纯选择或切换预览场景不会影响播出。等待、对阵、BP、比赛中与结果共用同一预览区域；HUD 预设只作用于比赛中画面，不会替换其他节目的主题。

需要调整位置、组件或外观时，点击「调整此预设」进入编辑器。编辑器可使用本地 EPL 实景录像与同步比赛数据预览；素材读取或解码失败时可切换静态样例。预览使用样例数据，实际 OBS 输出仍需在现场核对。

选择内置预设后「另存为」自己的副本，再调整组件、布局和外观。**保存后点击「启用当前预设」，让配置用于正式播出。** 预览与草稿独立保存，已启用配置可在重启后恢复。更改布局后，核对预设引用并再次保存、启用。

分享时先处理未保存修改，再「导出预设文件」。接收方「导入预设文件」后得到新副本，选择、预览并启用。`.mizar-hud.json` 文件包含组件、布局与受控外观，图片和比赛资料分别管理。多窗口编辑冲突时保留需要的修改，按提示重新读取版本。

左右选手栏分别提供「C4 伤害预测」开关。估算条件与支持地图见[数据源说明](data-source-capabilities.md#c4-爆炸伤害估算)。

## 网站资料更新与恢复

连接 RivalHub 后，当前已确认比赛的名单、BP 与解说资料会自动刷新，也可点击「刷新比赛资料与 BP」。本地补录与网站版本冲突时，核对候选并「确认加载网站版本」，再回工作台恢复数据源。

「停止作为数据源」会保持人工停止状态，点击「成为本场数据源」恢复；切换比赛或重新进入工作台会重新检查自动认领条件。BP 编辑断线时保留草稿，连接恢复后按版本提示核对并保存。

OBS 或 Mizar 重启后，会尝试重新加载当前 Mizar 场景集合内地址一致的播出网页源。修改过的来源或其他场景集合按自己的配置核对，具体接入条件见[数据源说明](data-source-capabilities.md)。

打开准备中心不要求 OBS 常驻，也不会尝试启动 OBS；在桌面版进入 OBS 配置时自动尝试打开，未安装或位置失效时在该页处理。完成配置可点击「完成 OBS 配置」。Host 只记录自己在本次配置中启动的实例；已存在、手动打开、制作中、输出中或无法确认的实例都会保留。当前 OBS 接口无法保证原子的安全退出，因此本次配置启动的空闲实例也保留，并提示在 OBS 中手动关闭。离开配置页或刷新时，Host 清理旧页面的配置会话并保留实例；下一页面给出核对与手动关闭提示，不停止任何输出。

OBS 设置的「检查画面」显示实际节目与 Mizar 选择、编排模式及「节目与捕获诊断」。场景不一致时，在工作台重新点击要播出的场景即可恢复；同场景重新播出不重启 BP 或对阵动画。等待、BP、半场与结果等全屏包装不使用游戏采集，要核对游戏画面请选择「比赛中」。多个可选 CS2 窗口时保留仍有效的已选目标，制作人员在 OBS 核对目标。

黑屏仍存在时，先保持 OBS 与 CS2 运行，通过现有入口导出一次诊断包，再打开来源投影，避免激活来源后丢失原状态。OBS 开启工作室模式时，左侧预览与右侧节目可以不同；实际播出以右侧节目为准。在来源列表右键「Mizar · CS2 Game Capture」，打开「窗口投影（来源）」核对：来源投影有游戏而节目没有，优先处理节目选择、图层启用、裁剪或遮挡；来源投影也没有游戏，优先检查捕获目标和 hook。来源投影可能激活原本未活动的捕获源；若打开后恢复，请记录该动作。不要以 GSI 正常、配置检查通过或来源尺寸非零代替实际画面核对。

诊断包内实时节目证据包含工作室预览是否与节目相同、当前节目顶层来源的顺序与几何；名称按角色导出，不含用户自定义名称。分组只标记顶层分组，组内遮挡、来源滤镜和实际像素仍需本机核对。已保存 OBS 配置与实时证据分开，近期 hook 日志及进程权限用于选择恢复分支，不能单独证明当前画面正常。

若诊断提示「OBS 捕获文件被占用（错误 32）」，先保存工作，正常退出可能使用捕获功能的程序，再正常退出并重开 OBS，重新检测画面。该错误不能确定占用程序，不要据此指定或自动结束某个进程；诊断改善也不等于捕获故障已修复。

如果来源投影有画面，按测得的问题重新播出目标场景，或仅修复受影响来源的启用、图层和变换。若 CS2 在本机有画面、游戏捕获仍失败，可在 OBS 为当前比赛中场景保留原来源并新增一个不同名称的「窗口捕获」，仅选择 CS2 窗口，放在游戏捕获上方、节目 Browser Source 下方，作为临时恢复；核对节目和观众端音画后再使用。此方式绕过游戏捕获 hook，不能保证所有机器均恢复；已尝试且失败时保留结果反馈，不再重复更改第三方兼容启动项或重启全部程序。不要用制作工作台窗口或显示器捕获替代正式来源。

源启用、目标窗口可选、OBS 报告活动与来源尺寸分别表示不同证据，均不证明已捕获正常游戏帧或实际捕获 PID。黑色画面可能是正常内容或游戏暂未渲染，应检查 OBS 实际节目与日志；CS2 捕获兼容性可参考 [OBS 官方排查说明](https://obsproject.com/kb/game-capture-troubleshooting)，不要仅凭 GSI 正常或配置检查通过断言音画正常。

## 出现问题时

| 现象 | 处理 |
| --- | --- |
| 双击后没有窗口 | 按启动错误提示查看日志；便携版先核对完整解压与目录可写。提示缺少 WebView2 时，按下方说明安装或修复 |
| 没有比赛数据 | 检查观战状态、GSI 配置与游戏重启情况，到运行诊断确认接收状态 |
| 队伍、名单或地图不符 | 核对当前比赛、首发、CT 对应队伍与地图绑定 |
| OBS 无画面或场景不一致 | 检查连接，停止输出后检查或修复场景，再查看实际画面 |
| 修改 HUD 后画面未更新 | 保存并启用所选预设，核对引用的布局 |
| 自动编排暂停 | 处理页面给出的数据或 OBS 提示，再恢复自动 |
| 工作台布局异常 | 确认显示器、游戏窗口模式与分辨率，使用「恢复布局」 |
| B 站状态无法确认 | 核对解说资料中的直播间地址、网络与实际直播间 |

WebView2 是 Mizar 显示桌面界面所用的微软运行组件，Windows 11 与大多数 Windows 10 设备已安装。若启动提示该组件缺失或损坏，请从[微软官方下载页](https://developer.microsoft.com/microsoft-edge/webview2/)安装或修复 Evergreen Runtime，再重新打开 Mizar。

GSI 配置缺失、变化或存在重复接收地址时，在「游戏设置」点击「修复 GSI」，无需先恢复再安装。显式修复会校验安装身份，保存修复前文件与记录到运行数据目录的 `data/gsi-repairs`，保留首次安装备份和原令牌后重建；自动准备仍不覆盖人工修改或未知配置。Mizar 会备份并停用同地址重复配置；「恢复原 GSI 配置」可撤销该操作。其他软件重新生成配置时保留现有文件并提示核对。操作后重启 CS2；更换安装位置前先完成游戏收尾与原 GSI 恢复。

## 导出诊断包与退出

退出工作台时，准备中心会显示正在处理的步骤。安全切场与数据源释放完成后，Mizar 才关闭本次游戏、恢复设置；失败会保留具体原因和「重试退出工作台」入口。可在收尾期间打开运行诊断，失败时导出诊断包反馈。Steam 启动待确认时，先取消 Steam 请求并确认 CS2 已关闭，再勾选确认、恢复配置并重试退出。隐藏工作区或关闭底栏不会丢失这次收尾结果。

更新失败时，「复制更新摘要」仅复制版本、失败阶段和处理建议；同处的「导出诊断包」打开统一的完整导出入口。在「高级设置 → 运行诊断 / 导出诊断包」保存 JSON。到 [GitHub Issues](https://github.com/Starfie1d1272/Mizar/issues)反馈版本、时间和操作步骤；诊断包含操作记录、技术路径、相关配置和比赛账号信息，请私下交付维护者。密码、登录令牌和推流密钥被替换，不会自动上传。默认导出全部保留日志，记录较多时可展开时间范围分次导出；压缩分卷与完整性信息保存在文件内，摘要仅作索引。

安装版日志位于 `%LOCALAPPDATA%/Mizar/logs`，便携版位于 `state/logs`。日志按单段最多 25 MiB、每类最多四段滚动保留，四类合计约 400 MiB。页面打不开而本地服务正常时，可访问 `http://127.0.0.1:3000/debug` 导出诊断包；服务启动失败时，原生「启动与配置恢复」对话框提供重新检查、查看日志和重试启动。只检查不会修改配置；CS2 正在运行时先完成当前游戏，正常退出后再重新检查。发现待恢复备份后可明确选择恢复，继续沿用原有进程、路径和读回保护；Steam 启动待确认时需先取消 Steam 请求并确认游戏关闭。Demo 试播隔离需要本地服务恢复后在准备中心处理，不能通过此入口解除。恢复失败或清理未完成时显示原始具体原因，保留原备份与记录；按提示处理文件占用、目录权限或记录冲突后，重新检查并恢复。原始日志和配置只供本机检查，服务恢复后导出脱敏诊断包反馈。

业务历史按比赛与制作会话独立保留，退出、重启或升级后仍可导出已落盘且尚未轮转的场次，并与服务端按业务 ID 核对。诊断包说明时间范围、来源版本以及未采集、轮转、导出省略、损坏或写入失败；重启后的当前空状态不代表此前没有故障。正常退出会等待日志提交，异常退出可能丢失尚未落盘的记录。故障发生后请尽早导出；旧版本未记录的信息无法补回。容量与保留规则见[架构](../reference/architecture.md)。

安装版的持久资料在 `%LOCALAPPDATA%/Mizar/data`，便携版在 `state/data`。`series-progress.json` 是随业务边界覆盖的当前系列检查点；`reliable-outbox.json` 是发送队列，待发送事件超过 24 小时转为过期，终态历史继续受条数上限约束。这两个文件不会因正常退出或重启删除，正常更新保留资料目录；继续制作会改变其内容。`capture` 每次启动生成新的采集目录，正常退出完成收尾后去掉 `.partial` 后缀，中断或写盘失败可能留下未完成目录；目前不自动到期清理或轮转覆盖。晚些时候通常仍能取到文件，但不保证旧检查点和旧队列内容保持不变。需要保留现场时，在正常退出后复制保留资料；文件含比赛资料，只在本机检查，公开反馈使用脱敏诊断包。

发送队列损坏时，Mizar 先另存原文件和恢复副本，仅在能确认属于同一次完整提交时恢复整个副本，并保留已确认回执；无法确认时隔离旧事件、暂停其发送，仍可启动，并在运行诊断说明“旧事件未确认送达”。待核对提示在重启后保留，新事件沿用原发送检查。请核对接收端结果，通过现有导出诊断包反馈，不直接删除原文件或重新发送旧结果。队列位于安装版 `%LOCALAPPDATA%/Mizar/data/reliable-outbox.json` 或便携版 `state/data/reliable-outbox.json`；另存文件名称带 `.corrupt-`，恢复副本为 `.last-good`。旧版因此无法启动时，先确认 Mizar 进程已退出，复制保留队列，再把原文件改名隔离后重启；其他配置与 CS2 配置备份不动。改名后旧队列暂不发送，无法保证损坏文件中的全部事件可恢复；原队列含比赛资料，只供本机检查，公开反馈使用脱敏诊断包。原子替换与文件同步降低中断风险，不保证所有磁盘故障或断电场景都能恢复。

关闭主窗口通常会收起到托盘。使用托盘「退出 Mizar」完成安全收尾并停止服务；托盘不可用时，主窗口标题会说明关闭退出行为。恢复失败时保留程序、游戏与备份，修正问题后重试。

### 官方示例素材缓存

在「高级设置 → 示例素材」查看现有资源 Store 的阶段、活动版本及错误信息。「刷新」只重新查询，不下载或修复素材。没有活动缓存不代表 Full 随包素材不可用；此处不验证随包文件。验证完成但未激活时，不表示素材已投入使用。

最近操作失败时可能仍保留活动版本，实际读取仍可能失败；请通过同页诊断入口导出诊断包排查。安装未完成时，回到安装器查看失败提示并重试；应用内暂不提供素材重新下载。


### 数字键观战配置

下载包包含专用 `mizar_observer.cfg`。受管制播启动把固定文件部署到选定 CS2 的 `game/csgo/cfg`，本次通过 `+exec mizar_observer.cfg` 请求设置 `spec_usenumberkeys_nobinds 0`，把数字键 1–9 分别绑定到 `slot1`–`slot9`，0 绑定到 `slot10`，使用武器槽绑定进行观战选择，并输出加载标记 `MIZAR_OBSERVER_CFG_LOADED`。已有相同绑定可重复使用，不修改其他按键。文件不会作为 autoexec 自动加载，Steam 保存的启动项与个人 autoexec 保持原样；保留原游戏设置进入工作台不加载它。

隐藏工作台会保留游戏进程；重新进入时沿用该进程，不再次执行观战 CFG。新的受管游戏启动才会提交本次 `+exec`。同名文件内容与当前固定 CFG 完全一致时可重复使用；旧版只设置观战变量的固定 CFG 可自动升级，自行编辑的同名文件会保留并跳过加载。

加载前，现有配置恢复机制在 `spectator-recovery.json` 单独保存原观战字段，以及当前账号主键位文件 `730/local/cfg/cs2_user_keys_0_slot0.vcfg` 中十个键的原命令；空命令与缺失字段分别记录，不备份整个键位文件。原观战字段缺失、重复或异常，存在可见 convars 用户或云镜像，原键位文件无法读取或解析，或数字键存在不同命令的重复字段时，只跳过观战 CFG 并显示原因，画质、帧率和工作台仍可使用。一致的重复绑定不阻塞加载。

停止游戏后，在当前主键位文件中只恢复这十个键，保留其他按键及其他字段的游戏写回。当前值仍为本次 `slotN` 或已经是原值时允许恢复；某个数字键被外部改成其他值时，保留该文件与备份，不覆盖外部修改。原观战字段与数字键分别尝试恢复；其中一项失败不阻塞另一项，也不阻塞帧率与画质恢复。原值与错误保留在 `spectator-recovery.json`，设置页提供「重试恢复观战原值」和「打开备份目录」。未解决前后续启动跳过观战 CFG，不覆盖这份记录。旧恢复记录继续只恢复原观战字段，不接管键位。确定本次未提交观战加载或 Steam 启动进程创建失败时，不恢复未接管的设置。

CFG 已部署、启动已提交不代表游戏内加载或切人已验证。当前变量带归档标志，移除 `+exec` 不保证恢复旧值；可见镜像探测也不证明所有 Steam Cloud 映射已知。仍需 Windows + 当前 CS2 验证：原值 0/1、数字键自定义／空／缺失绑定下启动，检查加载标记、运行时值和 1–9、0 的实际绑定，并在 GOTV/Demo 按 1–9、0；再核对退出恢复、普通重启与 Cloud 同步后原值及绑定。数字键仅恢复上述主键位文件，不回写其他键位文件或 Cloud 镜像。两位解说可以与导播同室共屏，不要求副屏、远控或独立 GOTV。

### 准备中的下一步

总览先选择已有比赛或创建本地比赛；只检查画面时，点击「创建 Demo 测试比赛」打开既有 Demo 试播，试播资料不入比赛库。已有比赛选择继续保留。

OBS 连接成功且推流、录制停止时，自动创建或启用 Mizar 集合、补齐自有场景与来源，并在首次创建／切换集合后切入当前编排选择的节目。其他集合保留不删除；已在 Mizar 集合内检查期间，如果用户切走集合则停止本次修复。随后补齐默认音频，已有自定义音频或游戏捕获音频时只检查、不重复采集。页面显示自动准备进度，剩余音频问题自动展开；名称冲突、静音、音轨和视频设置按具体原因处理，不自动覆盖。失败可点击重试自动配置，详细诊断沿用高级设置中的导出入口。

视频设置需在 OBS「设置 → 视频」手动确认画布、输出均为 1920×1080，常用 FPS 为 60；返回准备中心后自动复查。推流或录制中不修复配置。音频采集仍通过单独的明确操作添加，检查实际设备与音轨后录制试听。

游戏设置中的 GSI 状态区分尚未检测、正在检测、读取失败和实际安装结果；读取失败不会显示为待安装。GSI 文件与 CS2 窗口状态独立更新，任一读取失败可点击「重新检查 CS2 与 GSI」重查；工具阶段提示及完整脱敏记录沿用高级设置中的诊断与支持。进入工作台仍分别检查 GSI、OBS 和制作状态，不以某一项的界面状态代替全部就绪条件。

### 地图运镜与开场音效

设置 → 运镜，在“地图自动编排”添加地图、MulNX 活动包名称与自行选择的宏；回合随机列表和其他阶段按需展开。本图开场音效可选择已导入音乐配置中的曲目，留空沿用开场组。保存后在游戏内选中对应包，再连接 MulNX、确认活动包并启用自动；现场用接管或跳过控制。用“游戏内筛选”试播已保存候选，验证后导出 JSON 留待 RC 审查。入队不表示已经播放，当前接口限制与完整实机步骤见[地图自动编排](../reference/orchestration.md)。

### 比赛库与现场首发

本地赛事与 RivalHub 赛事在比赛库中切换浏览，均采用左侧赛程、右侧比赛资料。创建本地比赛只需双方队名与赛制；赛事归属选填，填写新赛事名称会自动建立并关联。创建时会说明：进入工作台，等待双方十名选手进服且观战数据就绪后，可从游戏识别首发，核对后保存。队标和替补名单可以随后补充，复用已保存队伍会带入队标与名单。

连接 RivalHub 后，约每分钟更新已授权赛事过去两周与未来两周的赛程（包括待排期比赛）。打开或切换详情时才读取该场名单、地图与 BP，持续浏览期间约每分钟核对这一场；「刷新比赛」可立即重试。当前制作比赛仍每十秒同步。界面显示赛程同步及单场核对时间。断网保留已浏览资料供查看，未浏览过的详情离线不可用；载入本场仍需联网核对并明确确认。网站名单与赛程仍在网站维护，浏览另一场不会切换本场。 授权网站提供账号信息时显示「授权账号：昵称」，并将「我认领的」未结束比赛置顶；认领关系以授权账号标识为准，不按同名推断，旧网站未提供时保持未知。其余赛程按网站状态将进行中的比赛放在前面，其后为按开赛时间排列的未结束比赛，未排期比赛放在未结束组末尾；已结束和已取消比赛放在底部，最近结束的在前。刷新会保留仍在列表中的已选比赛。

进入现场、连接游戏服务器并进入观战后，在工作台左栏识别完整十人首发；未选择比赛时可从服务器创建本地比赛。先预览 CT/T 队伍和选手、必要时指定队伍对应关系，再确认保存。名单或比赛上下文变化会使旧预览失效，需要重新识别。网站比赛沿用网站名单核对流程，现场识别不会覆盖官方名单。

### 游戏设置中的检查与维护

「CS2 与 GSI」分别显示配置文件、游戏窗口和实时数据状态。Mizar 自动检查并配置 GSI；未安装或有冲突时显示安装／修复入口，重复文件路径在配置详情中查看。未找到安装位置时展开「安装位置与维护」，其他时候可按需展开以更换路径、恢复原 GSI 或打开配置目录。新配置需在下次启动游戏时加载；已安装不代表已经收到游戏数据。

画质与帧率保存后在下次由 Mizar 启动游戏时生效。当前游戏的状态与恢复操作位于左侧「游戏连接」，有未完成恢复或已借用外部游戏时显示对应操作，正常时不显示空恢复区域。左侧「安装位置与维护」区分 GSI 配置和游戏设置备份；右侧「CS2 启动设置」仅管理下次启动偏好，与恢复流程解耦。Steam 头像默认显示配置与缓存摘要，点击「配置 Steam 头像」或「修改头像配置」再编辑。顶部「打开直播工作台」沿用原有启动前检查和游戏接入流程。

### OBS 连接页

OBS 页保持固定的连接与节目检查布局。左侧管理控制连接、OBS 路径和音频自动配置结果，右侧自动检查节目场景与游戏捕获；连接失败时优先填写端口与密码，成功后连接表单收起。捕获异常直接展开对应处理说明和重新检测操作。直播或录制期间，场景修复和添加音频来源不可用；实际设备、音轨与音画仍需在 OBS 核对。

「OBS 配置窗口管理」中的「结束本次配置会话」仅结束配置会话，不表示音画检查通过；离开 OBS 页也会自动结束会话。原生宿主依据实例归属与输出状态决定是否保留 OBS，界面显示其实际处理结果。

## 从旧备份恢复游戏设置

在游戏设置的「游戏设置备份」选择视频配置备份。退出 CS2 并完成上次恢复后，核对 Steam 昵称、头像和目标文件，再确认恢复。单个 `.bak` 恢复画质；选择包含 `cs2_video.txt` 与 `cs2_machine_convars.vcfg` 的备份时，也恢复帧率。Mizar 会先保存当前原件，保留其他设置。中断或文件被其他程序修改时，使用准备中心恢复入口继续检查；取消选择不会修改游戏配置。

## 私有观察辅助

按[游戏与观战](#游戏与观战)开启辅助；打开工作台后，从左栏「本图连接」填写并确认本场地址。组件复用 Mizar 自带的 Node，在游戏启动后托管一路早源接收；每个客户端使用独立端点。节目源地址用于真实 CS2，不会据此启动第二路延迟无头观察器。

早源收到有效击杀后，先按设置的延迟差估算提示时间；默认约 115 秒后进入五秒提示窗口。后台初次在配置延迟差前后 60 秒内，之后围绕当前估计，以节目死亡变化和早源事件的身份、地图及顺序配对；最近 60 秒内多个顺序一致的事件可校准延迟，证据暂时不足时保持上次可信估计；超过三分钟没有新证据时暂停提示并重新校准，尚未校准时使用配置值。已显示或已退休的提示不会因校准重新排程。测量不修改配置，不能保证与画面完全同步。暂停、数据过期、换图或来源变化会清空旧事件，恢复后只从新收到的事件计时。提示使用当前节目名单与观战槽位。保存辅助偏好不会确认地址或重新连接节目源；确认本场连接后准备早源。失败时，在提示区或观察辅助设置点击「重新连接早源」。正在准备、正常重连、失败和结束分别显示，重试仅在可用时开放，不重复已接受的节目连接。关闭时在「设置 → 观察辅助」取消启用并保存，只停止辅助，不恢复 HUD 或停止 MulNX 控制；更换地址使用工作台「本图连接」，或「游戏与观战 → 切换本图观战连接」。连接仅保存在服务内存，切换比赛或服务重启后重新确认。

退出工作台、游戏退出或桌面宿主异常退出会触发观察器回收。私有提示不进入正式 HUD、雷达、OBS 或网站；正式节目精确事件的后续范围见[路线图](../roadmap.md#2x--高级观战控制与事件驱动制播)。

在「设置 → 运镜」的 MulNX 管理中展开「停止控制」，点击「停止 MulNX 控制」，核对提示后选择「结束制作并停止控制」。此操作结束本场制作、恢复 HUD 并请求停止控制，保留 CS2；正常退出工作台不等于停止 MulNX 控制。入队回执只表示请求已提交，未知结果也保持待确认，需返回游戏核对实际停止；Host 在发送前保存与游戏 PID、创建时间及程序路径绑定的持久记录；入队或结果未知都不会向同一实例再次发送，刷新、重新借用或重启 Mizar 不会解除栅栏。结果未知时不要重复操作；请在游戏内核对，需要继续控制时先正常重启该游戏。保存记录失败不发送；CS2 不会因此被自动关闭。

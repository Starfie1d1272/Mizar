# 快速开始与操作手册

适用于 Windows x64 安装版与便携版。[南大云盘](https://box.nju.edu.cn/d/91dec4c27e5d47f38fcf/)提供国内下载，[GitHub Releases](https://github.com/Starfie1d1272/Mizar/releases)提供已发布版本、便携包与校验文件。功能适用范围见[数据源说明](data-source-capabilities.md)。

## 安装与升级

首次使用请选择名称以 `-Setup.exe` 结尾的中文安装包，按向导安装到当前用户目录。GitHub 发布页的 Assets 同时提供便携 ZIP、校验文件和开发资料；便携 ZIP 适合解压后运行、自行管理程序目录。安装后双击 Mizar 打开本场制播。

安装版将比赛、配置与日志保存在 `%LOCALAPPDATA%/Mizar`。升级前正常退出 Mizar 并备份该目录，再运行新版安装包。卸载会保留用户数据。

在「设置 → 更新与支持 → 应用更新」阅读更新日志，点击「一键更新」。程序完成验证、备份和安装后自动重新打开。制作期间请先保存并关闭编辑工具，结束制作并停止 OBS 推流或录制；下载可以保留到稍后安装。后台检查默认关闭，开启后最多每日一次，安装始终由你主动发起。无法完成来源验证时通过正式发布页手动更新。

安装取消或失败时恢复旧程序并保留用户资料。意外中断后，下次登录 Windows 尝试恢复；仍提示需要恢复时，在「应用更新」打开恢复目录，运行 `Restore-Mizar.cmd`。如果程序无法打开，可在用户数据目录的 `updates/install-*/` 找到同一恢复工具和备份；先关闭残留的 Mizar 与安装向导，再恢复。自定义用户数据目录位于安装目录内时请手动备份、更新。

便携版完整解压到可写目录后运行 `Mizar.exe`，数据位于同目录的 `state/`。升级时保留旧包与数据备份，将新版解压到新目录，按对应发布说明迁移数据。转用安装版时，先导出所需 HUD 预设，再在安装版中核对或导入比赛资料与连接设置。

1.0 使用未签名安装包。遇到 Windows 来源提示时，核对下载地址、文件名称和发布页校验值，再决定是否继续。

## 制作第一场比赛

1. 在「制播 → 本场资料」创建或选择本地比赛，填写队伍、名单、地图与 BP。使用 RivalHub 时，先在「设置 → RivalHub」完成授权，再选择比赛。
2. 在「设置 → CS2 / GSI」检查 CS2 与 GSI。本场制播会自动发现安装并配置 GSI；有多个安装或配置冲突时，选择本场使用的位置并按提示修复。安装目录、`game/bin/win64` 和 `cs2.exe` 均可用于定位。配置完成后重新启动游戏以加载。
3. 在 OBS「工具 → WebSocket 服务器设置」启用服务器并保留身份验证，再在 Mizar「设置 → OBS」填写相同端口与密码，点击「保存并测试」。连接成功且推流、录制已停止时，Mizar 会准备播出场景；有冲突时按提示检查与修复。
4. 点击顶部「启动新制作并进入现场」。启动前完成 GSI、OBS 连接与场景检查；已经自行打开 CS2 时，先退出游戏。工作台可以在等待观战数据时打开。
5. 在 CS2 开发者控制台执行赛事方提供的 `connect <GOTV 地址>`，进入观战。核对游戏数据、队伍、名单与地图；识别需要确认时，按制作提示选择 CT 对应队伍和实际地图。
6. 在工作台点击「复制隐藏命令」，回到 CS2 控制台粘贴并执行，隐藏游戏原生 HUD。
7. 核对 OBS 的游戏画面、HUD、混音器、静音与音轨分配，录制一段试听，再在 OBS 开始推流。

首次开播检查会自动检查并配置 GSI、尝试打开已安装的 OBS，并复用正在运行的实例。非标准路径可在设置中选择 `obs64.exe`。直播平台推流地址和密钥在 OBS 中配置。缺少音频来源时，停止推流与录制后使用「添加默认桌面音频与麦克风」，再到 OBS 核对实际设备；这项操作会采集系统声音和默认麦克风。

### 同一场比赛持续推进

左侧一级导航为「制播 / 资源 / 设置」。制播围绕当前比赛，依次提供开播检查、本场资料、双方与首发、地图与正式 BP、HUD 与本机显示、画面检查和恢复与收尾。OBS 连接及输出摘要常显，未知状态保留“无法确认”。

已有现场隐藏后点击「返回现有现场」，沿用当前比赛、游戏与制作状态，不重复启动 CS2 或走首次配置。自动准备仅在新制作的开播检查运行；受管理游戏或待恢复备份存在时先处理 Host 提示。开播检查收到游戏数据前仍会提示等待 GSI，这不是赛前 BP 的使用门槛。

资源浏览不会替换本场：「比赛与队伍」核对已保存资料，确认载入才切换；「赛事与赛程」保存赛事资料、赛程顺序与默认规则；「HUD 文件」进入同一真实编辑器管理五套预设。设置维护本机连接与启动偏好。

### CS2 游戏捕获

Mizar 通过 OBS 识别 `cs2.exe` 的实际窗口。场景可以提前准备，开播前通过 OBS 预览确认游戏捕获、HUD 和声音。

本次游戏使用 `-console -allow_third_party_software -worldwide`，并传入工作台所需的窗口模式、宽高与帧率。`-worldwide` 选择国际服，需要账号具有对应许可，见 [Steam 官方说明](https://help.steampowered.com/en/faqs/view/0653-C465-7FC1-44C1)。第三方软件选项用于 OBS 捕获兼容，可能影响信任系数，见 [Valve 受信任模式说明](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)。Steam 原有启动项保持原样，冲突时按设置提示处理。

## 比赛资料与工作台

本地赛事可以复用队伍、安排多场比赛并查看前后场。先创建最小比赛资料，再逐步补齐时间、名单和 BP。在「资源 → 赛事与赛程」维护默认地图池与 BO3 规则；在「制播 → 地图与正式 BP」编辑本场禁选与选边。网站比赛沿用平台提供的规则。

制播工作台将游戏、雷达、比赛资料和制作控制放在同一屏幕。左侧提供比赛概况与画面确认，底栏控制节目、BP 和本机 HUD，底栏工具区提供制作工具。三项常用操作是：

- 「隐藏工作区」：暂时收起制作页面，保留游戏和制作服务。
- 「现场恢复 → 恢复现有窗口布局」：重新排列本机窗口。
- 「结束制播」：安全收起节目、释放数据源、关闭本次受管理游戏并恢复原配置，返回本场制播。

「雷达」「其他 HUD」控制自己 CS2 画面上的覆盖层，OBS 持续使用已启用的播出预设。OBS 的推流与录制由操作者在 OBS 中启停。退出 Mizar 后 OBS 可继续运行。

正式 OBS 场景使用游戏捕获与播出网页源；显示器捕获会包含制作页面，适合工作台展示和远程制作。OBS 画面确认是定期更新的缩略图，直播状态的含义见[工作台状态说明](data-source-capabilities.md#工作台的状态边界)。

## 节目编排与现场控制

进入工作台后默认自动编排：赛前衔接 BP 与对阵，开局切入 HUD，半场和地图结束展示统计，随后进入图间或整场结果。临近开打会缩短或跳过开场。

点击场景按钮即可手动接管，点击「恢复自动」交回控制。自动暂停时，先处理数据过期、比赛归属或 OBS 切场提示，再恢复自动。观察视角、推流和录制继续由操作者控制。

「制播 → 画面检查」与独立节目预览只读，不改变正式节目；「地图与正式 BP」中的「播放 BP / 收起 BP」用于控制正式 BP 播出。BP 演示适合赛前检查，切换真实来源前先收起演示。

### CS2 启动与原设置恢复

默认以无边框窗口、适配工作台的分辨率、最高画质和 60 帧／秒启动。在「设置 → CS2 / GSI → CS2 启动设置」选择画质与帧率并保存，下次启动生效。中画质包含 FSR 缩放；「保留原画质」沿用自己的设置。60 帧／秒便于为雷达与 OBS 留出资源，30 帧／秒适合资源紧张或 30 帧播出。

游戏保持 16:9。1920×1080 屏幕对应 1440×810 游戏窗口，2560×1440 屏幕对应 1920×1080。更改屏幕分辨率后，若提示游戏未接受尺寸，退出工作台再重新进入；显示缩放变化由工作台自动适配。

Mizar 在启动前备份本账号视频与帧率设置，正常退出后恢复受管理字段，包括启动脚本中的直接 `fps_max` 赋值。受管理期间保留启动配置原样；外部改动或动态帧率命令需要按提示核对。其他游戏字段与键位继续使用自己的设置。

异常退出后，到本场制播或「设置 → CS2 / GSI」查看恢复提示。先确认 CS2 已关闭，再「恢复配置备份」。Steam 启动超时时保留待确认状态与备份；取消 Steam 启动请求并确认游戏退出后，勾选确认恢复。备份可通过「打开备份目录」查阅，保留待恢复记录供重试。

## HUD 预设与文件分享

在「制播 → HUD 与本机显示」使用本地 EPL 实景录像与同步比赛数据预览，选择 Mizar Pulse 或四套赛事风格。自动播放受限时点击播放；素材读取或解码失败时可切换静态样例继续编辑。

选择内置预设后「另存为」自己的副本，再调整组件、布局和外观。**保存后点击「启用当前预设」，让配置用于正式播出。** 预览与草稿独立保存，已启用配置可在重启后恢复。正式播出摘要读取失败时显示“无法确认”；最近确认的配置单独标注，不把默认配置或历史版本当作当前确认。更改布局后，核对预设引用并再次保存、启用。

分享时先处理未保存修改，再「导出预设文件」。接收方「导入预设文件」后得到新副本，选择、预览并启用。`.mizar-hud.json` 文件包含组件、布局与受控外观，图片和比赛资料分别管理。多窗口编辑冲突时保留需要的修改，按提示重新读取版本。

左右选手栏分别提供「C4 伤害预测」开关。估算条件与支持地图见[数据源说明](data-source-capabilities.md#c4-爆炸伤害估算)。

## 网站资料更新与恢复

连接 RivalHub 后，当前已确认比赛的名单、BP 与解说资料会自动刷新，也可点击「刷新比赛资料与 BP」。本地补录与网站版本冲突时，核对候选并「确认加载网站版本」，再回工作台恢复数据源。

启动新制作后，Companion 等待同场有效十人首发数据，有限重试认领未被占用的网站数据源；不会自动接管其他设备。返回已有现场不会重新发起认领。在「现场恢复」独立查看网站数据源。「停止提供网站数据」后不会因页面重开或重连自动认领；点击「恢复提供网站数据」明确恢复。其他设备占用时确认「接管为本场数据源」。节目手动保持与网站数据源相互独立。BP 编辑断线时保留草稿，连接恢复后按版本提示核对并保存。

OBS 或 Mizar 重启后，会尝试重新加载当前 Mizar 场景集合内地址一致的播出网页源。修改过的来源或其他场景集合按自己的配置核对，具体接入条件见[数据源说明](data-source-capabilities.md)。

### 现场恢复与收尾

点击底栏「现场恢复」，恢复面板占用左栏雷达区域，游戏和切场按钮继续可用。先查看真实状态与影响，再重连或恢复布局；重新连接不会自动交回人工节目控制。核对当前比赛、地图、节目和 OBS 实际音画后，才选择「恢复自动」。无 GSI 不代表 CS2 已退出，OBS 断开不代表推流已停止。

结束制播需确认后果。Companion 回执分别记录节目收起与网站源释放；Host 独立读取受管理游戏和配置备份。失败项在「恢复与收尾」保留并可重试；Host 不确定启动仍要求先取消 Steam 请求、确认游戏关闭。OBS 推流 / 录制和网站官方结果继续由操作者单独处理。

## 出现问题时

| 现象                   | 处理                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| 双击后没有窗口         | 按启动错误提示查看日志；便携版先核对完整解压与目录可写。提示缺少 WebView2 时，按下方说明安装或修复 |
| 没有比赛数据           | 检查观战状态、GSI 配置与游戏重启情况，到运行诊断确认接收状态                                       |
| 队伍、名单或地图不符   | 核对当前比赛、首发、CT 对应队伍与地图绑定                                                          |
| OBS 无画面或场景不一致 | 检查连接，停止输出后检查或修复场景，再查看实际画面                                                 |
| 修改 HUD 后画面未更新  | 保存并启用所选预设，核对引用的布局                                                                 |
| 自动编排暂停           | 处理页面给出的数据或 OBS 提示，再恢复自动                                                          |
| 工作台布局异常         | 确认显示器、游戏窗口模式与分辨率，使用「恢复布局」                                                 |
| B 站状态无法确认       | 核对解说资料中的直播间地址、网络与实际直播间                                                       |

WebView2 是 Mizar 显示桌面界面所用的微软运行组件，Windows 11 与大多数 Windows 10 设备已安装。若启动提示该组件缺失或损坏，请从[微软官方下载页](https://developer.microsoft.com/microsoft-edge/webview2/)安装或修复 Evergreen Runtime，再重新打开 Mizar。

GSI 配置缺失、变化或存在重复接收地址时，在「设置 → CS2 / GSI」按提示安装或修复。Mizar 会备份并停用同地址重复配置；「恢复原 GSI 配置」可撤销该操作。其他软件重新生成配置时保留现有文件并提示核对。操作后重启 CS2；更换安装位置前先完成游戏收尾与原 GSI 恢复。

## 导出诊断包与退出

在「设置 → 更新与支持 → 运行诊断 / 导出诊断包」保存 JSON，再到 [GitHub Issues](https://github.com/Starfie1d1272/Mizar/issues)反馈。附上版本、发生时间、操作步骤、预期结果和诊断包。诊断包提供经过限制与脱敏的状态摘要；原始日志、完整配置与凭据保留在本机。

安装版日志位于 `%LOCALAPPDATA%/Mizar/logs`，便携版位于 `state/logs`。日志按单段最多 25 MiB、每类最多四段滚动保留，四类合计约 400 MiB。页面打不开而本地服务正常时，可访问 `http://127.0.0.1:3000/debug` 导出诊断包；服务启动失败时按原生提示查看本机日志。

关闭主窗口通常会收起到托盘。使用托盘「退出 Mizar」完成安全收尾并停止服务；托盘不可用时，主窗口标题会说明关闭退出行为。恢复失败时保留程序、游戏与备份，修正问题后重试。

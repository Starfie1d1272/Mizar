# 快速开始与操作手册

适用于 Windows 便携版。下载与发布状态见 [Releases](https://github.com/Starfie1d1272/Mizar/releases)；候选包由对应 RC 记录提供。功能适用范围见[数据源能力](data-source-capabilities.md)。

## 第一次使用

1. 将完整 ZIP 解压到可写目录，不在压缩包内运行。安装 Microsoft Edge WebView2 Evergreen Runtime；包内已带 Node，无需开发工具。
2. 双击 `Mizar.exe`，进入「总览 / 比赛 / 画面 / 设置」准备中心。
3. 在「设置 → CS2 与 GSI」自动检测或选择安装目录，安装/修复 GSI，然后重启 CS2。
4. 打开 OBS；非标准安装位置可在 Mizar「设置 → OBS」通过「更改 OBS 路径」选择 `obs64.exe`。在 OBS「工具 → WebSocket 服务器设置」启用服务；在 Mizar 填写同一端口，以及 OBS 已启用身份验证时的密码，点击「保存并测试」。然后检查 Mizar 场景，缺失时停止推流/录制再修复；平台推流密钥仍在 OBS 配置。
5. 在「比赛」创建或选择比赛，填写双方队名与 BO，再补名单、地图与 BP。连接 RivalHub 时先授权，再选择并核对已有赛程。
6. 在「画面 → 节目预览」核对画面与资料；调整 HUD 后显式启用。普通场景预览不切换正式 OBS 场景，BP 播放/收起会影响 BP 播出。
7. 准备好后「进入现场」。连接或场景检查未通过会先进入 OBS 配置引导，完成后再次进入；通过后工作台围绕 CS2 展开，自动编排开始工作。OBS 推流仍由你确认启动。

### CS2 游戏捕获

先打开 CS2，再在「设置 → OBS」检查／修复 Mizar 场景。Mizar 使用 OBS 枚举的实际窗口标识与 `cs2.exe` 进程匹配，兼容不同标题；未启动游戏时保留完整预设目标。连接、场景结构检查通过只证明配置一致，仍需查看 OBS 的真实游戏画面。

国际服与国服选择是 CS2 的启动配置，不由 Mizar 场景修复修改。若游戏可见而 OBS 游戏捕获黑屏，核对 Steam 的 `-allow_third_party_software` 启动选项并重启游戏：[Steam 的受信任模式说明](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)指出该选项允许原本受阻的第三方软件，可能影响信任系数。Mizar 不自动添加该选项，也不自动添加 `-insecure`。完美平台及其他平台的捕获限制需按实际环境验证，不能把国际服通过视为所有启动方式通过。

## 比赛资料与工作台

本地赛事可复用队伍、排列比赛，并查看前后场。没有计划时间就保持未安排；没有 BP 不阻止创建比赛。名单可从当前服务器识别首发，无法确认双方对应关系时按提示核对 CT 对应队伍。

工作台提供大雷达、当前比赛、制作提示、场景控制、OBS 画面确认和直播状态。现场页面不滚动，场景按钮始终可见；完整任务、比赛资料、OBS 连接与本机设置通过按钮打开独立页面。雷达默认查看完整地图；等待 GSI 时显示已知地图底图或明确占位，实时选手位置保持缺失。

「隐藏现场」保留制作状态，「恢复现场」重新展开；「结束制作」返回准备状态并保留比赛资料。本机覆盖设置只影响你在 CS2 上看到的 HUD，不会同步隐藏 OBS 节目中的组件。桌面按钮启动的 OBS 独立运行，退出 Mizar 不会关闭 OBS；需要结束直播或录制时，在 OBS 中操作。

本地比赛资料与赛事资料保存成功后显示提示。重复双击 `Mizar.exe` 会唤回已有实例的准备中心；进入现场时恢复工作区与现场控制窗口，并把现场控制放到前台。

现场工作区和控制栏允许被远程桌面、串流、截图及任务栏预览捕获，支持远程制作。本机 HUD 覆盖同样允许捕获，便于远程观察游戏上的 HUD。OBS 游戏捕获需核对未重复叠入本机 HUD。正式 OBS 输出使用 Mizar 管理的游戏捕获和播出 Browser Source；显示器捕获或工作区窗口捕获会包含制作页面，请核对实际来源。浏览器备用入口为制播机上的 `http://127.0.0.1:3000/` 准备中心、`/operator` 制作控制和 `/workspace` 工作台预览。远程显示验证与实体显示器的布局、DPI 验证分别记录。

## 节目编排与现场控制

进入现场后默认自动编排。赛前资料与数据就绪时播放 BP，开局前衔接对阵与 HUD，半场和地图结束时展示对应数据；单图结果之后进入图间或整场结果。临近开打会缩短或跳过开场。

- 手动选择场景后保持当前控制权，点击「恢复自动」才交还。
- 比赛数据过期、归属冲突或 OBS 切场失败时，先处理提示，再恢复自动。
- 在「节目预览」的 BP 工作台填写或核对 BP，使用「播放 BP / 收起 BP」。BP 演示共用播出会话，应在正式制作前使用；切换或退出演示先收起。
- 在线 BP 恢复后核对摘要并确认切回，不会静默覆盖本地补录。
- 自动编排不控制游戏观察视角，也不替你开停推流。

统计范围和直播状态的解释见[产品边界](product.md#能力边界)与[数据源能力](data-source-capabilities.md#工作台的状态边界)。

## HUD 预设与文件分享

在「画面 → 打开 HUD 编辑器」选择内置方案并预览。需要修改时「另存为」自己的副本；组件设置调整信息与样式方案，布局调整位置、显隐和雷达尺寸。

**选择、编辑、保存、另存和导入都不改变正式节目；「启用当前预设」才会上屏。** 更改布局后确认预设引用正确，保存后再启用。已启用内容可在重启后恢复，之后继续保存草稿不会自动更新上屏内容。

分享前保存或放弃未保存修改，再「导出预设文件」。接收方「导入预设文件」后选择新副本、预览并启用。文件包含组件设置、布局与受控外观，不含比赛资料、图片或代码；导入不覆盖既有资源。格式不支持或导入失败时修正文件再试。

多窗口编辑发生冲突时保留需要的修改，再按提示重新读取或放弃，不反复保存覆盖另一窗口。当前不提供任意 CSS 编辑或第三方代码插件安装。

### C4 爆炸伤害预测

在「配置组件」选择左右选手栏，分别设置「C4 伤害预测」，保存并启用。内置预设默认开启；估算方式、支持地图和隐藏条件见[能力说明](data-source-capabilities.md#c4-爆炸伤害估算)。

## 出现问题时

| 现象                                                 | 处理                                                                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 双击后没有窗口                                       | 确认完整解压、目录可写与 WebView2；查看启动错误和 `state/logs/desktop.log`，提交版本与诊断                             |
| 没有比赛数据                                         | 检查 CS2 观战状态、GSI 检测/修复与重启；运行诊断中确认接收情况                                                         |
| 队伍、名单或地图不符                                 | 核对当前比赛与首发；按制作提示确认实际地图绑定，不靠改比分掩盖问题                                                     |
| OBS 无画面或场景不一致                               | 检查 OBS 连接，停止输出后检查/修复 Mizar 场景，再确认播出画面                                                          |
| 修改 HUD 未上屏                                      | 确认已保存且已启用所选预设，检查其布局引用                                                                             |
| 自动编排不继续                                       | 查看手动保持、数据过期或 OBS 提示，处理后恢复自动                                                                      |
| 工作台没有找到 CS2 或布局异常                        | 使用窗口化/无边框模式，确认显示器后点击“恢复布局”                                                                      |
| 旧 RC 远程画面只剩 CS2，工作台和底栏空白或预览为黑框 | RC4 移除了工作区和控制栏的捕获排除；使用完整解压的新包复验。若仍为空白，导出该版本诊断包；浏览器入口可作为备用操作方式 |
| B 站状态无法确认                                     | 检查解说资料中的直播间地址与网络；同时查看实际直播间                                                                   |

桌面不可用但本地服务正常时，可访问 `http://127.0.0.1:3000/`；诊断页为 `/debug`。完整网页入口与开发地址见[开发验证](development-validation.md#本地运行)。

## 导出诊断包与退出

在「设置 → 高级 → 运行诊断 / 导出诊断包」保存 JSON。提交 [Issue](https://github.com/Starfie1d1272/Mizar/issues) 时附版本、发生时间、操作步骤、预期结果和诊断包。不要直接公开整个 `state` 目录或原始日志。

关闭窗口通常只是隐藏；从托盘选择「退出 Mizar」才能明确停止服务。托盘不可用时按标题提示关闭退出。不再使用时可在 GSI 设置中恢复原配置。

升级前保留旧包和 `state` 备份，新包完整解压，不混拷 `resources`；1.0 前不承诺旧配置格式迁移。备份也不代表任意版本间可以直接恢复，按该版本发布说明操作。

## 未绑定 demo 与重启布局

播放任意 demo 并收到新鲜 GSI 后，可在现场手动选择“比赛中”，不要求先配置它的赛事地图或官方名单。手动切换保持人工控制；缺失身份/赛事资料保持缺失，自动编排与结果画面仍需可信绑定。恢复自动不会把 demo 登记为当前赛事。

CS2 重启后窗口跟踪重新识别进程/窗口，在物理像素坐标下恢复右上角位置。点击“恢复布局”会检查 CS2 是否存在及是否接受尺寸；失败时显示窗口模式操作提示，不把仅恢复工作区当作恢复游戏成功。

本机设置提供 `cl_draw_only_deathnotices 1` 与 `cl_draw_only_deathnotices 0` 的显示及复制，需在 CS2 启用开发者控制台后手动粘贴执行。复制成功不表示命令已应用；复制失败可选取文本。当前不实现自动控制台注入，也不改键位或 autoexec。

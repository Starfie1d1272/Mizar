# 快速开始与操作手册

适用于 Windows 便携版。首选[南大云盘下载完整包](https://box.nju.edu.cn/d/7e069258cb8045a1a5c7/)；备用下载与发布状态见 [GitHub Releases](https://github.com/Starfie1d1272/Mizar/releases)。当前已发布 RC14 开发预览版；候选包的验证记录见对应 Release，正式 1.0 实机验收仍由 #35 跟踪。功能适用范围见[数据源能力](data-source-capabilities.md)。

## 第一次使用

1. 将完整 ZIP 解压到可写目录，或运行同版本完整包 `.exe`（旧版本文件名以 `-extract.exe` 结尾）并选择新的可写目录，再打开目录内的 `Mizar.exe`。自解压入口只提取完整便携包，不安装服务或自动启动；不选择已有 Mizar 或 `state` 目录，不在压缩包内运行。安装 Microsoft Edge WebView2 Evergreen Runtime；包内已带 Node，无需开发工具。
2. 双击 `Mizar.exe`，进入默认最大化、带左侧导航的准备中心，保留标准标题栏和任务栏，可自行还原窗口。
3. 创建或选择比赛，核对队伍、名单、地图与 BP；连接 RivalHub 时先授权，再选择比赛。
4. 登录 Steam，先运行一次 CS2 生成账号配置后退出。在「游戏设置」重新检查 CS2 与 GSI；自动发现失败时选择安装目录、`game/bin/win64` 或 `cs2.exe`，再安装 / 修复 GSI。保存的位置同时用于游戏启动。
5. 配置 OBS 控制连接（WebSocket）：打开 OBS，在「工具 → WebSocket 服务器设置」启用服务器并保留身份验证，在 Mizar「OBS 连接」填写同一端口与密码，点击「保存并测试」。检查 Mizar 场景，缺失时停止推流 / 录制再修复。非标准安装路径可选择 `obs64.exe`；平台推流密钥在 OBS 配置。
6. 点击页面顶部「启动游戏并打开工作台」。首次启动前必须确认 GSI 已安装且无冲突，并通过 OBS 控制连接与场景检查；不要求尚未启动的游戏已有新鲜数据。已打开的外部 CS2 请先退出；工作台可以在等待观战数据时打开。
7. 在 CS2 开发者控制台输入赛事方提供的 `connect <GOTV 地址>` 并回车，进入本场观战。总览的游戏数据状态会自动更新；再核对队伍、地图与名单，缺失或不一致时按开播检查处理。
8. 在工作台复制隐藏原生 HUD 命令，回到 CS2 控制台粘贴并回车。复制提示仅说明已复制，需自行确认执行。
9. 核对 OBS 实际游戏画面、HUD 与声音，再在 OBS 开始推流。在「播出画面」预览、调整与启用 HUD；普通场景预览不切换正式播出，BP 播放 / 收起会影响 BP 播出。

OBS 先于 Mizar 启动或服务重新启动时，服务就绪后会尝试重新加载当前 Mizar 场景集合中地址一致的播出网页源。该恢复不会切换你正在使用的集合或场景；非 Mizar 集合、被改为其它地址的源需先自行核对。

### CS2 游戏捕获

先打开 CS2，再在「OBS 连接」检查／修复 Mizar 场景。Mizar 使用 OBS 枚举的实际窗口标识与 `cs2.exe` 进程匹配，兼容不同标题；未启动游戏时保留完整预设目标。连接、场景结构检查通过只证明配置一致，仍需查看 OBS 的真实游戏画面。

Mizar 为本次 Steam 启动传递基础直播启动项 `-console -allow_third_party_software -worldwide`，另外传递工作台所需的窗口模式与宽高。`-worldwide` 直接选择国际服并跳过区服提示，需账号具有国际服许可，见 [Steam 官方说明](https://help.steampowered.com/en/faqs/view/0653-C465-7FC1-44C1)。第三方软件选项用于 OBS 游戏捕获兼容，可能影响信任系数，见 [Valve 的受信任模式说明](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)。

启动项仅用于本次启动，Steam 中保存的原启动项保持原样；不添加 `-insecure`，也不默认套用社区的线程、优先级或无限帧率参数。若 Steam 的原启动项带有冲突的区服、窗口或自定义启动命令，请先核对后重试。画面与捕获兼容性按实际游戏、平台和驱动环境验证。

## 比赛资料与工作台

本地赛事可复用队伍、排列比赛，并查看前后场。没有计划时间就保持未安排；没有 BP 不阻止创建比赛。名单可从当前服务器识别首发，无法确认双方对应关系时按提示核对 CT 对应队伍。

在「比赛资料 → 地图与 BP」设置赛事的BO3默认规则：最后两次禁图由先禁方或后禁方先操作，决胜图由其中一方选边或留到游戏内决定。EPL示例为先禁方先完成最后禁图、两张选图由对手选边、决胜图游戏内决定（如拼刀），不预填CT/T。本场BP编辑器也可显式选择规则；更换规则时相关旧选项清空，需重新核对。赛事默认只用于新填写，不自动改写已有禁选和选边。

工作台比分以当前图的回合比分为主，系列比分另行标注。工作台提供大雷达、当前比赛、制作提示、场景控制、OBS 画面确认和直播状态。现场页面不滚动，场景按钮始终可见；完整任务、比赛资料、OBS 连接与本机设置通过按钮打开独立页面。雷达默认查看完整地图；等待 GSI 时显示已知地图底图或明确占位，实时选手位置保持缺失。

进入 Windows 现场工作台后，任务栏退到现场窗口后面，左栏及 OBS 画面贴屏幕底部；本次 CS2 使用无边框窗口，与左栏、底栏连续平铺。退出恢复原窗口设置。切换其它应用或隐藏/退出工作台时恢复正常任务栏层次，不改变系统的自动隐藏设置。Windows Shell 不可用时沿用原工作区布局。

「隐藏工作区」保留制作状态，「打开直播工作台」重新展开；右下角红色「退出工作台」收起节目、关闭本次 CS2 并恢复原配置，保留比赛资料。现场观战操作区提供「雷达」「其他 HUD」两个独立开关，只影响本机 CS2 画面。默认雷达关闭、其他 HUD 显示；OBS 播出保持当前预设。准备中心可在「播出画面 → 本机 HUD」操作。桌面按钮启动的 OBS 独立运行，退出 Mizar 不会关闭 OBS；需要结束直播或录制时，在 OBS 中操作。

本地比赛资料与赛事资料保存成功后显示提示。重复双击 `Mizar.exe` 会唤回已有实例的准备中心；进入现场时恢复工作区与现场控制窗口，并把现场控制放到前台。

现场工作区和控制栏允许被远程桌面、串流、截图及任务栏预览捕获，支持远程制作。本机 HUD 覆盖同样允许捕获，便于远程观察游戏上的 HUD。OBS 游戏捕获需核对未重复叠入本机 HUD。正式 OBS 输出使用 Mizar 管理的游戏捕获和播出 Browser Source；显示器捕获或工作区窗口捕获会包含制作页面，请核对实际来源。浏览器备用入口为制播机上的 `http://127.0.0.1:3000/` 准备中心、`/operator` 制作控制和 `/workspace` 工作台预览。远程显示验证与实体显示器的布局、DPI 验证分别记录。

## 节目编排与现场控制

### CS2 启动与原设置恢复

桌面默认以无边框窗口、适配工作台的分辨率、最高画质和 60 帧／秒上限启动 CS2。在「游戏设置 → CS2 启动设置」可分别选择画质和帧率：画质提供最高、高、中及保留原画质；中画质包含游戏原生 FSR 缩放，保留原画质沿用自己的画质及 FSR。修改后点击「保存启动设置」，下次从页面顶部「启动游戏并打开工作台」时使用。帧率提供 60、30 和不限帧；建议 60，为雷达与 OBS 留出图形资源，30 适合资源紧张或 30 帧播出，不限帧会显示红色卡顿风险提示。

已自行打开的 CS2 需要先退出。游戏保持 16:9，尺寸按主显示器的工作台布局计算；1920×1080 屏幕对应 1440×810，2560×1440 屏幕对应 1920×1080。运行中改变屏幕分辨率后，如果提示游戏未接受新尺寸，请退出工作台后重新进入；单纯改变 DPI 由工作台自动重排。

「隐藏工作区」保留游戏；「退出工作台」在成功收起节目后关闭本次由 Mizar 启动的 CS2，恢复启动前的视频设置与帧率。本次游戏内修改的受管理画质、分辨率、显示模式和 `fps_max` 也会恢复，其余游戏字段的修改保留。启动时加载的配置文件中，直接设置的 `fps_max` 会临时使用本次上限，退出后恢复原文件；Mizar 不修改 Steam 保存的启动项或键位。冲突的 `+fps_max`、动态帧率命令或不支持的配置会阻止启动并提示处理。受管理期间请勿编辑这些启动配置；外部修改会保留备份并停止自动恢复。

正常关闭超时请手动退出 CS2，再在总览或游戏设置中「恢复配置备份」。配置备份在 `state/data/cs2-session/pending.json`，成功恢复后最近一次原视频文件保留为 `last-original.txt`，帧率涉及的原文件保留为 `last-frame-rate-backup.json`；不要删除待恢复记录或公开整个备份。

正常退出 Mizar 与退出工作台共用安全收尾：先切到等待场景并释放数据源，再关闭本次受管理 CS2、恢复配置，最后停止服务。退出开始后拒绝新的启动与进入请求；安全收尾失败时保留程序和游戏，以原生提示说明原因，修复后可重试退出。退出恢复失败时，关闭提示仅收起提示；Mizar 保留服务供修复与重试。恢复成功后再次退出，桌面与本地服务一并关闭，OBS 保持运行。异常退出或恢复失败时，记录保留，总览与「游戏设置」会持续显示待恢复原因，提供「恢复配置备份」与「打开备份目录」。恢复成功后显示「原设置已恢复」。

启动、恢复和设置变更在同一个配置恢复区域提示进度；后台定期巡检不反复弹出操作提示，等待期间保留最近已确认的状态。

Steam 启动超时后，Mizar 保留「启动结果待确认」，游戏稍后出现会继续识别；不要将暂时无进程当作已经退出。若不再启动，先在 Steam 取消启动请求、退出 CS2，在恢复面板勾选确认后恢复。未恢复前不能启动新的受管理会话。浏览器入口不启动游戏或修改本机配置。

进入现场后默认自动编排。赛前资料与数据就绪时播放 BP，开局前衔接对阵与 HUD，半场和地图结束时展示对应数据；单图结果之后进入图间或整场结果。临近开打会缩短或跳过开场。

- 手动选择场景后保持当前控制权，点击「恢复自动」才交还。
- 比赛数据过期、归属冲突或 OBS 切场失败时，先处理提示，再恢复自动。
- 在「节目预览」的 BP 工作台填写或核对 BP，使用「播放 BP / 收起 BP」。BP 演示共用播出会话，应在正式制作前使用；切换或退出演示先收起。
- 在线 BP 恢复后核对摘要并确认切回，不会静默覆盖本地补录。
- 自动编排不控制游戏观察视角，也不替你开停推流。

统计范围和直播状态的解释见[产品边界](product.md#能力边界)与[数据源能力](data-source-capabilities.md#工作台的状态边界)。

## HUD 预设与文件分享

在「播出画面 → HUD」选择内置方案并预览。需要修改时「另存为」自己的副本；组件设置调整信息与样式方案，布局调整位置、显隐和雷达尺寸。

**选择、编辑、保存、另存和导入都不改变正式节目；「启用当前预设」才会上屏。** 更改布局后确认预设引用正确，保存后再启用。已启用内容可在重启后恢复，之后继续保存草稿不会自动更新上屏内容。

分享前保存或放弃未保存修改，再「导出预设文件」。接收方「导入预设文件」后选择新副本、预览并启用。文件包含组件设置、布局与受控外观，不含比赛资料、图片或代码；导入不覆盖既有资源。格式不支持或导入失败时修正文件再试。

多窗口编辑发生冲突时保留需要的修改，再按提示重新读取或放弃，不反复保存覆盖另一窗口。当前不提供任意 CSS 编辑或第三方代码插件安装。

### C4 爆炸伤害预测

在「配置组件」选择左右选手栏，分别设置「C4 伤害预测」，保存并启用。内置预设默认开启；估算方式、支持地图和隐藏条件见[能力说明](data-source-capabilities.md#c4-爆炸伤害估算)。

## 出现问题时

| 现象                                                 | 处理                                                                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 双击后没有窗口                                       | 确认完整解压、目录可写与 WebView2；查看启动错误和 `state/logs/desktop.log`，提交版本与诊断                             |
| 没有比赛数据                                         | 检查 CS2 观战状态、GSI 检测/修复与重启；运行诊断中确认接收情况                                                         |
| 队伍、名单或地图不符                                 | 核对当前比赛与首发；按制作提示确认实际地图绑定，不靠改比分掩盖问题                                                     |
| OBS 无画面或场景不一致                               | 检查 OBS 连接，停止输出后检查/修复 Mizar 场景，再确认播出画面                                                          |
| 修改 HUD 未上屏                                      | 确认已保存且已启用所选预设，检查其布局引用                                                                             |
| 自动编排不继续                                       | 查看手动保持、数据过期或 OBS 提示，处理后恢复自动                                                                      |
| 工作台没有找到 CS2 或布局异常                        | 使用窗口化/无边框模式，确认显示器后点击“恢复布局”                                                                      |
| 旧 RC 远程画面只剩 CS2，工作台和底栏空白或预览为黑框 | RC4 移除了工作区和控制栏的捕获排除；使用完整解压的新包复验。若仍为空白，导出该版本诊断包；浏览器入口可作为备用操作方式 |
| B 站状态无法确认                                     | 检查解说资料中的直播间地址与网络；同时查看实际直播间                                                                   |

桌面不可用但本地服务正常时，可访问 `http://127.0.0.1:3000/`；诊断页为 `/debug`。完整网页入口与开发地址见[开发验证](development-validation.md#本地运行)。

GSI 提示文件缺失或内容变化时，先备份当前文件，再恢复原 GSI 配置并重新安装。提示其他配置发送到相同地址时，点击「一键安装 / 修复 GSI」，自动备份并停用同地址重复配置；不同地址的其他软件配置可以继续共存。「恢复原 GSI 配置」可撤销停用。其他软件重新生成不同内容的文件时会保留双方文件和备份，并提示导出诊断包。操作后重启 CS2 以加载配置。读取失败时先检查文件访问权限并导出诊断包，保留安装记录与备份。更换游戏安装位置前先恢复当前 GSI；退出受管理游戏并恢复设置后再选择。

## 导出诊断包与退出

在「高级设置 → 运行诊断 / 导出诊断包」保存 JSON。提交 [Issue](https://github.com/Starfie1d1272/Mizar/issues) 时附版本、发生时间、操作步骤、预期结果和诊断包。诊断包包含 GSI 问题码、安装候选数、冲突文件数和最近配置操作阶段，不包含完整路径、配置内容或原始错误。状态采集失败与超时分别记录，未知状态不推断为安装失败。不要直接公开整个 `state` 目录或原始日志。

关闭窗口通常只是隐藏；从托盘选择「退出 Mizar」才能明确停止服务。托盘不可用时按标题提示关闭退出。不再使用时可在 GSI 设置中恢复原配置。

升级前保留旧包和 `state` 备份，新包完整解压，不混拷 `resources`；1.0 前不承诺旧配置格式迁移。备份也不代表任意版本间可以直接恢复，按该版本发布说明操作。

## 未绑定 demo 与重启布局

播放任意 demo 并收到新鲜 GSI 后，可在现场手动选择“比赛中”，不要求先配置它的赛事地图或官方名单。手动切换保持人工控制；缺失身份/赛事资料保持缺失，自动编排与结果画面仍需可信绑定。恢复自动不会把 demo 登记为当前赛事。

CS2 重启后窗口跟踪重新识别进程/窗口，在物理像素坐标下恢复右上角位置。点击“恢复布局”会检查 CS2 是否存在及是否接受尺寸；失败时显示窗口模式操作提示，不把仅恢复工作区当作恢复游戏成功。

现场工作台提供原生 HUD 的隐藏和恢复命令复制，复制结果在底栏显示。「播出画面 → 本机 HUD」也提供 `cl_draw_only_deathnotices 1` 与 `cl_draw_only_deathnotices 0` 的显示及复制，需在 CS2 启用开发者控制台后手动粘贴执行。复制成功不表示命令已应用；复制失败可选取文本。HUD 操作不自动注入控制台，也不修改键位或启动脚本。

## Steam 备用头像

在「准备中心 → 设置 → 游戏设置 → Steam 头像」可选填写 Steam Web API Key，推荐填写以自动加载备用头像。通过 [Steam 官方获取页面](https://steamcommunity.com/dev/apikey)登录并按提示申请或查看已有 Key；申请页的域名建议填 `localhost`，表示本机使用，无需购买或配置域名。复制 32 位 Key 回到 Mizar 保存；Steam 提示账号暂不能申请时可跳过此项。赛事提供的头像优先，缺少时按当前选手 Steam64 批量获取并缓存到本机；获取失败继续使用现有媒体或观察编号。已配置时输入框显示固定长度掩码；输入新 Key 后点击「更新密钥」，留空保留原配置。真实密钥不回显，也不写入比赛资料、预设和诊断包。停用在线获取保留缓存；“清除头像缓存”单独删除本机备用媒体。

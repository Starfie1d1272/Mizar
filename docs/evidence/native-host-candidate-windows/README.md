# 原生宿主候选的 Windows 验收

2026-10-08（北京时间），读取「调研 Issue149方案」最新完整回复后，对 [PR #173](https://github.com/Starfie1d1272/Mizar/pull/173) 的现成修复执行一次验收会话。当前门禁仍由 [#149](https://github.com/Starfie1d1272/Mizar/issues/149) 和 [#35](https://github.com/Starfie1d1272/Mizar/issues/35) 维护。

**性能结果为 FAIL：默认候选和预置的雷达进程隔离模式都没有消除长间隔。** 此结果不否认两项宿主源码修正的价值，但它们不足以解决本机故障；不合并候选并宣布性能通过、不发布成已修复 RC。

## 构建身份与方法

以完整 SHA `14b1268d3478a33ba5f8dcf2649b806c74183186` 运行 [Release Qualification](https://github.com/Starfie1d1272/Mizar/actions/runs/37670683831)，结果成功。候选使用 `release` 桌面配置，包内应用版本仍为 `1.0.0-rc.25`，但不是公开 RC25：内容摘要 `65a42a6c6c66fe4538e36641a0e2f6a511bf5fb9b1a47ae84b4e963a50116eea`，ZIP SHA-256 `4b9909c017469193cecbfa4fab268b5676b9c11d89b91ff1b77b36b94fc2aa1b`。下载后核对 ZIP，使用 Windows 解压器提取 3,586 文件，再以既有 `verifyPayload` 核对完整内容、源码和配置。

使用真实 EPL Falcons–Natus Vincere Inferno demo，1 倍速、tick 20000、开始时核对 b1t。原 RC25 做同会话 60 秒基线；正常退出后启动默认候选；默认失败后正常退出，仅启用 `MIZAR_RADAR_PROCESS_ISOLATION=1` 启动同一候选，测 120 秒。三段均是新页面/正常 Canvas 上下文，506×506、150% DPI、原 CSS 阴影、本机 HUD 与 OBS 原负载，MAA/MuMu/SteelSeries 保持运行。不重复无绘制、极简、阴影或限帧实验。

通过游戏窗口截图定位和关闭控制台；目标 Canvas 不提前读像素。主采样内不截图、读回或切窗口。候选用自动分配的只读 CDP 端口，独立目录拥有独立端口；没有修改 GPU、后台节流或其它产品选项。观察原回调的进入/退出、序号、Long Task 和 LoAF，保留原数据、模型和全部绘图。

## 实际结果

| 条件 | 实际采样跨度 | 最大进入间隔 | p99.9 | >100ms | >250ms | >100ms/分钟 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原 RC25 基线 | 60.0s | 535.2ms | 257.5ms | 75 | 10 | 75.0 |
| PR #173 默认 | 121.8s | 790.3ms | 425.8ms | 186 | 41 | 91.6 |
| PR #173 隔离 | 120.0s | 707.3ms | 450.1ms | 239 | 48 | 119.5 |

原回调体最大分别 2.0 / 2.3 / 2.4ms，三段均未记录 Long Task；这不能排除回调外工作。独立雷达接收最大间隔分别 78 / 106 / 81ms。CDP 聚合三通道不是实际雷达 JS listener、schema/notify 或源年龄分段证据。

默认采样工具使用宽字符串替换，把原定 120 秒期限误改成 140 秒，因此由采样器在约 122 秒显式停止；完整实际跨度和计数保留，不冒称精确 120 秒超时。隔离段已改为定向替换，120 秒超时正常恢复。该区别不改变默认模式仍有多次数百毫秒空窗的失败判定。各段 UI 操作有延迟，起始 demo 时间只近似重叠；隔离 profile 有独立页面存储，不声称所有偏好完全相同，亦不将发生率差异宣称为统计意义上的退化。

实际核对一套共享浏览器/GPU 进程集合变成两套，隔离左栏使用 `workspace-radar/EBWebView`。采样结束后的单次进程内存快照：默认工作集 1,056.69MiB、私有内存 803.84MiB；隔离合计 1,348.52MiB / 865.10MiB。约增加 292MiB 工作集，不是稳态内存基准。进程目录隔离已生效，但不隔离物理显卡或 Windows 桌面合成器。

## 同一窗口的呈现时间线

在失败的隔离模式保留正常完整雷达，单独采集 3 秒 `blink.user_timing,cc,gpu` 追踪及同目标探针；21,719,071 字符、116,256 事件，无数据丢失。此轮成功抓到一个目标回调间隔 107.4ms。

通过使用 `startTime=当前回调进入` 的性能标记映射到同一追踪时钟：

| 时间（追踪微秒） | 观测 |
| ---: | --- |
| 117493586600 | 前次目标回调进入 |
| 117493586993 | 隔离 GPU 的 `DXGISwapChainImageBacking::Present` 开始 |
| 117493692443 | Present 区段结束，历时 105.45ms |
| 117493692811 | renderer 收到 `CompositorFrameAck` |
| 117493693918 | 调度下一次 `SendBeginMainFrame` |
| 117493693950 | 下一次 `BeginMainFrame` 开始 |
| 117493694000 | 当前目标回调进入，距前次 107.4ms |

Present 区段与回调空窗重合 105.45ms，结束距新回调约 1.56ms；其父 `Scheduler::RunTask` 与它嵌套，不能累加。隔离 browser 只有左栏页面，GPU PID 与对应集合关联，较此前独立采样更接近目标呈现路径。

**这支持优先定位呈现完成／确认与后续主帧调度，但仍是相关时间线。** 尚未按逐帧标识联结所有提交与 ACK，不宣称驱动缺陷或完整因果证明；Present trace 区段也不等于 `Present1` 调用耗时或 GPU 执行耗时。数值、标记实际调用时间和选定事件见 [trace-timeline.json](trace-timeline.json)。原始 21.7MB 追踪留本机，没有上传完整日志或凭据。

## 窗口、输出与恢复

采样后正常地图、选手标记和实时数据可见；工作区隐藏后能恢复，诊断工具最小化后重新打开。隐藏触发准备页导航导致 CDP 旧执行上下文销毁，重新获取页面并核对窗口恢复，没有把辅助工具的异常当作产品命令失败。未取得实际 controller `IsVisible` COM 读回或实机几何 setter 次数，因此这两项为 INCONCLUSIVE，不以页面 visibility 或策略单测替代。

既有本机 HUD 仍覆盖前景诊断/OBS 窗口；关闭本机覆盖后，OBS 中独立游戏捕获和节目 HUD 均可见、输入继续更新，停止制作后回到等待。没有开始推流或录像，没有独立完成 C4 携带/丢弃/安放视觉验收。

三次正常退出后 Host 和 CS2 均退出、pending 消失，各自 17 项临时视频字段零差异。随包脚本显式恢复原 GSI，最终 RoundSense 文件 SHA-256 恢复为 `14249F65A2903446D1063C5788FF2E056935815FCA9FB358B9911CACA2784F8C`；本轮 OBS 正常退出。隔离变量仅随子进程传入，未持久设置；保留固定隔离 profile，不删除原页面数据。

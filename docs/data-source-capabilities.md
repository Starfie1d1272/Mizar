# 数据源能力与限制

本文集中说明数据来源决定的可用能力。操作步骤见[快速开始](quick-start.md)，输入解释见[游戏数据语义](telemetry.md)。

## 当前基础链路

```text
CS2 观战客户端 → GSI → 本地运行时 → HUD、雷达与节目流程
本地比赛资料 / RivalHub ────────↗
```

当前主要服务 Windows + CS2 观战 + OBS。直连 GOTV 地址由赛事提供方确认，不能通过端口加减推断无延迟/延迟地址，也不能假定固定观战延迟。`connect IP:port` 不是 HTTP Broadcast 地址。

| 能力 | 所需数据 | 缺失时 |
| --- | --- | --- |
| 比分、回合、选手与当前观察目标 | 对应 GSI 字段和有效身份、地图信息 | 保持未知或隐藏，不沿用旧帧伪造当前事实 |
| 雷达、楼层和道具 | GSI 位置/道具观测与地图几何资源 | 不支持地图或数据过期时不可用 |
| 自动节目流程 | GSI 比赛进展、有效比赛绑定、赛事资料与 OBS 状态 | 暂停自动推进并提示处理；BP 内容不由 GSI 推断 |
| 队名、队标、赛程、BP | 本地填写或赛事平台 | 可以从最小比赛资料开始，缺失内容不补造 |
| 网站实时状态与公共雷达 | 已验证的公开投影与已配置接收端 | 数据无效时不继续发布旧值；连接恢复按适用范围验证 |
| 精确伤害/击杀事件特效 | 可选的正式节目事件数据源 | 保留基础 GSI HUD；不伪造武器类型等精确事件 |
| 观察辅助 | 独立较早时间轴及有效对齐 | 当前仍属研发；不影响基础转播成立 |

GSI 支撑当前基础 HUD 和雷达，不要求赛事服务器安装插件。它不提供完整官方赛果、完整事件流或任意精度保证。HTTP CSTV 适配器只用于真正提供该类地址的数据源；无头直连 CSTV 客户端是独立研发方向。

## C4 爆炸伤害估算

内置数值资源覆盖 Ancient、Anubis、Cache、Dust II、Inferno、Mirage、Nuke、Overpass、Train、Vertigo；资源版本与许可由依赖和[第三方说明](../THIRD-PARTY-NOTICES.md)维护。

- 结果表示按当前位置与站立姿态估算的伤害，不代表观测到了真实姿态，也不保证必死或必活。
- 只在已下包/拆弹、有效爆炸倒计时最后十秒内展示；暂停、回合结束、过期或缺失输入时隐藏。零伤害不绘制覆盖层。
- 缺少地图资源、有效身份、位置或时间证据时不可用，真实血量与死亡状态不变。
- 资源覆盖不代表所有地图均完成实机精度验收；CS2 更新可能要求更新资源。

## 工作台的状态边界

OBS 画面确认是定期截取的当前场景缩略图，用于核对画面和场景，不是流畅视频监看。OBS 状态分别检查连接、推流、场景对齐和配置。

B 站状态依据已配置解说资料中的直播间地址查询开播状态；未配置、未开播和无法确认分别显示。它不证明观众端画面、声音和网络质量，不自动开停推流，也不影响游戏数据处理。

## 公开数据与平台适配

RivalHub 是当前第一方集成。其他网站可适配[输入与输出协议](protocol.md)，但不能只填一个网站地址就获得兼容。公开输出来自正式节目时间轴，可能随观战源延迟，不代表无延迟服务器实况。

连接模式恢复的具体缺口与联调由 [#121](https://github.com/Starfie1d1272/Mizar/issues/121) 追踪；不把平台端代码合并视为跨项目实测通过。

## 能力与证据

代码存在、自动测试通过、指定 RC 的实机验收是不同结论。实测支持范围随[发布说明](release-notes-draft.md)确认，流程见[RC 与发布](release-readiness.md)。未来信息不得进入正式节目或公开输出，隔离规则见[架构](architecture.md#正式节目与观察辅助隔离)。

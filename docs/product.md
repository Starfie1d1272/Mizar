# 产品定位与边界

Mizar 面向校园与社区 CS2 赛事，让规模有限的制作团队也能呈现职业赛事般完整的转播包装。“完整”指赛前到赛后的节目流程、统一视觉和现场制作工具共同工作。

## 核心体验

| 能力 | 用户得到什么 | 范围 |
| --- | --- | --- |
| 自动节目编排 | 随比赛进展呈现等待、BP、开场、比赛中、半场、单图结果、图间和整场结果 | 结合 GSI 与已配置赛事资料；支持人工接管 |
| 制播工作台 | 围绕真实游戏画面查看大雷达、比赛资料、制作提示与播出状态 | Windows 桌面工作台支持远程软件显示；浏览器提供工具与布局预览 |
| 赛事视觉 | Mizar Pulse 默认完整包装，以及四套其他风格 HUD | 其他风格目前是 HUD 预设，不是四套完整节目包 |
| 赛事连接 | 复用赛事网站资料，并向网站提供局内状态与雷达 | 当前第一方集成为 RivalHub，其他平台需要适配 |
| 连续运行 | 对断流、重连、重启和缺失数据提供明确处理 | 适用可靠性由对应构建包的验证结果证明 |

主要用户是解说、观察者与制作人员，可以由同一人兼任，也可以协作。节省常规操作服务于完整转播体验，不限定人员数量。

## 独立使用与平台连接

- **独立模式**：赛事、队伍、比赛与 BP 资料保存在本机，本地制播不依赖 RivalHub 持续在线。
- **RivalHub 连接模式**：授权后选择赛事平台已有比赛，核对资料并进入现场；两种模式使用同一本地运行时。

连接模式下，官方赛事资料与结果由赛事平台管理。Mizar 输出游戏观测，不自行宣布其为官方赛果；采集端也不直接访问网站内部数据库。

RivalHub、Mizar、DAK 分别面向赛事运营、现场制播、赛后分析。它们的协作不意味着当前已经提供任意赛事方一键部署的全套云端闭环。

## 产品原则

1. **比赛是主角。** 赛事名称、队伍和选手身份贯穿节目，产品品牌保持次级位置。
2. **自动推进，人工掌控。** 常规节目由比赛驱动；人工接管后保持，显式恢复才交还自动控制。
3. **先预览，再播出。** 编辑与保存不应意外改变正式节目；有播出副作用的操作明确标示。
4. **本地优先。** 核心转播可独立运行，平台服务是集成能力。
5. **只表达有依据的信息。** 缺失的身份、时间、统计和赛果保持缺失；推测与实测分开。
6. **中文优先。** 面向制作人员解释当前情况和可执行操作，代码术语留在技术参考。
7. **同一份比赛信息服务多个画面。** HUD、雷达、节目与公开输出不各自推导第二套比赛事实。

## 能力边界

- 自动编排负责节目场景，不负责自动选择游戏观察视角，也不会自行开始或停止推流。
- 工作台中的 OBS 图像用于定期画面确认；平台开播状态不等同于观众端音画质量检测。
- 半场与结果数据页使用单图统计，整场结果中的选手表展示最后一图，不承诺系列赛合计。
- 预设文件可分享已有组件、布局与外观，不安装任意第三方 HUD 代码。完整视觉包与第三方 HUD 适配见[路线图](roadmap.md)。
- Lookahead 与观察辅助仍属增强研发方向，不作为现成产品功能宣传。

具体环境支持、缺失数据与预测限制由[数据源能力](data-source-capabilities.md)维护；使用步骤见[操作手册](quick-start.md)。

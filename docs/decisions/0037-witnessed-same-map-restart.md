# ADR-0037：以完整热身证据识别同图重开

- 状态：**Accepted**
- 日期：2026-10-07
- 关联：ADR-0003、运行时连续性、系列赛历史恢复

2026-10-07 的 RC19 实测证明真实热身会省略 `round_wins`；“明确空历史”的必要条件由 [ADR-0038](0038-warmup-without-round-history.md) 修订，以下保留原决定以追溯失败原因。

## 背景

同一 CS2 进程可以结束当前执行并重新播放相同地图。地图名没有变化，菜单帧又可能缺少地图区块；仅按名称推进执行编号会把旧的回合历史和单图累计带入新执行。只看回合号回退也不可靠，因为部分观测、回放定位和其他输入变化不必然证明地图重开。

## 决定

由 Core 的既有地图连续性状态保留有界的正式阶段观测证明。这是执行范围内的历史证据，不是当前地图阶段，不成为第二份遥测或独立状态来源。

在该证明存在时，当前完整地图观测必须同时给出相同已知地图名、热身阶段、回合零、双方零分和明确空回合历史，才建立新的执行编号。重复热身观测不重复重置。字段缺失、降级、单独的回合回退及数据源重连均不触发重开。

转换使用既有 `map_execution_changed`，以 `observed-same-map-restart` 表达真实观测原因。Companion 把它交给已有系列赛重开规则，清除未完成当前图的历史；已完成地图的冻结结果保持。单图统计、目标计时、身份、媒体和渲染连续性沿用已有执行范围，不在各消费面分别推断重开。

本决定扩展 ADR-0003 的地图执行识别方式，不改变正式节目与辅助数据隔离、冻结结果职责或人工明确重置入口。运行时恢复仍遵循原有检查点兼容性与当前观测核验；不能仅凭新服务启动证明地图重开。

## 代价与验证

完整热身证据缺失时采用保守行为，不猜重开。自动化覆盖正式阶段→缺失菜单→完整热身、重复热身、缺失历史/比分、非零比分、降级、普通回合回退与重复帧；组合测试覆盖旧回合历史清除及原状态不可变。最终 RC 仍须在同图真实 demo 重开中核对执行编号与历史，并继续验证自然多图流程。

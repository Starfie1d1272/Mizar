# ADR-0012：设计系统文档、源码职责与验证边界

- 状态：Accepted
- 日期：2026-09-28
- 决策来源：[冻结规格 #96](https://github.com/Starfie1d1272/Mizar/issues/96)

## 背景

产品导航、BP、制播工作区、HUD 编辑器、诊断与播出画面的视觉基础散落在页面，缺少共享维护入口和可验证约束。页面改造需要从源码明确规范、界面类别、设计变量与允许的例外。

## 决策

`docs/design/` 是设计系统的唯一文档入口。`brand`、`ui-system`、`product-language` 分别维护品牌、界面规则与用户文案；`terminology` 继续维护机器格式和开发者术语。`packages/design-tokens` 管理符合 DTCG 格式的 JSON 与生成的 CSS，按原始值 → 用途 → 界面差异 → 稳定复用的组件/组合分层。Web `ui/` 放基础组件，`patterns/` 放组合组件，功能页面从既有领域模块读取业务事实。

产品界面采用以 BP 工作台为参考的 Graphite Instrument；播出画面以赛事为主，参考 BP 全屏画面；诊断界面使用同一产品基础与更高的信息密度。赛事、参赛双方、CT/T 与状态颜色各有职责，动态颜色通道由 `ui-system.md` 统一规定，不按界面另建调色板。播出展示字体通过实际视觉稿比较决定。

架构检查约束变量、命名空间、依赖与产品/诊断界面的通用样式。旧页面使用精确且只递减的迁移清单；播出几何与特定画面风格使用有文档的局部例外。Storybook 只展示共享组件；交互和 axe 无障碍检查不会进入产品构建。设计变量与组件检查是独立的定向 CI，不因普通变量改动触发 Windows 现场验收打包。

1.0 视觉定稿前不维护全站像素基线，定稿或 RC 阶段只建立小型标准视觉用例集。自动化、人工视觉审查与 Windows + CS2 + OBS 验收证明不同层级，不能互相替代。Gameplay 长期约束继续由 ADR-0007 负责。

## 演进规则

页面迁移逐步删除历史 CSS，不永久保留两套系统。变量数值与组件样式的非语义调整更新规范并经 PR 审查；新增可复用组合或界面规则同步样例和检查；产品级语义改变需要新 ADR 或明确产品决策。设计系统只管理呈现规则，不改变运行时、数据安全或比赛事实。

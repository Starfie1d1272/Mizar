# ADR-0029：现场工作区的全屏 Shell 协作与窗口外框避让

状态：Accepted

## 背景

RC11 实机反馈要求进入现场后让任务栏退出画面，并让左栏延伸到显示器底部。已有布局按显示器工作区分配游戏客户区、左栏和底栏，尚未为 CS2 的原生窗口外框留出边界；游戏下边框可能覆盖底栏顶部。

## 决策

- Host 对当前现场左栏、底栏和已发现的 CS2 窗口使用 Windows `ITaskbarList2::MarkFullscreenWindow`。现场窗口处于活动状态时由 Shell 将任务栏置于其后；切换其它应用仍由 Windows 恢复正常任务栏层次。
- 不修改任务栏的全局自动隐藏设置，不直接隐藏 Explorer 窗口，也不增加独立任务栏守护进程。标记按窗口句柄维护，重复显示不重复提交；隐藏现场、结束制作、正常退出和更换游戏窗口时撤销旧标记。已销毁句柄可直接释放记录。
- Shell 标记成功后采用目标显示器完整边界；游戏保持 75% 上限和 16:9 客户区，左栏延伸到屏幕底部，底栏使用游戏下方的余量。标记失败时保留原工作区布局，不假定任务栏已经退出画面。
- 游戏完成定位后测量原生外框，左栏避让左边框，底栏从外框下沿开始；DPI、工作区或游戏窗口变化时共同重排。窗口坐标统一使用物理像素。
- Host 只管理窗口展示和 Shell 标记，不增加制作状态或改变正式 OBS 来源。退出收尾失败时现场继续存在，标记和后台跟踪继续有效，修复后可以重试。

## 与既有决定的关系

本决策替代 ADR-0023 的“不占用系统任务栏”边界和 ADR-0026 的“75% 可用区域”所使用的工作区来源；比例、游戏启动/备份、现场生命周期、OBS 准备检查与远程捕获规则保持有效。对应当前规则在架构、设计系统与操作手册维护。

## 代价与验证

依赖 Windows Shell 的窗口级全屏提示，不能等同于修改系统任务栏偏好。异常退出时系统偏好不发生变更；仍存活的游戏窗口可能继续被 Shell 视为全屏，切换应用或关闭游戏可恢复其任务栏行为。

自动化检查标记去重、更换窗口、撤销失败重试与回退，并检查不同原生边框宽度下的面板边界。指定 RC 还需实测进入、隐藏/恢复、切换其它应用、正常退出、CS2 重启和多显示器/DPI，以及左栏贴底与底栏不被游戏覆盖。

Windows 语义来源：[ITaskbarList2::MarkFullscreenWindow](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist2-markfullscreenwindow)。

# ADR-0026：CS2 启动、临时视频配置与恢复

状态：Accepted（2026-10-06，用户确认默认启动设置与结束时退出恢复）。

## 决定

补充 ADR-0014 的桌面物理职责：Desktop Host 管理本次启动的 CS2 和临时视频配置；Companion 仍独立拥有制作生命周期、等待场景与数据源释放。Host 不复制比赛、OBS 或制作状态。

桌面进入现场先通过已有 OBS 准备检查，再由 Host 启动或复用本次受管理的 CS2，随后提交 Companion 制作命令并展示现场。设置页也可提前启动游戏。已由用户打开的外部游戏要求先自行退出，不自动关闭。启动成功但进入现场命令失败时保留受管理游戏，可重试进入或在设置页退出恢复；避免并发页面的失败回滚关闭另一页面正在使用的游戏。

启动前复用 GSI 安装目录发现，使用 Steam 活动账号的本机 `cs2_video.txt`，只接受唯一安装和配置位置。Steam 必须已运行并登录。通过当前运行的 Steam 客户端 `-applaunch 730` 启动，传递窗口、宽高参数，并核对新游戏属于发现的安装位置；不加入 demo 的 `-insecure`，不修改持久 Steam 启动选项、键位、autoexec 或其它账号配置。

默认窗口模式、1920×1080 和游戏 Very High 预设；「保留原画质」只跳过画质字段，保留其 FSR 等现有设置。现场仍按显示器可用区域的 75% 宽、高限制排布，保持 16:9；不承诺实际渲染始终为 1080p，不增加缩放捕获或另一种游戏承载方式。最高预设字段来源在 RFC-0002 记录。

修改前将原始 UTF-8 字节、应用结果、字段集合、路径及进程身份持久化并读回验证。只修改本会话白名单字段；未知字段、注释、换行和 BOM 保留。不接受格式不明、重复字段或缺少关键字段的配置。恢复使用启动前的白名单值，也撤销游戏自动保存的窗口尺寸及这些字段的会话内修改；其它字段的修改保留。备份记录损坏或当前格式无法解析时停止恢复，保留备份。

隐藏现场只管理窗口。结束制作先由 Companion 成功切换等待场景并释放数据源，再回到准备窗口、正常关闭本次受管理游戏；进程身份同时核对 PID、创建时间、程序路径并持有进程句柄。启动前要求没有 CS2，Steam 启动后仅认领来自该安装、创建于本次请求之后的唯一游戏进程；启动身份不明时不认领，保留恢复记录。不按进程名强杀。关闭超时、身份不明或其它 CS2 正在运行时保留待恢复状态。确认退出后等待写盘，再恢复并读回验证，成功后才清理待恢复记录。

退出 Mizar 不强制关闭游戏，持久记录跨重启保留；重新打开后检测游戏是否退出，退出后重试恢复。未完成记录不可被下一次启动覆盖。恢复入口在游戏数据设置页，不能通过网页传入任意文件路径。成功恢复后保留最近一次原配置副本。

## 后续决定

ADR-0027 补充启动结果待确认、跨窗口状态与临时启动项策略，并替代正常退出 Mizar 时保留游戏的决定；本篇保留原始理由。

## 验证边界

配置变换、备份与重启恢复、损坏记录、画质保留和制作调用顺序可自动验证。Windows 进程、Steam 在线启动、游戏接受配置、Steam Cloud、OBS 捕获及实际性能仍需指定构建实测；缺少该证据不阻止实现，也不宣称通过真实制播验收。

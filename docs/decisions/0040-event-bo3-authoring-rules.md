# ADR-0040：赛事 BO3 禁选规则与本场 BP 事实

- 状态：Accepted
- 日期：2026-10-07

## 背景

真实 EPL24 比赛使用先禁方先做最后一次禁图、选图对方选边、决胜图在游戏内决定阵营。RivalHub 当前在线流程与 Mizar 旧编辑器使用另一种固定 BO3 顺序，不能将其当作所有赛事的规则。

## 决策

本机赛事资产沿用现有 LocalTournamentStore，增加可选的 BO3 默认规则：最后两次禁图先后，以及决胜图由先禁方、后禁方选边或在游戏内决定。未配置的旧赛事保留原 RivalHub 默认，BO1/BO5 的现有流程不变。先禁方是 Veto A，队伍 A/B 稳定身份不因角色改变而交换；两张选图仍由对手选边。

规则是制作输入，实际地图、禁图方和选边仍由同一编译路径写入 MatchDocument / MatchContext 的有序 veto 与 maps。没有第二份运行时 BP 状态，也不扩展 Gameplay/Radar 公共数据。游戏内决定时不生成决胜图 side_pick，不预填起始阵营。

赛事默认只用于尚未录入 BP 的比赛。已经存在的禁选顺序和选边优先用于恢复本场编辑草稿；修改赛事默认不重写旧 BP。本场规则调整需显式编辑并保存，只改变本场事实，不顺带改写赛事默认。新建独立 BP 的赛事可使用该草稿规则初始化；规则与赛事资产一并持久化。

本地工作区草稿响应升级为 `mizar.bp-workspace.v5`。旧请求未带规则字段时仍接受，并使用当前已有 BP 或所选本机赛事规则；不得因省略字段回写成另一种固定顺序。在线来源身份继续锁定，本地补录不修改 RivalHub 网站规则、数据库或官方身份。现有平台 BP 事实照常展示，不重新套用本机默认规则。

## 验证

覆盖真实 EPL 九步、两个对手选边、决胜图留空、旧默认、未知规则拒绝、规则继承、默认变更不改旧事实、重新保存、重启恢复和组件键盘/禁用状态。公开 RC 的 Windows 实测与规则自动化分别记录，不将旧包截图转写为新实现通过。

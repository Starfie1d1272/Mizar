# ADR-0022：远程制作窗口的捕获策略

状态：Accepted

## 背景

RC3 的工作区与控制栏强制启用 Windows 内容保护。原机用户通过远程串流操作，工作区被捕获链路排除，使现场控制不可见。浏览器备用入口不能替代已交付桌面工作台的远程可用性。用户明确要求移除该限制。

## 决策

- `workspace-left` 与 `workspace-dock` 不设置捕获排除，允许远程软件、截图与任务栏预览显示。无需增加远程模式开关或另一份运行状态。
- 本机 Program Overlay 同样不设置捕获排除，使远程操作者能看到游戏上的 HUD；其焦点、穿透和几何策略保持既有职责。
- OBS 正式场景通过游戏捕获和独立的 Program Browser Source 组成，不通过捕获制作工作区隔离节目。选择显示器捕获或工作区窗口捕获时，制作信息可能进入录制；操作手册明确来源选择。
- Program/Assist 的投影和协议隔离继续遵循 ADR-0004。此变更只调整当前制作窗口，不授权把未来观察辅助字段放入公开投影，也不改变独立 Assist 窗口的隔离要求。

## 后果与验证

此决策替代 RC3 实现中制作窗口必须排除捕获的策略；ADR-0010 的 Host 职责和 ADR-0004 的数据隔离继续有效。用户可通过远程软件操作原生工作台，也能截取制作界面。

指定 RC 在 Windows 上检查工作区、控制栏和本机 HUD 的捕获标志与实际远程显示；检查 OBS 正式来源仍使用游戏与节目画面，并验证游戏捕获没有重复叠入本机 HUD。远程截图只证明该捕获路径的显示，实体显示器布局、多屏与 DPI 仍单独验收。

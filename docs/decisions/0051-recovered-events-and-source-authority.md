# ADR-0051：恢复事件与数据源授权隔离

状态：Accepted

## 决策

补充 ADR-0021 和 ADR-0050：持久队列恢复继续保留事件原生产实例，不改写事件游标。RivalHub 适配器上传前核对事件的生产实例与会话是否匹配当前认领；不匹配时在本机返回终止投递结果，保留原事件与结果记录，不发起网络请求、不撤销新认领。附带的当前首发证据也必须匹配生产实例、会话、代际和地图执行。

## 原因与边界

跨进程恢复可以恢复相同 liveSessionId，但网站的数据源授权同时绑定 producerInstanceId。旧进程事件使用新进程的认领上传会被网站正确拒绝，客户端却随之清除正常的新认领。仅比较比赛、会话和地图执行不足以保证上传授权一致。

通用 outbox 的原事件恢复与重试退避保持不变；本决策属于 RivalHub 传输边界。新进程仍由新的真实观测生成开始证明，不重写旧事件冒充新证据。与当前认领一致的真实 403 仍停止上传。

## 在途请求的有效性

补充 ADR-0050 的回执边界：同次认领的地图开始回执还必须属于最近一次开始投递，不能只比较认领对象。可靠队列拥有本次发送的截止时间与取消信号，RivalHub 和通用 HTTP 适配器向网络传递该信号；超时取消后，即使传输层仍返回响应，也不再修改认领或地图确认。直接调用 RivalHub 可靠发送采用相同的默认等待上限。低频控制请求的等待上限不用于可靠队列。

后台比赛刷新不抢占正在加载的明确选择，提交时仍核对候选代次。BP 编辑使用最后有效资料保留用户输入，连接失败只改变可保存状态，不卸载编辑器；恢复后的版本冲突继续使用既有检查。

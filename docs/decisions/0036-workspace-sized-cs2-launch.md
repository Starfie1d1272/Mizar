# ADR-0036：受管理 CS2 按工作台尺寸启动

状态：Accepted

## 背景与替代范围

替代 ADR-0026 的固定 1920×1080 启动分辨率，保留窗口模式、临时画质、进程认领与持久恢复事务；补充 ADR-0031 的窗口对齐边界。

真实 Windows 检查发现：1920×1080 屏幕的工作台游戏槽为 1440×810，CS2 却保留启动时的 1920×1080 客户区。原生外框接受缩放不等于引擎接受新的客户区尺寸；根据两者差值再次缩小无边框外框会造成裁切，不能据此宣称已对齐。

## 决定

Host 启动前从物理显示器边界调用既有 `workspace_layout`，取其游戏槽的宽高，同时用于 Steam 本次 `-w / -h` 参数与临时视频配置。尺寸来自 Host，不接受网页提供的任意尺寸，不新增布局计算来源。启动前没有游戏时沿用既有主显示器选择；游戏发现后的显示器跟踪与窗口职责不变。

恢复记录继续只接受原有允许列表字段和两个既定画质方案，允许宽高为正整数且严格 16:9；原来的 1920×1080 记录仍受支持。恢复仍核对原配置、应用结果和字段集合的一致性，不扩展任意配置写入。

无边框窗口已接受目标外框而客户区不同，Host 保持目标外框，不再通过再次缩小外框补偿。运行中更改显示器分辨率后，若游戏拒绝客户区调整，本机 HUD 保持隐藏并明确提示退出工作台后重新进入，以新尺寸重新启动；不自动关闭游戏，不注入游戏控制台命令。DPI 改变但物理游戏槽不变仍由既有自动重排处理。显示器边界改变时重新给予既有有界对齐重试预算。

## 验证

自动化覆盖多种 16:9 启动尺寸的持久恢复、旧记录兼容、未知字段拒绝与无效尺寸。实际屏幕、DPI、游戏客户区、OBS 捕获与退出恢复仍在同一最终 RC 上验证；诊断构建只用于定位，不作为发布资格。

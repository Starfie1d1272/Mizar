# ADR-0045：受管理游戏的画质与帧率预算

状态：Accepted（2026-10-08，用户要求默认限制游戏帧率，并提供独立画质预设）。

## 背景与替代范围

同机 CS2 不限帧时可使 WebView 呈现长时间阻塞。雷达绘图脚本很短、减少图形复杂度或分离 WebView 进程都不足以排除该问题。默认给游戏无限帧率与制播工作台需要共享图形资源的用途不匹配。

本决定局部替代 ADR-0026 的画质选项与“不修改 autoexec”边界：只把启动配置中的直接 `fps_max` 赋值纳入临时恢复事务。窗口尺寸继续遵循 ADR-0036，制作生命周期、游戏进程身份与正常退出顺序继续遵循 ADR-0027、0028、0033。不修改键位、Steam 持久启动项或其他账号。

## 决定

画质提供最高、高、中、保留原画质；默认最高。高、中采用游戏原生预设，不按数值大小猜测等级；中包含原生 FSR，界面说明清晰度取舍。字段来源是 [Valve 游戏配置的固定快照](https://github.com/SteamDatabase/GameTracking-CS2/tree/ac1278dbbff39b7fe5030fba42a010e455c011f6/game/csgo/pak01_dir/cfg)中的 `video_defaults_1/2/3.txt`，精确字段由 `cs2_video.rs` 维护。

帧率独立提供 60、30、不限帧，默认 60。不限帧保留用户选择，显示红色及文字卡顿风险。这个上限针对 CS2；不改变雷达时钟、GSI 数据含义、显示器刷新率或 OBS 配置。用户主动在游戏内再次修改命令时，上限可能改变；不建立持续控制台注入器。

只传 `+fps_max` 不足以保证启动结果：Steam 保存的 `+exec auto.cfg` 可以在后面再次执行 `fps_max 0`。Host 在修改任何游戏文件前，读取当前账号的帧率配置及 Steam 启动项，解析 `autoexec.cfg` 和启动项引用的 cfg，以及有限的嵌套 `exec / execifexists`。仅替换直接的 `fps_max` 数值，保留其他字节；不执行读取到的命令。拒绝冲突的 Steam `+fps_max`、已识别的动态帧率命令、异步执行、不明格式、越界路径及超限输入，不把失败报告为已应用。

视频、游戏帧率配置与需要修改的启动脚本共用 Host 的持久备份。先完整保存及读回，再写配置并提交 Steam 启动；中途失败保留恢复记录。旧版本恢复记录仍可恢复。游戏退出后，视频与 convars 只恢复受管理字段，其他游戏写入保留；启动脚本恢复原文件，出现外部编辑时停止恢复并保留备份。最近一次原文件仅在本机保存，不进入状态响应或支持导出。Steam `localconfig.vdf` 只读取所需启动项，不复制到备份。

## 代价与验证边界

临时修改脚本扩大了恢复事务；任意动态脚本无法静态证明其最终运行值，因此实现只支持明确的有限命令形式。新事务需验证中断、重启恢复、外部编辑冲突、路径边界及旧偏好迁移。实机必须核对游戏真正的帧率、启动脚本覆盖与结束后恢复，不能用设置值代替实际结果。

锁帧能缓解已观测的资源竞争，但不能保证所有显卡、驱动、显示器路由和其他后台负载下无卡顿，也不把操作系统或驱动的具体等待机制认定为已证明。既有窗口几何去重和 WebView 可见性同步作为宿主修正保留；无收益的独立雷达进程和 Canvas 参数实验不成为产品设置。

# ADR-0029：C4 解码、索引与预测的线程隔离

状态：Accepted（2026-10-06）。补充 ADR-0020 的资源执行边界，替代主服务线程直接构建与调用预测器的实现；预测模型、资格条件和公开协议不变。

## 决定与理由

返回 Promise 的地图加载仍含同步解压、JSON 解析和预测索引构建，会阻塞 GSI 与 HTTP。Companion 用一个 Worker 执行完整资源准备和站立预测；调用 Core 已有准备函数，不把 field 或索引传回主线程重新构建，也不在 Worker 保存比赛状态。

主线程仍拥有唯一当前投影与数据资格。异步预测暂时不可用；结果按地图、数据源代际、地图执行和全部计算输入匹配缓存，只请求当前状态重新投影。Core 每次继续检查当前序号、活人、名单、回合、覆盖和新鲜度。过期上下文结果丢弃，不能直接发布请求时保存的帧。

同时最多一个地图加载、十个在途预测、每图三十二个计算结果；主线程与 Worker 同步淘汰到最多两张缓存地图。准备第三张地图时旧两张与构建中的资源可以短暂共存。关闭、Worker 故障和十五秒超时拒绝待处理任务并终止线程，预测降级，不影响正式遥测。Worker 不自动重启，避免持续失败循环。

代价是预测需一次消息往返，等待时不显示估算。离散重放和样例工具显式等待当前预测任务，再读取同一投影；现场 GSI 接收不等待。实机长时延迟、内存平台期和真实 OBS 渲染仍须在指定 RC 上测量，模块探针只证明主线程阻塞的变化。

# ADR-0027：CS2 启动结果与跨窗口恢复流程

状态：Accepted（2026-10-06，用户要求软件退出恢复与异常退出后的手动恢复）。

## 决定与替代范围

补充 ADR-0026；替代其中「退出 Mizar 不关闭游戏」的行为。正常退出 Mizar 与「退出工作台」均尝试正常关闭本次受管理游戏并恢复视频配置；退出工作台仍先完成 Companion 的节目收起与数据源释放。隐藏窗口保留游戏，OBS 独立进程保持原有职责。异常退出或恢复失败保留磁盘记录，下次启动能继续恢复。

Steam 已收到启动请求但未取得游戏身份，是独立的待确认状态。超时、重启或暂时没有进程都不能清理备份。后台继续核对唯一新进程的路径和创建时间，确认后纳入原会话；无法确认时，用户先取消 Steam 的启动请求并确认游戏关闭，再显式恢复备份。任何恢复路径都不能绕过这项判断或覆盖旧记录。

状态命令在后台读取，遇到长操作锁竞争立即返回「正在启动／正在恢复／正在检查」，不等待同一把操作锁。忙碌响应不补造游戏或配置状态；各窗口保留最近快照并单独显示操作阶段。

游戏已启动而制作提交或窗口展示失败时，重新读取 Companion 实际状态，保留新启动与复用游戏，不自动回滚关闭。准备中心持续从 Host 读取备份与恢复结果，提供打开工作台、退出恢复和打开备份目录；失败不只显示在隐藏底栏。

启动项只通过本次 `Steam -applaunch` 传递，加入开发者控制台、OBS 游戏捕获兼容与国际服选择；不写入 Steam 保存的启动项，因此没有持久启动项覆盖或恢复步骤。只恢复 Mizar 实际修改的视频字段，不照搬 Demo 录制工具的 `-insecure`、全配置覆盖或其它账号恢复策略。

## 依据与代价

参考 [CS2 Insight Agent 的磁盘备份与读回核验设计](https://github.com/DrEAmSs59/CS2-insight-agent/blob/f05c698c755dc7806855bb13a5c823dbf6a21de6/backend/app/cs2_config_backup.py)，独立实现，不复制代码或引入其依赖。其录制环境与 Mizar 在线观战的安全启动、配置修改范围不同。

Valve 的[国际服说明](https://help.steampowered.com/en/faqs/view/0653-C465-7FC1-44C1)支持国际服选择及跳过区服提示；[受信任模式说明](https://help.steampowered.com/en/faqs/view/09A0-4879-4353-EF95)解释第三方软件选项。后者可能影响信任系数，设置帮助中明确显示。社区启动项清单相互矛盾，不默认加入线程、优先级、无限帧率或旧 CS:GO 参数。

待确认启动的恢复需要用户取消尚未完成的 Steam 请求；Mizar 不宣称可从「当前无进程」证明 Steam 已取消。完整 Windows、Steam、CS2、OBS、Steam Cloud 与长时制播仍需指定包实测。

# ADR-0038：热身省略回合历史时的执行边界

- 状态：**Accepted**
- 日期：2026-10-07
- 修订：ADR-0037 的“明确空历史”必要条件

## 背景

RC19 最终发布包在同一 CS2 进程执行真实 Nuke `playdemo` 后，收到完整的 `warmup`、回合零与 CT/T 零分，但源 `map` 没有 `round_wins` 字段。旧执行的 15 个回合因 ADR-0037 的显式空历史要求而残留。此前对缺失字段使用零长度摘要，错误地把源缺失描述为显式空历史；实机证据须按实际字段形状更正。

## 决定

沿用 Core 唯一执行边界和“曾观测正式阶段”的有界证明。在相同已知地图、完整地图覆盖、热身、零回合、双方明确零分同时成立时，历史字段允许为空或省略；明确非空历史仍与该基线冲突并拒绝转换。缺失历史不被适配器改写成收到空历史，数据覆盖语义保持不变。

重复热身仍只推进一次。缺少热身、回合或任一方比分、地图降级、单独回合降低、菜单帧及重连本身仍不能证明重开。不扩展为根据普通 live/0:0 猜测执行，不增加展示层或系列赛层的独立重开推断。

既有转换继续重建统计、目标计时和未完成当前图的历史，已完成地图的冻结结果保持。

## 验证

覆盖显式空历史与源省略历史两种热身、重复热身、冲突非空历史、缺失比分、非零比分、降级、普通 live 回退和重复输入；组合验证未完成旧历史清除与原状态不可变。最终 RC 必须在真实同进程重播中确认新执行编号、空的新执行历史及后续自然半场历史，自动化不替代实机结果。

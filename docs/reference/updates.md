# 应用内更新

更新属于分发能力，由 Companion 验证版本和下载，桌面宿主负责执行用户发起的升级与正常退出。既有比赛、节目、OBS 和用户资料继续由原模块持有。

## 可信元数据

Stable 使用 `update-manifest.json`，结构标识为 `mizar.update.v1`，包含仓库、正式版本、源码 SHA、中文更新说明、兼容的旧版范围及 Windows x64 NSIS 安装包的名称、字节数、SHA-256 和内容摘要。中文更新说明从 CHANGELOG 的精确版本正文在构建时转换为纯文本，提取与格式规则由[发布流程](../development/release-readiness.md#更新日志与发布正文)维护；客户端只显示文本。资格构建在便携包与安装包通过验证后从原始分发清单生成，签发同一 GitHub 构建来源证明，并保存原始 `update-provenance.json` 验证包；晋级上传原清单、证明和原安装包，不重新打包。发布配置中的版本必须与应用版本一致。

检查匿名读取 GitHub 的 `releases/latest/download/machine-metadata.json`，从原机器元数据提取 `mizar.update-index.v2` 信封。信封包含原更新清单、原正式发布确认的 Base64 字节及各自的原始 Sigstore 证明。客户端必须验证证书、透明日志及文件摘要：更新清单由本仓库 main 的 Release Qualification 签发，清单源码等于其构建源码；发布确认由 main 的 Release Promotion 在正式 Release 实际发布并核对原资产后签发，绑定版本、产品源码、原清单摘要、Release ID、发布时间及晋级工作流源码。资格通过不等于正式发布授权，缺少发布确认不能作为 Stable。固定版本认证读取 `releases/download/v<版本>/machine-metadata.json` 并核对原清单版本；安装器不会因 latest 推进而改装其它版本。

元数据请求不调用匿名 Releases API、不携带 Token、不持久缓存运输结果；GitHub 运输失败才尝试固定 GH-Proxy 地址，每路最多 15 秒、载体最多 16 MiB，重定向仍受允许列表约束。字节取得后只执行一次原双签名与 SDK 验证，格式、签名、身份、摘要、信任服务或反回退失败保持失败，不再切源认证。代理只是公开字节的运输来源，不提供信任；小元数据采用顺序回退，不额外测速。`no-store` 不能保证远端代理没有旧缓存，签名只证明已知正式版本，不证明此刻不存在更新版本。本机最高版本及同版本身份约束继续拒绝回退。GitHub latest 已推进但该版本机器元数据尚未发布完成时检查失败，保留本机版本，之后重新检查；不把旧 Box 指针或上次成功结果当作已确认最新。

过渡期继续向 Box 发布旧客户端所需的 `/Updates/latest.json` 和 `/Runtime/v<版本>/machine-metadata.json`，使用原协议及原始签名字节。停止新增大文件不删除、移动或覆盖历史资产，Box 只读 Token 及旧路径保留。旧安装器不能远程修补：已发布安装器的 Box 前置检查和固定后端仍可能依赖旧文件。退出兼容前必须按实际发布版本验证升级或桥接入口，不能按经过几个版本自动停服。

Sigstore 的内置 TUF 根负责信任根更新、轮换与吊销，不接受下载源指定的公钥、证书或信任根；验证优先使用 SDK 支持的 `tufForceCache`：缓存仍须通过签名、角色绑定、有效期及目标摘要检查；缺失、损坏或过期时按 SDK 刷新和轮换，不接受失效材料。资源完成阶段的既有 `createMizarVerifier` 同样使用此 SDK 缓存策略，保留原精确证书源码 OID 约束，避免更新来源认证后立即重复刷新。每个信任请求最多重试一次，单请求 8 秒，更新来源认证的调用阶段 20 秒；每个元数据来源运输有独立 15 秒预算，检查仍受总计 60 秒约束。SDK 没有取消接口，调用阶段超时后在途初始化继续受 SDK 请求限制，现有共用 TUF 验证入口按缓存绝对路径串行初始化，跨签名策略与新来源实例都等待后台 SDK 真正结束；排队调用到期后不再启动 SDK。同一进程之外沿用桌面正常退出和安装/资源写入所有权约束，不新增全局文件锁。信任端点失败直接保留该原因，不通过另一个分发源重试同一信任服务；版本发现运输或发行证明失败保持失败；已知固定版本的原资产仍可经受控下载来源取得并按同一证明验证。阶段耗时与原因进入既有诊断日志。签名索引不可验证、元数据缺失或兼容范围不匹配时仅保留正式 Release 页面，不能下载安装。

现代客户端从原机器元数据验证同次 Qualification 对 Full/Core 原始构建与分发清单的证明，绑定精确 subject、源码、版本、派生摘要和 Windows x64 NSIS 身份后选择轻量 Core。缺少或损坏 Core 元数据不能退回未经验证的安装；两个来源使用相同规则。历史 Full 安装包继续保留在 GitHub；国内镜像不再维护旧更新器后端，新构建更新范围从 1.6.0 起。

客户端保留已验证版本和摘要，拒绝回退及同版本换包。此记录只在完整来源验证后更新；网络检查失败不覆盖已验证信息。更新说明作为文本显示，不执行 HTML、脚本或清单提供的链接。

## 检查与下载

更新目录创建或校验、启动扫描、暂存清理失败时，记录具体阶段及脱敏的原始原因链，仅停用本次运行的更新功能，其他健康的主应用功能继续启动。检查、下载、准备安装、取消和修改自动检查设置均拒绝执行；保留现有更新、备份与恢复记录，核对目录权限、占用和空间后重启，不删除记录绕过校验。

用户可主动检查 Mizar 和 MulNX，两个产品共用桌面启动与周期检查偏好。进入制作前若自动检查开启，等待两项有界检查；失败或超时保留本地版本继续。发现更新时可进入维护或选择稍后，进入维护会取消本次进入意图；导航或制作修订变化时不迟到启动。检查不自动下载或安装。新安装和缺失的自动检查字段默认开启；已保存的 false 保持关闭，不推测它是历史默认还是主动选择，也不增加迁移弹窗。每次真正启动桌面宿主时通知既有 UpdateManager 检查一次，复用 Companion 时同样执行；同一启动标识去重，页面重载和重复挂载不触发。持续运行每 6 小时复查，按实际经过时间判断，休眠恢复后只补一次到期检查；失败也计入间隔。启动、定时与手动检查共用同一任务，下载和准备安装期间延后，不后台下载或安装。

已验证的新版本在准备中心用现有 Dialog 展示版本、纯文本更新说明和「查看更新 / 稍后」。「查看更新」进入高级设置的既有应用更新入口；关闭和稍后都不发起下载。制作、场景切换/接管、OBS 推流/录制及无法确认 OBS 状态时延后；界面失焦、正在输入或已有模态框时也延后。读取提醒候选不消费版本；输入、失焦或制作状态变化只延后显示，轮询刷新不会取消仍在途的读取。用户点击「稍后」「关闭」或「查看更新」时，UpdateManager 才记录该已验证版本已确认，本次宿主运行不再提醒，页面重载仍去重；下次真正启动可以再次提醒该版本。后台检查失败和没有新版时不弹窗，设置页保留真实错误及手动检查入口。提醒不改变原安装安全门禁。检查、下载和失败阶段写入有界本机日志，日志记录阶段、版本、操作关联标识和脱敏的有界错误原因链；网络失败保留来源域名与 HTTP 状态，回退前保留原来源错误。凭据、临时下载地址及响应正文不进入日志，常规界面只显示简短错误。原始本机日志供维护者定位；支持包保留更新与 CS2 工具的脱敏原因及相关输出，未知异常也保留原始 message 与 cause。普通界面显示阶段、已知原因和下一步，未知原因明确标为未知；信任元数据联网失败不表示签名无效。

下载前先认证发行身份，再以最多两路有界并发请求测量公开 GitHub 原资产和 [GH-Proxy](https://gh-proxy.com/docs/github-accelerator) 加速文件的少量字节。每路最多三秒、最多读取 64 KiB，这是可达性与响应探测，不代表持续吞吐或保证最快；排序按同大小样本耗时计算并在进程内缓存六小时，实际下载重新请求完整文件；全部测量失败时仍依次尝试 GitHub 和加速。探测日志记录候选、各源耗时、HTTP 状态、Range 是否被忽略、失败原因及排序缓存命中；下载日志记录切源原因和最终通过校验的来源。下载失败使该资产排序失效，下次重新探测；不主动检测网络切换，网络变化后的旧排序最多保留到缓存到期，期间仍按完整下载结果回退。加速服务只传输公开 Release 文件，不接收凭据，也可运输小元数据，但不参与来源认证。各来源均使用已认证清单的大小与 SHA-256 验证全部字节；云盘清单和 `.sha256` 不作为发布者认证。请求和重定向限定 HTTPS 允许地址，响应、磁盘写入和时长均有上限。每次下载使用程序资源目录外的独立暂存目录；取消、失败及重试清理不完整文件。下载完成可稍后安装，重启后重新验证元数据和完整文件。

MulNX 独立跟随上游公开发行，读取国内 Box 签名索引。索引必须通过专用 main 工作流的 Sigstore 证明，绑定上游发行、资产和附属许可文件的大小与摘要；信任根有效期、签名身份和本机最高版本防回退检查保持独立。索引的 `checkedAt` 在六小时内时采用该快照，界面标为「上次确认版本」，并分别显示「版本确认时间」与「本次检查时间」；前者使用索引记录的上游检查时间，后者为客户端本次检查完成时间。六小时是客户端认定该索引近期完成上游检查的窗口，不证明此刻没有新发行；每小时同步可能发生调度或故障延误。索引缺失或不可验证时检查失败，不回退匿名 GitHub；超出窗口的可信索引只展示已知版本和确认时间，检查与更新准备保持失败，本地已选版本仍可启动。上游 API 查询仅在构建及同步工作流中使用已有认证身份，身份不进入客户端。

同步在认证查询上游后刷新并重签轻量索引；发行身份和许可摘要与已有已验证签名快照一致时复用已发布归档，不重复搬运未变化的文件。新快照仍须完整传输与回读核验，发布指针前再次核对上游身份；客户端实际下载始终校验字节，不将历史发布证明当作当前归档可达性证明。同步失败保留旧指针。

诊断分别记录索引认证、新鲜度及业务结果，不因保留旧候选就记录检查成功。只有与所选发行身份一致的镜像参与下载；归档可按已认证摘要使用其他受控资产来源，附属许可文件必须从同一签名索引约束的镜像获取并验证，失败保持失败，不调用 Contents API。下载显示来源和真实字节，取消或本地写入失败不切源，准备安装开始后不提供下载取消。

EPL 官方资源的元数据继续通过原目录双证明和 SDK 认证。同一次资源认证与后续加载按版本复用内存中的机器元数据原字节，逐项大小限制和原签名认证不变；运输回退在认证前完成，不跨操作保存信任结果。Companion 的 `distribution/resources.ts` 唯一编排目录获取、SDK 认证和 ZIP 获取／验证；`fetchPublishedResource({ core, tufCachePath, signal, onProgress? })` 返回 SDK 的已验证成员、清单和 receipt。Core 身份来自已认证运行环境，不能由页面传入。安装器通过同模块的 `authenticatePublishedResource` 先取得授权，缓存不可复用时才调用返回的 `loadVerified`；恢复调用直接完成同一链路。入口不访问 Store、不激活、不向安装目录写入，归档临时传输文件由 `resource-transport.ts` 清理。已授权 ZIP 使用同一 `distribution/sources.ts` 响应探测和 `transfer.ts` 暂存、大小／SHA-256 校验及回退；候选为公开 GitHub 和加速资产。坏包在传输层拒绝并尝试下一源，本地写盘失败或取消不切源。唯一元数据运输入口不再接受 ZIP，避免绕回旧的内存下载路径。完整归档经临时文件核验后交回原 SDK 校验发布证明与成员；Store 继续独占资源缓存和激活，不因传输排序改变授权。EPL 运输阶段、切源与最终摘要写入安装桥既有 stderr 日志；现有安装界面的资源阶段不新增逐源进度契约。

Mizar 的新版本发现、固定版本认证、安装器和官方资源不依赖 Box。MulNX 是独立链路，继续使用专用公开资料库只读 Token，查询时核对 Mizar 资料库和 `r` 权限；Token 不承担签名职责，不进入日志、不随下载重定向发送，不能复用发布工作流的读写凭据。

Box Sync 先验证 GitHub 原发行身份、双签名与原资产字节，再仅同步每版机器元数据，完整回读通过后最后替换并回读 `Updates/latest.json`。失败保留旧指针，同版本异内容及乱序回退拒绝。GitHub 发布成功与 Box 兼容同步成功分别报告；两者均不替代旧版真实升级验收。发布步骤和兼容保留条件见[发布流程](../development/release-readiness.md#分发镜像与应用内更新)。

## 安装与恢复

更新记录读取失败和暂存清理失败按本机故障提供下一步，不推断网络问题。诊断保留原异常及操作关联号；损坏的设置或安装恢复记录不自动删除、重置或覆盖，安装结果身份无法确认时保留原恢复提示。安装结果或其身份记录读取失败在设置页持续显示，检查成功、下载或取消不会清除未解决的恢复说明；服务重启后从原记录重新核对。偏好修改和设置文件保存串行执行，失败恢复原值后再处理下一次修改，检查等待在途偏好保存，不让旧失败覆盖较新的成功状态。先保留当前版本、备份和恢复记录，检查目录权限、空间或文件占用并导出诊断；只有明确网络失败才提示检查连接后重新检查。

安装版通过既有 `installed.flag` 识别。便携版只显示更新说明及正式下载入口，不启动 Setup，不迁移 `state/`。自动安装只支持同一兼容范围，跨主版本或回退通过人工备份、迁移及验收处理。

安装包下载总时限到期显示下载超时及重新检查、下载的下一步，保留原超时原因链；不将超时归为用户取消。用户主动取消仍撤销本次安装意图并清理部分下载。两者均不得提供未完成的安装包。

更新页默认展示版本与更新日志。「一键更新」是用户对下载及安装的明确授权，验证通过后自动衔接安全退出、静默安装和重新打开，不再要求第二次确认或备份勾选。选择「稍后」、取消、验证失败或进入制作会取消本次安装意图；保留的下载不会因后台轮询或退出制作自行安装。Live、隐藏但仍在制作、节目手动接管或切换中、OBS 推流或录制中、OBS 仍在运行但无法核对播出状态，以及打开的编辑工具均阻止安装；下载可以保留。OBS 未启动时无需先启动或连接 OBS：Windows 成功查询全部进程并确认没有 obs64/obs32 进程后允许空闲更新；进程查询失败或超时不能作为 OBS 已关闭的证据。安装计划重新查询，不能复用更新页较早的判断。先保存资料、关闭编辑工具并结束制作，再升级。宿主重新核对条件，禁止浏览器提交路径、安装命令或任意下载地址。来源认证与安装工具暂存期间不锁住制作或 OBS 输出；暂存完成后重新核对并预留退出，只有此时禁止新的制作、场景接管与 Mizar 发出的开始输出请求。停止输出仍可用。

更新准备由整个 Host 进程持有，桌面恢复不会建立第二个并行准备任务。每次尝试绑定独立编号，Companion 的准备、提交、复核和释放均核对该编号；旧尝试不能释放新尝试，释放未确认时保留原编号供核对。Host 启动时在后台等待旧准备任务真正结束，再核对并释放被复用 Companion 的孤儿预留，不依赖已锁住的更新按钮；正常 OBS 缺席下的失败重连不算新的播出变化。每个 GUI 在接收命令前绑定固定代际票据，桌面退出使旧票据失效；迟到才开始的旧命令也不能领取新代际，旧 GUI 的取消不能清掉新 GUI 的预留。同一 GUI 内取消更新只撤销该准备任务，不使当前窗口永久失效。迟到的暂存完成不能向重建后的界面提交退出。退出收尾开始前、收尾完成后及停止 Companion 前重新核对 OBS；已观察到开播、录制、过渡或未知状态时拒绝更新，保留原程序与已有下载。外部 OBS 手动操作与服务关闭之间没有原子协议，最后核对不保证其后到进程实际退出之间不发生外部开播。

安装前重新认证失败时，接口和桌面设置页保留本次复核的已知原因及下一步，例如镜像不可用或缓存安装包摘要不符；损坏的缓存仍按原策略丢弃，下一次检查清空旧操作原因。未知原因保持未知，原始异常仅进入脱敏诊断，不以通用重新检查提示替代已知拒绝原因。

宿主以规范化后的实际目录核对安装工具必须是用户数据 `updates` 的直接子目录，名称为 `install-` 加 32 位十六进制标识；既有目录的大小写差异不改变资格。`updates` 或工具目录为重解析点时拒绝，不以规范化绕过目录边界。检查失败不启动安装，诊断保留校验原因或文件系统错误码及阶段，界面给出保留旧版、导出诊断与正式下载入口的下一步。

旧版本在准备安装工具时报告「安装工具目录不在允许范围内」后，仍由旧宿主执行该检查，下载新版不能替换它。此时保留旧程序与用户资料，先导出诊断；保存资料、结束制作及游戏、关闭 Mizar 后，从正式发布页下载目标版本安装器并安装到原目录。不要删除用户数据、备份或恢复目录，也不要改名目录绕过检查。若存在未完成安装或配置恢复提示，先按其恢复指引处理；这条路径检查错误本身不证明安装已启动，也不证明用户现场失败的具体原因。

退出复用正常制作收尾、游戏恢复、持久化写盘和本地服务关闭。任一收尾失败取消安装，原程序保持可用。安装工具在资源目录外独立运行，确认宿主和服务退出、重新核验安装包后，备份旧程序，再以原目录静默调用 NSIS；受控升级固定原安装目录，不覆盖运行中的文件。新程序完整载荷验证通过后恢复用户已有桌面快捷方式；原来没有快捷方式时不新增。Core 升级还须通过已核验载荷内的安装桥，完成资源目录授权、缓存及实际内容验证；资源准备失败走原程序回滚。Full 使用随包资源或已授权缓存，Core 使用已授权缓存，同素材复用保留原主 catalog/声明/归档证明，仅附加新 Core 的独立目录授权；替换素材时沿用 Store 的 previous 快照，程序回滚可恢复旧 Core 的缓存。随后提交升级并自动重新打开。

宿主仍持有桌面互斥时启动更新工具，通过本次私有就绪事件确认工具已接管同一桌面互斥后才退出；接力失败时只取消尚未写入的本次工具，不进入安装。工具从等待宿主退出到安装、完整性核验、失败保全和回滚结束持续持有桌面互斥及唯一写入锁；新桌面和无窗口启动明确提示更新或恢复进行中，重复安装、恢复或回滚不能进入事务。仅在提交和清理全部完成、释放互斥后重新打开应用。不强制结束制作人员的应用来完成安装或恢复。

更新工具使用独立的原生状态窗口显示实际等待、备份、安装、素材核验与恢复阶段，不显示推算百分比；宿主退出后窗口继续显示。尚未替换程序时可以取消，取消请求等待当前非破坏性步骤结束；程序替换或恢复开始后禁止取消，关闭窗口只提示等待，不中断工具或安装器。重复启动尝试聚焦当前更新窗口，系统不允许切换焦点时提示任务栏注意该窗口；被拒绝的程序立即退出，不用同步错误对话框继续占用 EXE。删除旧文件前还须成功取得 EXE 的独占读写句柄，阻止加载时序绕过进程快照；无法独占时不删除旧文件。恢复目录交换同样核对独占资格。全部事务结束后，窗口说明安装、回滚、未启动或需要恢复的真实结果，提供下一步和本机更新日志目录；成功重开后关闭，失败结果由用户关闭。需要恢复且旧版备份通过完整核验时，窗口提供「恢复旧版」，制作人员关闭 Mizar 与安装向导后明确发起；同一工具重新核对进程、安装器占用、备份、登记与路径后回滚，不自动重试安装。没有可核验备份时提示正常退出后手动安装正式安装包，保留现有目录和资料。窗口线程不拥有第二份下载或制作状态。

安装工具记录恢复日志并注册当前用户登录后的恢复入口。取消、错误或新版完整性检查失败时恢复备份的程序、卸载登记和快捷方式；中断后下次登录完成恢复。恢复失败保留备份和可直接运行的恢复工具，明确报告恢复位置，禁止自动重试安装。设置页的「打开恢复目录」只打开用户数据的 `updates` 目录；保存资料并关闭 Mizar 与残留安装向导后，在对应 `install-*` 安装记录目录运行 `Restore-Mizar.cmd`，保留备份和恢复记录。成功核对新版内容和版本后才提交、清理备份。用户数据位于程序目录之外；自定义数据目录位于安装目录内时禁止自动安装，避免目录替换影响资料。

原生安装、更新与素材准备超时保持需要恢复的原判定，并在既有脱敏诊断中保留原超时异常链；超时不证明进程已停止。安装器自身启动失败同样记录脱敏原因并显示诊断位置，卸载文件清理仍受阻时保留最后的系统异常。素材准备未完成时先核对诊断中的原因、网络、缓存权限与空间，必要时使用正式完整离线包，不从这项状态单独推断网络故障。

新恢复工具只作用于原安装实例。NSIS 在既有 `installed.flag` 中保存本次实例；独立安装及同包重装产生新实例，受控更新和首次轻量安装分别使用本事务标识。准备工具固定原标记字节，备份、恢复和提交同时核对内容与实例，版本和程序摘要不授予目录所有权。替换前的成对目录标记支持本事务半写恢复；目标已不存在时，只有恢复与被替换目录均保留本事务配对证据才继续交换，空路径本身不证明恢复权。其他实例或证据不足的旧记录原样保留，不猜测归属。当前和备份快捷方式均核对目标，恢复只处理三个已确认链接，不递归删除开始菜单目录。独立 NSIS 安装、卸载和更新工具复用同一写入互斥；新更新子进程由父事务覆盖，首次轻量安装的 NSIS 自行持锁。受控调用也不由 `/MIZARUPDATE` 推断父锁归属：安装器核对实际写者进程、父子链、暂存计划与当前安装包；受控卸载还核对本次父安装器的临时交接凭据。首次轻量安装及其回滚在取锁后复核原 bootstrap 标记，不能以同版本或相同卸载文件接管后继实例。

已完成回滚同时保存结果和恢复终态；重入先复验旧程序、原实例及结果，只补完本事务残留清理，不再次替换或重写登记。新更新可交接经完整核验的旧终态登录登记和目录标记；未知责任保留，其他任务的登录入口不被旧恢复删除。

新更新工具、独立安装器和独立卸载器在改变所选目标前交接已知旧恢复入口。当前识别 v1.11.1–v1.11.4 的精确原脚本字节，核对目标与数据根后，先排除迟到的脚本装载，再确认已加载的旧 PowerShell 和暂存安装器均已退出；结果窗口仍开着、锁空闲或 journal 的终态都不算退出证明。原脚本和 cmd 移到不可普通执行的归档名，原脚本路径替换为固定拒绝入口，精确匹配的登录登记被撤销；匹配的 bootstrap pending 在原独占文件租约下原字节归档。计划、journal、备份和其他目标的资料不删除，归档中断可继续，冲突或未知来源保留并拒绝本次替换。不要手动运行归档或将旧脚本复制回来覆盖当前安装。进程检查覆盖已知脚本入口、参数缩写和可展开的短路径；不将任意复制、交互加载或编码命令执行的脚本称为已确认退役。

正在调用本次 NSIS 的旧 helper 仍负责自己的当前事务，只有真实父子链、进程创建时间、来源脚本及 stage 安装包摘要均匹配时才保留这一项；不将它标为已退休。下一次新版替代入口必须先交接它。旧轻量安装器仍持文件租约而不能交接可验证的真实句柄时，本次操作明确停止：先关闭旧更新窗口和轻量安装器，再使用完整安装包，不绕过锁或终止进程。独立 Setup、卸载和新版恢复工具在整个写入窗口持有 bootstrap 独占文件租约，零候选也不跳过；受控父子通过实际进程实例和文件句柄复制延续同一租约，核对最终文件路径与排他共享模式，不凭跳过参数放行，父进程提前退出也不释放子进程的副本。旧调用者本身在调用新 NSIS 前已执行的修改及其原有并发边界不由新安装器追溯保证。

交接使用本次明确的数据根、默认用户数据目录及可由精确登录登记核对的旧根；新安装登记保存实际 StateRoot，后续独立卸载沿用它。产品的自定义数据根仍由启动环境 `MIZAR_STATE_ROOT` 选择；安装器的 `/MIZARSTATE=<绝对路径>` 仅明确提供交接扫描根，不改变以后启动程序的环境。历史自定义目录若没有现存登记，不能自动发现，须提供原目录；不扫描整盘或声称默认目录扫描覆盖所有历史记录。已中断交换的成对侧目录也不能证明用户随后安装再卸载的完整历史。

事务已经提交后，恢复仍须重新核对新版完整性；日志的 `committed` 标记不代替文件校验。新版已损坏时保留恢复入口并报告需要恢复，不能记录升级成功；如果旧备份已按成功流程清理，须从正式发布入口重新安装，用户资料继续保留。

非活动 `download-*` 暂存目录清理失败保留诊断，不禁用本进程更新；下次检查或下载时重试。已由安装结果、计划与当前程序摘要共同确认成功安装的旧 ready 先撤销安装资格，其目录和记录清理失败同样留痕重试。当前待安装 ready、身份不明的结果和安装恢复记录不参与这项清理，当前下载的摘要与签名复验保持不变。

更新成功后，启动核对安装结果、计划和当前程序摘要；仅清理版本与摘要均属于这次成功安装的已下载安装包及 ready 记录，其他候选、恢复记录和备份保留。更新页的已完成安装、回滚或取消提示只适用于该次操作结束后的程序包。启动时从同一恢复目录的安装计划核对结果版本与内容摘要；成功安装使用目标包摘要，回滚或取消使用原程序摘要。手动安装使当前包摘要改变后，不再显示旧操作提示，即使版本号相同；原始结果、安装计划和恢复资料仍保留。需要恢复的警告不因当前摘要改变而自动隐藏；安装计划缺失、无效或无法安全读取时保留原提示，不把身份不明解释为恢复成功。

显式 Windows 受控验证使用可控安装器桩检查真实文件系统上的取消、失败、进程残留和中断恢复；常规 CI 不运行这些生命周期验证。安装器桩不证明真实 NSIS 卸载／安装或登录触发恢复的完整链路；真实 Windows 旧版到新 Stable 的升级及 CS2 / OBS 制作保护仍按[发布规则](../development/release-readiness.md)实测。

轻量安装器的覆盖更新在 Core 与资源就绪、最后一次取消检查之后，显式结束回滚窗口，再由原恢复工具取得更新互斥并核对 committed、实际新版完整性及原路径，清理本次旧程序备份、暂存 Installer.exe 与原下载包。清理失败保留诊断、待恢复记录及剩余现场，不自动回滚，也不显示完成；未提交、写入未退出或其他安装仍在进行时不清理。恢复计划和活动日志保留，bootstrap-cache 的跨安装器缓存暂不纳入此事务清理。

后台 PowerShell 工具统一在启动参数前设置 `-NoProfile` 与 `-NonInteractive`，不加载用户 profile，不等待交互输入；原脚本的退出状态和诊断仍按实际结果记录。

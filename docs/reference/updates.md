# 应用内更新

更新属于分发能力，由 Companion 验证版本和下载，桌面宿主负责执行用户发起的升级与正常退出。既有比赛、节目、OBS 和用户资料继续由原模块持有。

## 可信元数据

Stable 使用 `update-manifest.json`，结构标识为 `mizar.update.v1`，包含仓库、正式版本、源码 SHA、中文更新说明、兼容的旧版范围及 Windows x64 NSIS 安装包的名称、字节数、SHA-256 和内容摘要。中文更新说明从 CHANGELOG 的精确版本正文在构建时转换为纯文本，提取与格式规则由[发布流程](../development/release-readiness.md#更新日志与发布正文)维护；客户端只显示文本。资格构建在便携包与安装包通过验证后从原始分发清单生成，签发同一 GitHub 构建来源证明，并保存原始 `update-provenance.json` 验证包；晋级上传原清单、证明和原安装包，不重新打包。发布配置中的版本必须与应用版本一致。

检查优先读取南大 Box 的 `Updates/latest.json`。该 `mizar.update-index.v2` 信封包含原更新清单、原正式发布确认的 Base64 字节及各自的原始 Sigstore 证明，不另同步整套发布证据。客户端必须验证证书、透明日志及文件摘要：更新清单由本仓库 main 的 Release Qualification 签发，清单源码等于其构建源码；发布确认由 main 的 Release Promotion 在正式 Release 实际发布并核对原资产后签发，绑定版本、产品源码、原清单摘要、Release ID、发布时间及晋级工作流源码。资格通过本身不等于正式发布授权，缺少发布确认的镜像不能作为 Stable。Box 未同步、不可用或验证失败时回退到内置仓库的 GitHub HTTPS 接口，排除草稿和预发布版本，按 SemVer 判断新旧，再核对证明、正式标签和资产身份。客户端保留的最高版本还用于排除落后的镜像。

Sigstore 的内置 TUF 根负责信任根更新、轮换与吊销，不接受下载源指定的公钥、证书或信任根；验证需要可用的 Sigstore 信任元数据网络。两个分发源均不可验证、元数据缺失或兼容范围不匹配时仅保留正式 Release 页面，不能下载安装。

现代客户端从原机器元数据验证同次 Qualification 对 Full/Core 原始构建与分发清单的证明，绑定精确 subject、源码、版本、派生摘要和 Windows x64 NSIS 身份后选择轻量 Core。缺少或损坏 Core 元数据不能退回未经验证的安装；两个来源使用相同规则。旧 1.1 清单与 Full 安装包保留兼容。

客户端保留已验证版本和摘要，拒绝回退及同版本换包。此记录只在完整来源验证后更新；网络检查失败不覆盖已验证信息。更新说明作为文本显示，不执行 HTML、脚本或清单提供的链接。

## 检查与下载

用户可主动检查。后台检查默认关闭，开启后最多每日一次，失败同样计入频率限制；退出制作中心不会弹窗、抢焦点或安装。检查、下载和失败阶段写入有界本机日志，日志记录阶段、版本、操作关联标识和脱敏的有界错误原因链；网络失败保留来源域名与 HTTP 状态，回退前保留原来源错误。凭据、临时下载地址及响应正文不进入日志，常规界面只显示简短错误。原始本机日志供维护者定位；支持包继续按允许字段投影，不自动复制自由文本。

下载优先核对南大云盘 Stable 的精确文件名与大小，失败回退 GitHub 原资产。两者均使用已认证清单的大小与 SHA-256 验证全部字节；云盘清单和 `.sha256` 不作为发布者认证。请求和重定向限定 HTTPS 允许地址，响应、磁盘写入和时长均有上限。每次下载使用程序资源目录外的独立暂存目录；取消、失败及重试清理不完整文件。下载完成可稍后安装，重启后重新验证元数据和完整文件。

客户端使用专用的公开资料库只读 Token，查询时核对 Mizar 资料库和 `r` 权限；只允许列目录和获取下载链接。Token 不承担签名职责，不进入日志，不随下载重定向发送，不能复用发布工作流的读写凭据。Token 失效时回退 GitHub。

`Stable/` 按文件类型保留最新轻量 WebInstaller.exe 和应用内更新所需的 Setup.exe；`Offline/` 保留最新完整离线 ZIP，`Archive/` 归档历史正式安装包，既有公开根分享入口不变，不推测子目录分享链接。`Resources/v<版本>/` 保存原资源及原证明。Box Sync 验证原资格证明和正式发布确认，上传并回读两个下载包、更新后端和资源，核对历史归档后最后替换并回读 `Updates/latest.json`；前序失败保留旧更新指针。GitHub 使用同一份 v2 更新索引保存原双签名消息和证明，失败回退原 GitHub 资产。未真实同步不能声称页面已同步。

## 安装与恢复

安装版通过既有 `installed.flag` 识别。便携版只显示更新说明及正式下载入口，不启动 Setup，不迁移 `state/`。自动安装只支持同一兼容范围，跨主版本或回退通过人工备份、迁移及验收处理。

更新页默认展示版本与更新日志。「一键更新」是用户对下载及安装的明确授权，验证通过后自动衔接安全退出、静默安装和重新打开，不再要求第二次确认或备份勾选。选择「稍后」、取消、验证失败或进入制作会取消本次安装意图；保留的下载不会因后台轮询或退出制作自行安装。Live、隐藏但仍在制作、节目手动接管或切换中、OBS 推流或录制中、无法核对播出状态，以及打开的编辑工具均阻止安装；下载可以保留。先保存资料、关闭编辑工具并结束制作，再升级。宿主重新核对条件，禁止浏览器提交路径、安装命令或任意下载地址；准备升级期间禁止新的制作与场景接管。

退出复用正常制作收尾、游戏恢复、持久化写盘和本地服务关闭。任一收尾失败取消安装，原程序保持可用。安装工具在资源目录外独立运行，确认宿主和服务退出、重新核验安装包后，备份旧程序，再以原目录静默调用 NSIS；受控升级固定原安装目录，不覆盖运行中的文件。新程序完整载荷验证通过后恢复用户已有桌面快捷方式；原来没有快捷方式时不新增。Core 升级还须通过已核验载荷内的安装桥，完成资源目录授权、缓存及实际内容验证；资源准备失败走原程序回滚。Full 使用随包资源或已授权缓存，Core 使用已授权缓存，同素材复用保留原主 catalog/声明/归档证明，仅附加新 Core 的独立目录授权；替换素材时沿用 Store 的 previous 快照，程序回滚可恢复旧 Core 的缓存。随后提交升级并自动重新打开。

安装工具记录恢复日志并注册当前用户登录后的恢复入口。取消、错误或新版完整性检查失败时恢复备份的程序、卸载登记和快捷方式；中断后下次登录完成恢复。恢复失败保留备份和可直接运行的恢复工具，明确报告恢复位置，禁止自动重试安装。成功核对新版内容和版本后才提交、清理备份。用户数据位于程序目录之外；自定义数据目录位于安装目录内时禁止自动安装，避免目录替换影响资料。

事务已经提交后，恢复仍须重新核对新版完整性；日志的 `committed` 标记不代替文件校验。新版已损坏时保留恢复入口并报告需要恢复，不能记录升级成功；如果旧备份已按成功流程清理，须从正式发布入口重新安装，用户资料继续保留。

更新页的已完成安装、回滚或取消提示只适用于该次操作结束后的程序包。启动时从同一恢复目录的安装计划核对结果版本与内容摘要；成功安装使用目标包摘要，回滚或取消使用原程序摘要。手动安装使当前包摘要改变后，不再显示旧操作提示，即使版本号相同；原始结果、安装计划和恢复资料仍保留。需要恢复的警告不因当前摘要改变而自动隐藏；安装计划缺失、无效或无法安全读取时保留原提示，不把身份不明解释为恢复成功。

Windows CI 使用可控安装器桩验证真实文件系统上的取消、失败、进程残留和中断恢复，不证明真实 NSIS 卸载／安装或登录触发恢复的完整链路；真实 Windows 旧版到新 Stable 的升级及 CS2 / OBS 制作保护仍按[发布规则](../development/release-readiness.md)实测。

# 游戏数据语义

本文维护 GSI、CSTV 的输入解释和派生规则。支持哪些环境见[数据源能力](../guide/data-source-capabilities.md)，对外结构见[协议](protocol.md)。

## 输入边界

```text
原始 GSI → Companion 接收与有界采集 → telemetry-gsi → TelemetryObservation → Core
CSTV → telemetry-cstv → 带数据源角色的 GameEventObservation → 对应消费者
```

原始 GSI 与第三方解析器对象不越过适配器。GSI 接收入口只做认证、大小限制、接收时间与序号记录、交给采集和解析、快速响应，不等待磁盘或赛事平台请求。

`TelemetryObservation` 由 Core 定义，包含接收时间/序号、来源、字段覆盖情况与当前观测；不包含官方身份、赛果、场景控制、人工覆盖、统计累计结果或未来提示。

## 当前观测与字段缺失

GSI 每帧解释为当前观测，禁止 `deepMerge(previous, current)`，也禁止“字段缺失就保留上一帧”的通用策略。

适配器分别描述 `map`、`round`、`phase_countdowns`、`player`、`allplayers`、`bomb`、`grenades` 的 `present / absent / degraded`。缺失可能表示当前不存在、不支持、暂未提供或正在转换，变化判定需要额外证据。跨帧保留只能针对已有证据支持的局部语义。

- `previously`、`added` 仅用于变化提示、诊断与回归校验，不能直接产生领域转换。
- 当前 `allplayers` 是输入中的玩家集合，正式十人名单由身份归一化确认；临时额外成员、教练、观察者由 Core 解释。
- `round.bomb` 是回合目标事实，不能凭字段名将它与根 `bomb` 的当前行动状态混为一谈。
- 字段、枚举与归一化细节以[适配器源码](../../packages/telemetry-gsi/src)和真实输入测试为准；真实记录与旧假设冲突时保留证据并修正解释。

真实 CS2 demo 可同时报告根炸弹 `dropped` 和存活持包者当前物品栏中的 `weapon_c4`。适配器仅在同一完整、未降级观测中，唯一存活持包者的 C4 为 `active / holstered`、且身份明确匹配 `bomb.player` 时将该状态归一化为 `carried`。缺失、身份冲突、多人持包、死亡或不完整观测保持原状态；不凭位置邻近或上一帧推断。安放中、已安放、拆弹与终止状态不被物品栏覆盖，所有消费面共用归一化结果。

## 地图与回合历史输入

地图名称只通过明确别名和空白/大小写规范化，例如 `Dust II` 与 `de_dust2`，不模糊匹配。`map.round_wins` 映射为规范化回合结果；已知原因映射为消灭、爆炸、拆弹或超时，未知获胜方/原因保持 `unknown` 并记录诊断。

GSI的`map.round`保留原始回合计数，不作为可直接显示的当前回合序号：实际demo首回合冻结期为0、第四回合冻结期为3，比赛结束时为完成回合数。五套HUD共用比赛信息展示层转换；冻结和对局阶段显示下一回合，回合结束和gameover显示已结算回合，完整CT/T比分可证明结算回合数。热身、未知阶段或缺少回合计数不补造序号；该转换不修改Core历史或公开原始计数。

只有证明键是当前地图的绝对连续回合号时才恢复历史；加时局部编号可能重置时标记 `partial`，不猜偏移。输入与历史均有上限。历史冻结和冲突处理见[系列赛恢复](architecture.md#系列赛进展与恢复)。

地图结束观测可能同时提供最后一回合的 round_wins，而 round.phase 已进入 freezetime，没有独立的回合结束转换。系列赛先按既有绝对回合证据规则消费该观测的历史，再冻结同一帧的地图结果；冻结后仍不接受后续观测回写。

同图重开不由回合号降低单独推断。正式阶段之后，当前完整地图观测同时证明 `warmup`、`roundNumber = 0`、CT/T 比分均为零，且 `roundWins` 为空或省略时，Core 建立新的地图执行；非空历史与零回合基线冲突，不触发该转换。CS2 真实 demo 的热身可省略 `round_wins`，此时不制造“收到空历史”的事实；执行识别依赖同一观测中的明确热身、回合与比分。中途菜单帧不会抹掉“曾观测正式阶段”的证明。新执行重新建立历史、统计和计时，渲染层沿用同一执行边界，见 [ADR-0038](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0038-warmup-without-round-history.md)。

已录制样例中，热身可缺少整个回合或炸弹区块，回合目标与胜方字段会在对应语义结束后消失，变化提示也可能不完整。这些证据支持按当前观测解释，不能推断所有 CS2 版本形状永远一致。

## 目标计时

根 `bomb.countdown` 随状态改变含义：

| `bomb.state`                       | 倒计时含义                         |
| ---------------------------------- | ---------------------------------- |
| `carried` / `dropped`              | 没有目标行动计时                   |
| `planting`                         | 安放动作剩余时间                   |
| `planted`                          | 爆炸剩余时间                       |
| `defusing`                         | 拆弹动作剩余时间，不能当成爆炸时间 |
| `defused` / `exploded` / `unknown` | 已结束或不可用                     |

`phase_countdowns` 只表达当前阶段时间；拆弹时不能将它当作爆炸时间的备用来源。

Core 在 `objectiveTiming` 保存仅供内部使用的爆炸计时锚点。只有当前有效、非回合结束的 `planted` 倒计时可建立或校准；拆弹或短时缺少倒计时保留既有锚点，但不拿拆弹时间覆盖它。首次观测就是拆弹且没有锚点时，爆炸时间保持 `null`，不补造固定时长。

携带、掉落、安放、终止、未知状态，炸弹区块缺失或降级，地图/数据源代际变化，以及 `gap-resync / stale-recovery` 都使旧锚点失效。恢复需要新的已下包观测。

进度分母来自连续观测到的安放和下包过程；中途接入或连续性中断不继承旧分母，也不声称它就是服务器 `mp_c4timer`。拆弹钳只从当前对应选手的证据读取，字段缺失时钳子状态保持未知；操作者缺失不抹掉已观测行动时间。钳子证据不足时，当前拆弹倒计时超过五秒（容忍 1/64 秒采样误差）可证明十秒动作；连续观测到 `planted → defusing`，且首个剩余时间与两帧接收间隔能覆盖五秒起点时，可证明五秒动作。该时长只在同代际、同地图执行、同操作者的连续拆弹中保留，缺段、过期恢复、停止或换操作者后清除。它不回写选手的钳子字段；中途接入只看到不足五秒且没有钳子证据时，进度分母仍为空。

目标时间使用独立的短有效窗口，策略由 [objective-timing-policy.json](../../packages/core/src/runtime/objective-timing-policy.json)维护。过期后保留状态、清空数值；渲染层不保存锚点或自行补计时。精度承诺必须经过[目标计时专项验收](../validation/objective-timing.md)，不能由小数位数推断。

## 名单与伤害统计

`ActiveLineupResolution` 与 `MapPlayerStatsAccumulator` 分别派生稳定名单和单图统计。

- 只有当前 `allPlayers = present`、十个唯一 Steam64、CT/T 各五人且无歧义，才能建立或替换名单基线。
- 临时缺失、额外成员或降级观测可以保留已建立名单，并标记 `retained / degraded`；没有旧基线时不能把不完整证据升级为有效名单。
- `absent` 不触发名单变化。保留只涵盖身份与槽位，缺失选手的生命、装备、武器和观察位保持未知。
- Steam64 身份与当前阵营分开，换边不重建逻辑选手；同图重连保留成员但用当前代际重新证明，不复用旧动态数据。
- 平台名单用于匹配和消歧，不把未知但稳定的 Steam64 选手从局内画面中强行删除；无法确认的官方身份保持空并报告诊断。

网站比赛中，Steam64 在本场名单唯一绑定且登记昵称非空时，播出优先使用登记昵称；否则使用当前新鲜且 `allPlayers = present` 的游戏昵称。本地独立比赛仍优先使用游戏昵称，缺失、空白、降级或过期时回退人工保存的名单昵称，不重用旧帧昵称。Core 呈现层统一供五套 HUD、选手卡、统计、雷达和提前提示使用，观测昵称统一裁去已确认队伍名称的开头前缀。例如当前所属队伍为 `The Beast` 时，`The Beast TomatoDebu` 展示为 `TomatoDebu`。队伍名称来自当前 Steam64 身份映射对应的比赛资料，或当前完整、新鲜地图观测中该选手所在阵营的队名；来源直接提供的不同队名可共同作为明确前缀，不从全名猜简称或标签。匹配忽略大小写，但要求完整队名（可明确包裹为 `[队名]` 或 `【队名】` 队标）后有空白或明确分隔符（`|`、`｜`、`:`、`：`、`·`、`-`、`–`、`—`）。未知队伍、部分匹配、队名只在中间、无分隔边界或裁剪后为空时保留原文，昵称自身的空格保留。

本地服务器名单捕获为新增选手复用同一裁剪规则，保存本人昵称，已有名单昵称、选手 ID 与头像保持不变。历史保存的名单没有昵称来源标记，不猜测其是否由旧自动捕获生成；带前缀的旧名单可在比赛资料中人工修正。原始观测、采集和诊断保留完整昵称，身份匹配始终使用 Steam64，渲染层不再单独处理前缀。

受管观战游戏启用 MulNX 时，同步网站本场名单的唯一 Steam64 昵称；名单变动时更新并清除移出人员，连接恢复后重新发送，结束制作时清除本场发送过的账号，不清除其他账号。昵称含 NUL、超过 127 个 UTF-8 字节或名单超过 64 条时不发送。网关回执仅确认入队；连接中断时清理可能未送达，游戏内显示和原生击杀条覆盖范围需在 Windows / CS2 实机确认。该功能依赖上游 Name/Player/Set 接口。

平均每回合伤害按 Steam64 累计 `roundTotalDamage`，每个计入回合取最大值，避免阵亡后归零。只有完整观察到冻结期进入实战的回合才计入；中途任何 `allPlayers != present` 使该回合失效，不插值填洞。已完成有效统计保留，之后完整回合可继续统计。

`liveAdr` 可包含当前有效回合，`completedAdr` 只包含已完成有效回合。生命周期由阶段转换与连续性驱动，`map.round` 仅辅助校验；换地图执行编号才清空单图历史。系列比分与回合历史的冻结和恢复由[架构](architecture.md#系列赛进展与恢复)维护。

当前完整地图明确进入 `gameover` 时，也会结算同一执行中已完整观察、连续且有效的最后回合；无需等待可能不会出现的 `round.phase = over`。仍校验回合号提示、选手覆盖与连续性；缺段、缺选手或中途接入不升级为有效统计，重复赛后观测不重复累计。

## 可选精确事件

普通观察者记录的归一化入口复用同一事件模型，但只接收已绑定的 source/channel/world 及正有效 snapshot tick。ahead 仅进入 lookahead，delayed 仅进入 program。事件的 controller slot 不作为 userid 使用；必须采用已解析 userinfo 的真实 userid 与一致的 Steam64，身份缺失或矛盾时不伪造补齐。普通观察者复用既有来源管理者：成功快照游标后才进入 live，重复/乱序和旧世界记录丢弃，断流、恢复与换图使旧对齐失效；重新附接由本地进程所有者提供身份，不让数据行自行替换来源。标准输出读取同时限制块与行的字节数，坏 JSON、坏 UTF-8、超限和 EOF 都退出就绪状态。读取器不伪造 HTTP fragment 元数据，也不自行启动进程或读取路径。独立的显式进程组合只使用本地安装资源所有者提供的绝对运行时路径，无 shell；普通观战地址和密码通过一次有界 stdin 传递，不进入 argv、继承环境或应用日志。托管驱动只向 stdout 写事件，不默认保存事件和通道采样；结束报告留本地；组合层只保留有界报告中的固定原因码、SDK 数字结果及清理失败阶段，不保存原始 stderr 或任意异常文本，报告缺失与超限明确区分。取消不掩盖报告中已确认的清理失败。配置发送后保持 stdin 打开，停止时先关闭投递并发送 EOF，让驱动正常关闭 SDK 和解析器，超时才终止本实例。注入 Companion 的来源必须使用进程组合返回的 source，而不是仅负责数据的 manager；既有 app.close() 调用 source.stop() 时必须等待子进程退出，避免停止接收但遗留观众进程。导入模块不启动进程，默认生产配置仍不自动启用该来源。当前组合明确限定已研究和实测的 hostVersion 14191、14192，不将其他版本数字相近视为兼容；首次就绪有 30 秒本地看门狗，失败输出不升级成接入成功。

进程所有者在初始化超时、阶段超时或允许的连接中断后自动重连：先等待旧子进程退出，再按 1、2、4、8、15 秒上限退避，新尝试使用独立的报告目录和来源身份，并复用同一数据来源管理器重新附接。来源管理器的旧事件与就绪状态立即失效；私有提示保留同图已接收事件和延迟估计，等待新快照后恢复投影。人工停止同时取消重连等待；已确认的清理失败、鉴权或未分类拒绝不自动重试。正常比赛结束的 HLTVSTOP 1038 不重连，结合 closed 报告和退出码 0 确认结束。标准错误只解析有界内容中的末行固定结构报告，前面的 SDK 文本不保留。实际换图需要更换 GOTV 地址时，由调用方停止当前来源并以新地址创建新来源，不把同连接内换图作为该使用流程的必要门禁。

普通观众进程输出的公开序号在每次来源尝试内递增，世界重置不归零；它不同于解析消息的内部完成序号。事件时刻优先使用有效的 `eventServerTick`，缺省才使用明确的传输上下文 `tick`，不改写原始输入。Steam64 按个体账号的位结构校验，保留字符串精度。进程读取按单条 UTF-8 JSONL 记录限制预算，不把操作系统合并的多个记录当作超大单条记录。

本地启动器接受有效的非零 uint32 host 数字；它不是协议兼容保证。默认持续至来源结束或主动停止，显式诊断时限可单独指定。终态优先读取事实型报告中的排空及清理结果，同时兼容既有研究版报告；不能将 `closed` 与清理成功直接画等号。

CSTV 适配器维护自己的连接代际、序号、时刻与健康，只复制受支持事件为 Mizar 标量结构，不直接修改运行状态。

`CstvSourceManager` 连接和初始化阶段的事件仅进入有界诊断记录；就绪后实时收到的新事件才通知消费者。`ProgramCueCoordinator` 只接受 `program` 角色，检查当前节目新鲜度、地图与选手身份；过期、错图、缺目标或非实时事件立即丢弃，不等待后续数据补播。

Lookahead 使用独立数据源，同图重连保留提示时间线，不改变正式节目的地图执行。增强不可用时基础 GSI HUD 继续工作；隔离原则见[架构](architecture.md#正式节目与观察辅助隔离)。

### 私有击杀提示

第一版采用一个早源观察器与一个延迟 CS2 节目客户端。预期延迟差默认 120 秒、提前 5 秒，两项均可保存调整，已有保存值不会被新默认值覆盖。有效早源击杀按本机接收单调时间加配置延迟差计算预计发生时间；默认约缓冲 115 秒后进入五秒提示窗口。测量锚点不作为显示门槛，也不会自动修改配置：真实延迟在 119–121 秒时，固定 120 秒估算仍可能偏差约一秒。这不是 Windows 实测或精确预知，未收到的事件不能预告。

完整当前十人身份、同图、新鲜 Program 与可用早源仍是安全边界。时钟测量使用节目 GSI 原始 `phase_countdowns` 接收值和提前源同游标 GameRules 字段；两路原始回合计数直接比较，不盲目加一，也不写死回合时长。仅普通未暂停、未下包的连续 live 段可用于测量；缺失字段、异常跳变、暂停和非 live 倒计时保留原估计。冻结结束事件仅提供辅助接收边界，其 committed tick 不冒充精确事件 tick。Program 存活到阵亡的变化只撤下唯一可归属的提示，不作为延迟测量；多个候选不猜测。源事件按接收时间排期，积压可能使它和时钟样本受到不同延迟，不能把估计称为服务器全链路延迟。

快捷键来自唯一 `observerSlot`，冲突显示未知。调整 `leadSeconds` 或 `expectedDelaySeconds` 保留缓冲与测量历史并立即重新投影；已显示提示保持原截止时间。相同有效值再次保存不改变修订，不重连游戏。暂停、恢复及普通同图重连不清空事件或延迟；比赛、现场或地图执行变化仍隔离时间线。资格暂时不足时停止投影。队列上限 4096 条，窗口内超过六条时仍保留最早发生的六条。显示时按真实剩余时间从长到短排列，新进入窗口的事件靠上，相同时间保持原顺序。辅助通道每 200 毫秒独立更新，不改变 Program 和公开雷达发布节奏。

来源管理器在验证通过的本机 cursor、HTTP sync/tail 实际进展及有效事件接收处记录同一单调时钟的最近接收时间，重置/代际变化清空。新鲜度以本机接收年龄判断，不能把上游 `rcvage` 当成本机接收时间；持续 cursor 而无击杀仍保持新鲜，管道未关闭但 cursor 停止超过阈值会暂停提示并保留缓冲。缺少接收时间的兼容来源明确诊断为 `unknown`，沿用原有 connected 与 Program 门槛，不冒充已测得新鲜。诊断回调失败只记录独立原因码，不中断业务投影。

普通本机诊断导出与私有 runtime 诊断包含来源健康/代际、最近接收时间、最近 64 条事件的种类计数与进程内累计有效死亡/丢弃原因计数、缓冲与待展示数量、首个预计时间/距窗口、Program 死亡变化、时钟样本数及离散范围、最近重置及当前阻塞原因。此摘要仅含计数与时间，不含姓名、Steam64、密码或原始帧；重要状态变化最多每五秒记入既有会话日志。无匹配锚点不等于早源未接收；无击杀、被过滤、正在缓冲与被安全边界阻止可分别定位。


## 采集、重放与时间

采集器属于 Companion，队列同时限制数量与字节。溢出标记降级，写入失败不阻塞运行，退出有时限并明确记录不完整状态。接收序号、时间和完整性信息必须足以追溯到真实输入。

重放重新经过生产解析器、规范化、Core 和投影，不能用伪造最终状态替代数据语义验证。测试工具可注入丢包、重复、乱序、抖动、重连、慢消费者与代际变化。

持续时间、超时、插值与有效窗口使用单调时钟；跨机器时间、报告和审计使用 UTC。接收序号、运行时序号与通道序号各有范围，不混用。

## 来源与隐私

真实输入用于证明数据源行为，合成样例用于边界条件；展示样例不能冒充实机验收。生成与复核方式见[开发验证](../development/development-validation.md)。

入库前执行脱敏与完整性检查，移除凭据、私有地址、绝对本机路径和机器元数据。公开比赛样例可以保留原始 Steam64、选手昵称与队名以验证身份连续性；私人账号素材不能伪装成公开比赛。诊断导出与原始采集记录是不同产物，不能直接公开整个状态目录。

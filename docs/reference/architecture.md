# 系统架构

本文说明当前职责、数据流和恢复边界。接口字段与命令见[协议](protocol.md)，输入含义见[游戏数据语义](telemetry.md)，操作步骤见[使用手册](../guide/quick-start.md)。实现细节以各领域源码为准；决定的理由和历史见[决策维护](../decisions/README.md)。

## 数据与控制

```text
本地比赛资料 / RivalHub       CS2 GSI / 可选事件源
           ↓                        ↓
        赛事适配器               遥测适配器
           └────────→ Core ←────────┘
                运行状态、身份、连续性
                         ↓
                  各消费面的独立投影
                  ├─ 播出画面与雷达
                  ├─ 制作控制与诊断
                  └─ 私有观察辅助

Companion 组装运行时、持久化和接口
  ├─ 节目编排 → 场景控制 → OBS
  ├─ 公开投影 → 网站输出
  └─ Web / Windows Host → 制作人员
```

赛事平台拥有官方资料与结果，Mizar 拥有本地实时观测。独立模式与连接模式共享运行时，仅资料来源和外部输出资格不同。不直连 RivalHub 内部数据库，也不把赛后证据放入低延迟播出循环。

## 比赛与赛事上下文

`MatchDocumentV1` 以单场比赛为根。参赛方、赛制、地图和 BP 属于比赛；赛事、阶段及赛程是可选组织信息。无赛事比赛不创建占位赛事，也不伪造在线授权。空名单是合法资料状态，游戏身份另由遥测归一化判断。

- `MatchContextController` 串行协调选择、保存和激活，写盘前核对上下文修订与选择代次。资料库编辑不隐式激活比赛；脏草稿发生冲突时保留并要求重新核对。
- `LocalTournamentStore` 原子保存资料、赛程与回收站。比赛引用、已开打地图和已记录结果受保护；任一数值比分（包括 0）或完成时间都属于既有事实，不能由 BP 编辑裁剪覆盖。
- 本地赛事可提供 BO3 默认禁选规则；本场 BP 使用同一比赛文档的 `veto/maps`。本场调整不修改赛事默认，默认变化不追改已有 BP。
- 在线同场资料兼容时自动刷新；手动选择优先。BP 或计划冲突保留本地事实和网站候选，等待明确确认。资料来源、当前绑定与推送资格分别表达。
- 回收当前比赛必须先解除引用；现场与隐藏工作区禁止删除当前比赛。接收过游戏数据或重启恢复的选择，只能以 Host 核实游戏已退出的证据解除，不能用数据过期代替。恢复回收站资料不自动选场。

本地库读取或解析失败只隔离该库，保留原文件并拒绝基于空库或旧内存写回。修复后可显式重载，不改变当前比赛。容量、合法迁移和错误码由[资料库实现](../../apps/companion/src/match-context/local-tournament-store.ts)与[协议](protocol.md#比赛输入与缓存)维护。

## 单一事实与独立投影

Core 只有一份 `RuntimeState`，向 `ProgramProjection`、`RadarFrame`、`OperatorProjection`、`ObserverAssistProjection` 和 `DebugProjection` 提供各自需要的信息。

- 投影刷新不推进系列事实、不写检查点、不执行业务命令；输入提交后的投影、可靠输出和节目提示沿同一发布顺序接线。
- 渲染层不重新解释生死、身份、统计或时钟。Steam64 是稳定选手身份，参赛方与 CT/T 阵营分开。
- 诊断不是播出数据源；展示配置和展示摘要不回写比赛事实。
- `SeriesProgress` 维护观测地图和胜场，不把上游总比分塞回地图计数器。上游已结束结果可以是 `recorded / pending / omitted`；后两者不补造比分，也不把比赛改回进行中。

名单、统计与计时的具体语义见[遥测](telemetry.md)。

## 系列赛进展与恢复

Core 定义 `SeriesProgress`，Companion 的唯一运行时组合持有它。它消费比赛资料、运行时转换和已证明的阵营映射，保存地图计划与实际执行的绑定、有限回合历史、冻结结果及系列比分。

### 计划与执行

- 创建时冻结计划模式和指纹：`planned` 严格匹配地图顺序；`awaiting_plan` 等待赛事 BP；明确的 `unplanned` 才可按真实观测追加图池内的本地地图。追加不创建平台正式地图。
- 没有执行、回合或赛果的准备阶段可以更新计划。开始后刷新只更新兼容展示资料，不覆盖执行绑定、回合历史或冻结结果。
- 网站完整比分与完成时间可以补入兼容计划中尚未知的结果，帮助接续相邻图；冲突保留本地事实并要求核对，不补造遥测结束事件。
- 地图、身份或顺序不能证明时保留局内观测，系列绑定进入 `needs_operator`。人员差异的展示例外不授予官方比分、胜者或网站推送资格。

### 执行归属与连续性

一次地图执行只能属于已证明的比赛。切场不转让旧执行，GSI 的地图名也不能证明它属于哪场比赛。跨场冲突或恢复证据不足时，界面显示待确认，只有满足原门槛的显式绑图才能建立关联。

每次受管游戏启动使用独立 GSI 来源标识，由 Host 核实进程和配置后确认。Companion 在认证后、分配接收序号前拒绝未知或已退役标识；恢复同一来源也须重新核实。外部来源可供本机展示，但不据此推断正式结果归属。

回合结束转换是历史的首要来源，`map_round_wins` 只补缺、完善未知胜因或校验。最终观测先归约可证明的绝对回合历史，再冻结地图结果；后续冲突不覆盖已冻结事实。

### 检查点

检查点按比赛、参赛方、赛制、冻结计划和执行归属核验，在业务边界原子持久化。重启还须以新观测核对连续性；缺少证明的历史保留为未验证，不恢复成有效比分。切场前无法验证的旧事实按原比赛隔离保存，不能套给新比赛。关闭先停止生产者，再等待已提交写入。实现见[系列进展](../../packages/core/src/series-progress/)与[检查点存储](../../apps/companion/src/series-progress/checkpoint-store.ts)。

## 连续性与事件

| 概念 | 含义 |
| --- | --- |
| `liveSessionId` | 比赛与生产会话的绑定 |
| `producerInstanceId` | 一次本地服务运行 |
| `mapEpoch` | 地图的一次实际执行 |
| `sourceGeneration` / 数据源序号 | 单个来源的连接与读取连续性 |
| 高频快照 | 可被新状态覆盖的当前视图 |
| `RuntimeTransition` | 已观测到的边界 |
| `OperatorCommand` | 有明确结果的人工操作 |
| `ReliableObservation` | 使用转换发生时上下文派生的可靠事实 |
| `Incident` | 运行问题与诊断 |

这些概念不能合并成全局序号或万能事件。重连只使依赖该来源的证明失效，可选事件源或 Lookahead 重连不推进正式地图执行。曾观测正式阶段后，同图完整热身、零回合、零比分及无冲突历史才可证明重开；普通回退、缺字段或重连本身不能。已完成地图不因重开撤销。投递和背压见[实时通道](protocol.md#本地实时通道)。

## 正式节目与观察辅助隔离

正式节目消费观战客户端的 GSI，精确事件是可选增强。Lookahead 是独立较早时间轴，只生成私有辅助信息，不能作为节目备用源。隔离由投影、类型和协议保证，不能先公开未来数据再靠窗口或 CSS 遮挡。

Host 验证受管 CS2 后提交连接意图，Companion 串行管理观察器进程、来源代际和私有订阅。用户逐图确认 GoTV 地址与密码；打开工作台、保存偏好和重建窗口都不自动连接历史地址。节目连接、HUD 操作与辅助接收分别去重，辅助重试不重发已接受的游戏命令。

[观察辅助作用域](../../apps/companion/src/telemetry/observer-assist-scope.ts)持有本图确认与等待换图状态，按节目投影中的比赛与地图执行判断何时清除旧确认。观察辅助和运镜读取同一确认结果。

观察器归属独立 Windows Job；正常停止等待组件收尾，宿主异常退出由系统回收子树。Host 持有游戏身份并续约，租约失效或结束制作停止辅助。未知启动、连接和清理结果保留责任，不把命令入队当作实际连接成功。组件版本与来源由[组件配置](../../apps/companion/src/telemetry/observer-component.json)维护，控制契约见[观察器接口](protocol.md#本机观察器控制)。

提前提示根据同图、同回合和连续 live 段的两路时钟证据校准，缺证时等待；不使用固定延迟，也不以死亡事件校准。首次可靠校准或显式重新校准后的基线供提示估算；比赛或执行边界清空旧事件，停滞、暂停和来源变化不跨段补造时刻。时钟估算不能消除源内积压与接收延迟，提示始终是估计值。

人工选择 Gameplay 不要求新鲜遥测，包括未绑定的 Demo；切画面不建立赛事归属。身份不符时播出使用中立身份，自动编排和外部输出继续执行各自严格门槛。

C4 资源解析、索引与预测在 Companion Worker 中进行，Core 核对输入资格。结果按完整输入与连续性匹配，只重投影当前状态；有界等待保留旧完整快照及原游标，超时显示等待，不把旧估算拼到新帧。资格或连续性边界立即发布。

## 雷达与展示配置

雷达领域完成世界坐标校准，展示包负责插值、平滑、自动聚焦和有界纹理缓存。公共消费者只按显示尺寸缩放，不重复校准或补造位置。共享 HUD 渲染器与编辑器使用同一配置解析结果；浏览器缓存不是权威来源。集成见 [radar-view](../../packages/radar-view/README.md)、[hud-view](../../packages/hud-view/README.md)及[设计系统](../design/README.md)。

### 播出资源

[播出配置 Store](../../apps/companion/src/broadcast-config/store.ts)统一管理 HUD、场景、音乐、运镜及组合方案。保存/复制只改草稿，显式使用才应用。各模块独立记录目标、已应用版本和错误；单个依赖失败不阻断其他模块，并保留其最后有效配置和资源引用。

消费者实际应用成功后提交持久回执。回执写盘失败显示未确认并保留新旧引用；重试只补回执，不重复设备操作。内容相同可以跳过重载，不能跳过选中身份与来源版本。运行中的播放、监听和游戏状态不进入可分享配置。

官方资源由[资源 Store](../../apps/companion/src/resource-store/README.md)维护验证缓存和活动版本，安装器复用同一契约。离线缓存须复核清单和文件；普通启动可回退 Full 随包来源，安装器准备入口则必须成功打开 Store。资源激活与制作/更新互斥，现场仅准备素材。音乐文件与 MulNX 内容由各自提供方持有，删除前核对引用；缺失内容只隔离依赖它的模块。

## 制作生命周期与节目编排

Companion 拥有 `preparation / live / hidden` 制作生命周期，它不等同于比赛阶段或 OBS 状态。Host 拥有唯一准备任务、进入意图和原生资源归属，页面可以销毁重建。自动许可 `automaticAllowed` 等同 `presentationAllowed`：当前会话有效且未冻结退出、等待更新或隔离试播。OBS 综合准备结果不作为共同运行开关；场景、音乐与游戏声音在操作边界各自核验目标、来源和事务，失败只影响对应能力。

### 进入、隐藏与退出

1. 显式启动按任务身份建立制作会话并显示工作台。未选比赛、未填 GoTV 或 OBS 未连接不阻止面板呈现；游戏与 OBS 按真实依赖各自准备。OBS 启动等待同时核对连接和可读的输出状态，避免将 WebSocket 提前就绪当作程序已完成初始化。
2. 重试向各领域核验当前证据，并复用已确认实例和事务。未知提交只核对原请求，不能当成未执行而启动第二次。页面卸载不取消 Host 已接管的任务。
3. 隐藏只改变呈现；重新显示不切场、不认领来源、不恢复自动控制。取消和退出使旧进入代次失效，迟到回调不能重新显示窗口或取得控制权。
4. 退出先冻结自动操作并交接本地来源，再停止辅助及受管游戏、恢复临时配置并收拢窗口，最后完成制作收尾。Demo 恢复与制作收尾共用 Companion 操作锁，顺序执行，不并发争用。OBS 等待画面、视频恢复、网站可靠交付和来源释放分别报告；远端失败不阻塞已经安全交接的本地清理，也不自动停止 OBS 输出。
5. 失败保留原事务、原因和重试入口。原生会话恢复有界读取旧记录，启动阶段只能推进同一快照的已证明字段，未知恢复字段随原记录保留。正常关闭必须依据对应 Companion 实例的实际退出结果，以及本地写入和采集收尾结果，不能以 HTTP 无响应代替完成。

### 节目、音乐与运镜

`ProgramDirector` 消费投影和 BP，经唯一 `ProgramSceneController` 请求切场。新制作会话默认自动；人工选择或外部切场形成保持，须显式恢复。自动请求有上下文、代际和时限，最多一个在途且不离线排队；来源重连不重播已消费赛果。

`ProgramPresentationStore` 冻结已确认地图比分和选手摘要，用于跨图展示；后续同执行终局观测只能完善已证明的选手数据，不改冻结比分。赛前展示和静态赛果各用自己的证据门槛，不能放宽新开场与实时比赛资格。具体顺序见[节目规范](../design/program-direction-v1.md)。

`MusicDirector` 独立消费节目投影、制作生命周期和实际 Take started，不把画面人工保持等同于音乐控制权。背景音乐互斥，开场音效可叠加；配置、游标、已消费事件与人工停止由音乐领域保存。`BpSession` 只维护播放状态，正式 BP 来自比赛投影。

音乐通过[设备端口](../../apps/companion/src/music/device.ts)读写播放状态、媒体文件、增益、静音和监听模式。[OBS 音乐设备](../../apps/companion/src/obs/music-device.ts)负责协议转换、连接、资源核验与请求发出前的身份检查。[音频模式恢复](../../apps/companion/src/obs/audio-mode-recovery.ts)根据 OBS 读回与事务记录决定回退或确认，向音乐提交对应的监听回执。恢复记录沿用既有字段和值。

音乐来源查找与播放资格核验只读；创建、改名、挂载和初始化恢复只在显式准备中执行。来源按 UUID 与实例/集合身份登记，其他场景未决项不阻断当前已核验来源的媒体控制。试听的临时监听由音乐状态单一写者保存逐字段回执，按原身份、原值和应用值恢复；人工修改让权，未知结果只保留相关监听责任，不阻止停音或视觉准备。自动与人工播放、监听及试听见[节目音乐](music.md)。

### OBS 准备与恢复

OBS 领域核对端点、集合、来源 UUID、类型、连接代际与当前控制意图。人工修改或外部接管使旧操作失效；后台恢复每次副作用前重新检查资格。状态、检查、现有设备枚举和采集证据复用只读连接，不占配置写入队列；每次仍核验实际集合身份，禁止非 Get 请求。超时只淘汰原读连接，配置变更和关闭释放连接，不影响输出观察或事务连接。观察跨代或被更新结果替代后不得提交；未连接时重复连接失败不构成配置变化，状态查询仍返回实际不可用原因。查询只更新诊断，不签发或续期工作台进入许可。临时探针创建仍串行；只读检查不创建来源、不刷新网页，也不解除导演的人工保持。

创建/切换集合、结构修复和视频准备要求直播、录像、回放缓冲与虚拟摄像头全部明确空闲。查询失败保持未知，不能据此写入；任何路径都不自动停止输出。显式准备只调整约定的画布、输出尺寸和帧率，不修改编码器、推流凭据或任意个人集合。视觉建立并修复已登记音乐项的零面积布局后，调用音乐显式准备，最后一次对齐目标场景并核验进入许可；音乐失败单独提示，不以音乐总状态撤销已核实的视觉能力。准备与切场共用目标视觉规则，包括来源身份、浏览器地址和尺寸、画面变换、层序及游戏捕获设置；其他场景的损坏不阻断当前目标。

视频、音频切换与临时游戏捕获各由本领域事务持有：写前保存身份、原值和目标，写后读回；不确定结果先核对。恢复只覆盖仍为本次受管值的字段，保留用户新值及无法确认的记录。OBS 不提供比较交换，不能宣称消除了外部并发竞争。

游戏捕获必须匹配唯一实际 CS2 窗口，默认窗口字符串不算存在证据。预热临时项目先禁用、设零面积并核对后才启用，相关租约覆盖创建至清理并阻止新输出。其他集合的未决记录分开保全，不阻断当前集合；当前相关事务仍须安全恢复，原项目身份或变换不符时保留责任。输出启动与结构写入串行，停止输出不等待只读扫描，并使在途准备租约失效。已开始输出后仅只读核对，不把清理完成当作画面正常。

显式进入可授权刷新当前专用集合中身份、类型和本机 URL 匹配的已有浏览器源；资格与场景/音频准备分开。断线、外部切场、集合切换或退出撤销它，不能靠重连自动取得新授权。

### 网站来源与可靠交付

网站同步是本机制作之外的独立职责。在线比赛进入现场且当前遥测、上下文、身份和十人名单就绪时，Companion 可自动首次认领；不接管其他设备，不恢复主动停止的来源。返回工作台不触发认领或恢复，人工恢复使用显式来源命令。

[RivalHub 读取客户端](../../apps/companion/src/match-context/rivalhub-read-client.ts)持有赛程、比赛资料与统计缓存；[授权会话](../../apps/companion/src/match-context/rivalhub-authorization.ts)持有凭据和配对过程。更换授权、认领、交接和释放由[连接协调器](../../apps/companion/src/match-context/rivalhub-connection.ts)使用同一串行队列，读取结果按原授权身份核对。

- 来源控制先持久保存各场认领意图，再保存网站确认的完整身份，才启用发送。未知意图按网站、赛事、安装与比赛阻止同场重复认领，包括新生产者或会话；其他比赛仍按当前资格独立认领。
- 清理在有界预算内轮转核对原请求，迟到确认直接进入该场待释放责任，不取得当前发送资格或退役其他场来源。切场/退出交接旧身份，重启仅恢复清理；重新配对先处理旧责任，来源文件不保存凭据。
- `ReliableOutbox` 拥有交付顺序，`OutboxRepository` 独占 SQLite 队列、检查点、归档和撤权证据。捕获区间、原事件、回执与连续提交水位按同一事务提交；网络等待不占用本机运行时提交路径。 已封口、取得原来源释放与归档证明、且无未知标记或受损围栏的区间只在旧身份核对时读回，不占活动容量。原区间与证据留在同一个 SQLite 中。
- [Outbox worker](../../apps/companion/src/output/outbox-worker.ts)独占数据库连接并执行快照校验、SQLite 提交和历史查询。主线程冻结原始输入并按顺序提交，收到回执后才发布持久状态。当前投递和观察只读取已提交的范围视图，旧范围按需查询。
- 实时选场与已接受事实的交付目标分开。旧事件固定原来源与幂等键，不借新认领代发；各独立来源可以继续收尾。已落盘、远端接收和来源释放是不同证明。进程退出时，远端收尾有独立期限。来源账本和可靠队列关闭后才能写出实例的本地退出回执。远端未确认的来源按原身份留待恢复。
- 失败的边界或检查点保留原请求、身份和顺序，恢复只重试原请求。后续成功不能越过缺口，空队列不能证明完整；崩溃前未落盘的正文无法重建。
- 停止捕获后仍须核对已登记的在途边界及完整区间，才能结清来源。撤权隔离不等于送达，未知记录不能自动清空或伪造完成。

来源文件与 SQLite 各有生命周期写者锁，先取得来源写者，再打开队列和恢复区间，最后启动发送。任一步失败只隔离网站同步，保留原文件与责任，本机投影继续。来源或播出配置文件不可用时，不以空文件代替未知状态；保全原件和撤权证据，修复权限或使用已核实备份后重启。详细交付契约与恢复入口见[公开输出](protocol.md#公开实时输出)和[同步健康](protocol.md#本机网站同步健康)。

## 安全、采集与扩展

### 受管游戏与配置

桌面启动入口负责组装与运行生命周期；恢复窗口重试启动时先取消旧宿主的更新意图，再从原程序入口创建新宿主和启动身份，不在旧身份下复用退出记录或桌面事件循环。[命令适配器](../../apps/desktop/src-tauri/src/desktop_commands.rs)将统一 IPC 契约接到领域操作，任务状态由对应宿主持有。[受管 CS2](../../apps/desktop/src-tauri/src/managed_cs2.rs)协调启动、控制与恢复，[进程模块](../../apps/desktop/src-tauri/src/cs2_process.rs)负责 Win32 句柄、Steam 发现和启动提交。独立帧率与 HUD 事务复用窄进程身份类型。

[会话记录](../../apps/desktop/src-tauri/src/cs2_session_record.rs)绑定版本、配置和进程身份，启动只能经准备、提交、绑定或取消迁移。[配置存储](../../apps/desktop/src-tauri/src/cs2_session.rs)负责原子写入和恢复，继续读取 v1–v4 记录并保留扩展证据；损坏记录保留原件。旧完整键位快照保留恢复读者，当前启动不再产生这类快照。具体文件内容仍由各格式模块验证。

Host 统一发现 CS2 安装、Steam 账号与 GSI 位置。提交启动前核对唯一进程、程序路径、创建时间和当前账号；持有原生句柄，不凭 PID、安装目录或启动偏好授予控制权。GSI 自动准备不覆盖未知文件，显式修复保留修复前原件及首次恢复备份。

启动前以同一配置事务备份受影响的视频、帧率、观战键位和启动脚本，验证应用计划并持久记录，再提交启动。可选择保留画质与帧率；这一选择不免除进程、备份、观战设置和恢复门槛。偏好只影响下次启动，不修改本次冻结的原值与应用值。

Steam 和 MulNX 的未知启动结果都保留待确认记录，不自动重发。MulNX 还须核实网关属于同一游戏实例；卸载请求入队不等于模块消失，收尾须确认卸载和正常游戏退出。结束失败的 MulNX 启动时，若游戏已退出，仍持有本次启动器原生句柄的 Host 先关闭启动器，再由原配置恢复流程取消待确认记录。不能按进程名关闭外部游戏或启动器，Host 重启也不能凭旧 PID 恢复关闭权。

恢复只对已核实目标和仍为原值/应用值的受管字段写回，用户新值让出；未知文件、重复冲突、链接和未完成事务保留。游戏退出用实际进程证据确认，正常关闭失败由用户在游戏内退出后重试，不自动强杀。Companion 离线时，Host 的恢复入口可完成同一原生事务，但不确认制作结束或资料回收资格。配置事务与 Steam Cloud 不构成跨进程原子操作。

现场帧率、手动旧备份恢复、MulNX 启动项及本机 HUD 自动隐藏分别沿各自有限事务持有身份与原值，不创建通用游戏命令入口。相关实现见[受管 CS2](../../apps/desktop/src-tauri/src/managed_cs2.rs)、[配置会话](../../apps/desktop/src-tauri/src/cs2_session.rs)和[启动恢复](../../apps/desktop/src-tauri/src/startup_recovery.rs)。

### 窗口与本地 HUD

Host 管理独立游戏、左右面板、底栏和工具窗口，不嵌入游戏、不复制比赛状态。布局使用已核验游戏的实际客户区和 DPI；目标布局不等于实际对齐，API 成功也须读回确认。隐藏/退出撤销旧布局和呈现意图，显隐在窗口线程按真实原生状态确认。

初次进入只在原准备中心仍为前台时有限尝试聚焦；之后由“返回游戏”表达新意图。普通面板操作、切节目、恢复布局和重新显示不抢焦点。同组窗口联动保留用户当前输入目标，不修改系统自动隐藏、永久置顶或其他应用窗口。

本机 HUD 仅在受管游戏或工作台控制窗口前台且客户区合法时显示，其他工具窗口前台时隐藏。重建 HUD 不改变比赛、OBS 或游戏。正式输出使用独立游戏捕获与 Browser Source，不依赖本机窗口遮挡或捕获排除。

### Demo 与采集

Demo 试播复用制作生命周期和生产解析器，以临时资料及独立运行会话隔离。启动前持久暂停正式检查点、资料修改、采集和网站输出；服务重启遇到未完成试播先隔离输入，不自动恢复正式绑定。

结束先隔离在途输入、确认等待画面，再由 Host 关闭受管游戏和恢复配置；成功后恢复资料、清空试播观测并推进连续性。重新明确进入正式制作前继续拒绝迟到 Demo 输入。已结束会话的临时 CFG 清理与未结束游戏事务分开，残留仍按原身份安全清理。见 [Demo 模块](../../apps/companion/src/demo-test/README.md)。

采集写盘不能阻塞 GSI，重放必须经过生产适配器；真实样例、时间与来源要求见[遥测](telemetry.md#采集重放与时间)和[开发验证](../development/development-validation.md#样例重放与来源)。

### 诊断证据、历史与导出

诊断只观察，不修正比赛、OBS、网站交付或播出资格。Host、Companion 和文档记录统一的事件身份、原业务范围、操作/尝试、观测时间、原因及覆盖证据；跨进程墙钟仅辅助排序。受理、持久化、交付和未知分别表达，不能承诺崩溃或断电零丢失。

Host 可离线写入，文档向 Host 交接后收到原事件的持久回执才移出内存；纯浏览器的单次 HTTP 交接没有同等保留队列。Companion 由 SessionJournal 保存正文，BusinessJournal 记录业务变化，索引不另存第二份正文。重复后台观察可聚合首末时间、次数和原因变化，用户操作仍保留独立身份。

导出流程由 [support](../../apps/companion/src/support/) 拥有：

1. 发起文档有界交接当前尾部，各 producer 固定提交水位和源身份；无法安全固定的来源标记缺口，其余继续。固定不是跨进程原子快照。
2. Worker 按有界块读取、脱敏、去重、索引和压缩。默认包含全部保留证据，超限分卷或明确失败，不截几条后称完整。
3. ZIP 包含正文、导航、当前快照、附件、测量及 `coverage.json`。`bundle.json.complete` 仅证明归档写完；未提交、过期、排除、读取失败及未知范围另行说明。CRC32 和 SHA 校验覆盖条目与分卷。
4. Web 只持任务 ID、阶段和摘要。Host 取得保存租约及固定源句柄后打开对话框，流式复制并校验；重新保存复用同一快照。浏览器只能报告已发起下载。
5. 固定和保存租约在对应任务结束并确认不再使用后释放。未知归属不按时间自动删除；安全可计量的过期残留计入预算，不明身份或预算不足则拒绝。当前仍有未闭合的原生固定/孤儿租约回收边界，重启不等于已恢复。

只读取固定产品来源，拒绝链接、硬链接、非普通文件和身份变化，不接受任意路径。精确替换凭据，保留技术上下文和原始原因；不收集任意私人文件、音视频、原始聊天或 console-history。OBS 附件只读取范围受限、含 Mizar 来源标记的近期日志；缺少安全脱敏证据则记录缺口。

各生产者保留预算与 pin 状态独立，云端 ACK 不删除仍被活动会话引用的唯一证据。Companion 的活动保护用于带任务身份的操作和业务记录；普通后台观察及连接失败按现有预算轮转，失败本身不建立进程存续期间的永久保留。显式问题标记、导出和正在读取的回传仍沿用各自固定责任。当前导出只处理新版 ZIP，旧日志和旧包保留原位，不自动迁移或删除。诊断回传的同意、撤回及接收器契约见[技术诊断回传](diagnostics-delivery.md)；完整性审查见[开发验证](../development/development-validation.md#操作记录与失败可诊断性审查)。日志、就绪和命令成功都不能证明实际像素与声音正常。

### 解说 CFG 与键位恢复

Steam、Demo 和 MulNX 使用同一受管 `mizar_observer.cfg`：数字键用于原生观战选择，H 切换原生 HUD。Host 启动前备份受影响键位与变量，核对键身份和文件结构；冲突不猜测，未知文件不覆盖。 数字键与 H 分别确认能力：数字键原值无法可靠备份时，只部署有独立原值记录的 H，不写数字键或观战变量；共享键位文件结构异常仍不写入。既有观战记录的 v4 仅代表 H-only，v2/v3 继续按原范围恢复，不建立平行事务。

个人启动 CFG 的执行顺序由既有配置事务处理，接入 exec 前核验所选字段与固定 CFG，原件先持久保存再临时调整，取消、失败和退出恢复。提交前若配置再次变化，保留恢复责任，不仅清除能力标记后继续启动。数字键与 H 独立计算恢复，共享文件由同一写者一次写回；冲突字段保留记录，不阻断另一字段恢复。只恢复本次写入字段，人工新值让出；不新建完整键位快照。已有旧版恢复记录继续履行原责任，不能为迁移清空。MulNX 自动隐藏另保存游戏内 HUD 原值，未知提交不重复覆盖用户 H 操作。实际加载、键位生效和退出写回仍需 Windows CS2 实测。

## 可选地图运镜编排

Host 持有本次受管 MulNX 游戏的已验证句柄并续约，Companion 的 `orchestration/` 持有本机地图预设和调度，独立适配器调用 MulNX。租约绑定当前制作会话与实例；退出、不再唯一或续约失败撤销控制，旧心跳不能恢复新会话。浏览器备用模式需在准备阶段显式选择，不能由原生迟到消息接管。

运镜消费既有 Program 投影、音乐阶段和实际开场 Take，不建立另一份比赛事实。包必须经磁盘验证、应用并回读；活动包和空自动列表的回读不等于资源已加载。连续性变化使准备失效，重新准备后只等待新事件。未知或过期动作不自动重放，停止和退出由原所有者完成。内容格式、启动/卸载证据及上游限制见[地图自动编排](orchestration.md)。

## 专用集合音频与迁移

视觉准备只整理自身场景、浏览器和画面字段；显式准备中的音频迁移、整理和最终观察分别使用独立连接与时限，不消耗视觉修复或最终核验预算。音频超时保留告警与未决责任，关闭原连接并拒绝迟到请求的后续 OBS 写入；之后仍须重新核验实际视觉，不能将音频失败转换成共享身份、启用状态或零面积布局已安全的证据。原生宿主仅为显式 OBS 准备保留覆盖多阶段结算的独立总时限；取消仍立即关闭在途请求，其他请求不延长，超时不得取得进入许可。音频事务按 UUID 和场景项目持有启用、监听、附带音频及来源切换责任；视觉修复不得覆盖共享字段、删除责任来源或最后一个引用。同名冲突只隔离该目标，责任不可读时保留受影响来源与字段，其他不相交视觉操作继续。切场核对目标的实际视觉、转场及已启用音乐项目的身份与零面积布局，不能把音频总状态代替目标证据。

音频模式、角色绑定和应用选择是本机操作员配置，操作时核对端点、集合、UUID、类型与修订。桌面混音与独立分路共用受管来源，游戏、解说、麦克风、音乐和音效各有明确角色，不从其他个人集合任意挑选来源。

音频诊断分别保留当前 RPC 观察、持久配置和历史 WASAPI 日志。当前观察带受管 UUID、连接及集合/来源代际、设备选择和显式设置与 OBS 默认值合成后的 `use_device_timing`；持久配置不推断有效默认值。日志保留初始化采样率与仅在本次采集内有效的名称引用，相同名称只作排查线索，不能证明与当前 UUID 同源。默认设备、重名、改名、来源重建或重连不猜配实际端点；设备枚举不证明当前采集成功，历史采样率也不冒充当前值。读取失败标记缺口，不阻塞播出、不调整 timing，也不据此宣称已修复重音或驱动问题。

离开旧集合前，音频迁移在独立时限内读取明确受管的角色及设备、音量、静音、音轨、滤镜和监听意图；失败保留原绑定与恢复责任，不消耗后续视觉准备预算。新来源完整回读后才提交绑定，旧来源不修改或删除。显式准备的读取不占用切场队列，集合变更和实际写入保持互斥；新的切场意图撤销旧准备，迟到读取不能再写入或抢回场景。未确认副作用或冲突保留事务，重试继续原目标，不重置用户偏好。集合结构操作要求视频输出空闲，已准备好的音频模式可沿原模式事务切换。基础音频只计划实际参与的音乐监听字段；音乐存储不可用但已核验无需改动且无回采风险时可用空音乐计划，不能据此清除已有未知监听责任。

监听必须核对版本、实际设备和回采路径。OBS 33 不再具有旧“仅监听”的输出抑制语义；同设备或关系未知时保留节目直出并暂缓监听，不能猜测默认设备或改动用户音轨。桌面模式可直接更换采集设备，但须证明仍保留实际监听与节目路径；未知或会重复/丢失声音时只拒绝本次换址，不恢复音乐库或重放旧监听备份。音轨配置只提供就绪证据，最终仍须录制试听。

中场游戏音频策略只修改经身份核验的游戏来源，默认保持。逐字段保存原值和目标，人工改动、断线或身份变化即让权；未知写入不重放，重启后待核对。音乐人工控制、监听和试听由[音乐契约](music.md)维护；混音接口见[协议](protocol.md#本机混音控制)。

## 更新与故障隔离

Companion 持有认证版本、检查偏好与下载状态；Host 通过本次运行的私有能力核对安装计划，在正常收尾后启动资源目录外的恢复工具。浏览器不能提交可执行路径或安装命令。信任根、元数据和恢复协议见[应用内更新](updates.md)。

领域读取或恢复失败先隔离其能力，保留原文件、未知责任和具体原因。不能以默认空状态覆盖比赛资料、来源、音频或恢复事务；普通本机制作应继续使用不依赖故障领域的已核实能力。只有原领域的重新加载、持久回执或外部读回才能解除故障，界面提示和诊断不能代替证明。

# 系统架构

本文维护当前职责与依赖规则；产品价值见[产品定位](../guide/product.md)，接口和输入解释分别见[协议](protocol.md)、[游戏数据语义](telemetry.md)。决策理由保存在 [ADR](../decisions/README.md)。

## 数据与控制

```text
本地比赛资料 / RivalHub      CS2 GSI / 可选事件源
           ↓                       ↓
        赛事适配器              遥测适配器
           └────────→ Core ←───────┘
                  运行状态、身份、连续性
                          ↓
                  各消费面的独立投影
                  ├─ 播出画面与雷达
                  ├─ 制作控制与诊断
                  └─ 私有观察辅助

Companion 组装运行时、持久化和接口
  ├─ 节目编排 → 场景控制 → OBS
  ├─ 公开投影 → 外部数据输出
  └─ Web / Windows 桌面 → 制作人员
```

赛事平台拥有官方赛事资料与结果，Mizar 拥有本地实时观测。独立模式与连接模式共享运行时，仅赛事资料来源不同。Mizar 不直连 RivalHub 内部数据库；DAK 等赛后证据不进入低延迟播出主循环。

本机赛事的BO3默认禁选规则保存在既有LocalTournamentStore赛事资产中，供未录入BP的比赛继承；本场草稿使用规则编译出同一MatchDocument的veto/maps事实，已有事实优先恢复，赛事默认变更不改旧BP。本场规则调整不顺带修改赛事默认，在线补录不改平台身份或网站数据。缺省旧配置保留既有流程，见[ADR-0040](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0040-event-bo3-authoring-rules.md)。

## 模块职责

应用内更新由 Companion 持有已认证版本、检查偏好及下载状态；桌面宿主通过本次运行的私有能力核对安装计划，正常退出后启动资源目录外的恢复工具。浏览器不能提供可执行路径或调用安装命令，更新不成为比赛或制作状态的第二来源。元数据、信任根与恢复契约见[应用内更新](updates.md)。

官方示例素材由 Companion 的[单一资源 Store](../../apps/companion/src/resource-store/README.md)持有独立持久缓存和状态。安装器复用同一 Store；来源授权与清单消费复用资源契约模块，缓存启动离线复验证据及实际文件。原资源 URL 从活动版本读取；无活动缓存时保留 Full 随包来源，错误不混合版本。激活与制作生命周期及更新共用互斥保护，现场只准备素材。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `apps/companion` | 组装运行时、HTTP/WebSocket、输入输出、持久化、节目与 OBS、采集 | 在传输层重新推导比赛事实 |
| `apps/desktop` | 启动同包服务；受管理 CS2 启动、临时视频配置与恢复；窗口、布局、焦点、穿透、托盘与工具窗口 | 复制比赛、运行状态、场景或 OBS 状态 |
| `apps/web` | 播出、工作台、准备中心、编辑器、诊断与交互 | 读取原始 GSI、整个运行状态或平台内部表 |
| `packages/core` | 状态、转换、身份、连续性、统计、系列赛进展与投影 | React、网络实现、OBS、具体第三方解析器 |
| `packages/protocol` | Mizar 接口结构、版本、场景注册表和接收校验 | 业务状态机 |
| `packages/telemetry-gsi` / `telemetry-cstv` | 原始输入解析、规范化与数据源诊断 | 将原始类型泄漏给消费者 |
| `packages/rivalhub` | 公开赛事资料的解析、验证与转换 | 核心运行时和雷达逻辑 |
| `packages/radar` | 地图几何、坐标投影、楼层和道具语义 | 动画、平滑或前端框架 |
| `packages/radar-view` | 共享 React Canvas 雷达、资源与展示平滑 | 再做世界坐标校准或比赛推断 |
| `packages/hud-config` | 预设、布局、外观、组件描述、校验与解析 | 比赛数据、文件系统或 React |
| `packages/design-tokens` | 静态设计变量与生成 CSS | 运行时业务 |
| `packages/cs2-assets` | 官方展示资产、目录、来源与解析入口 | 地图几何或比赛数据 |
| `packages/replay` | 独立于框架的离散回放游标与调度 | 读取原始采集文件或伪造比赛状态 |
| `packages/testkit` | 真实输入重放、模拟、故障注入与断言 | 成为生产运行时依赖 |

依赖顺序为适配器 → Mizar 领域模型 → 投影 → 渲染或传输。不得通过深层导入、TypeScript 路径映射或共享数据库绕过模块边界。

## 比赛与赛事上下文

`MatchContext` 与 `MatchDocumentV1` 以单场比赛为根，`competition` 和 `stage` 可以为空。两方名称、赛制、地图及 BP 引用属于比赛；赛事名称和赛程窗口是可选组织信息。空名单表示未提供名单，不能阻止文档导入、本地保存或节目投影；游戏观察身份仍由既有遥测归一化负责。

来源适配器保留 opaque 参赛方标识，不将它解释成赛事报名 ID。赛事比赛继续使用已有标识与行为；无赛事比赛不创建占位赛事，也不进入赛事赛程。现有赛事授权的在线输出需要真实赛事上下文；无赛事本地制作不会伪造授权并回传。

已配对的当前赛事比赛由 Companion 定期刷新；正在加载的手动选择优先，后台刷新不能使其失效。兼容的同场资料自动激活；地图计划更新复用运行时的未执行判定。本地 BP 冲突时保留地图和禁选、刷新名单与解说，并保留网站候选供明确确认。关联比赛、资料来源与推送资格分别展示；不通过本地覆盖获取在线授权。见 [ADR-0049](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0049-connected-match-refresh-and-diagnostic-retention.md)。

本地比赛回收站与比赛列表由同一 LocalTournamentStore 原子持久化。移入回收站同时清理赛事赛程和旧选择引用，最终写盘前再次检查 MatchContext 当前引用；现场和隐藏工作区的当前比赛禁止删除。准备状态和等待画面下，未接收游戏数据且未启动游戏的新选择可明确确认解除；已有游戏接收证据或重启恢复的选择，需要 Host 实际完成游戏收尾并确认全机 CS2 已退出，通过私有运行时令牌确认当前比赛与上下文修订。该资格仅在内存保存，绑定、制作修订和游戏接收游标变化后失效，重启需重新确认；不以数据过期或浏览器自报推断游戏关闭。回收最后一场并解除选择使用制作生命周期的同一互斥，最终写盘守卫也检查此资格。回收保留完整比赛文档和原赛程位置，不移除共享队伍与赛事资产。恢复保留比赛身份、名单、地图、BP 与结果，赛事展示资料采用现有赛事最新值，恢复不激活比赛或修改当前运行进度。

## 单一事实与独立投影

`SeriesProgress` 只拥有已知地图及观测胜场，不把上游总比分塞回地图计数器。比赛文档的终局结论独立保留 `recorded / pending / omitted`：已结束时节目投影使用上游确认的总比分；待补或不提交结果仍是已结束，比分为空。该投影规则同时供系列摘要和具备身份映射的队伍比分使用，不补造地图。进行中的上游汇总比分不覆盖实时观测胜场。

Core 只维护一份 `RuntimeState`，通过 `ProgramProjection`、`RadarFrame`、`OperatorProjection`、`ObserverAssistProjection` 和 `DebugProjection` 提供不同视图。

- 渲染层只消费自己需要的投影，不重新解释生死、名单、伤害统计或游戏时钟。
- 诊断可以看到更多信息，但不成为正式节目的数据源。
- 选手稳定身份使用 Steam64，阵营与参赛方身份分开。名单和统计算法由[遥测语义](telemetry.md#名单与伤害统计)统一说明。
- 展示配置故障不改变比赛数据；展示摘要也不向领域状态回写。

## 系列赛进展与恢复

`SeriesProgress` 由 Core 定义、Companion 的唯一运行时组合持有，消费 `RuntimeTransition`、比赛资料与已证明的阵营映射。它维护可选计划与实际执行的绑定、有限回合历史、已冻结地图结果和系列比分。创建时冻结 sourcePlan 的 planned / awaiting_plan / unplanned 模式、允许图池和指纹；已有地图为 planned，无地图的赛事比赛为 awaiting_plan，无地图的独立比赛为 unplanned。awaiting_plan 不接受 GSI 自动建图，BP 形成后可在没有执行事实的准备状态平滑切换 planned；指纹来自上游计划，不从可变观测记录重新计算。明确为 unplanned 时，图池内的真实地图可以按观测顺序追加 mapId 为空、selection 未知的本地记录；不创建上游 canonical 地图。只有上一图已经完成、实际地图尚未使用且未达系列胜场或图数上限时才追加下一图，缺少阵营证明时保留观测但不确认胜者。已有计划仍要求严格匹配，错图或缺失上一图结果不能自动跳过。

尚未绑定任何地图执行、回合或赛果的准备状态允许更新地图计划；首次建立时可使用比赛资料中的已完成结果；明确只有人员差异且完整当前双方账号、阵营与计划地图均已证明时，可记录观察到的单图结束并接续相邻计划图，但保持正式比分、胜者为空且不增加系列胜场，由结果待核对诊断说明；运行后普通资料刷新不能回写已运行或冻结的赛果。后续推进来自运行时转换、系列赛归约器与明确人工证据。实际地图与计划不符时保留局内数据，系列绑定进入 `needs_operator`，等待确认。

比赛、参赛方、赛制和有序地图计划兼容时，普通资料刷新更新系列展示中的队名与队标，并由既有检查点保存；不替换地图执行绑定、比分、回合历史或已捕获选手摘要。身份或计划冲突时保留原展示身份与系列事实，不能把新参赛方资料套在已运行系列上。

回合结束转换是回合历史的首要来源；`map_round_wins` 仅恢复缺失、补充未知胜因或校验，不覆盖已冻结获胜方。冲突保留原事实、标记 `partial` 并报告诊断。

同一地图结束观测中的可证明绝对回合历史在地图结果冻结前完成归约，涵盖没有独立回合结束转换的最后一回合；这不允许后续输入改写已完成地图。

恢复检查点使用 v2，有大小上限，按比赛、参赛方、赛制和冻结 sourcePlan（包括图池）核对兼容性，仅在业务边界原子写盘。空计划、空观测是合法初始状态；后续追加观测不会改变计划指纹，刷新和重启保留这些记录。旧检查点不迁移，按既有不兼容诊断处理。恢复后还要与当前回合、比分和回合历史核对，结构与执行兼容性分别核对。关闭服务先停止生产者，再等待已提交检查点写完。

## 连续性与事件

| 标识或类型 | 表达 |
| --- | --- |
| `liveSessionId` | 比赛与生产会话的绑定 |
| `producerInstanceId` | 一次本地服务运行 |
| `mapEpoch` | 地图的一次实际执行 |
| `sourceGeneration` / 数据源序号 | 单个数据源的连接与读取连续性 |
| 高频快照 | 当前状态，可被更新覆盖 |
| `RuntimeTransition` | 已观测到的状态边界 |
| `OperatorCommand` | 有明确结果的人工操作 |
| `ReliableObservation` | 转换发生时的上下文派生的可靠观测 |
| `Incident` | 运行问题与诊断 |

这些概念不能合并成全局序号或万能事件。数据源重连只使依赖它的证明失效；可选事件源或 Lookahead 重连不自行推进正式节目的地图执行编号。投递、去重和背压由[协议](protocol.md#本地实时通道)维护。

Core 在地图执行中保留一个“曾观测正式阶段”的连续性证明，不把它作为当前阶段。只有同图重新出现完整的热身、回合零、双方零分且没有冲突的非空历史时，才推进执行编号，并通过既有转换清除未完成地图的历史、单图统计和目标计时。CS2 热身可以省略历史字段，零回合与零比分的完整热身仍提供执行重开的证据；地图关键字段缺失、降级、普通回合回退和重连本身不证明重开。已冻结完成地图不因该转换被撤销。决定见 [ADR-0037](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0037-witnessed-same-map-restart.md) 与其条件修订 [ADR-0038](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0038-warmup-without-round-history.md)。

## 正式节目与观察辅助隔离

新鲜正式输入允许手动选择 Gameplay，包括未绑定赛事的 demo；这只接管画面，不建立赛事归属或官方身份。Core 的 Gameplay 展示投影在地图未绑定或身份不符时使用中立身份，制作控制保留后台选择与系列事实。手动摘要展示不确认赛果，自动编排仍受严格绑定与阶段门槛约束，见 [ADR-0032](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0032-manual-summary-and-demo-presentation.md)。

正式节目消费观战客户端的 GSI；精确事件是可选增强。Lookahead 使用独立的较早时间轴，只能形成私有辅助信息。

- Lookahead 不能作为正式节目备用源；任一链路故障不改变另一链路的角色。
- 未来字段不能先进入公开数据，再依靠 CSS、窗口或 OBS 裁剪隐藏。
- 安全边界由投影、类型和协议结构保证，窗口捕获策略是额外防线。
- 制作工作区、控制栏和本机 HUD 覆盖允许远程捕获；正式 OBS 输出使用独立的游戏捕获与播出 Browser Source，不依赖制作窗口的捕获排除。策略理由见 [ADR-0022](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0022-remote-workspace-capture.md)。
- Lookahead 重连后旧时间轴对齐立即失效。

接入能力见[数据源矩阵](../guide/data-source-capabilities.md)，尚未交付的研究见 [RFC](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/rfcs/0001-lookahead-observer.md)。

C4 资源的解压、解析、预测索引与计算由 Companion 的单个 Worker 承担，最多保留两张地图和十个在途预测。Core 继续校验当前数据资格；结果按地图、数据源代际、地图执行和完整预测输入匹配，只触发当前状态重新投影。同一投影的十人预测合并为一次 Worker 消息，整批写入精确输入缓存后通知刷新。普通实战帧的等待发布最多合并十六毫秒，既有完整快照保留原游标；未变化的不可用项（例如已阵亡选手）不阻止其余选手的等待合并，新出现的不可用原因立即发布。完成时重投影最新状态，超时公开等待，不把旧估算拼接到新帧。新鲜度、代际、地图、身份、回合或比分边界立即发布。见 [ADR-0029](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0029-c4-worker-isolation.md)与 [ADR-0035](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0035-bounded-c4-publish-coalescing.md)。

## 雷达与展示配置

雷达领域完成世界坐标到地图坐标的转换；共享展示包负责插值、平滑、跳变重置和自动聚焦动画。外部网站消费已经校准的公共坐标，不复制地图校准。[包说明](../../packages/radar-view/README.md)维护集成方法。

共享雷达展示缓存底图滤镜、烟雾纹理、火焰模糊及 C4 着色，缓存按表面大小、样式和地图边界失效，有界保留，不改变地图校准与插值。火焰模糊按亚像素栅格精度复用近似纹理，避免自动缩放的连续浮点值让每帧重建缓存；精度由[缓存实现](../../packages/radar-view/src/render-cache.ts)维护。烟雾生命周期容忍一 tick 的寿命回跳，明显回退或位置断裂仍重建；同生命周期已知阵营不因死亡后的 owner 变化而丢失。

HUD 配置独立于比赛数据：组件内容、布局、外观和比赛投影分别拥有自己的职责。描述符维护组件方案、设置和尺寸，编辑器与播出使用同一解析结果和渲染器。Companion 持久化配置，浏览器缓存不是权威来源。保存、启用、版本校验与文件交换规则见[协议](protocol.md#hud-配置)。

设计变量 → 基础组件 → 组合组件 → 功能页面的规则由[设计系统](../design/README.md)维护。

## 制作生命周期与节目编排

Companion 拥有 `preparation / live / hidden` 制作生命周期；它们不等同于比赛或 OBS 状态。进入现场需要比赛资料；结束制作通过场景控制器核实 OBS 等待画面、再释放平台数据源，失败保留现场状态供重试，不删除本地比赛。人工重新选择当前场景仍核实 OBS；退出使用独立的安全收尾意图。OBS 切场失败时仅在本次原生进程检测明确证明 OBS 未运行后完成本地等待状态，适用于从未启动 OBS 以及制作人员已关闭 OBS 的恢复；断线、鉴权失败或检测未知本身不能证明输出已停止。OBS 仍运行时保留安全切场要求，提示连接后重试，或人工确认停止输出并关闭 OBS 后重试，不自动停止输出或关闭用户启动的 OBS。安全收尾成功后 Host 才关闭受管 CS2 并恢复设置，恢复失败保留原恢复事务与重试入口。

Host 持有已验证进程身份的句柄发送正常关闭请求，分别保留窗口枚举失败、关闭消息拒绝、无可关闭窗口、等待超时与等待失败的原因。消息发送成功不证明游戏已退出，权限拒绝也不能放宽身份或配置恢复检查；本机诊断记录阶段、API、错误码与受管 PID／创建时间，并随既有退出事件进入诊断包。失败时由使用者在游戏内正常退出后重试，不自动强杀或关闭不归属进程。

本地 Demo 试播在同一制作生命周期内使用临时比赛资料及独立运行会话，不新增运行时或 Demo 管理库。Host 持有原生文件选择能力和播放请求；Companion 在启动前持久记录试播隔离，暂停正式检查点读写、资料修改、采集及在线输出，真实 GSI 仍经过原生产解析与投影。服务重启发现未完成记录时先隔离输入，不自动恢复正式绑定。试播保持手动编排；进程运行、收到有效观战数据和加载选定 Demo 是不同事实。

结束试播先隔离在途 GSI 并确认 OBS 等待画面，Host 只按既有进程身份关闭受管游戏并恢复配置，成功后才确认完成隔离事务；失败保留恢复记录供重试。完成后恢复正式资料、清空试播遥测、统计、计时和提示，推进会话与数据源代际；在明确重新进入正式制作前继续拒绝 GSI，避免迟到的 Demo 输入污染正式检查点。用户显式启用的 HUD 配置保留。

桌面和 Web 的进入现场入口先读取当前 OBS 连接与场景检查结果；未通过时打开连接引导，不提交制作命令。此准备门禁不复制生命周期状态，也不改变现场运行后的离线恢复能力；理由见 [ADR-0023](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0023-workspace-preflight-and-density.md)。

CS2 的自动发现、手动安装选择和 GSI 配置目录统一由 Host 管理。按 Steam AppID 730 清单定位，验证程序与新版 cfg，按安装根目录去重；保存的手动位置同时供 GSI 与启动使用。文件冲突、重复发送与读取失败分别展示，支持包只导出有限问题码、数量和阶段；见 [ADR-0047](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0047-shared-cs2-installation-discovery.md)。

桌面通过准备检查后，由 Host 启动或复用本次受管理 CS2，再提交进入现场。启动发现要求唯一 Steam 进程、可读取且存在的程序位置，以及有效的当前账号整数；Host 通过持有的原生进程句柄读取映像路径与创建时间，不依赖 PowerShell 的模块路径，安装目录候选不能替代运行进程身份。发现期间及提交 Steam 启动请求前复核唯一进程的 PID、创建时间、程序路径和当前账号，变化或读取失败时拒绝提交；缺失、格式异常或越界账号明确报告账号不可用，不猜测 userdata 目录。注册表的有符号 DWORD 仍按原 32 位账号恢复，底层读取异常保留在本机诊断。 配置接管前先在本机保存视频与机器帧率文件的原始字节；机器帧率文件确实不存在时记录缺失而不构造文件，正常接管仍拒绝、保留模式可继续，存在但不可读仍报错；`fps_max` 原值可为有限非负小数，恢复保留原始文本。重复视频字段分别诊断同值与冲突，嵌套与格式错误单独报告，不自动取第一或最后值。备份成功且接管失败未留下待恢复事务时，可明确选择「保持原游戏设置继续」：仍由 Host 跟踪 Steam 请求及进程身份，但不应用自动画质、帧率、游戏窗口布局或本机 HUD 覆盖，结束后只清理启动记录，保留现场备份且不覆盖游戏的新设置。备份失败、未完成事务及进程归属不明仍阻止危险操作。结束制作成功后正常关闭该游戏并恢复临时视频与帧率配置；隐藏现场不关闭。配置文件与进程身份、备份及重启恢复只由 Host 管理，网页发送固定意图。画质与帧率使用独立的有限选项，默认最高画质与 60 帧／秒；启动脚本中直接设置的帧率纳入同一恢复事务，避免覆盖本次上限。细节见 [ADR-0026](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0026-managed-cs2-launch-and-restoration.md)及其局部替代 [ADR-0045](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0045-managed-game-quality-and-frame-budget.md)。

现场工作台由独立 CS2 与两块桌面面板组成。每个受管 CS2 进程首次进入现场时，仅在准备中心仍为前台的情况下尝试一次聚焦游戏；首入在后台最多等待渲染窗口三十秒，期间前台切走或游戏退出即取消；窗口就绪后只尝试一次聚焦，超时或失败不后台重试。底栏的「返回游戏」是新的显式聚焦意图，Host 校验调用面板仍为前台、工作台可用以及受管进程身份后才尝试；执行时已切换面板或应用、隐藏或退出会使请求失效。普通面板操作、节目「比赛中／BP」切换和「恢复布局」不申请游戏焦点，重新显示面板也不主动选择输入目标。Host 在既有有界窗口巡检中检测从其他应用切回成员，只为本次受管理进程恢复最小化的同组窗口并调整普通 Z 序，保留用户选中的输入焦点；联动不重排布局、不修改缩放或置顶状态、不嵌入游戏，也不操作外部启动的游戏。进程身份沿用 ManagedCs2 的 PID、创建时间与程序路径验证，操作期间持有原进程句柄；游戏最小化不释放既有窗口目标。隐藏、退出、成员失效、模态窗口和前台再次切走会取消联动；异步恢复只提交一次，并以单调时钟观察最多两秒，不在后台反复抢焦点；API 失败或超时按本次事务在既有 DesktopLog 中记录一次阶段、API、错误码和受管 PID／创建时间，不记录路径，正常取消不记故障。Alt-Tab 与任务栏仍由 Windows 展示各顶层窗口，置顶或独占全屏游戏不参与自动联动；原生效果与 CS2／OBS 捕获仍须实机验证。

现场窗口采用窗口级全屏 Shell 标记，让任务栏在现场处于活动状态时退到其后，不修改系统自动隐藏设置；隐藏、退出或更换游戏窗口撤销标记。标记成功后按完整显示器边界排布，失败沿用工作区。受管理 CS2 使用无边框窗口，启动参数与临时视频配置都使用既有工作台布局算出的游戏尺寸，保持 75% 上限与 16:9 客户区，左栏贴屏幕底部，与游戏、底栏连续平铺；游戏拒绝无边框时保留原生外框避让。外框缩放成功不代替客户区对齐；游戏拒绝运行中的分辨率变更时不再次缩小无边框外框，本机覆盖保持隐藏并提示重新进入工作台。DPI 与窗口变化共用同一 Host 物理布局；现场 WebView 自身的缩放变化也通过既有工作线程合并重排，不依赖游戏窗口同时改变尺寸或 DPI，隐藏期间的变化在恢复现场时处理。决策及异常退出边界见 [ADR-0030](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0030-workspace-fullscreen-shell.md)、[ADR-0031](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0031-borderless-workspace-game.md)与[ADR-0036](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0036-workspace-sized-cs2-launch.md)。

`ProgramDirector` 消费既有投影与 BP，通过唯一 `ProgramSceneController` 请求 OBS 切场。现场默认自动，手动操作保持到显式恢复。自动切场最多一个在途请求、不离线排队；切换前后检查上下文、代际、版本与时限。失败停止自动推进。具体节目顺序与时长来源见[节目规范](../design/program-direction-v1.md)。

`BpSession` 只维护播放状态；正式 BP 由比赛投影派生。本地补录不改写在线比赛身份，演示来源只在 BP 内存会话生效。命令与来源切换见[协议](protocol.md#bp-播放与补录)。

`ProgramPresentationStore` 在地图结束时冻结已确认比分并捕获选手摘要，最多保留五图。相同生产实例、会话、来源代际和地图执行的后续新鲜 gameover 观测，只有阵营名单完全一致且比分不变时，才允许已观察到的 K/A/D 收敛；缺失字段不擦除已捕获值，不回写比分或回合历史。换执行、来源、比赛、断流或身份不符后保留已捕获摘要，跨图保留、换比赛清除。静态画面的进入资格与已播连续性分开，不恢复旧游戏时钟；见 [ADR-0039](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0039-terminal-player-summary-settlement.md)。

Companion 的 OBS 模块持有唯一输出控制状态，通过持续的 Outputs 订阅和重连快照观察直播、录像与外部手动操作；快照不能覆盖读取期间的新事件，旧连接回调不能写入新代际。人工开始／停止使用明确请求，不依赖本地切换布尔值。每类输出的在途保护跨窗口生效，并与配置修改和修复互斥；请求回执与实际完成分别判断，超时后核实状态，不自动重放命令。网页只消费本机输出视图和提交有限意图，桌面、Core 与自动节目编排不持有输出控制权。

OBS 由 Companion 检查和修复，只管理 Mizar 自有场景；推流或录制期间不修复场景集合，不自动改全局输出设置。桌面只处理窗口和本机覆盖显隐，不复制节目状态。Companion 解析 OBS 启动路径，桌面 Host 在服务 Runtime Job 外启动独立 OBS，退出 Mizar 不连带终止 OBS。HTTP 服务就绪后，Companion 有界串行重试刷新当前 Mizar 集合内名称、类型与本机节目 URL 都匹配的 Browser Source，每个源每次服务启动最多成功刷新一次；不切换集合、场景或输出设置，关闭时取消重试。此刷新可恢复 OBS 先启动及服务重启时加载失败的页面，不能替代实际画面核对；理由见 [ADR-0024](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0024-independent-obs-process.md)。

制作提示从现有状态生成；B 站查询有缓存、超时和并发上限，只服务本机状态提示，不进入公开输出或节目切换门禁。实现见 [ADR-0019](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0019-production-guidance-and-platform-status.md)。

## 安全、采集与扩展

本地监听、Origin 校验和凭据分离见[协议安全](protocol.md#本地访问与安全)。采集写盘不能阻塞 GSI 接收，重放必须经过生产适配器，规则见[遥测语义](telemetry.md#采集重放与时间)。

新增数据源优先增加适配器，新增画面优先复用已有投影，新增可靠输出不改变高频快照语义。第二个真实消费者、提供方或独立发行需求出现前，不建设通用插件框架。

Desktop 的 CS2 启动、临时配置与恢复遵循 [ADR-0026](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0026-managed-cs2-launch-and-restoration.md) 和 [ADR-0027](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0027-cs2-launch-recovery-workflow.md)。状态查询不等待启动或退出操作锁；Steam 请求提交后立即释放启动命令锁，准备中心显示正在等待，不因固定等待时限判定失败。后台继续按 PID、创建时间与规范化程序路径认领唯一晚启动进程；等待期间不提交进入现场，保留本次进入意图，游戏被确认运行后继续打开工作台；取消请求或导航离开会取消进入意图，不重发 Steam 启动。本地服务启动失败时，Host 原生恢复入口只读取同一 SessionStore、观战恢复与试播清理记录，不调用可能自动写回的 poll；用户明确恢复后复用 ManagedCs2 原有进程、路径和读回门禁，不关闭游戏、不启动 Steam，也不确认制作结束或本场回收资格。运行中的 CS2、未知进程状态及 Demo 试播隔离拒绝离线写回；Steam 待确认要求原有显式取消确认。恢复返回的软警告同样显示原原因与下一步，不以检查完成掩盖仍待恢复的记录。错误继续保存在本机 DesktopLog，诊断导出保留脱敏的原因和 stderr。Steam 请求待确认时保留持久记录，取消等待必须先取消 Steam 请求并确认游戏关闭，再显式恢复备份。未确认启动会阻断正常退出；正常退出（含 `--stop`）先由 Host 请求 Companion 安全切场与释放数据源，再关闭受管理游戏、恢复配置，成功后才停止服务；收尾失败保留 Host，退出期间拒绝新启动与工作台进入，异常退出后的恢复状态跨窗口可见。工作台退出也由 Host 执行同一安全收尾顺序；打开准备中心后保留工作台直到收尾成功，不因隐藏或网页导航丢失任务。Host 只保存此次退出的阶段、忙状态和错误反馈，准备中心与底栏只读同一结果，不复制制作或恢复事实；失败释放退出门禁，保留原始本地日志、备份、重试与诊断入口。退出开始使此前的工作台进入代次失效；现场窗口先隐藏创建，主线程把显示、聚焦、隐藏准备中心和清理旧反馈与退出开始互斥提交，已完成或失败的退出也不会被旧进入覆盖。Steam 取消确认仍显式提交给原恢复门禁。启动项只传给本次 Steam 调用，不修改持久启动项。退出请求与失败重试见 [ADR-0033](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0033-host-first-exit-request.md)。

可选 Steam 头像由 Companion 的本机媒体缓存提供，赛事头像优先；不修改身份或比赛文档。密钥与缓存独立于采集、预设和支持包，见 [ADR-0034](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0034-local-steam-avatar-fallback.md)。

安装版的数据目录与自动准备所有权边界见 [ADR-0048](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0048-installed-state-and-safe-preparation.md)：安装版使用当前用户数据目录，便携模式保持原路径；自动 GSI 不取得未知文件所有权，OBS 重连不覆盖手动配置。

桌面窗口对齐只在实际客户端范围与目标一致后确认成功。系统调用失败、画面范围不一致及保留原设置分别反馈；权限拒绝不推断为管理员权限差异，也不自动提权。窗口组恢复错误保留失败目标角色，工作台与准备中心显示同一 Host 反馈；新的成功恢复清除对应告警；手动命令保留 Host 错误归属，不在页面复制旧原因。隐藏期间完成恢复后，只有 SessionStore 核心记录已清理且全机 CS2 已确认停止才清理窗口反馈，读取失败或仍待恢复时继续保留。诊断只投影有限窗口范围、显示器工作区、DPI、失败阶段及当前 Host／游戏提权状态，不包含窗口标题、句柄或私有路径；读取失败为未知，游戏退出后的状态不能还原运行时权限。

本机支持包按有限尾部读取桌面、监督器和服务日志，并读取宿主实际轮转的 `desktop.<序号>.ndjson`；兼容旧尾缀命名。窗口加载成功在宿主按累计次数的二次幂采样，在导出时按启动会话聚合；失败和告警优先占用有限事件窗口，保留已知阶段的脱敏原始原因。日志尾部之外的历史仍受读取上限约束，聚合不保证无限保留。素材缓存打开与复验证失败写入既有服务日志，不改变 Full 回退或资源激活规则。

业务诊断独立写入 `logs/business.ndjson`，由现有投影和发送队列提交结果提供事实，不作为恢复或比赛状态来源。上下文、地图执行、比分、身份、绑定、数据新鲜度和判定码变化才写入运行摘要，游标随边界保留，不按 GSI 帧逐条写盘。队列提交后记录入队、重试与终态；发送守卫阻止也保留证据。接收结果只提供三态时，拒绝或重试的具体原因标记未知，不解释成网络错误或接收端业务拒绝。启动从既有队列记录恢复摘要，但不据此推断本次已发送。

业务日志每段最多 64 KiB，当前与三段历史合计最多 256 KiB；不会因正常退出或重启清空，满额才覆盖最旧段。只写白名单状态、错误码、数值和会话内加盐的关联摘要，不写原始遥测、名单、Steam64、凭据、远端正文或完整配置；标准地图名称可保留，未知地图只保留关联摘要。导出再次核对字段白名单并重新加盐，不同会话或导出间不能据此追踪同一私人身份。日志写入失败不影响比赛归约或队列提交，支持包标记 `businessLog: write_failed`；下一次写入成功恢复状态。有限历史、导出事件窗口与磁盘故障仍可能缺证据，旧版本没有写下的历史无法补回。

采集故障沿用 Recorder 的结构化错误码、操作及有限系统错误码进入服务日志和支持包；当前快照保留 `lastErrorCode`。不为诊断重新启动采集或读取原始采集正文。

OBS 输出 RPC 与操作失败在支持包中分别保留 `obs_output`、`obs_output_command` 阶段及有界、脱敏的业务码、OBS 数值码和原因链；配置忙碌时拒绝输出操作也记录在同一诊断边界。导出额外移除输出错误中的 URL 和带推流密钥的行，不改写本机日志，不连接 OBS 或重放命令。旧支持包已过滤掉的原因无法还原。

支持包还并行读取 Windows OBS 原生证据，总采集期限 7 秒、导出投影最多 24 KiB，不启动、停止或重配 OBS/CS2。只从 APPDATA 候选目录或运行中 OBS 的 portable 目录读取已选 profile/collection，目录项最多 128、日志最多两份，取 24 小时内日志的有限头尾，仅投影最近两小时的 hook 尝试、重试、失败、成功、停止与渲染器错误。日志窗口保留最近失败；文件缺失、拒绝访问、超限和整体超时分别留下状态。配置仅投影已保存 Program（与预览分开）、分组可见性及有限捕获/视频字段；不导出 profile/场景/窗口私有名称、URL、推流密钥、配置正文或完整命令行。只读进程查询保留 OBS/CS2 PID、创建时间、提权状态（读取失败为未知），以及 CS2 第三方捕获参数是否存在；可执行路径只在内部定位 portable 目录。日志与进程仅按时间关联，不能当作 hook PID 证明；已保存配置不等同于当前 Program，hook 成功和源尺寸不证明当前像素正常。可选采集失败保留普通支持包，旧包缺失的原生日志无法补回。 读取前核对完整祖先及下级路径，拒绝 junction/symlink；打开后以 ino/dev 核对文件身份并复核路径身份。portable 兼容官方四种存在性标记。原生事件分类保留 helper 十进制退出码、DLL/plugin hook 版本，以及 D3D11 HRESULT 十六进制值与数值；不依赖错误正文一定包含 fail/error 关键词。JSON 最终 UTF-8 大小仍超限时返回明确 export_budget 截断后备状态，不输出超限投影。



### 最小数字键观战配置

受管制播启动使用固定 `mizar_observer.cfg` 与白名单 `+exec` 参数。源文件随下载包提供，并由桌面启动路径部署到已发现的游戏 cfg 目录。CFG 设置 `spec_usenumberkeys_nobinds 0`，仅将数字键 1–9 绑定到对应 `slot1`–`slot9`，0 绑定到 `slot10`，使用武器槽绑定进行观战选择，并输出固定加载标记；不修改其他按键、Steam 长期启动项或个人 autoexec，不开放任意控制台。部署只创建缺失文件、接受完全一致的当前字节，或升级完全一致的旧版固定字节；未知同名文件、符号链接及不完整文件不覆盖、不执行。保留设置启动不加载该 CFG；已有受管游戏进程时重进工作台沿用进程，不重新 exec。

恢复职责仍在 `cs2_session::SessionStore`。在允许启动 exec 前，第二版 `spectator-recovery.json` 持久保存原观战字段及主键位文件 `730/local/cfg/cs2_user_keys_0_slot0.vcfg` 中 1–9、0 的原命令 token；缺项以 null 表示，空命令单独保留，不保存整份键位文件。字段与文件解析、大小、重复配置段和符号链接有界校验；同一数字键的重复字段命令一致时允许，不一致时跳过可选预设。启动前再次核对十键备份仍与原文件一致，在 Steam 请求前持久标记本次可能加载；确定未提交或启动进程创建失败时，不恢复未接管的观战字段与键位，只清理可选记录。启动结果不明确时仍沿用核心退出确认门禁。准备阶段不预写观战归档字段或键位，不扩展帧率 `original/applied` 的职责。

核心 FPS/视频恢复完成后分别尝试观战字段与十键恢复。键位恢复基于当前文件的字段位置，只替换本次 `slotN` 对应的原命令或移除原来缺失的字段；已恢复的原值允许重试，其他键和其他字段的游戏写回保持原样。当前数字键不是本次值或原值时，保留外部修改、原值备份与具体诊断，不覆盖该键位文件。恢复写入前再次核对当前文件未变。原观战字段恢复仍只替换单一 token；镜像、缺项、未知值或外部关闭冲突不盲目覆盖。第一版恢复记录兼容原单字段恢复，不接管键位。

可选恢复失败保留独立记录与重试，不返回核心恢复失败、不保留核心 pending、不阻塞工作台或启动设置。后续启动仅跳过观战 CFG，直到操作员确认游戏退出后重试恢复。记录损坏、读取或写入失败只隔离可选功能，未放宽既有核心恢复门禁。不回写其他键位文件或 remote/lastclouded 镜像，不导出私人配置。

UI 删除冗余观战选择开关，正常说明放在启动详情；仅未加载或恢复未完成时显示具体原因。恢复不完整时不宣称所有原设置已恢复。部署及 Steam 请求提交不是运行时生效证明；当前 CS2 加载顺序、真实 GOTV/Demo 数字键切人、归档位置、退出写回与 Cloud 同步尚待指定 Windows 包实测。

观战 CFG 准备与原值恢复的宿主事件纳入现有用户诊断包投影；保留固定阶段、运行时未验证标记、OS error kind/code 和 JSON 类别/行列，配置正文及任意附加 JSON 字段不导出。

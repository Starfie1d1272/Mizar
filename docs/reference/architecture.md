# 系统架构

本文维护当前职责与依赖规则；产品价值见[产品定位](../guide/product.md)，接口和输入解释分别见[协议](protocol.md)、[游戏数据语义](telemetry.md)。决策理由保存在 [ADR](../decisions/README.md)。

## 数据与控制

```text
本地比赛资料 / RivalHub      CS2 GSI / 可选事件源
           ↓                       ↓
        赛事适配器              遥测适配器
           └────────→ Core ←───────┘
                  运行状态、身份、连续性
                          ↓
                  各消费面的独立投影
                  ├─ 播出画面与雷达
                  ├─ 制作控制与诊断
                  └─ 私有观察辅助

Companion 组装运行时、持久化和接口
  ├─ 节目编排 → 场景控制 → OBS
  ├─ 公开投影 → 外部数据输出
  └─ Web / Windows 桌面 → 制作人员
```

赛事平台拥有官方赛事资料与结果，Mizar 拥有本地实时观测。独立模式与连接模式共享运行时，仅赛事资料来源不同。Mizar 不直连 RivalHub 内部数据库；DAK 等赛后证据不进入低延迟播出主循环。

本机赛事的BO3默认禁选规则保存在既有LocalTournamentStore赛事资产中，供未录入BP的比赛继承；本场草稿使用规则编译出同一MatchDocument的veto/maps事实，已有事实优先恢复，赛事默认变更不改旧BP。本场规则调整不顺带修改赛事默认，在线补录不改平台身份或网站数据。本地地图已有任一数值比分（包括 0）或完成时间时，BP 和比赛资料编辑保留该图及赛制，不因缺少完成时间而允许裁剪或覆盖；双方比分与完成时间均为空的未开打计划仍可编辑。缺省旧配置保留既有流程，见[ADR-0040](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0040-event-bo3-authoring-rules.md)。

## 模块职责

应用内更新由 Companion 持有已认证版本、检查偏好及下载状态；桌面宿主通过本次运行的私有能力核对安装计划，正常退出后启动资源目录外的恢复工具。浏览器不能提供可执行路径或调用安装命令，更新不成为比赛或制作状态的第二来源。元数据、信任根与恢复契约见[应用内更新](updates.md)。

正常停止以监督进程记录的匹配 Companion 实例实际退出结果为准；HTTP 不再响应并不能证明本地收尾完成。Companion 停止生产者后分别尝试本地持久化和采集收尾，远端来源释放随后有限执行，失败保留待恢复状态。可靠队列写入失败、录制落盘失败以及未提交的业务或会话日志均不能作为完成；收尾失败或超时不报告成功。宿主仅在明确的制播进程退出超时异常路径强制终止所属进程；程序包校验本身超时不能证明本地收尾已超时。

官方示例素材由 Companion 的[单一资源 Store](../../apps/companion/src/resource-store/README.md)持有独立持久缓存和状态。安装器复用同一 Store；来源授权与清单消费复用资源契约模块，缓存启动离线复验证据及实际文件。原资源 URL 从活动版本读取；无活动缓存时保留 Full 随包来源，错误不混合版本。激活与制作生命周期及更新共用互斥保护，现场只准备素材。

资源管理通过单一播出配置 Store 管理 HUD、场景、音乐、运镜模块及方案；保存和复制只修改草稿，显式使用才切换活动配置。各模块分别记录目标、已应用版本及错误；组合方案中单个模块依赖不可用时，其余可用模块仍可应用，失败模块保留最后有效配置与资源引用。当前可重试请求与历史指纹分开保存；每个消费者仅保留自身实际配置及依赖，历史回执不再固定旧素材。现场制作不要求先结束或切到等待画面才能应用配置；正在准备或执行的镜头仅阻止改变对应运镜配置，其他模块继续应用。资源身份与来源版本变化仍同步消费者和回执；内容相同仅跳过设备内容重载，不跳过选中身份。旧入口提交活动内容时同步来源版本，过期消费者不得以相同内容修订覆盖新资源身份。旧编辑接口只转换请求并调用该 Store；首次导入与后续重启共用一次配置绑定，导入在绑定前结束。HUD 编辑视图直接采用该 Store 已确认的活动身份，只有尚无已确认配置时保留本地初始显示。首次迁移保留旧音乐的完整配置和素材身份，缺失或损坏音频只阻止音乐消费者应用，不阻止 HUD、节目和运镜进入资源管理。原音乐配置与旧文件备份继续保留；显式恢复音频由音乐资产层验证原音频，保留损坏文件并核对目标未变化后原子替换，不修改配置或开始播放；显式重新使用资源后再完整验证并提交音乐回执。消费者实际应用成功后，在自身串行操作中向中央 Store 提交回执。回执写盘失败保留已生效结果及新旧资源引用，界面显示未确认；后续只重试回执持久化，不重复设备应用。正常关闭再次提交未确认回执，重启仅采用已落盘证据。运行中的播放、监听及游戏状态单独保存，不进入可分享配置。资源字节和来源由资源 Store、音乐资源及 MulNX 内容提供方持有，删除前检查引用。MulNX 镜头内容仍属于已验证的发行来源，缺失时该运镜资源不可用，不阻止其他资源。

安装器的素材准备入口必须成功打开 Store；初始化失败时，启动错误通过 `cause` 保留原始异常，由安装器既有脱敏日志出口记录错误码和系统调用等细节。普通 Companion 启动仍允许回退 Full 随包素材，不改变其容错行为。

Companion 的 `ProgramRuntime` 在绑定上下文、提交输入或操作命令时统一解析身份、核对执行归属并推进系列事实，提交结果携带同一版本快照与转换。Program 与 Operator 从该快照投影；投影刷新不推进系列事实、不写检查点，也不执行业务命令。输入提交后的投影、可靠输出与节目提示沿同一发布顺序接线。

## 比赛与赛事上下文

`MatchContext` 与 `MatchDocumentV1` 以单场比赛为根，`competition` 和 `stage` 可以为空。两方名称、赛制、地图及 BP 引用属于比赛；赛事名称和赛程窗口是可选组织信息。空名单表示未提供名单，不能阻止文档导入、本地保存或节目投影；游戏观察身份仍由既有遥测归一化负责。

来源适配器保留 opaque 参赛方标识，不将它解释成赛事报名 ID。赛事比赛继续使用已有标识与行为；无赛事比赛不创建占位赛事，也不进入赛事赛程。现有赛事授权的在线输出需要真实赛事上下文；无赛事本地制作不会伪造授权并回传。

已配对的当前赛事比赛由 Companion 定期刷新；正在加载的手动选择优先，后台刷新不能使其失效。兼容的同场资料自动激活；地图计划更新复用运行时的未执行判定。本地 BP 冲突时保留地图和禁选、刷新名单与解说，并保留网站候选供明确确认。关联比赛、资料来源与推送资格分别展示；不通过本地覆盖获取在线授权。见 [ADR-0049](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0049-connected-match-refresh-and-diagnostic-retention.md)。

当前本地比赛的修改、选择和激活由 `MatchContextController` 串行协调，在原子写盘前核对上下文修订和选择代次。BP 与服务器名单保存复用该业务操作，`LocalTournamentStore` 只负责文档持久化；资料库编辑不隐式激活比赛。选择或创建在激活前读取最新已存文档。赛事资料保存进入同一串行队列后再判断当前受影响比赛；排在前面的选择生效后，保存刷新对应当前比赛，已切出的比赛只更新资料库，写盘期间的新选择或修订仍使旧刷新失效。本场资料编辑固定已核对的文档与上下文修订；脏草稿不随轮询升级修订，版本或选择冲突时保留草稿并禁止保存，取消后重新核对。

本地比赛回收站与比赛列表由同一 LocalTournamentStore 原子持久化。本地库以紧凑 JSON 的实际 UTF-8 字节统一执行 2 MB 读写上限；旧版缩进文件只在有界读取、原结构与内容容量校验通过后保留原件并原子转为紧凑格式，不能以恢复为由接受更大的有效资料。移入回收站同时清理赛事赛程和旧选择引用，最终写盘前再次检查 MatchContext 当前引用；现场和隐藏工作区的当前比赛禁止删除。准备状态下，未接收游戏数据且未启动游戏的新选择可明确确认解除；已有游戏接收证据或重启恢复的选择，需要 Host 实际完成游戏收尾并确认全机 CS2 已退出，通过私有运行时令牌确认当前比赛与上下文修订。该资格仅在内存保存，绑定、制作会话和游戏接收游标变化后失效，重启需重新确认；不以数据过期或浏览器自报推断游戏关闭。回收最后一场并解除选择使用制作生命周期的同一互斥，最终写盘守卫也检查此资格。回收保留完整比赛文档和原赛程位置，不移除共享队伍与赛事资产。恢复保留比赛身份、名单、地图、BP 与结果，赛事展示资料采用现有赛事最新值，恢复不激活比赛或修改当前运行进度。

## 单一事实与独立投影

`SeriesProgress` 只拥有已知地图及观测胜场，不把上游总比分塞回地图计数器。比赛文档的终局结论独立保留 `recorded / pending / omitted`：已结束时节目投影使用上游确认的总比分；待补或不提交结果仍是已结束，比分为空。该投影规则同时供系列摘要和具备身份映射的队伍比分使用，不补造地图。进行中的上游汇总比分不覆盖实时观测胜场。

Core 只维护一份 `RuntimeState`，通过 `ProgramProjection`、`RadarFrame`、`OperatorProjection`、`ObserverAssistProjection` 和 `DebugProjection` 提供不同视图。

- 渲染层只消费自己需要的投影，不重新解释生死、名单、伤害统计或游戏时钟。 Web 的 `ProgramView` 接收 HUD、节目场景或 BP 展示输入；实时订阅和雷达通道适配留在宿主，导演进度由场景状态传入。
- 诊断可以看到更多信息，但不成为正式节目的数据源。
- 选手稳定身份使用 Steam64，阵营与参赛方身份分开。名单和统计算法由[遥测语义](telemetry.md#名单与伤害统计)统一说明。
- 展示配置故障不改变比赛数据；展示摘要也不向领域状态回写。

## 系列赛进展与恢复

`SeriesProgress` 由 Core 定义、Companion 的唯一运行时组合持有，消费 `RuntimeTransition`、比赛资料与已证明的阵营映射。它维护可选计划与实际执行的绑定、有限回合历史、已冻结地图结果和系列比分。创建时冻结 sourcePlan 的 planned / awaiting_plan / unplanned 模式、允许图池和指纹；已有地图为 planned，无地图的赛事比赛为 awaiting_plan，无地图的独立比赛为 unplanned。awaiting_plan 不接受 GSI 自动建图，BP 形成后可在没有执行事实的准备状态平滑切换 planned；指纹来自上游计划，不从可变观测记录重新计算。明确为 unplanned 时，图池内的真实地图可以按观测顺序追加 mapId 为空、selection 未知的本地记录；不创建上游 canonical 地图。只有上一图已经完成、实际地图尚未使用且未达系列胜场或图数上限时才追加下一图，缺少阵营证明时保留观测但不确认胜者。已有计划仍要求严格匹配，错图或缺失上一图结果不能自动跳过。

尚未绑定任何地图执行、回合或赛果的准备状态允许更新地图计划；首次建立时可使用比赛资料中的已完成结果；明确只有人员差异且完整当前双方账号、阵营与计划地图均已证明时，可记录观察到的单图结束并接续相邻计划图，但保持正式比分、胜者为空且不增加系列胜场，由结果待核对诊断说明；运行后普通资料刷新不能覆盖本地已冻结赛果。来自网站绑定或其有效缓存、具有完整比分和完成时间的同图结果属于明确上游完成证据：比赛、参赛方、赛制及冻结计划兼容、前序图已完成且本地比分未知时，可补入该结果以恢复相邻图接续；保留实际执行与原回合历史，不补造遥测结束事件，不改名单或回写网站。网站结果与本地比分、已知回合胜者数量或未进行状态冲突时保留本地事实并显示核对网站赛果提示。后续推进来自运行时转换、系列赛归约器与明确人工证据。实际地图与计划不符时保留局内数据，系列绑定进入 `needs_operator`，等待确认。

比赛、参赛方、赛制和有序地图计划兼容时，普通资料刷新更新系列展示中的队名与队标，并由既有检查点保存；不替换地图执行绑定、回合历史或已捕获选手摘要；未知比分仅按上述明确完成证据补入。地图比分与完成时间不属于计划变化；实际 BP、选边、地图或参赛方变化仍走原确认门禁。身份或计划冲突时保留原展示身份与系列事实，不能把新参赛方资料套在已运行系列上。

运行时将地图执行归属于当前比赛；切换比赛或暂时移除资料不转让已有执行，旧执行的重复观测不能用于新比赛的系列结果或远端输出。干净会话中未归属的执行可由当前比赛接管；跨场冲突后，即使出现新的地图执行边界，其归属仍为未知，只有已有的显式绑图等明确证据可以建立关联。同场资料刷新保留归属。系列检查点保存会话、来源代际、地图执行和地图名的归属证明；重启时只有该证明与恢复的连续性和新观测一致才恢复归属。缺少证明的旧本地系列事实保留为未验证历史，不直接恢复成有效比分；本地 HUD 仍可显示观测。GSI 不包含比赛 ID，地图变化能证明新执行，不能证明迟到的数据属于哪场比赛。

工作台与现有“确认当前图”入口显示只读执行归属状态：已关联、旧场执行未退役、恢复证明不足或新执行待确认。只有确有新执行且地图、身份与目标位置满足原门禁时，才提供既有绑图操作；提示不改变开播资格，也不暴露来源标识或凭据。

未选择比赛、未填写 GoTV、OBS 未连接都不阻止呈现工作台。既有 Host 准备 Task 并行推进 OBS 与游戏准备；游戏只等待安装、GSI 和进程身份等真实前置，捕获确认等待两路各自可用。失败只暂停所属步骤，重试复用已成功步骤和受管游戏；页面卸载不取消已由 Host 接管的任务。进程所有权、配置恢复、制作控制和执行归属安全门禁保持不变。

切换比赛前，旧检查点中无法验证的事实按原比赛和内容身份隔离保存；已有文件内容不符时停止覆盖并报告持久化失败，不把旧事实套给新比赛。

受管 CS2 的每次新启动在已有配置事务中使用独立 GSI 来源标识；Host 验证游戏进程身份后确认关联，退出时先验证游戏停止并确认来源退役。Companion 在认证之后、分配接收序号之前识别标识，丢弃已退役或未知的带标识输入，防止迟到帧进入新来源。恢复同一受管来源需 Host 再次验证进程和配置，以恢复新鲜输入；历史系列归属另需归属证明与连续性一致。外部或无法确认的来源维持未知结果归属，不妨碍本机 HUD 显示。

回合结束转换是回合历史的首要来源；`map_round_wins` 仅恢复缺失、补充未知胜因或校验，不覆盖已冻结获胜方。冲突保留原事实、标记 `partial` 并报告诊断。

同一地图结束观测中的可证明绝对回合历史在地图结果冻结前完成归约，涵盖没有独立回合结束转换的最后一回合；这不允许后续输入改写已完成地图。

恢复检查点使用 v2，有大小上限，按比赛、参赛方、赛制和冻结 sourcePlan（包括图池）核对兼容性，仅在业务边界原子写盘。空计划、空观测是合法初始状态；后续追加观测不会改变计划指纹，刷新和重启保留这些记录。旧检查点不迁移，按既有不兼容诊断处理。兼容检查点加载后同样核对网站明确完成证据，避免旧的未知结果遮住新赛果；本地冻结结果优先，冲突显式保留。恢复后还要与当前回合、比分和回合历史核对，结构与执行兼容性分别核对。关闭服务先停止生产者，再等待已提交检查点写完。

## 连续性与事件

| 标识或类型                      | 表达                             |
| ------------------------------- | -------------------------------- |
| `liveSessionId`                 | 比赛与生产会话的绑定             |
| `producerInstanceId`            | 一次本地服务运行                 |
| `mapEpoch`                      | 地图的一次实际执行               |
| `sourceGeneration` / 数据源序号 | 单个数据源的连接与读取连续性     |
| 高频快照                        | 当前状态，可被更新覆盖           |
| `RuntimeTransition`             | 已观测到的状态边界               |
| `OperatorCommand`               | 有明确结果的人工操作             |
| `ReliableObservation`           | 转换发生时的上下文派生的可靠观测 |
| `Incident`                      | 运行问题与诊断                   |

这些概念不能合并成全局序号或万能事件。数据源重连只使依赖它的证明失效；可选事件源或 Lookahead 重连不自行推进正式节目的地图执行编号。投递、去重和背压由[协议](protocol.md#本地实时通道)维护。

Core 在地图执行中保留一个“曾观测正式阶段”的连续性证明，不把它作为当前阶段。只有同图重新出现完整的热身、回合零、双方零分且没有冲突的非空历史时，才推进执行编号，并通过既有转换清除未完成地图的历史、单图统计和目标计时。CS2 热身可以省略历史字段，零回合与零比分的完整热身仍提供执行重开的证据；地图关键字段缺失、降级、普通回合回退和重连本身不证明重开。已冻结完成地图不因该转换被撤销。决定见 [ADR-0037](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0037-witnessed-same-map-restart.md) 与其条件修订 [ADR-0038](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0038-warmup-without-round-history.md)。

## 正式节目与观察辅助隔离

新鲜正式输入允许手动选择 Gameplay，包括未绑定赛事的 demo；这只接管画面，不建立赛事归属或官方身份。Core 的 Gameplay 展示投影在地图未绑定或身份不符时使用中立身份，制作控制保留后台选择与系列事实。手动摘要展示不确认赛果，自动编排仍受严格绑定与阶段门槛约束，见 [ADR-0032](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0032-manual-summary-and-demo-presentation.md)。

正式节目消费观战客户端的 GSI；精确事件是可选增强。Lookahead 使用独立的较早时间轴，只能形成私有辅助信息。

桌面包携带固定版本的观察器 external-node 组件，解析器复用同包 Companion 的 Node。构建时核对发行 ZIP、组件清单及文件摘要；版本、来源提交和入口由[组件配置](../../apps/companion/src/telemetry/observer-component.json)维护。源码与许可随组件保存。

打开工作台保留按当前偏好受管启动 CS2 的一键流程，不要求 GoTV 地址，不自动重连历史地址。每张图由用户在工作台显式确认该图地址与密码后，才提交节目连接和独立早源意图；输入草稿、保存偏好和窗口呈现不提交连接。MulNX 自动控制资格来自当前受管实例的进程身份及网关归属，不能只由启动偏好推断；HUD 原值在真实控制操作前保存，退出仍通过既有事务恢复。换图的新地址更新两路，停止旧早源并清空旧提示与时间对齐；工作台、OBS 与游戏继续运行。同地址早源重试复用配置修订、租约和已接受的节目命令，不能将旧地址重试视为换图完成。

Companion 启动观察器前在已验证的 state 下逐级创建并核对 `data/observer` 父目录，拒绝非目录、符号链接和不可写路径；独立 UUID 末级目录仍由组件 driver 非递归创建；每次重试使用同一已验证父目录下的新末级，不依赖前次建目录成功。每次尝试保留编号、次数、终止阶段、退出码／信号、进程启动原生码、就绪与超时／取消、stdout 协议结果及报告分类；只接收允许列表原因与原生码，不保存子进程原始 stderr、密码或任意路径。在有界 stderr 缓冲中从后向前选择最后一份通过固定 schema 校验的终止报告，尾随文本不覆盖报告；找不到报告时再对明确的 pre-report token 单独归因，组件未暴露的细分阶段保持未知。诊断订阅者异常分别隔离，不阻断子进程清理或重连。既有会话日志记录各次尝试，私有状态另保留最多八次有观察器会话关联的摘要；再次启动清空当前故障，历史保持独立。所属进程主动停止使用取消原因，stdout 随后的同次关闭不覆盖为运行失败；未请求停止的断连仍保留失败。支持包直接包含结构化观察器状态及保留期内日志，日志轮转与缺口沿用既有契约。

工作台通过 Host 确认当前由 Mizar 启动的 CS2 实例，再提交私有观察器连接意图。Host 依据该实例的安装位置选择 Steam API 和当前 host 版本，Companion 串行管理启动、停止与来源切换；每次新连接推进来源代际，已有私有消费者沿用同一订阅入口。连接信息通过 stdin 交给组件，输出目录位于用户运行数据目录。

观察器使用独立的 Windows Job，句柄由当前 Desktop 持有。Host 启动观察辅助时先提取已验证的游戏句柄与会话身份，长请求不占用游戏状态锁；游戏启动、替换、恢复、关闭与观察器启动和停止由同一后台操作锁按顺序执行，先取该锁再取游戏状态锁；退出等待已提交的有限操作收尾，再正常关闭游戏。观察器提交前复核游戏身份和退出代次，运镜续约不取该操作锁。启动中继先加入该 Job，再建立本次尝试的嵌套 Job 并启动 Python，解析器继承进程归属。正常停止使用 stdin EOF 等待组件收尾；中继或 Desktop 异常退出由 Windows 回收对应子树。Host 的独立续租线程每两秒核对持有的游戏句柄、会话与退出代次，不等待启动操作锁或游戏状态锁；隐藏面板仅改变呈现，不结束租约。新租约在配置启动成功且当前接收修订复核后签发，准备等待不计入续租期限；Companion 在六秒租约过期后停止观察器。私有租约绑定本次连接意图，同一有效意图在最后成功续租后三十秒内可恢复接收一次，等待旧进程收尾并重新确认无清理失败，不重发游戏连接或 HUD 命令；主动暂停、关闭提示、切换连接、结束制作与身份失效立即撤销恢复资格。正常停止、身份失效和续租超时分别记录有限原因，旧租约不能续约或停止新连接。结束工作台先完成观察器停止，再继续游戏收尾。Companion 的既有异常恢复策略继续负责其余制播状态。

- Lookahead 不能作为正式节目备用源；任一链路故障不改变另一链路的角色。
- 未来字段不能先进入公开数据，再依靠 CSS、窗口或 OBS 裁剪隐藏。
- 安全边界由投影、类型和协议结构保证，窗口捕获策略是额外防线。
- 制作工作区、控制栏和本机 HUD 覆盖允许远程捕获；正式 OBS 输出使用独立的游戏捕获与播出 Browser Source，不依赖制作窗口的捕获排除。策略理由见 [ADR-0022](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0022-remote-workspace-capture.md)。
- 本机 HUD 仅在受管游戏或现场工作区、控制栏位于前台时显示；准备中心、核对弹窗等其他窗口位于前台时隐藏，避免遮挡操作。工作台恢复入口只销毁并重建本机 HUD 窗口，等文档和策略就绪后按现有显示条件呈现；退出、隐藏和旧文档回调不能使它重新显示。窗口与 WebView2 的有界诊断只记录 HUD 和游戏的关系，不记录其他应用窗口标题；文档就绪不证明画面已被肉眼看到。
- 同一地图执行的普通重连、暂停与恢复保留已有早源事件和延迟估计；不同比赛或地图执行仍隔离。
- 私有提示在可靠校准前等待，不使用固定延迟估计。提前源 cursor 的回合时钟与节目 GSI 原始倒计时按地图、原始回合计数和连续 live 段匹配；短间隔正常推进时插值到相同剩余时间，用进程内单调接收时刻差形成样本。至少三个样本跨五秒且偏差稳定才更新中位估计，同时到达的成批记录和明显速率跳变不能当作独立推进；契约没有批次标识，按实时速率释放的上游积压无法排除。冻结结束事件单独接纳，以接收时刻作为辅助边界；未经验证的事件 tick 不是精确时间。炸弹、拆弹、暂停、断点与未知状态不跨段插值；暂停累计 tick 的含义未验证，暂停或累计值未知时不测量；累计值非零时，下一回合仅在规则开始时间与冻结结束提交 tick 接近且累计值稳定时采样，不推测暂停补偿。已知提前源新比赛或正式期后明确归零热身时隔离时钟，等待节目地图执行切换；两路 world 并非共同执行 ID，缺少边界证据时不能排除同名同回合重启歧义。死亡变化只撤下唯一可归属的已发生提示和提供诊断，不再参与校准。短间隔内量化后相同的倒计时不推进有效采样点；倒退、长间隔、暂停和回合切换仍中断该段证据。执行计数只在同一来源代际内比较；已确认早源进入新执行时保持隔离，直到节目确认执行边界，再清除旧事件与估计并重新校准。短时缺证保持估计，断流或停滞引起连续性丢失后暂停提示直到新证据恢复；比赛或同图新执行边界清空；提前源先换图时，等待节目切换并保留有界的新图事件；临时不新鲜保留缓冲。已显示提示固定截止时刻，未显示事件允许按新估计调整。事件按其接收时刻调度；源内部或进程管道积压可能使事件接收时刻与 cursor 接收时刻的偏差不同，时钟估计不保证精确事件时刻。

接入能力见[数据源矩阵](../guide/data-source-capabilities.md)，尚未交付的研究见 [RFC](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/rfcs/0001-lookahead-observer.md)。

C4 资源的解压、解析、预测索引与计算由 Companion 的单个 Worker 承担，最多保留两张地图和十个在途预测。Core 继续校验当前数据资格；结果按地图、数据源代际、地图执行和完整预测输入匹配，只触发当前状态重新投影。同一投影的十人预测合并为一次 Worker 消息，整批写入精确输入缓存后通知刷新。普通实战帧的等待发布最多合并十六毫秒，既有完整快照保留原游标；未变化的不可用项（例如已阵亡选手）不阻止其余选手的等待合并，新出现的不可用原因立即发布。完成时重投影最新状态，超时公开等待，不把旧估算拼接到新帧。新鲜度、代际、地图、身份、回合或比分边界立即发布。见 [ADR-0029](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0029-c4-worker-isolation.md)与 [ADR-0035](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0035-bounded-c4-publish-coalescing.md)。

## 雷达与展示配置

雷达领域完成世界坐标到地图坐标的转换；共享展示包负责插值、平滑、跳变重置和自动聚焦动画。外部网站消费已经校准的公共坐标，不复制地图校准。[包说明](../../packages/radar-view/README.md)维护集成方法。

共享雷达展示缓存底图滤镜、烟雾纹理、火焰模糊及 C4 着色，缓存按表面大小、样式和地图边界失效，有界保留，不改变地图校准与插值。火焰模糊按亚像素栅格精度复用近似纹理，避免自动缩放的连续浮点值让每帧重建缓存；精度由[缓存实现](../../packages/radar-view/src/render-cache.ts)维护。烟雾生命周期容忍一 tick 的寿命回跳，明显回退或位置断裂仍重建；同生命周期已知阵营不因死亡后的 owner 变化而丢失。

HUD 配置独立于比赛数据：组件内容、布局、外观和比赛投影分别拥有自己的职责。描述符维护组件方案、设置和尺寸，编辑器与播出使用同一解析结果和渲染器。Companion 持久化配置，浏览器缓存不是权威来源。保存、启用、版本校验与文件交换规则见[协议](protocol.md#hud-配置)。

设计变量 → 基础组件 → 组合组件 → 功能页面的规则由[设计系统](../design/README.md)维护。

## 制作生命周期与节目编排

Host 的准备与退出流程调用专属游戏、GSI、Demo、OBS 和窗口能力，IPC 只校验调用边界并转发。共享宿主状态、进入意图和准备票据有明确模块归属，业务模块不反向调用 main 的命令函数。main 保留运行时组合、窗口事件与传输注册；Tauri 的 AppHandle 只在宿主适配层访问共享状态，不进入比赛领域。

显式启动先按准备任务身份建立制作会话，再展示工作台面板；游戏与 OBS 随后按各自依赖准备。单纯重新显示面板不切换制作状态、OBS 场景或未归属游戏布局。Host 持有唯一准备任务及资源归属，窗口可重建；失败以可关闭提示呈现，重试使用同一事务补做未完成步骤，不重复启动已确认的游戏。准备期间隐藏面板不改变制作修订；后台游戏就绪只升级同一呈现代次的已显示面板，不重新显示已隐藏的工作区或关闭用户后来打开的设置页。进入请求结果未知时，以准备任务身份查询 Companion 已提交的进入结果；未确认前保留 OBS 视频事务，取消得到服务端确认后才恢复。辅助检查不阻止面板；主动开播仅等待 OBS 当前配置写入及临时采集租约安全收尾，操作失败仍返回具体原因。退出代次绑定启动意图，取消或退出使迟到的原生准备与展示失效；仅展示面板时退出不强制切换 OBS 场景。新制作会话默认启用自动编排；操作员手动切场后保持手动，直到明确恢复自动。隐藏后重新显示工作台保留原有的手动或自动状态。

Companion 拥有 `preparation / live / hidden` 制作生命周期；它们不等同于比赛或 OBS 状态。 制作对象统一持有会话、资源与更新互斥、试播和退出任务，并按顺序调用节目场景、OBS、运镜、观察设置、Demo 与来源交接；HTTP 路由只处理传输校验和调用，OBS 退出结果由独立存储持久化。工作台结束与应用关闭共用本地来源交接及精确进程清理；可靠事件与远端释放由原来源后台继续，OBS 等待画面及视频恢复分别报告确认状态，不阻塞已完成交接的本地退出，也不停止 OBS 输出。重复结束复用同一 OBS 收尾任务，失败后的明确重试继续原目标；断线或外部操作撤销旧控制资格，新的明确重试重新核对实际场景。未确认状态跨重启保留供核对。Host 核对受管 CS2 已停止后，将本地比赛、制作会话和观测游标绑定的证据交给 Companion；显示修订及 OBS 等待画面不决定游戏停机事实。恢复失败保留原事务和重试入口。

在线绑定且已配对的比赛进入现场后，由 Companion 后台维护在当前遥测、上下文、身份与完整十人名单就绪时自动首次认领网站来源，不依赖工作台页面轮询。自动认领复用原来源命令队列和资格检查，不接管其他设备，不恢复本进程主动停止或已有来源；同场旧来源仍待核对、交接或请求结果未知时保留原责任，由既有清理对账或人工恢复处理。其他比赛的可靠收尾独立继续。

RivalHub 来源认领先持久保存意图，再保存网站确认的完整来源身份后启用发送。切场和退出将原身份移交待释放状态；重启只恢复清理，不恢复旧进程发送资格。释放前停止该范围的新可靠事件并等待既有队列的接收或终态，未确认时保留待重试记录。本地队列写盘不代表远端确认。来源控制记录不保存凭据；清理请求仅使用当前受保护连接的地址和安装凭据，重新配对须先完成旧来源清理。

来源状态文件 `rivalhub-source-state.json` 或播出配置 `broadcast-config.json` 无法读取、解析或恢复时，Companion 保留原文件并启动其他领域；对应来源操作或播出配置应用返回不可用。来源清理数量未知时不报告为空；本地退出继续执行，来源交接仍显示未确认，不当作远端释放成功。检查诊断后停止 Companion，保全故障文件及其 `.revoked` 证据目录，再修复权限或以已核实且包含未完成来源记录的备份恢复文件，重启后由原领域重新加载和清理；不要用空文件替代未知的来源证据。播出配置同样可在保全原件后修复权限或恢复已核实的备份，再重启加载。

可靠事件交付由 Companion 的 `ReliableOutbox` 拥有发送顺序与回执语义，`OutboxRepository` 独占本地 SQLite 存储。活动队列、确认归档和撤权证据在同一事务提交，历史按来源或交付范围索引读取，不再由多个 JSON 文件和镜像相互协调。网络回执等待不占用持久提交队列，发送前仍核对资格，回执按当前状态提交。首次打开只读导入旧队列及归档，导入标记与数据原子提交；原文件保留但不继续双写。旧队列无法确认导致导入失败时保留原文件，输出服务不可用并停止本次可靠交付；可识别范围的旧归档损坏保留范围阻断。SQLite 使用 WAL 与完整同步；停止生产者和发送后先确认本地持久化，远端来源收尾结束后再关闭数据库。已落盘不代表网站已确认，撤权隔离不视为送达。

可靠输出边界保存失败时，原边界请求、执行游标、精确来源和检查点由同一 SQLite 存储保留，确认回执与实际边界变更在同一事务提交。恢复只幂等重试原请求，并核对事务回执，不清库、生成新来源或用后续帧补造旧事实；仅在原边界得到证明后解除对应故障隔离。隔离期间真实产生的结束事实沿既有待写队列保留原身份和顺序，后续边界不能抢先发送；其他领域继续运行。待写内容有数量和字节上限，无法保留时明确报告缺口，不宣布恢复。已落盘请求可在重启后继续核对，尚未落盘即丢失进程的内容不能还原。恢复本机记录不等于网站恢复接收，当前来源、可靠开始确认及新实时回执仍分别核验；本机重试入口见[协议](protocol.md#本机网站同步健康)。

ProgramRuntime 在 reducer 前后给出只读 executionBoundary，区分明确无执行、已归属执行和历史未知，附原始游标。OutputService 不从当前 binding 或 authority 推测旧执行；明确准备期的代际变化不生成比赛 gap，真实旧执行证据缺失与未知历史保持保护。新 gap 保存规则版本、原因和已知执行范围，旧 gap 不全局清除，可靠依赖和高水位语义保持不变。返回现有工作台只恢复窗口，不隐式 cleanup、claim 或 resume；主动停止后的恢复网站同步是独立显式命令，在原 sourceCommands 串行区核对 scope/revision、旧尾部与所有权，默认不接管其他设备。claim 成功不是同步成功，当前执行可靠开始 ACK 与预期 LIVE accepted 分别确认。来源动作和本机同步说明共同读取 OutputService 的当前投影资格，区分无绑定、过期、身份不匹配、缺少首发与投影失败，不把空快照统一解释为名单未齐。所有显式来源动作核对比赛与上下文修订；异步认领返回后再次核对，已被网站接受但目标失效的认领保留原身份清理责任，不启用旧来源。

显式进入制作授予本次浏览器源恢复资格，与场景及音频准备资格分开。仅刷新当前「Mizar 制播」集合中名称、类型、身份及本机节目 URL 匹配的已有浏览器源；每个来源在本进程目标版本内最多成功刷新一次。外部切场、切换集合、断线或退出撤销资格，不自动重新授予；暂时连接失败在资格有效时重试。刷新不创建来源、修改配置、切场或停止输出。

工作台显式启动的视频准备先只读核对 OBS 当前配置档、视频设置及全部视频输出；仅在需要调整时要求输出空闲。回放缓冲状态查询明确返回输出不存在时，按无活动回放输出处理；其他查询失败仍保留未知状态，不能据此取得准备资格。使用当前配置档设置 1920×1080 画布及输出和 60fps，不修改编码器、推流配置或音频偏好。写入前持久保存端点、配置档和受影响的视频参数对，回读确认；不确定结果先核对，不盲目重放。已确认事务的端点、配置档与当前参数仍完全匹配目标时，可重新绑定本次意图并保留原备份，无需在输出期间恢复后重写；旧意图的取消不能撤销新事务。取消、失败与结束制作时恢复仍保持受管值的参数对，保留用户修改；配置档或端点不匹配、输出活跃或连接失败时不覆盖，保留记录供重试。服务重启时尝试恢复未完成记录。OBS 不提供视频设置的比较交换，外部并发修改与写入之间仍有竞争窗口；任何路径都不自动停止输出。

显式启动的准备阶段遇到旧受管游戏采集来源缺少附带音频键时，核对来源身份和默认设置后只写入该键为关闭并回读；已开启或无法确认时保留现状并提示处理，不更改其他音频偏好。游戏启动后、捕获预热前重新枚举可用 CS2 窗口；只有唯一实际候选才能纠正受管来源的旧窗口目标，默认字符串不作为窗口存在的证据。无候选时有界等待，多候选时提示关闭多余窗口，不自动猜测；写入仍需输出空闲、来源身份和原目标未变化，并回读确认。显式启动在确认无活动视频输出、等待场景和游戏来源身份及来源附带音频关闭后，可临时在等待场景添加同一游戏来源。项目先禁用创建、设为零面积并回读，再启用以初始化捕获；不改变正式场景布局或全局音频。租约在目标修复后取得，绑定制作修订、OBS 连接、节目与输出代际及项目身份，输出开始、外部接管、取消或退出撤销资格。确认唯一游戏窗口与保存目标严格一致和实际捕获尺寸后，按身份及零变换核对清理，完成该准备阶段；未知结果或用户改动保留记录，下一次显式准备时安全核对，不停止输出或按名称批量删除。配置准备先恢复遗留的画面预热事务，再迁移集合和整理来源；待清理事务同时进入配置就绪判定。清理已有项目只核对原端点、集合、场景、来源、项目和预期变换，不要求其场景仍为当前节目；旧版未记录集合名时，仅在两个 Mizar 集合中按原场景与来源 UUID 查找，输出空闲且准备意图仍有效才临时切换，清理后返回原集合，不按旧名称猜测新来源；原候选集合、场景或来源已不存在，且完整查询确认没有原 UUID 副作用时，将原记录原样归档，不再阻碍当前准备；检查中切场后可使用新的空闲输出租约完成清理，不切回用户场景。工作台的「重新检查游戏画面」沿同一所有者和串行队列恢复已有检查，再读取当前配置与捕获证据；请求绑定当前制作修订，不重启游戏、不重建临时项目，也不将清理完成解释为实际画面正常。等待游戏主菜单不依赖比赛 GSI。OBS 输出命令与配置写入共用既有串行队列，临时捕获租约从建立到核对清理期间阻止新输出；收到开播请求不会提前释放必要检查。已开始输出时，后续准备只读核对，不能创建临时来源、修改视频或把未确认画面报为就绪。外部开播导致无法安全清理时保留责任，不自动停播；历史准备结果与当前待清理状态分别呈现。

进入时自动更新检查异步发起，结果通过既有通知呈现，不等待网络或通知选择；取消准备由 Host 确认并执行安全恢复。

标准 Steam 与 MulNX 均在启动前准备同一受管配置事务。用户显式启动工作台时，Host 先确认安装与唯一游戏身份，恢复原受管配置后正常关闭已有游戏，再按既有启动偏好受管启动；相同准备事务重试复用其已启动实例。标准启动和 MulNX 受管启动均为本次启动加入 `-allow_third_party_software`；MulNX 临时启动项复用原行备份，恢复时不覆盖用户新修改。MulNX 提交启动前持久记录待确认状态，核对唯一新游戏进程、所选程序路径和游戏网关所属 PID 后才绑定该事务；待确认期间后台恢复不能自行认领游戏。已提交请求中，仍存活进程的程序路径暂不可读时，只在原确认期限内继续只读核验；身份未知不视为没有游戏，不绑定受管事务、不提交第二次启动。启动器首次窗口使用隐藏启动参数。退出受管 MulNX 先持有本次注入的卸载事件并提交一次停止，再等待信号并核对同一游戏进程中的模块已消失；入队或断线不是完成证明。确认结果持久绑定进程身份，游戏正常关闭失败后重试先复核模块仍不存在，再继续关闭与恢复，不重复提交停止。事件或模块检查失败保留游戏与事务。历史外部 Demo 标记仅用于资料恢复，不创建借用或游戏关闭权。

MulNX 启动超时后，状态的 `mulnxLaunchResumable` 表示同一 Host 仍持有本次已提交请求的启动器句柄；`launch_mulnx` 的 `resumeOnly` 只核对该请求，记录不存在或未提交时返回 `result: not-found`，不会启动新游戏。调用时仍须重新验证实例。满足条件时可重试原进入意图，只核对已提交请求对应的启动器和唯一游戏实例、网关与受管事务，清理启动参数后接续，不再次发送启动请求。卸载已提交但信号或落盘未确认时，重试只核对同一存活实例中的模块是否消失，确认后继续收尾，不再次发送停止命令。受管游戏收尾中，Host 保留本次停止操作的只读进程句柄，以便确认迟到的卸载；不会再次发送停止命令。Host 重启后不凭旧启动器 PID 认领游戏。新启动先完成配置事务准备，再在既有取消门禁内登记启动器 pending，随后才配置并提交启动器；登记失败或此前取消沿原未提交恢复链收尾，旧未知 pending 不可被当作本次请求覆盖。

MulNX 启动记录尚未清理时，受管事务对外显示启动结果待确认；恢复入口要求用户确认已取消启动并关闭游戏与启动器，Host 再核查进程与目标后恢复，不以普通恢复请求的返回值代替完成证明。

Host 持有已验证进程身份的句柄发送正常关闭请求，分别保留窗口枚举失败、关闭消息拒绝、无可关闭窗口、等待超时与等待失败的原因。消息发送成功不证明游戏已退出，权限拒绝也不能放宽身份或配置恢复检查；本机诊断记录阶段、API、错误码与受管 PID／创建时间，并随既有退出事件进入诊断包。失败时由使用者在游戏内正常退出后重试，不自动强杀或关闭不归属进程。

本地 Demo 试播在同一制作生命周期内使用临时比赛资料及独立运行会话，不新增运行时或 Demo 管理库。Host 持有原生文件选择能力和播放请求；Companion 在启动前持久记录试播隔离，暂停正式检查点读写、资料修改、采集及在线输出，真实 GSI 仍经过原生产解析与投影。服务重启发现未完成记录时先隔离输入，不自动恢复正式绑定。试播保持手动编排；进程运行、收到有效观战数据和加载选定 Demo 是不同事实。

结束试播先隔离在途 GSI 并确认 OBS 等待画面，Host 只按既有进程身份关闭受管游戏并恢复配置，成功后才确认完成隔离事务；失败保留恢复记录供重试。完成后恢复正式资料、清空试播遥测、统计、计时和提示，推进会话与数据源代际；在明确重新进入正式制作前继续拒绝 GSI，避免迟到的 Demo 输入污染正式检查点。用户显式启用的 HUD 配置保留。

Demo 播放 CFG 先写入同目录临时文件，完整同步并读回后再无覆盖发布，写入失败不留下可被启动参数引用的半成品。核心配置、观战原值、启动请求和 Demo 资料隔离完成恢复后，独立清理记录中的旧会话 CFG 不再阻止普通 Steam、MulNX 启动或备份操作；新启动仍使用完整的受管配置流程。字节不符、文件不可读或无法删除时保留原文件、清理记录和原因，明确重试清理仍按原规则验证，不覆盖未知文件，也不把尚未结束的游戏或启动请求视为清理残留。

CS2 的自动发现、手动安装选择和 GSI 配置目录统一由 Host 管理。按 Steam AppID 730 清单定位，验证程序与新版 cfg，按安装根目录去重；保存的手动位置同时供 GSI 与启动使用。显式 GSI 修复仅重建当前安装记录绑定的 Mizar 文件，先保留修复前文件与记录，沿用原令牌与首次恢复备份，原子替换配置并更新指纹；自动准备不覆盖人工修改，身份或备份不完整时保留现场并报错。修复归档独立于安装恢复目录，恢复不删除修复前文件。文件冲突、重复发送与读取失败分别展示，支持包只导出有限问题码、数量和阶段；见 [ADR-0047](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0047-shared-cs2-installation-discovery.md)。

Host 先建立工作台会话并展示面板，游戏与 OBS 准备按各自依赖并行；能安全登记的 GoTV 输入立即受理，依赖游戏的副作用沿同一意图等待确认。启动发现要求唯一 Steam 进程、可读取且存在的程序位置，以及有效的当前账号整数；Host 通过持有的原生进程句柄读取映像路径与创建时间，不依赖 PowerShell 的模块路径，安装目录候选不能替代运行进程身份。发现期间及提交 Steam 启动请求前复核唯一进程的 PID、创建时间、程序路径和当前账号，变化或读取失败时拒绝提交；缺失、格式异常或越界账号明确报告账号不可用，不猜测 userdata 目录。注册表的有符号 DWORD 仍按原 32 位账号恢复，底层读取异常保留在本机诊断。 配置接管前先在本机保存视频与机器帧率文件的原始字节；机器帧率文件确实不存在时记录缺失而不构造文件，正常接管仍拒绝、保留模式可继续，存在但不可读仍报错；`fps_max` 原值可为有限非负小数，恢复保留原始文本。视频与帧率同值重复字段保留全部位置，应用与字段级恢复覆盖全部位置；帧率恢复只在逻辑当前值仍为本次 original/applied 时写回，人工值让出，文件字节未变化时精确恢复原件；冲突重复保留原件并要求明确选择，嵌套与格式错误单独报告，不自动取第一或最后值。视频与帧率的无副作用计划先于观战 CFG 部署和恢复记录写入；准备失败只清理本次尚未提交且归属明确的观战记录，已写入的核心事务继续保留恢复职责。准备中心可明确选择「保留画质与帧率」，不以先发生一次接管失败为资格：状态只依据当前未完成事务和进程提供请求入口，任何已有观战恢复记录必须先完成恢复，启动时重新核验账号、程序、配置和进程，再完成原件备份；不保存“曾经失败”的继续授权，重启也无需重演失败。该方式仍由 Host 跟踪 Steam 请求及进程身份，只保留画质与帧率；窗口几何复用原视频事务，先保存完整原件和应用内容，再按明确目标更新全部受管重复位置，非几何字段原样保留；Steam 与 MulNX 共用此磁盘准备，提交前复查应用字节，Steam 同时使用一致的窗口参数而不添加帧率参数；标准启动只读复核当前账号保存的 Steam 启动选项，合法引号交由 Windows 原生解析，空选项及与目标一致的几何参数允许；发现已有全屏或不同尺寸覆盖时明确拒绝，不改动 Steam 设置或猜测重复参数优先级。MulNX 将 journal 的严格有限尺寸经既有私有准备请求交给原启动参数 owner，替换全部可明确识别的模式/尺寸参数并保留其他参数原文，结束时仍按原完整 launchOptions 记录恢复，未知回执或人工改动不强行清理；本机 HUD 仍依据已验证窗口身份与合法实际客户区跟随，不以目标布局对齐为显示门槛，结束后对仍为本次应用值的几何字段恢复原值、重复数量和原始表示，完整应用字节未变时精确还原原件；人工新值或删除让出；重复键中任一值偏离应用目标时整个逻辑字段让出，并明确报告保留了新值。恢复保留当前注释与换行，非受管字段及备份保留。旧版已存在的无几何启动事务仍按其原恢复职责结束，不据此重放启动。备份失败、未完成事务及进程归属不明仍阻止危险操作。结束制作成功后正常关闭该游戏并恢复临时视频与帧率配置；隐藏现场不关闭。配置文件与进程身份、备份及重启恢复只由 Host 管理，网页发送固定意图。观战、视频和试播清理分别按本职责的未完成事实确认结果；可请求使用当前设置启动不代表恢复未完成。画质与帧率使用独立的有限选项，新安装默认中画质（含 FSR）与 60 帧／秒，已有保存偏好不迁移覆盖；运行中可保存下次启动偏好，本次原值、应用值和恢复所有权保持冻结；启动脚本中直接设置的帧率纳入同一恢复事务，避免覆盖本次上限。细节见 [ADR-0026](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0026-managed-cs2-launch-and-restoration.md)及其局部替代 [ADR-0045](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0045-managed-game-quality-and-frame-budget.md)。

现场 `fps_max` 是独立的有限运行期事务，不修改本次启动配置备份或下次偏好。仅在同一已核验受管 MulNX 实例、有效现有控制 lease 和已启用控制台记录下允许新应用；UI 先读取当前值，再提供 30/60 帧。写前持久原值、目标值、实例身份和唯一 attempt，固定命令与 marker 读回一致才确认。未知写入只检查原回执，不自动重发；恢复前再次读回，当前仍等于本次 applied 才恢复原值，人工变更则让出控制。正常结束在撤销 lease 前尝试恢复，服务已停止或进程已结束不再发送命令；恢复记录照实保留或标记 ended。FPS 复用 console 层有界 marker 回执读取及日期前缀、UTF-8/16 解码，不在 HUD 中重复解析。控制台不提供 CAS，读写间人工并发不能伪称原子；这条有限路径不验证完整画质预设，也不自动开启采集、改变启动方式或结束制作。

现场核对使用独立 `tool-review` WebView 和轻量只读投影，不挂载完整工作台组件，也不保存正常成功的 acknowledged、fingerprint 或完成状态。持续名单问题保留按比赛的展示偏好，网站同步使用固定入口而非自动弹窗；故障是否清除仍由原 owner 决定。只读核对之间切换不建立业务任务锁，进入准备中心处理成功后关闭原核对窗口；草稿保护仍由各编辑领域负责。GoTV 单独使用稳定 `tool-connection` 和 `/workspace/connection`，本图与下一图复用同窗，重复打开聚焦且保留草稿；普通换图不自动抢焦点。登记当前连接仅启动提示接收，不发送游戏 connect。提交仍核对制作、目标和配置 revision；标准路径就地提供复制并前往游戏，Host 只在调用窗口仍在前台且游戏身份匹配时尝试焦点切换。复制或入队不证明实际连接。游戏连接发送前以进程身份与意图标记去重；重启或网关结果未知不自动重发，持久标记不可写时保留本机制作并提示人工处理。

现场工作台由独立 CS2 与两块桌面面板组成。每个受管 CS2 进程首次进入现场时，仅在准备中心仍为前台的情况下尝试一次聚焦游戏；首入在后台最多等待渲染窗口三十秒，期间前台切走或游戏退出即取消；窗口就绪后只尝试一次聚焦，超时或失败不后台重试。底栏的「返回游戏」是新的显式聚焦意图，Host 校验调用面板仍为前台、工作台可用以及受管进程身份后才尝试；执行时已切换面板或应用、隐藏或退出会使请求失效。普通面板操作、节目「比赛中／BP」切换和「恢复布局」不申请游戏焦点，重新显示面板也不主动选择输入目标。Host 在既有有界窗口巡检中检测从其他应用切回成员，只为本次受管理进程恢复最小化的同组窗口并调整普通 Z 序，保留用户选中的输入焦点；联动不重排布局、不修改缩放或置顶状态、不嵌入游戏，也不操作外部启动的游戏。进程身份沿用 ManagedCs2 的 PID、创建时间与程序路径验证，操作期间持有原进程句柄；显式借用的外部实例仅允许用户点击“返回游戏”时验证身份并聚焦，不参加自动首入聚焦、布局或窗口组联动。游戏最小化不释放既有窗口目标。隐藏、退出、成员失效、模态窗口和前台再次切走会取消联动；异步恢复只提交一次，并以单调时钟观察最多两秒，不在后台反复抢焦点；API 失败或超时按本次事务在既有 DesktopLog 中记录一次阶段、API、错误码和受管 PID／创建时间，不记录路径，正常取消不记故障。Alt-Tab 与任务栏仍由 Windows 展示各顶层窗口，置顶或独占全屏游戏不参与自动联动；原生效果与 CS2／OBS 捕获仍须实机验证。

现场窗口采用窗口级全屏 Shell 标记，让任务栏在现场处于活动状态时退到其后，不修改系统自动隐藏设置；隐藏、退出或更换游戏窗口撤销标记。标记成功后按完整显示器边界排布，失败沿用工作区。受管理 CS2 使用无边框窗口，启动参数与临时视频配置都使用既有工作台布局算出的游戏尺寸，保持 75% 上限与 16:9 客户区，左栏贴屏幕底部，与游戏、底栏连续平铺；游戏拒绝无边框时保留原生外框避让。外框缩放成功不代替客户区对齐；游戏拒绝运行中的分辨率变更时不再次缩小无边框外框，布局状态保留未对齐原因。本机 HUD 依据已核验游戏窗口的合法实际客户区跟随，目标分辨率尚未达到不单独阻止显示；窗口身份或客户区无效时仍隐藏。DPI 与窗口变化共用同一 Host 物理布局；现场 WebView 自身的缩放变化也通过既有工作线程合并重排，不依赖游戏窗口同时改变尺寸或 DPI，隐藏期间的变化在恢复现场时处理。决策及异常退出边界见 [ADR-0030](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0030-workspace-fullscreen-shell.md)、[ADR-0031](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0031-borderless-workspace-game.md)与[ADR-0036](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0036-workspace-sized-cs2-launch.md)。

`ProgramDirector` 消费既有投影与 BP，通过唯一 `ProgramSceneController` 请求 OBS 切场。新制作会话成功进入后默认自动；隐藏现场后返回不改变人工接管。外部切场或人工选择后的保持仍须显式恢复自动。节目消费进度属于地图执行，来源重连不重播已消费的单图结果；实际执行或比赛变化时重新开始。赛前仅按新鲜比赛资料与尚未开始的地图计划，允许等待与有效 BP 之间切换；不以此放宽局内、开场或赛果的实时证据门槛。自动切场最多一个在途请求、不离线排队；切换前后检查上下文、来源代际、版本与时限。失败停止自动推进。具体节目顺序与时长来源见[节目规范](../design/program-direction-v1.md)。

OBS 外部切场撤销已排队或在途的旧切场与退出意图，也撤销后台恢复的准备资格；后台恢复在每次实际 OBS 请求前复核代际。完整只读配置检查可在同一连接与配置代际、未暂停或退出且没有阻断项时重新确认准备资格，包括 OBS 已在直播时；检查不创建或修改场景、音源，不刷新网页，也不解除 Director 的人工保持。结构变化、检查失败或迟到扫描不授予资格。显式准备仍负责必要的配置修复。

`MusicDirector` 独立消费同一节目投影、制作生命周期与实际 Take 的 started 边界，不把画面 hold 或 Director 的 blocked 当成音乐控制权。背景音乐互斥，开场音效独立叠加；不建立比赛事实的第二来源。比赛、参赛方、地图顺序及执行编号组成音频实例键，暂停实例跨标签变化保持，来源重连不建立新实例。当前游标、已消费事件、人工停止和随机安装身份以本机原子状态保存，过期请求在每个 OBS 副作用前取消。普通淡化由轮询推进，不延迟紧急停音或画面切换。图间和赛后音乐可在遥测过期后沿用展示层已冻结的同场、同地图与同来源执行的终局比分；当前上下文、绑定、身份及终局阶段仍须明确。比赛进行中或归属未知不以冻结结果放宽停音保护。

OBS 音乐适配通过持久连接核对媒体状态，在已核验的「Mizar 制播」集合中使用「音乐」「音效」两路固定来源。MusicStore 保存播放状态与对应来源 UUID、实例及集合身份；旧集合的来源名、UUID 或受管目录证据不能推断新集合归属。更换集合保留本机音乐库和配置，重新登记新来源。缺少音乐场景、来源冲突、加载和播放失败分别表达，保留脱敏原始 cause，不把所有错误归为 OBS 断线。新建或挂载来源要求全部视频输出明确空闲，普通播放不重复改写已有几何。音乐模块不修改游戏声、麦克风或其他集合；实际声音仍需试听。音乐 ZIP 使用既有安全目录与原子写入，不冒充官方资源签名；见[节目音乐](music.md)。

`BpSession` 只维护播放状态；正式 BP 由比赛投影派生。本地补录不改写在线比赛身份，演示来源只在 BP 内存会话生效。命令与来源切换见[协议](protocol.md#bp-播放与补录)。

`ProgramPresentationStore` 在地图结束时冻结已确认比分并捕获选手摘要，最多保留五图。相同生产实例、会话、来源代际和地图执行的后续新鲜 gameover 观测，只有阵营名单完全一致且比分不变时，才允许已观察到的 K/A/D 收敛；缺失字段不擦除已捕获值，不回写比分或回合历史。换执行、来源、比赛、断流或身份不符后保留已捕获摘要，跨图保留、换比赛清除。静态画面的进入资格与已播连续性分开，不恢复旧游戏时钟；见 [ADR-0039](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0039-terminal-player-summary-settlement.md)。

Companion 的 OBS 模块持有唯一输出控制状态，通过持续的 Outputs 订阅和重连快照观察直播、录像与外部手动操作；快照不能覆盖读取期间的新事件，旧连接回调不能写入新代际。人工开始／停止使用明确请求，不依赖本地切换布尔值。每类输出的在途保护跨窗口生效，并与配置修改和修复互斥；请求回执与实际完成分别判断，超时后核实状态，不自动重放命令。网页只消费本机输出视图和提交有限意图，桌面、Core 与自动节目编排不持有输出控制权。

OBS 以整个「Mizar 制播」专用集合为资源维护边界，不在旧「Mizar」或其他集合中继续修补兼容。首次明确准备仅在目标集合不存在时创建并登记；已有同名但未登记的集合不接管，也不另加后缀创建。归属由本机登记、`OBS_WEBSOCKET_DATA_REALM_GLOBAL` 中的随机实例标记，以及至少一个仍存在的已登记资源 UUID 共同核验；collectionIdentity 是本机登记编号，不是远端集合 UUID。所有已知 UUID 消失、标记不符或创建结果未确认时保留记录并阻止写入，不凭名称猜测身份。连接端口改变时，实例标记仅用于找到唯一候选登记，不授予资源写入资格；当前停留在个人集合时，只读检查不切场，显式准备在输出空闲后选择专用集合并核对已登记 UUID 图，通过后才恢复写入资格，核验失败则安全返回原集合。网络连接使用新地址，音频、画面与音乐恢复记录继续使用原身份键，不批量改写事务或按同名集合接管。同一实例内保留完全相同 UUID 图的集合克隆仍无法由官方协议独立区分。普通查询只观察，工作台准备或显式修复才创建、登记和修改。

集合内保留八个节目场景，来源使用固定简洁中文名，不添加序号或随机后缀。对阵与比赛中使用游戏画面和对应网页，其余场景使用全屏网页；比赛中的紧凑禁选底栏是合法受管变体。准备按目标结构恢复名称、设置与缺失资源，音乐与音效引用保持零缩放、无边界的纯音频布局，删除额外场景、来源、嵌套路径和重复引用。用户应在 Mizar 保存模式与设备选择，不依赖 OBS 内的手动结构修改。非活动模式仅在赛前等待保留一个禁用引用，以维持 OBS 来源对象和已选设备；其他场景移除其引用。新集合内异常全局音频按通道命名、静音并关闭监听，读回确认后才视为隔离；OBS 没有设置全局通道的对应请求，不将 `RemoveInput` 视为已经解除通道。旧集合的全局音频不修改。

连接和重连仅检查；工作台准备和显式修复沿原 Task 推进，写入前复核制作修订、输出与资源身份。直播、录像、回放缓冲、虚拟摄像头任一活动或未知时，不自动改结构或刷新网页。网页刷新按 endpoint、实例、集合、来源 UUID、URL 和应用 build 去重；未知提交不盲目重放，刷新受理不是像素或网页握手正常。单个状态查询失败保留已建立的控制连接，对应输出为未知。输出命令区分 accepted、pending、started、failed、unknown；有界等待结束仍无实际证据时显示未确认，不自动重复 StartStream。#790 的唯一 CS2 捕获目标、预热租约与活动输出保护继续适用。

OBS 外部切场、切集合或断线撤销旧编排控制，明确恢复自动后继续；自身 Take 目标事件不触发人工保持。退出时仅在已确认当前输出不属 Mizar 时保留用户画面，连接未知不是该证据。Host 在 Runtime Job 外启动独立 OBS，退出 Mizar 不连带关闭它；桌面只拥有窗口和本机覆盖，不复制节目状态。实际网页画面、音轨与声音仍需独立核对。

制作提示从现有状态生成；B 站查询有缓存、超时和并发上限，只服务本机状态提示，不进入公开输出或节目切换门禁。实现见 [ADR-0019](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0019-production-guidance-and-platform-status.md)。

## 安全、采集与扩展

本地监听、Origin 校验和凭据分离见[协议安全](protocol.md#本地访问与安全)。采集写盘不能阻塞 GSI 接收，重放必须经过生产适配器，规则见[遥测语义](telemetry.md#采集重放与时间)。

新增数据源优先增加适配器，新增画面优先复用已有投影，新增可靠输出不改变高频快照语义。第二个真实消费者、提供方或独立发行需求出现前，不建设通用插件框架。

Desktop 的 CS2 启动、临时配置与恢复遵循 [ADR-0026](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0026-managed-cs2-launch-and-restoration.md) 和 [ADR-0027](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0027-cs2-launch-recovery-workflow.md)。状态查询不等待启动或退出操作锁；Steam 请求提交后立即释放启动命令锁，准备中心显示正在等待，不因固定等待时限判定失败。后台继续按 PID、创建时间与规范化程序路径认领唯一晚启动进程；工作台会话先建立并展示面板；游戏与 OBS 按各自条件准备，游戏确认运行后继续同一连接意图，不等待 OBS 捕获；明确取消请求会撤销进入意图；页面重建不取消 Host 持有的准备任务，也不重发 Steam 启动。本地服务启动失败时，Host 原生恢复入口只读取同一 SessionStore、观战恢复与试播清理记录，不调用可能自动写回的 poll；用户明确恢复后复用 ManagedCs2 原有进程、路径和读回门禁，不关闭游戏、不启动 Steam，也不确认制作结束或本场回收资格。运行中的 CS2 或未知进程状态拒绝离线写回；Demo 资料保持隔离，不阻止已确认游戏退出后的本机配置恢复。Steam 待确认要求原有显式取消确认。恢复返回的软警告同样显示原原因与下一步，不以检查完成掩盖仍待恢复的记录。错误继续保存在本机 DesktopLog，诊断导出保留脱敏的原因和 stderr。Steam 请求待确认时保留持久记录，取消等待必须先取消 Steam 请求并确认游戏关闭，再显式恢复备份。未确认启动仍按原恢复门禁处理；正常退出（含 `--stop`）与工作台退出均由 Host 请求本地来源交接，随后关闭精确归属的受管理游戏并恢复配置。OBS 安全切场与远端交付、释放独立收尾；未确认状态保留并单独报告，不阻止已交接的本地清理。来源交接或本机恢复未确认时保留错误与恢复记录，不伪称成功；退出期间拒绝新启动与工作台进入，异常退出后的恢复状态跨窗口可见。工作台退出先尝试打开准备中心，Host 持有任务，不因隐藏或网页导航丢失。首次打开失败只记录本机原因，不跳过安全收尾；清理完成后释放游戏锁并重新尝试呈现准备中心，以最后一次呈现结果判定窗口收尾。准备中心缺失、取消最小化或显示失败明确返回错误，不宣称退出成功。工作台两块面板分别尝试隐藏，单块失败仍尝试另一块并保留 HUD 隐藏请求；面板隐藏失败记录本机原因，退出返回错误并允许在准备中心重试，不因制作已结束而宣称窗口收尾成功。Host 只保存此次退出的阶段、忙状态和错误反馈，准备中心与底栏只读同一结果，不复制制作或恢复事实；失败释放退出门禁，保留原始本地日志、备份、重试与诊断入口。退出开始使此前的工作台进入代次失效；现场窗口先隐藏创建，主线程把显示、聚焦、隐藏准备中心和清理旧反馈与退出开始互斥提交，已完成或失败的退出也不会被旧进入覆盖。Steam 取消确认仍显式提交给原恢复门禁。启动项只传给本次 Steam 调用，不修改持久启动项。退出请求与失败重试见 [ADR-0033](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0033-host-first-exit-request.md)。

Host 持有本次启动的 MulNX 启动器进程句柄。成功关闭游戏并确认没有 CS2、且启动请求不再待确认后，先请求启动器正常关闭，超时才结束该句柄所指进程；失败保留恢复状态，不按进程名关闭外部启动器。Host 重启后无法凭旧 PID 单独取得关闭权限，未确认的启动仍要求人工核对。

MulNX 启动期间，窗口定位不等待游戏控制网关就绪。Host 先以本次已提交启动事务、唯一进程、创建时间及程序路径核对游戏，持有进程句柄后由既有工作台窗口跟踪器提前归位；不因此提交遥测来源或取得运镜控制资格。定位沿用保留原设置、隐藏、取消和退出门禁及原窗口恢复记录。只有游戏网关归属也确认后才完成 MulNX 启动交接；未监听时先做短时端口探测，避免反复启动端口归属查询阻塞窗口发现。

工作台面板初始隐藏，进入时为保持焦点采用原生非激活显示。准备阶段在游戏启动前显示两块面板；准备中心仍为前台时，先将面板放到准备中心紧后方的普通窗口层级，再隐藏准备中心，避免面板已经显示却被其他应用遮挡。前台已切走或准备中心被外部设为置顶时不抬高面板；不永久置顶、不主动转移输入焦点。游戏窗口组首次可用也需恢复一次同组层级，不能因游戏已经位于前台而跳过。Tao 0.37.1 的隐藏操作比较缓存 `VISIBLE`，但可见性查询读取 HWND；原生显示不会补写缓存，后续 Tauri hide 可能不做任何操作却返回成功。因此面板的显隐都在拥有窗口的 UI 线程执行同一原生非激活路径，并读取真实 HWND 可见性核对结果；退出等待实际隐藏结果，读回不符不能完成收尾。此项修复针对已证明的 API 状态不对称，不代替现场锁等待、窗口调用和系统错误的逐阶段证据，也不证明所有历史退出停滞由此造成。

手动恢复旧备份由 Desktop Host 持有原生文件选择和预览。只读取当前已验证 Steam 账号的配置，界面使用本机昵称及可用的缓存头像确认目标，Steam64 仅用于内部校验；读取不到昵称时提示重新登录。原生确认重新核对账号、程序、配置与所选文件字节，以及无受管/外部游戏、无既有恢复或试播事务。先保存当前原件，再以同一 SessionStore 的版本 4 恢复记录提交字段级变更；视频只恢复已识别设置，配套机器配置只恢复 fps_max，未知内容保留。显式恢复可按选定备份消除相关重复键，不自动选择冲突值。中断后复用恢复入口，已完成的同值写入跳过，外部修改时保留原件与事务等待核对；写前复核不宣称与 Steam Cloud 构成跨进程原子事务。

可选 Steam 头像由 Companion 的本机媒体缓存提供，赛事头像优先；不修改身份或比赛文档。密钥与缓存独立于采集、预设和支持包，见 [ADR-0034](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0034-local-steam-avatar-fallback.md)。

安装版的数据目录与自动准备所有权边界见 [ADR-0048](https://github.com/Starfie1d1272/Mizar/blob/3b187e168ad755ede595eb8371bfaf5933c044fa/docs/decisions/0048-installed-state-and-safe-preparation.md)：安装版使用当前用户数据目录，便携模式保持原路径；自动 GSI 不取得未知文件所有权，OBS 重连不覆盖手动配置。

桌面恢复布局先提交后台窗口请求，界面显示等待确认；Host 发出的异步窗口变化仍属于该请求的有限确认与修正期，不因一次客户区变化提前清掉请求；完成后的外部窗口变化仅跟随，不强制纠正用户布局。Host 后续读取的实际客户端范围与目标一致后才确认对齐。隐藏或退出后的旧面板布局结果不再应用；退出代次变化时窗口线程排入原始游戏窗口矩形恢复，已提交给 Windows 的定位或恢复不视为实际完成。系统调用失败、画面范围不一致及保留原设置分别反馈；权限拒绝不推断为管理员权限差异，也不自动提权。窗口组恢复错误保留失败目标角色，工作台与准备中心显示同一 Host 反馈；新的成功恢复清除对应告警；手动命令保留 Host 错误归属，不在页面复制旧原因。隐藏期间完成恢复后，只有 SessionStore 核心记录已清理且全机 CS2 已确认停止才清理窗口反馈，读取失败或仍待恢复时继续保留。诊断只投影有限窗口范围、显示器工作区、DPI、失败阶段及当前 Host／游戏提权状态，不包含窗口标题、句柄或私有路径；读取失败为未知，游戏退出后的状态不能还原运行时权限。

### 诊断证据、历史与导出

诊断观察产品边界，不修正比赛、OBS、网站交付或播出资格。 网站 LIVE 的来源不可用证据区分来源缺失、比赛、生产者与会话身份不匹配，不改变认领或开图回执门槛。认领沿原操作记录开始、持久意图、来源发布与终态，准备或持久化失败也保留原始原因；来源退役记录原身份及原因，开图 ACK 只在仍有效的来源操作中确认。OBS 原生日志区分音频缓冲上限、时间戳异常、落后后重启和 WASAPI 启动/窗口失败，并保留缓冲增长、设备失效重试、默认设备变化与初始化回执。只保存固定音源角色及落后/缓冲毫秒数，不收集设备名；初始化回执不证明时间线已稳定或观众有声，原生日志的落后量也不等同观众实际延迟。GPU 优先级设置失败不计为渲染器故障。Host、Companion、Mizar 文档分别记录 `mizar-diagnostic-event/2`：原生产者与运行身份、sequence/eventId、观测和记录时间、任务/操作/attempt、原业务 scope、evidence 与 coverage。稳定源身份重放时保持 eventId，两次真实点击保留两个身份；跨进程墙钟只辅助排序。已接纳、已提交、未提交和未知分别表达，不能以队列受理宣称断电零丢失。

Host 在 Companion 离线时独立持久化。桌面文档通过有界证据 IPC 交给 Host，收到文档原 eventId 的持久回执后才移出内存，未确认的事件在文档存活期间重试。纯浏览器通过 control-event HTTP 单次交接同一事件合同，服务持久化后返回 204；发送失败只计入后续事件的失败摘要，没有桌面 IPC 的保留重试队列，响应未知时也不能保证交付。一份文档不双投，文档关闭前未交接的尾部仍可能丢失。Host 正文不再通过 NativeSource 复制进 SessionJournal 和云 outbox。ProgramChat 使用自己的固定来源输入适配器，沿原受管身份、本机同意、Program 代次和五秒新鲜度接收 ALL 聊天，不等待诊断 ACK；TEAM、私聊及技术报错不进入节目。

导出前，发起操作的文档先登记当前状态与性能摘要，再固定本页事件序号截止点；最多等待三秒、推进十六批交接，不追逐截止点后的新事件。交接无进展或超时仍继续导出；已在途操作不被取消，也不因此重发。请求独立携带本页截止点、未确认数量与首末序号范围、累计未确认记录及失败尝试数，不依赖这些信息自己先排入同一队列。支持包将未确认交接计入覆盖缺口，晚回执可能已在 pin 前落盘，不能将未确认直接等同实际遗漏。累计计数属于本页存活期间，可能超出所选导出时间；其他文档、截止点后事件和关闭前未交接尾部仍未知。该截止点与各 producer pin 不是原子快照，未上报覆盖信息的旧客户端也不得声称本页完整。

Host 导出 pin 的 prepare/commit 合计最多等待八秒，用户取消会停止后续阶段。超时或失败不向 Companion 交付该 pin ID，独立覆盖报告将 Host 未确认固定计入缺口；原生调用迟到返回后才串行尝试释放自己的 ID，不重发 prepare/commit，也不等待错误日志或释放完成。每页最多保留一个尚未确认释放的 pin 操作，后续导出跳过 Host 固定并报告缺口。成功 pin 交给 Companion 后，页面独立限时核对确切任务：只有收到匹配 ID、终态且任务已结束输入使用与收尾尝试的证明才释放；尚未发出生成请求或本次 409 拒绝明确确认该 ID 未被既存任务使用时也可释放。生成 POST 不自动重试、不跟随重定向；cancelled 只确认取消请求，不证明收集任务已经退出。身份冲突、未知或超时结果仍保守保留，不能在后台仍可能使用时提前释放。此机制只限定页面等待，不强制取消 Host I/O；receipt 的十五分钟租约不保证悬挂 pin_work、partial 或孤儿元数据被清理，页面关闭和释放失败的回收仍未闭合。

Host 普通事件遇到原 writer 锁忙时，最多暂存 256 条、512 KiB，保留原任务关联、观测时间和单调时钟；后台每次最多排水十六条，不在业务入口批量补写。recordedAt 与 sequence 表示实际持久化时间和顺序，不冒充原始跨线程顺序。争用、溢出或写入失败以有界缺口计数保留原因、字节与原时间范围；pin 在准备时固定待写及未报告缺口，支持包明确标记 memory-only，不能把内存受理当作持久化。进程退出仍可能丢失未提交尾部；未争用的原单次磁盘写入也不承诺零延迟。文档持久回执与显式 pin 在阻塞工作线程完成后返回，不提前确认。

SessionJournal 是 Companion 的有界异步普通 writer；BusinessJournal 只把业务变化记录到它，业务导航由导出索引派生，不维护第二份正文或旧业务历史视图。性能异常窗口直接成为最终压缩正文，普通日志仅保存引用；问题标记使用各 producer 的持久 pin 回执，不在每次标记时重压所有日志。用户意图和故障首末保留，重复后台观察按上下文聚合首末时间、次数和代表样本；聚合没有持久的尾部范围保持未知。音乐轮询的同一错误和网站 LIVE 的同一来源不可用／开图待确认，在错误、制作范围或来源身份变化时立即留证；不变状态每五秒汇总次数、首末时间和代表错误，恢复与正常关闭前写出尾部。只合并诊断，不改变 RPC、实际投递或失败判断；进程崩溃前尚未写出的五秒内聚合尾部仍未知。网络请求前的 LIVE 来源守卫只写一条 canonical 业务证据，不另写等价 website_live_evidence；实际响应的完整原始证据仍保留。

普通正文使用约 1 MiB 的不可复用分段名；Companion 普通预算 64 MiB、Host 100 MiB，性能正文压缩 64 MiB/展开 256 MiB/4,096 文件。producer 在自己的 writer 串行区确认 pin；导出 pin 有期限并在结束、取消或失败时释放，现场标记使用共享八份/64 MiB 的预算。活动制作和仍被引用的独有证据不能因云 ACK 被立即删除，空间不足或保留失败明确记录覆盖缺口。有限空间不能承诺无限历史；`console-history` 原始控制台不进入诊断包或云投影，也不是可随诊断轮转的副本。

当前版本仅接纳新版诊断来源，不迁移、重编码或自动删除旧版本日志、旧 JSON 包及旧业务历史。待传 gzip 只在有界读取后识别格式，旧 event/1 正文记为排除，不进入当前证据、投递或迁移。旧文件留在原位置，与当前采集、保留预算和导出隔离；需要处理时使用对应旧版本工具。新版已接纳的未上传事件与不可变传输批次继续保留，不能因 wire 外壳仍为 `/1` 就当作旧数据。确认上传只释放有 canonical 覆盖证明的精确批次，不再制造迁移正文。同意、暂停、撤回、自动窗口及接收器能力要求见[技术诊断回传](diagnostics-delivery.md)。

人工默认包为标准 ZIP，包含 `bundle.json`、`events/*.ndjson`、`indexes/journey.json`、`indexes/business.json`、`snapshots/current.json`、`attachments/obs/*.log`、`measurements.json` 和 `coverage.json`。`bundle.json.complete` 仅表示归档分卷已写完，不表示所有历史来源完整；`coverage.json` 同时说明无法安全固定的来源、旧格式排除与实际证据缺口，历史缺失不会由导出重建。 Host 与 Companion 在写者串行边界封段后，将确切后继段名随固定回执声明；只有固定提交成功且名称匹配时，导出将其列为截止范围外，而非证据缺口。未声明的段、固定失败和未知来源仍保留缺口，不以文件时间推测。正文与 variant 保留一份，导航只引用。开始时固定各 producer 提交水位、pin 回执、源句柄/长度、pending 与 asOf；这不是跨进程原子瞬间。计数与 health 使用同一快照，区分 uniqueEvents、carrierRecords、aggregatedOccurrences、未知范围、排除、缺口、字节和 SHA。不能在归档后读取 live health 冒充同一水位。窗口退出反馈的周期检查仅在实际退役或检查失败时记日志，无待退役反馈的空轮询不生成操作记录。新版包不附未提交的 memory-only 正文，只按同一 pin 水位报告 pending 数量、health 与排除原因；文档已关闭前尚未交接的尾部保持未知。

解析、脱敏、计数、摘要与压缩在一个有限生命周期的 worker 内按有界块进行。原生日志附件按脱敏后每行的 UTF-8 字节累计分段，不为每行重新扫描已累计正文；分段边界与完整内容保持不变。gzip 正文首遍解码后将精确比较事实保存在本次临时身份索引，NDJSON 保存准确记录长度；后续覆盖核对复用这些事实，不因每条投影重复解压整段，也不只按 eventId 删除不同正文。临时比较事实纳入同一 256 MiB 缓存预算。默认包含全部保留证据，可显式选起止时间；时间未知的上下文保守附带。每份 ZIP 压缩不超过 18 MiB、展开不超过 256 MiB，缓存内全部未过期生成物与正在生成的任务合计不超过 256 MiB；超出时同一次构建滚动分卷或明确失败，不静默裁剪最近片段。读取器核对每个条目的 ZIP CRC32（含覆盖元数据）及索引中的 SHA。普通单份 ZIP 内包含最终覆盖、条目索引及 partCount=1，可独立交付；多卷才另附总清单，列出每卷数量、字节和 SHA，读取器验证缺卷。首次配置 5 MB 和常见 BO3 单份 18 MiB 是需实测的工程目标，不是用截断达到的保证。

每卷在关闭前写入 `measurements.json`，包含已完成的来源固定耗时、worker 累计读取/解码/编码和边界内存采样；截止点为测量条目、覆盖清单及当前卷关闭之前，不预报它们的耗时或最终保存结果。后续关闭、同步及保存日志以 exportId 关联。

Web 只持 exportId、阶段、字节进度与有限摘要，不取得大 JSON/text/Buffer，也不经 IPC 传全文。导出在第一次异步操作前独占接纳区，同一时刻只有一个活动任务。各来源独立固定，无法安全固定的来源不读并记录缺口，其余安全来源继续；缓存目录不可信或输出写入失败仍停止整个任务。Companion 在固定 `support-export/<exportId>/` 中生成并原子发布内部清单；Host 先取得保存 lease 和固定源句柄，再打开对话框。单 ZIP 选择一个按时间命名的文件，多卷选择目录并附总清单。Host 拒绝重解析、身份变化和冲突目标，流式复制并校验 SHA；lease 覆盖对话框等待。过期缓存清理者通过排他创建保存 lease 取得归属，在删除其他内容期间保留它，结束时仅按文件身份释放自身 lease。删除失败保留原过期时间和诊断原因，下一次生成或进程重启可立即重试；仍可核对身份并安全计量的残留计入缓存预算，预算足够时继续生成并报告清理未确认，不以旧清理故障阻断新导出；身份不明、无法安全计量或预算不足时才拒绝；最后只删除空目录，不跨过新取得的保存 lease。已有未知 lease 不按空内容或时间自动删除；它与旧进程、原生保存任务的归属未被证明时保留缓存，并明确提示占用未确认。旧残留的自动恢复尚需 Host 保存任务与 Companion 监督共同提供退出及排他证据，普通重启不等于已恢复。未在保存中的成品闲置十五分钟可回收，桌面重新保存和浏览器重新下载都复用同一 exportId，只有明确重新生成才改变快照。对话框等待与复制耗时分别记录；取消、部分来源缺失和保存失败分别说明。纯浏览器只称已发起下载，不假造磁盘保存回执。

旧 `POST /debug/support-bundle`、JSON/Base64 生成适配器及旧 JSON 维护读取分支已退役。当前导出、原生保存与维护读取器只处理新版 ZIP，不以兼容读取重新创建拥有保留或恢复权限的 writer。

导出只读固定产品来源，拒绝链接、硬链接、非普通文件和身份变化，不接收任意路径。密码、令牌、Cookie 和推流密钥精确替换，保留技术上下文、原始原因和可定位业务身份；音视频、任意私人文件、原始聊天与 console-history 不进入包。OBS 附件只来自既有固定根和命名、24 小时内且日志含 Mizar 来源标记的会话；精确凭据上下文不可用时拒绝原文并记录缺口。沿用最多两个根、每根八个候选、单文件 25 MiB/合计 64 MiB 和七秒采集限制；不启动或重配 OBS/CS2。索引、捕获成功码、网页就绪或已保存配置都不能证明最终像素和声音正常。

RivalHub 配对读取区分读取、解析和校验失败，保留位置/错误链并移除凭据片段；未知远端原因保持 unknown。采集与 OBS 请求故障在各自真实边界保留原因、阶段和实际回执，诊断失败不改变业务结果或递归报错。回归复用既有入口与公开/合成夹具；真实用户包仅私下核对覆盖和成本，不进仓库或 CI。Windows、CS2、OBS 最终行为仍须独立实机证据。

### 解说 CFG 与键位恢复

维护一份 `mizar_observer.cfg`：数字键 1–9、0 对应武器槽选择，H 切换 CS2 原生 HUD，`spec_usenumberkeys_nobinds 0` 启用对应观战选择。标准 Steam 启动（含保留画质）、Demo 和 MulNX 自动启动均请求执行同一文件；Demo 另用会话临时文件播放所选录像。实际游戏加载顺序、键位生效及退出写回仍待 Windows CS2 实测。标准启动时 HUD 初始状态保持游戏原状。MulNX 自动隐藏开启时，Host 先读回并保存当前 HUD 原值，再在本游戏实例首次连接准备中提交一次隐藏；提交前持久记录尝试，未知结果或重试不再次覆盖 H 的人工操作，结束时恢复原值。已确认没有 CS2 时，旧进程 HUD 恢复记录损坏、不可读或无法清理只保留原件并禁用本次自动 HUD 写入，不阻止新启动；可核记录仍检查实际进程身份，核心配置及观战备份的恢复门禁不变。退出仍执行核心配置恢复，HUD 记录未恢复单独报告。按键由 CS2 原生处理，不通过网页 HUD 或 OBS 控制。

Host 在游戏启动前检查当前账号的 slot0 主键位文件，并保存受影响数字键、H 候选及原观战变量的原值；空值与缺失分开记录。只有可唯一识别 `h` 或 `scancode11` 时，才在同一 CFG 中输出该固定键名；两个候选均缺失时使用标准物理 H 的 `scancode11` 并记录缺项；冲突或重复时保留数字键功能并说明 H 未接管。同名文件仅在字节完全匹配受管理版本时升级，未知文件与链接不覆盖。启动前复核原绑定并持久标记可能加载；退出后只恢复本次所写字段，若当前值既不是原值也不是受管值，或键身份发生变化，保留当前文件和备份供重试。运行时 HUD 显隐值不承诺恢复。

VCFG 解析支持带引号与不带引号的 KeyValues 字段和值，按原始字节范围备份和恢复，其他字段使用合法的无引号标量不会阻断解说键位准备。条件表达式、文件引用指令和不完整结构仍拒绝接管；准备失败记录具体文件、备份阶段及可确定的字节位置，不跳过校验强行覆盖 H。

Steam 可能在本次启动参数之后执行个人 CFG。Host 在有界读取 `autoexec.cfg`、Steam `+exec` 和同步引用后，于这些启动文件末尾临时追加固定解说 CFG 的执行命令，避免 `binddefaults` 或个人 H 绑定覆盖本次配置；不修改 Steam 持久启动项，也不执行读取到的命令。正常模式复用帧率文件事务，保留画质与 MulNX 模式复用观战恢复记录且不修改帧率。原件先落盘，再应用并读回核对；取消、失败和正常退出均恢复原文件，外部改动保留备份并阻止覆盖。异步执行、自定义别名调用及直接修改键位的 Steam 参数无法保证顺序时拒绝该接管，不把提交启动请求当作键位已生效。

MulNX 自动启动通过其现有 `launchOptions` 临时追加同一个 `+exec`，绑定确认后的 PID、创建时间与程序路径；启动项清理不覆盖用户新修改。受管游戏按正常退出路径关闭，键位恢复记录保留至游戏退出后重试。两种启动方式均由 Mizar 管理解说配置；自行启动的游戏须退出后重新从 Mizar 启动，不提供手动准备 CFG 或通用借用入口。启动前已有的受影响键位按同一恢复事务保存。

不再为新启动创建全键位配置或提供完整键位选择。已存在的完整快照和旧版观战恢复记录继续按各自版本恢复，保留身份、进程停止与冲突门禁；不得因迁移清除待恢复记录。多文件和 Steam Cloud 不构成原子事务。来源资料：[Valve 2024-02-15 更新](https://store.steampowered.com/news/app/730/view/6856237235656946987)、[SDL scancode 定义](https://github.com/libsdl-org/SDL/blob/main/include/SDL3/SDL_scancode.h)。

## 可选地图运镜编排

选择 MulNX 启动时，Host 先建立工作台会话并展示面板，再由同一准备任务继续准备和启动。现场状态下的 MulNX 准备请求携带原任务 ID 与当前制作修订；Host 核对任务仍在执行、已进入、未取消或退役且未开始退出，Companion 核对进入任务身份、制作修订及取消、忙碌和退出状态。该许可仅覆盖本次启动准备，不授予现场更新、切换版本或 Demo 操作。退出恢复使用独立的清理目的：只恢复已安装实例中本机登记的启动参数，核对游戏路径与原值/应用值，不安装、下载或改写其它配置；因此本机清理可在结束制作提交前完成，任务失效不会重新获得启动许可。安装位置仍由 Host 发现，Companion 只准备受管工具及配置。同一次启动意图通过启动器消息总线发起一次请求，入队回执不代表启动成功；Host 核对实际游戏的 PID、创建时间、程序路径和游戏内网关监听进程，再绑定受管配置事务，并以当前制作修订建立原生运镜租约。Host 持有已验证的游戏进程句柄，在独立调度中每两秒续约；续约与撤权由同一租约状态串行，实例退出、不再唯一或续约失败时隔离租约，结束游戏时撤销租约。若撤销结果未知，Host 在停止续约后等待超过两个六秒租约周期，以覆盖一个可能迟到的在途续约，再继续原生游戏收尾；已确认服务停止时可直接继续。该等待不替代 MulNX 卸载核验。启动结果未知或实例变化时保留工作台会话与准备状态，不授予未经核验的游戏控制许可；游戏与 OBS 按各自状态就绪，Host 接入游戏前必须核验本机持久化的 Mizar 进程记录。完整启动流程及上游能力边界见[地图自动编排](orchestration.md)。

Companion 的 `orchestration/` 消费既有 Program 投影、音乐阶段分类和实际开场 Take，保存本机地图预设，调用隔离的 MulNX WebSocket 适配器。Core、Program Director 和音乐模块继续拥有原有事实及职责；预设不进入公开投影。连接、人工保持和 Cue 为本进程临时状态；连续性变化保留人工或自动选择，但使准备状态失效，重新应用本图包并回读后只等待新事件。新阶段只允许一个有期限、绑定上下文的清空后交接；隔离包磁盘验证为调度前提，自动和手动播放均需活动包与空自动列表回读；该回读不证明资源加载。Host 只持有本次受管游戏的已验证句柄；实例退出或不再唯一时撤销对应原生控制许可。Companion 只维护该会话的六秒租约，Host 每两秒续约；旧会话不由迟到心跳恢复。产品 Companion 重启默认待确认，Host 重新核对受管记录后恢复，不支持外部游戏借用。浏览器备用模式仅在制作准备阶段显式选择，之后独立于 Host 生命周期，不被旧原生消息撤销。入队与执行证据分离、过期保护及剩余上游缺口见[地图自动编排](orchestration.md)。

结束本次制作失败时，Host 保留原始退出结果，并复用居中、聚焦的原生核对窗口展示 `kind=exit`。此窗口仅在存在退出异常时允许打开，不受工作台隐藏状态限制；它读取 Host 退出状态，提供返回准备中心处理与运行诊断入口，不直接重跑收尾。配置恢复按钮按游戏是否已关闭和失败阶段命名，外部 CS2 接入不显示无关备份入口。

核对窗口关闭命令只授予 `tool-review` 窗口；Windows 原生 IPC 按来源而非页面路径匹配本机权限，命令自身仍核对窗口身份。

### 专用集合音频与迁移

音频模式、角色绑定和应用选择属于本机操作员配置，保存端点、集合、UUID、类型与修订，并在操作时重新核验。首次准备默认桌面混音：桌面声音、麦克风、音乐和音效进入各节目场景；独立分路使用游戏声音、其他解说、麦克风、音乐和音效。来源共用，设备和应用选择在 Mizar 保存，准备时据此修复；不从其他个人集合任意挑选来源。

升级仅迁移旧「Mizar」集合中明确保存的 WASAPI 音频角色绑定。离开旧集合前只读保存设备设置、静音、音量、音轨、滤镜、监听及启用意图；全局麦克风引用同样计入启用意图，静音状态独立保留。新集合中创建对应来源并完整回读后提交新绑定。旧音频来源不写入、不删除。创建回执已确认但不再被选中的旧来源记录、仅等待应用出现的记录和未发送的来源切换计划，在迁移提交时保全归档，不强制绑定到当前选择；缺少创建回执、已发送未确认或不认识的结构仍保留为阻塞。来源切换写入发送标记后若写前校验失败，且本次尚未调用设置请求，只将仍匹配本次计划的记录恢复为未发送；请求已调用后的未知结果不重放。归档中断按原内容复核后续行，不能丢弃待恢复副作用。已确认的旧模式备份保留原文件，仅将已复制来源的监听恢复字段映射到新备份，不携带旧场景引用与画面附音。旧模式或来源事务未决、当前不在原绑定集合、绑定身份不符、画面附带音频绑定或同一角色存在不同来源选择时，明确阻止自动迁移，不静默重置偏好。失败保留快照及恢复责任，重试继续原事务；音乐库和音乐配置独立保留。

创建、切换集合与结构修复要求直播、录像、回放缓冲和虚拟摄像头全部明确空闲，从不自动停止输出。已准备好的音频模式仍可通过既有模式事务在输出期间切换，不因此重新准备集合。切换保存目标、来源身份、场景引用和监听原值，在同一连接观察人工变化；未确认结果保留记录，外部修改时让权，不自动重放。音乐元数据与模式提交后才清理已确认记录。缺少独立来源或所选解说应用未运行时保留现有模式，等待操作员启动应用后手动重试；取消、改选和结束制作使旧等待失效。

桌面采集与 OBS 监听设备相同时，仅 OBS 32 及更早版本使用仅监听并由桌面采集输出，切回独立分路时按记录恢复。OBS 33 已取消旧接口的仅监听输出抑制，此时或版本与设备关系无法确认时，保持节目直出并暂缓本机监听、保留监听偏好，不改用户音轨，也不猜测默认设备实际指向；可选择未被桌面采集的监听设备。麦克风监听可能回灌时记录并关闭，按仍有效的事务恢复。应用候选短期有效，保存时重新核对连接、集合与偏好修订；来源目标变更要求停止输出并核验 UUID 与原目标，未知结果保留记录。就绪检查只读核对来源音轨与当前配置的直播音轨求交：简单模式为第 1 轨，高级 RTMP 为 TrackIndex，SRT/RIST 为 StreamMultiTrackAudioMixes；未知服务或配置明确提示无法确认。不将录像或 VOD 轨当直播轨，也不将配置匹配当运行中编码器或实际声音证据。模式、设备、音轨和实际声音必须在 OBS 核对并录制试听。

中场游戏音频策略默认保持。操作员可选择降低音量或静音，仅作用于明确绑定并经当前 OBS 端点、集合、UUID 和类型核对的游戏来源；解说、麦克风和音乐不受该策略修改。策略以可信比赛状态驱动，逐字段保存原值、写入值、操作、绑定修订与连接代际，并持续观察 OBS 音量和静音事件。人工改动、断线或身份变化时让权；未知写入结果不重放，进程重启后待人工核对并恢复自动控制。OBS 不提供比较并交换，外部并发修改与控制请求之间仍可能竞争。

当前实时选择与已接受事实的交付目标分离。可靠队列保存原事件及精确来源，RivalHub 连接仅在同一安装授权和原来源仍可用时发送；切场先将旧来源交给持久来源 owner，后台先收齐该范围交付结果再释放，不让旧网络故障阻止新场认领。不同范围的终图发送互不形成队首阻塞。暂态本地入队失败由原队列持有请求本体并重试，关闭仍未落盘就报告未确认。来源结清同时检查已经登记、尚未完成的原范围边界捕获，不能把尚未进入持久队列的边界当作空队列；缺少原范围证据时保留未确认状态。网站采集在认领请求前持久保存同一队列库身份的区间引用，远端认领确认后先持久启用区间，再以当前真实游标同步开始捕获并发布来源；认领前快照只是锚点，不把网络等待期间算作已采集。激活同时冻结当前投影与完整来源，首条跨图边界不能借用旧来源。普通事件和边界请求共同按原顺序编号，原事件、捕获回执与连续提交水位在同一 SQLite 事务提交；后续写入成功不能跨过前面的缺口。停止、切场与退出先同步关闭新捕获，再重试原请求，只有完整区间和所有交付责任都确认后才结清。网站磁盘或网络等待不进入本机运行时提交路径。独立连续性检查点写盘失败也保留原参数与受理顺序；更早的原事件可先恢复，后续推进检查点的提交不能越过失败的检查点或用新范围成功清除旧失败；既有记录的交付状态可保持原检查点及引用独立更新，不新增事实或改变来源。只有原检查点实际持久成功才解除屏障，空队列、缺口或空操作不算完成。该屏障保护同一数据库的共享检查点，恢复期间可能暂缓其他来源的持久提交，不阻塞本机制作。

队列数据库以进程生命周期的 SQLite 独占写者持有，来源状态文件在读取、恢复与修改前持有独立的生命周期写者锁。启动统一先取得来源写者，再取得队列写者并恢复采集区间，全部完成后才启动网站发送与后台重试；失败仅关闭本实例已持有的句柄，保留原文件和未知责任，修复后重启。本机投影继续更新，不因网站启动回滚而冻结。失去写者资格只使网站同步不可用，不阻断本机制作；这些锁不覆盖 OBS 音频等其他状态，也不支持旧版本已运行进程忽略新来源锁的混用，升级前必须退出旧实例。重启发现未封口区间、旧版缺少引用或库身份不匹配时保留完整性未知，不能因旧会话消失、远端已关闭或队列为空改成完整。首次原请求未落盘即崩溃时只能检测缺口，无法重建已经丢失的正文；已有原请求日志仍按原身份恢复。未知记录不自动丢弃或伪造数据，状态提示导出诊断并核对网站赛果。

自动编排的赛果推进复用已冻结的地图结果，核对比赛、地图执行身份与比分后，允许在 GoTV 中断时完成 GG、地图赛果及图间／赛后展示；新开场和实时比赛动作仍要求可信实时数据。OBS 技术断线取消在途自动请求但保留自动意图，重连只在端点、集合和场景身份一致时继续；身份未知或实际外部切场保持人工接管。准备资格只监视依赖配置：已确认 UUID 的媒体播放设置不撤销资格，结构、浏览器、采集与设备变动仍须重新核验，断线和集合切换清除媒体分类。

桌面准备重试向各领域所有者重新核验当前证据，不把上次成功当作当前就绪。OBS 连接、场景集合与采集由 OBS 所有者确认，人工接管或输出中仅检查；未完成的预热仍由原事务恢复。受管游戏所有者验证进程、所属 GSI 配置及恢复记录，只有旧进程和事务已确认结束才重新进入完整启动；运镜须有当前借用，未确认提交不自动重放，也不先启动新游戏；这类情况须完成结束制作及恢复后重新准备，由原制作修订失效隔离迟到提交。已完成采集的只读复核保留当前唯一 OBS 会话的已有故障证据，只有新预热事务才按启动时间过滤诊断。

BP 全屏／紧凑展示偏好独立于比赛事实和 OBS 事务。偏好读取失败只在内存使用全屏样式，保留原文件与错误原因，不阻断本机制作。操作员显式重新保存时先备份原文件，再原子保存所选样式；备份或保存失败保持待恢复状态，恢复存储后可重试，包括重新保存当前全屏样式。该降级不适用于比赛资料或未知 OBS 事务。

制作会话的自动许可只表达当前会话意图，并排除退出、升级和试播隔离。OBS 综合准备检查仅供准备页和显式准备流程使用，不作为音乐、游戏声音或自动场景的共同运行开关。自动场景在执行时由 OBS 核对本次目标和转场，音乐由自身来源与路由核验，游戏声音由绑定及策略事务核验；各自失败不撤销其他领域的可用能力。

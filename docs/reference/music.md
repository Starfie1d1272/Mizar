# 本机节目音乐

使用步骤见[操作手册](../guide/quick-start.md#节目音乐)。Companion 的 `music/` 模块保存本机音频配置、播放意图及人工停止，消费 Core 的节目投影；精确结构由 [music.ts](../../packages/protocol/src/music.ts) 维护。此格式不属于官方签名资源包，不进入公开比赛协议。

## 音乐包

ZIP 根目录包含 UTF-8 `music.json`，音频使用相对路径。使用普通 ZIP32（存储或 Deflate），允许目录项；拒绝加密、多卷、ZIP64、符号链接、设备文件、路径穿越、绝对路径、Windows 保留名称、重复路径、脚本及可执行文件。最多 129 个 ZIP 项，压缩包及总解压数据上限 128 MiB，单首 32 MiB，清单 128 KiB；超过 1 MiB 的文件压缩比不超过 100。仅允许清单引用的音频，不解压到任意清单路径。

```json
{
  "format": "mizar.local-music",
  "version": 1,
  "groups": {
    "waiting": {
      "tracks": [{ "path": "audio/wait.wav" }],
      "order": "shuffle",
      "volume": 0.5,
      "fadeInMs": 600,
      "fadeOutMs": 600
    },
    "tactical": { "tracks": [] },
    "technical": { "tracks": [] },
    "halftime": { "tracks": [] },
    "mapVictory": { "tracks": [] },
    "matchVictory": { "tracks": [] },
    "opening": { "tracks": [] }
  }
}
```

七组都必须提供；默认启用，空数组静音，不借用其他组。等待与技术暂停每组最多 64 首，其余固定主题至多一首，总计最多 128 首。曲目可提供 `startMs`（默认 0）和 `endMs`（默认 null，自然结束）。起点必须早于终点；单段不超过 24 小时。支持的扩展名和媒体头为 WAV、MP3、OGG、FLAC、M4A，最终解码由 OBS 判断。

导入完整验证后写入以内容摘要命名的本机文件，最后通过同目录原子替换提交配置。失败不更换活动配置；未启用的暂存文件没有播放或对外下载入口。写盘使用限制权限和文件 fsync，不沿用压缩包路径，也不更改官方资源的签名、授权或来源约束。不自动下载、上传或分享曲目。

## 控制与恢复

音乐来源只输出声音。自有媒体源的场景项保持激活以混音，视频变换设为零面积；创建和重连时均核对自有输入 UUID，并处理已有场景项，防止音频内嵌专辑封面进入播出画面。新挂载的场景项先完成视频隔离再启用，不隐藏或静音音乐来源来代替此约束，不修改其他 OBS 来源。

背景音乐互斥，一次性开场音效可叠加。正式单图结果触发胜利主题，图间不截断；自然结束接共享等待，正式比赛恢复立即停音。最终图只播放整场主题；完成后静音。中场优先于暂停，暂停根据真实 phase 分类，不使用断流猜技术暂停，不假定 30／80 秒。普通主题切换渐隐；真实恢复、过期状态与人工停止优先，结束选段及已知媒体时长可提前淡出。

每个副作用前核对当前意图代际，持久记录一次性触发与人工停止。人工命令另有独立有效性标识；恢复在每次持久化等待返回及发放解除静音许可前确认仍为当前命令，准备期间保持停音。较新停止、OBS 人工接管或关闭使旧恢复失效，普通遥测推进不取消当前人工命令。来源名字包含本机随机身份，且必须与登记的输入 UUID 和类型同时匹配；OBS 需支持输入 UUID（OBS 30.2／WebSocket 5.4 及以后）。连接恢复先读取媒体文件、游标、播放／结束／失败、静音与音量，不盲目 Restart。每次换曲、触发音效或系统停音前，先核对两层现有来源的人工控制；识别到停止、暂停、静音或音量调整时先持久保留人工 hold，不能把该操作归因为系统断流停音。系统自己发出的 STOP 单独记录来源 UUID，避免误认成人工操作。相同媒体仍在播放则沿用；系统自行停音后按保存游标恢复，OBS 中的人工操作形成独立音乐 hold，只有明确恢复自动才能解除。音频故障只降级音乐，不改变节目或赛事状态。

开场音效仅消费当前实际 Take started，使用该 Take 的修订身份，超过一秒的排队事件舍弃；快照、刷新、启动和重连不合成事件。各图可通过[地图自动编排](orchestration.md)覆盖开场曲目，仍使用同一 OBS 音效层、开场组音量与启用状态。开场事件和在播音效绑定地图及来源连续性，换图或来源变化后不补播；MulNX 入队回执不触发音效。网络回执和实际声音仍是不同证据。

Restart 回执只代表命令已接收。启动、循环换曲和恢复均等待 OBS 报告播放中再开始淡入；恢复非零游标或选段起点也在此时设置，最多等待两秒，避免加载期间反复 Restart。等待期间仍保留新的停止、静音和暂停操作。淡入初始音量在发出 Restart 前登记，避免把系统设置的零音量误判为人工接管。

## Windows + OBS 实机交接

每次验收记录精确提交、构建标识、Windows／OBS 版本、输出音轨、试听录制和结果。自动化协议／界面测试不能替代以下实测：

- [ ] 使用合成音频或自有授权音频；配置七组、选段、音量、顺序／随机，重启后核对保存。
- [ ] 等待 → BP → 热身 → 图间连续；跨场景不重启，游戏声、环境声和麦克风电平／输出音轨保持。
- [ ] 战术暂停与技术暂停独立，新暂停从头；真实恢复立即停音，同暂停标签变化不重播，中场跨 paused／冻结不重播。
- [ ] 单图胜利跨图间自然结束后接等待；下一图提前恢复时优先停止；BO1／BO3 最终图仅播整场主题，结束后静音。
- [ ] 实际开场 Take 一次音效，可叠加 BGM；切走、快速切换、重复遥测、刷新和重连不补播过期音效。
- [ ] UI 手动停止，刷新／Companion 重启／OBS 重连后仍停止；OBS 直接停止／暂停／静音／改音量后不抢回控制；明确恢复自动可继续。
- [ ] OBS 先开／后开、WebSocket 断开、应用重启、换场／换图和数据断流后重新核对；断连时按提示在 OBS 停音。
- [ ] 缺失／损坏／全部失效曲目静音降级，失败导入保留原配置，非自有来源及游戏／麦克风保持原状态。
- [ ] 在 1080p、1440p 的 100%／125%／150% Windows 缩放检查现场操作、焦点和布局；录制并分别核对实际播出音轨与观众端试听。

# 地图自动编排与 MulNX

自动编排由 Companion 消费既有 `ProgramProjection`、Program 场景与实际 OBS 开场 Take，MulNX 负责游戏内摄像机。此功能可选，默认未连接、人工模式、空预设；不分发镜头、歌曲或 MulNX 二进制。设置 → **音乐与运镜** 编辑预设，现场提供接管和跳过。普通 GSI、HUD、OBS 和节目音乐不依赖 MulNX。

## 触发与控制

- 只有制作已开始、非内置演练来源、比赛资料和遥测新鲜、地图绑定可信、Program 未人工保持时才启用自动运镜。地图、比赛/参赛方、Producer、会话、来源代际、地图执行或预设修订改变，立即失效并回到人工。
- 进入热身、战术暂停、技术暂停、中场、单图胜利和整场胜利时，可发送本图对应的一个宏。阶段分类复用音乐模块，暂停标签变化不创建新实例，中场优先，最终图不叠加单图胜利。
- 开场宏只消费实际当前 OBS matchup Take started，同图至多一次。首回合由开场负责；后续新回合冻结期从本图候选列表随机选一个，尽可能不连续重复。回合号回退不补播，剩余时间未知或不超过五秒时不发镜头。
- 每个宏可设置 500–60000 毫秒时限。时限从提交起计算，仅用作清空请求的本地期限；冻结期还受实际倒计时约束，至少预留五秒，在跳入实战、阶段退出或事实失效时请求清空。时限**不表示镜头真实时长、开始或完成**。
- 保存/导入、启动、重连及恢复自动不播放当前阶段，只观察之后的新边界。重复边界先消费后执行；失败不重试，未连接期间的事件不补播。去重记录单图有界，达到上限后保持人工。
- 新阶段或实际开场 Take 到来时，若前一镜头正在清空，最多保留一个 **1 秒有效**的交接。仅在清空的网关入队回执后，重新核对上下文、连接、阶段、隔离文件与安全条件，提交一次新镜头。接管、跳过、过期、换图、重连和事实失效均丢弃交接；不存在清空实际完成的推断，也没有执行失败重试。
- **接管运镜**立即禁止自动并请求清空全部 MulNX 槽；**跳过本次**结束当前镜头请求，后续新阶段仍可自动。清空不会禁用 MulNX 包自身的后续自动列表；必须维持隔离包前提。上游没有通用鼠标/键盘接管事件，操作者应使用 Mizar 接管按钮；不能承诺在游戏内任意操作都被自动识别。
- **游戏内筛选 → 确认活动隔离包并试播**只读取当前地图已保存的候选，同样检查比赛和连接；不会发送编辑中的任意字符串。试播后保持人工，时限/接管继续生效。游戏内观感由操作者判断。

**仍无法消除的上游边界：** 已投入 MulNX 内部队列的命令无法由 Mizar 撤销，也没有上游到期拒绝协议。Mizar 不保存离线队列、不重发、旧回执不恢复自动，并发送清空请求；不能保证游戏线程长时间停顿后一定不会执行已经入队的旧宏，也不能证明清空已经生效。此类场景必须在游戏内确认，不能宣布完整自动运镜闭环已验收。

## 音频与预设

背景音乐沿用[七组节目音乐](music.md)，使用同一阶段事实及 OBS 受管来源，不建立另一播放器。各图可以选择一个已导入本机的曲目作为开场短音效；不选择则沿用原开场组。音量、淡入淡出及启用状态仍由原开场组管理，选段沿用所选曲目的设置。音效消费实际 OBS Take，**不消费 MulNX 入队回执**；因此现阶段只承诺与开场画面关联，不承诺与游戏镜头 started 同步。换图/来源变化后的旧开场音效不再补播；人工音乐停止仍由原音乐控制独立管理。

预设结构由 [`orchestration.ts`](../../packages/protocol/src/orchestration.ts) 唯一维护：`mizar.orchestration` v1，名称、地图列表、期望包名、开场宏/音效、回合候选和阶段宏。最大 32 张地图，每图 64 个回合候选，名称 120 字符；拒绝重复地图、未知字段和无效时限。无默认镜头或曲目。JSON 文件与接口上限 256 KiB；本机 `orchestration/preset.json` 原子写入，失败保留原预设，损坏文件拒绝启用，不悄悄覆盖。

导入只填入草稿，检查后保存；保存使自动运镜暂停，明确确认后才启用。导出只含预设及音频内容摘要引用，不带本机绝对路径或资源字节，不修改七组音乐配置。换机先导入对应音乐包，再导入/保存编排；缺少引用音频时保存失败。后续 RC 筛选后将验证版本导出，经维护者审查才考虑作为默认预设；本实现不替使用者选内容。

只读 `/local/v1/orchestration` 和写入 `/operator/orchestration` 属本机私有控制面，不进入 Program、公开比赛数据、RivalHub 或采集回放。恢复/试播携带当前上下文与连接代际，过期 UI 操作拒绝。预设提交、操作者命令、Cue、报文提交、网关结果与失效原因进入现有 SessionJournal，随用户主动导出的诊断包保留；日志不把 queued 标成执行成功。

## 专用隔离包与本机入口

`prepare-pack` 工具仅复制操作者提供的 `CamMacros`、`Campaths` 到新建的 `Mizar_<随机标识>` 包，不覆盖原包、不安装资源。专用包元数据固定为 JSON 格式的 YAML：三个自动列表均为空，包切换快捷键关闭。工具拒绝符号链接、硬链接与过大的资源树；失败副本不会生成可验证的元数据。原包许可证和第三方资源使用条件由资源提供方保留，本项目不分发副本。

在 **MulNX 启动、加载包之前**准备隔离包。RC 根目录 PowerShell 示例（路径换成自己的目录）：

```powershell
& .\resources\runtime\node.exe .\resources\app\dist\orchestration\prepare-pack.js 'D:\MulNX\CS2OBTool\CameraSystem\CamPacks\Mtp' 'D:\MulNX\CS2OBTool\CameraSystem\CamPacks'
$env:MIZAR_MULNX_CAM_PACKS_ROOT = 'D:\MulNX\CS2OBTool\CameraSystem\CamPacks'
.\Mizar.exe
```

先在没有 CS2 运行时完成 Mizar 的游戏安装位置、GSI 与 OBS 配置，再通过 MulNX 启动 CS2，让本次 GSI 配置随游戏加载。将工具输出的 `name` 填入本图“MulNX 活动包名称”。源代码环境也可在构建后运行 `node apps/companion/dist/orchestration/prepare-pack.js <原包目录> <CamPacks目录>`。Mizar 从受信任的启动环境读取根目录，网页不接受任意文件路径；启用、试播和每轮调度都会检查包元数据。缺少根目录、文件不符或列表不为空时禁止发镜头；运行期间不符立即回到人工。未增加通用 YAML 解析依赖，只有工具生成的精确格式通过。**MulNX 保存/改写包后，即使列表仍为空，也可能验证失败；退出 MulNX 后重新复制成新隔离包并重新载入、更新预设。** 不在已载入的同名包上改文件来冒充内存已更新。

文件验证只证明磁盘前提。上游仍无活动包和内存列表读回，故操作者必须在游戏内选中刚载入的唯一包；启用和试播按钮都明确要求确认。不要再切回带自动列表的原包；在人工模式跨回合观察无额外镜头后再启用。若不能确认实际加载状态，则停止联调，不能声称只有 Mizar 在调度。

桌面设置折叠项“MulNX 浏览器联调”提供：

- **检查游戏实例**：只读枚举 CS2 的内核进程身份（PID、创建标识、程序路径），按现有受管记录和持有的进程句柄区分受管/外部；不创建受管记录、不写回游戏配置、不关闭进程。不能证明启动器来源或 MulNX 就绪。
- **打开浏览器联调**：打开固定 `http://127.0.0.1:3000/`。保持 Host 和本地服务运行，在浏览器准备真实比赛、检查 OBS 后点“打开直播工作台”。浏览器只进入 Companion 制作流程，不调用 `start_managed_cs2` 或桌面窗口嵌入；浏览器结束制作也不调用 Host 关闭游戏。原启动方负责退出外部游戏；结束浏览器制作后先退出该游戏，再退出 Mizar，以满足 Host 原有退出检查。

**本地尚未闭合的 Host 工作**：原生入口仍拒绝已启动的外部 CS2（`ManagedCs2::start_internal`）；需补充官方启动器交接契约、只借用游戏实例的生命周期与句柄、窗口布局/焦点恢复、退出时保留外部进程及配置、GSI/观战配置归属与故障恢复。这些是 Mizar 集成工作，不能全部归因于上游。上游另需提供可信实例/就绪/执行和活动包回读。本次完成只读身份准备与可用浏览器联调路径，**不是原生受管交接完成**。

## RC 游戏内验收交接

以下均为 **待实机验收**。在主会话审查 PR 后，为指定提交构建 RC；不把云端单测、浏览器或 WebSocket 模拟标成 Windows/CS2/OBS PASS，不在此任务发布版本。

1. 记录 Mizar commit/RC 包摘要、MulNX 发行版本/文件摘要、CS2/Windows/OBS 版本、地图、实际包名及录制时间。使用受支持的 MulNX 启动方式；按上节先准备专用隔离包，启动 Mizar 配好 GSI/OBS，再通过 MulNX 启动 CS2；通过折叠项核对外部进程身份并打开浏览器。在浏览器选择真实比赛与数据源、核对 OBS，再打开直播工作台（直接只打开 `/workspace` 不会开始制作）。Host 原生受管交接仍未闭合。
2. 在 MulNX 手动选刚加载的唯一隔离包，记录其磁盘元数据、实际包名；在人工模式跨至少两个回合确认原 `OnNewRound: [begin]` 没有播放。使用原 Mtp 名、缺失根目录或修改隔离元数据时，Mizar 必须禁止启用/试播。随后核对可用宏；在设置添加空白地图条目，填写自己选出的候选，保存。试播开场和回合候选，逐个核对镜头/时限/停止后的正常观察；不合适的删除或修改。测试不存在的宏时，Mizar 最多显示入队/执行未确认，不能显示播放成功。
3. 导入自有或合成音频，配置七组阶段音乐及本图开场音效。录制实际 OBS 开场 Take，检查音效只发生一次，BGM、游戏声和麦克风混音不被改变。不能因只有镜头 ACK 就起音；对照节目阶段与镜头真实开始的差异。
4. 在热身先连接并确认活动包、启用自动；按实际比赛进入首回合开场、后续冻结期、战术/技术暂停、中场、图终/赛终。镜头未结束时，从冻结期进入战术暂停、从旧阶段切入实际开场 Take，核对各自只触发一次新镜头；延迟清空回执超过一秒时不补播。重复遥测/界面刷新不重触发；记录每个阶段实际宏、声音和网关状态。少于五秒及实战阶段不得启动冻结期运镜。
5. 镜头期间点接管，确认全部槽清空并能正常观察；保持期间后续回合不抢控制。显式恢复只等下一边界。另测跳过只结束本次、试播后保持人工、Program 人工保持时停止自动镜头。无上游手动接管事件时必须按按钮。
6. 分别注入 MulNX 断联、晚回复、不回复、错误回包、GSI 过期/恢复、同图重开、换地图及 Companion 重启。确认本地不补播、旧回复不解除人工状态；在新图手动选包并重新确认。游戏线程停顿后排队命令的实际行为另记，无法可靠撤销则为联调缺口，不能勾选通过。
7. 导出候选 JSON，重启核对；再导入回草稿，确认保存前无影响；损坏 JSON、缺失音频和错误地图保持原预设。将通过的候选与游戏/OBS 录制、诊断包一起交回，未验证内容不设默认。

尚需上游/后续工作：关联执行/完成/失败/停止事件、活动包与资源查询、能力与可信游戏实例身份、队列期限/撤销、可靠控制让渡，以及上节列出的 Mizar Host 与官方启动器交接。安装器、注入、HSI 正式事件归一化和运镜引擎均不在本次范围。

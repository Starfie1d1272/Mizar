# 地图自动编排与 MulNX

自动编排由 Companion 消费既有 `ProgramProjection`、Program 场景与实际 OBS 开场 Take，MulNX 负责游戏内摄像机。此功能可选，默认未连接、人工模式、空预设；正式候选附带构建时最新的 MulNX 官方发行包及原有运镜资源；歌曲由使用者导入。设置 → **运镜** 编辑预设，现场提供接管和跳过。普通 GSI、HUD、OBS 和节目音乐不依赖 MulNX。比赛事实推进使自动 Take 取消时，编排重新评估当前事实；该取消不锁成 OBS 故障，真实连接或切换失败仍须明确处理。

## 触发与控制

- 只有制作已开始、非内置演练来源、比赛资料和遥测新鲜、地图绑定可信、Program 未人工保持时才启用自动运镜。地图、比赛/参赛方、Producer、会话、来源代际、地图执行或预设修订改变，立即失效并回到人工。
- 进入热身、战术暂停、技术暂停、中场、单图胜利和整场胜利时，可发送本图对应的一个宏。阶段分类复用音乐模块，暂停标签变化不创建新实例，中场优先，最终图不叠加单图胜利。
- 开场宏只消费实际当前 OBS matchup Take started，同图至多一次。首回合由开场负责；后续新回合冻结期从本图候选列表随机选一个，尽可能不连续重复。回合号回退不补播，冻结剩余时间未知或已到零时不发镜头。
- 每个宏可设置 500–60000 毫秒时限。时限从提交起计算，仅用作清空请求的本地期限；回合开场镜头可从冻结期延续到同一回合的实战阶段，按所选宏时限结束；换回合、暂停、阶段退出或事实失效时请求清空。时限**不表示镜头真实时长、开始或完成**。
- 保存/导入、启动、重连及恢复自动不播放当前阶段，只观察之后的新边界。重复边界先消费后执行；失败不重试，未连接期间的事件不补播。去重记录单图有界，达到上限后保持人工。
- 新阶段或实际开场 Take 到来时，若前一镜头正在清空，最多保留一个 **1 秒有效**的交接。仅在清空的网关入队回执后，重新核对上下文、连接、阶段、隔离文件与安全条件，提交一次新镜头。接管、跳过、过期、换图、重连和事实失效均丢弃交接；不存在清空实际完成的推断，也没有执行失败重试。
- **接管运镜**立即禁止自动并请求清空全部 MulNX 槽；**跳过本次**结束当前镜头请求，后续新阶段仍可自动。清空不会禁用 MulNX 包自身的后续自动列表；必须维持隔离包前提。上游没有通用鼠标/键盘接管事件，操作者应使用 Mizar 接管按钮；不能承诺在游戏内任意操作都被自动识别。
- **游戏内筛选 → 确认活动隔离包并试播**只读取当前地图已保存的候选，同样检查比赛和连接；不会发送编辑中的任意字符串。试播后保持人工，时限/接管继续生效。游戏内观感由操作者判断。

**仍无法消除的上游边界：** 已投入 MulNX 内部队列的命令无法由 Mizar 撤销，也没有上游到期拒绝协议。Mizar 不保存离线队列、不重发、旧回执不恢复自动，并发送清空请求；不能保证游戏线程长时间停顿后一定不会执行已经入队的旧宏，也不能证明清空已经生效。此类场景必须在游戏内确认，不能宣布完整自动运镜闭环已验收。

## 音频与预设

背景音乐沿用[七组节目音乐](music.md)，使用同一阶段事实及 OBS 受管来源，不建立另一播放器。各图可以选择一个已导入本机的曲目作为开场短音效；不选择则沿用原开场组。音量、淡入淡出及启用状态仍由原开场组管理，选段沿用所选曲目的设置。音效消费实际 OBS Take，**不消费 MulNX 入队回执**；因此现阶段只承诺与开场画面关联，不承诺与游戏镜头 started 同步。换图/来源变化后的旧开场音效不再补播；人工音乐停止仍由原音乐控制独立管理。

预设结构由 [`orchestration.ts`](../../packages/protocol/src/orchestration.ts) 唯一维护：`mizar.orchestration` v1，名称、地图列表、期望包名、开场宏/音效、回合候选和阶段宏。最大 32 张地图，每图 64 个回合候选，名称 120 字符；拒绝重复地图、未知字段和无效时限。无默认镜头或曲目。JSON 文件与接口上限 256 KiB；本机 `orchestration/preset.json` 原子写入，失败保留原预设，损坏文件拒绝启用，不悄悄覆盖。

导入只填入草稿，检查后保存；保存使自动运镜暂停，明确确认后才启用。导出只含预设及音频内容摘要引用，不带本机绝对路径或资源字节，不修改七组音乐配置。换机先导入对应音乐包，再导入/保存编排；缺少引用音频时保存失败。后续试用筛选后将验证版本导出，经维护者审查才考虑作为默认预设；本实现不替使用者选内容。

只读 `/local/v1/orchestration` 和写入 `/operator/orchestration` 属本机私有控制面，不进入 Program、公开比赛数据、RivalHub 或采集回放。恢复/试播携带当前上下文与连接代际，过期 UI 操作拒绝。预设提交、操作者命令、Cue、报文提交、网关结果与失效原因进入现有 SessionJournal，随用户主动导出的诊断包保留；日志不把 queued 标成执行成功。

## 专用隔离包与本机入口

`prepare-pack` 工具仅复制操作者提供的 `CamMacros`、`Campaths` 到新建的 `Mizar_<随机标识>` 包，不覆盖原包。专用包元数据固定为 JSON 格式的 YAML：三个自动列表均为空，包切换快捷键关闭。工具拒绝符号链接、硬链接与过大的资源树；失败副本不会生成可验证的元数据。原包许可证和第三方资源使用条件由资源提供方保留，随包保留上游许可证、资源署名和源码链接。

### 内置发行与独立更新

Mizar 与 MulNX 独立管理版本。每次正式候选构建通过工作流已有 GitHub CLI 身份读取上游公开元数据，解析最新公开 Release（包含 Beta），打包原始归档、校验摘要、来源和许可文件；候选的内容摘要固定这次实际打包的字节。构建读取仅限 MulNX 与 7-Zip 的既定 GitHub API 路径，保留响应大小与超时边界；客户端更新仍为匿名读取，发行文件不携带构建身份。

准备中心提供独立更新操作。进入工作台优先使用已安装版本，首次准备使用产品包内资源及元数据，执行摘要与解压校验。检查与更新操作负责查询上游，进入流程使用本地已准备的字节。

支持启动协议 1 的 MulNX 可由 Mizar 填写游戏路径、执行官方环境检查并返回游戏身份。Host 校验阶段、PID、创建时间和路径后，在同一进入流程借用该实例；已有游戏沿用明确选择和借用流程。官方发行包需要包含协议标记，入口见 [MulNX PR #8](https://github.com/Co1Swet/MulNX_CS2/pull/8)。

自动连接采用操作者确认的相邻端口规则或明确节目源。HUD 自动隐藏先经本机控制台读回原值，再保存进程级恢复记录；正常退出与下次启动尝试恢复，设置页提供重试入口。静默停止游戏内 MulNX 的上游入口见 [PR #9](https://github.com/Co1Swet/MulNX_CS2/pull/9)，发行能力按实际版本核对。

运行时版本存放在本机数据目录的 mulnx 子目录。每版完整解压到新目录，验证成功后原子切换当前版本；下载、校验或解压失败保留原版本。网页只发起操作，CS2 安装位置由原生 Host 的既有 GSI 检查确定。原生 Host 在启动前重新检查游戏进程和受管路径。上游的启动参数及平台检查继续保留。

每个原始运镜包生成一个独立调度副本，三个自动列表为空，包名由原始包名稳定生成。更新 MulNX 保留单独存放的 Mizar 编排预设；新版本同名资源仍对应原隔离包名。打开 MulNX 后，在游戏内选择对应隔离包，再借用游戏进入工作台、连接和试播。

外部安装仍可使用 prepare-pack 工具和 MIZAR_MULNX_CAM_PACKS_ROOT。文件验证要求元数据与工具生成内容一致；MulNX 改写后重新准备副本再载入。

文件验证只证明磁盘前提。上游仍无活动包和内存列表读回，故操作者必须在游戏内选中刚载入的唯一包；启用和试播按钮都明确要求确认。不要再切回带自动列表的原包；在人工模式跨回合观察无额外镜头后再启用。若不能确认实际加载状态，则停止联调，不能声称只有 Mizar 在调度。

桌面设置折叠项“MulNX 游戏交接”提供原生借用入口和浏览器备用入口。先准备比赛，再“检查游戏实例”，按真实 PID、创建标识与路径确认后点“借用此游戏并进入工作台”：

- Host 沿用 GSI 的安装位置发现，检查配置可读、已安装且无冲突；网页只提交 PID、创建标识和制作修订，不提供可执行路径。仅允许准备阶段、唯一 CS2 实例，原有配置恢复或 Demo 记录必须先完成。再次读取所选进程身份并持有查询/等待句柄，拒绝旧 PID、创建时间变化和其他安装。
- 交接先断开旧 MulNX 连接并撤销旧回收资格，再进入同一 Companion 制作生命周期。进入后重新连接和确认隔离包，不自动恢复镜头。借用期间保持原画质、帧率、观战设置与游戏窗口；本机 HUD 覆盖停用。原生面板可用，不自动调整/聚焦/联动外部游戏；“返回游戏”仍是针对持有句柄所验证实例的显式聚焦操作。
- Host 以既有两秒巡检检查原实例存活与唯一性。退出、出现另一个 CS2 或查询失败会使借用永久失效，本次意图不追随替代进程；通过受运行时身份保护的本地接口撤销借用代际；Companion 锁定原生门禁并断开旧运镜连接。失败保留待处理状态并在后续巡检重试；成功后不再给失效代际续约。此重试仅用于失效隔离，不重发镜头。
- 退出工作台先停用自动运镜，再完成 OBS 等待画面与数据源释放；制作收尾失败保留借用供重试。成功后只释放查询句柄，外部游戏继续由原启动方负责退出，不调用受管关闭/配置恢复，也不发放“CS2 已退出”的比赛回收资格。页面、退出反馈和诊断明确写“解除借用”。
- 借用不生成受管进程/配置事务，不持久化自动恢复意图。正常退出 Host 亦只解除借用；Host 异常终止后外部游戏保持运行。Host 新进程在呈现界面前撤销 Companion 中的旧原生会话；异常退出后即使 Companion 继续运行、GSI 新鲜，原生租约到期仍会锁定并断开连接。重启需先结束旧制作，再重新检查并显式借用，不按旧 PID 自动接管；没有被修改的游戏配置或窗口布局需要补偿恢复。原有受管启动、Demo、配置恢复与真实停机证明继续使用原门禁。
- “打开浏览器联调”仍打开固定 `http://127.0.0.1:3000/`；在浏览器准备中心的“浏览器联调”折叠项显式选择“使用浏览器联调模式”，检查 OBS 后进入制作。切换只允许制作已成功回到准备阶段，并检查当前制作修订；不能在 live/hidden 或 OBS 收尾失败时借此绕过原生锁定。此路径不借用/启动/关闭游戏，也不依赖 Host 租约；Host 启动、退出及旧原生消息不撤销已选择的浏览器模式。

Companion 持有独立的原生控制许可，不复制比赛事实。Host 启动标识与每次借用的随机代际绑定；Host 在两秒巡检中校验句柄存活/唯一性后续约，本地单调时钟期限为六秒，100 毫秒编排巡检及每条操作都会检查期限。超时、实例变化、续约失败、Host 重启或制作收尾一旦失效就锁定：迟到心跳不能恢复，`connect`、`resume`、`audition`、开场和自动阶段均受同一门禁约束。只有成功结束制作后的新借用能建立新代际；旧清空回执和旧代际消息不影响新会话。续约不会解除人工保持，也不会补播已观察阶段。

产品 Companion 每次启动默认原生待确认，不持久恢复旧控制许可；开发环境的独立浏览器服务保持浏览器模式。产品浏览器备用入口需显式选择，服务重启后重新选择。租约只保证本地停止发出新运镜意图；Host 刚异常退出到六秒期限之间存在检测窗口，已进入上游队列的命令仍受下述上游限制，不能当作真实停止屏障。

**分开看待本地交接与运行隔离：** 上述实现闭合了 Mizar 的显式借用、原生制作入口、解除借用与重启后重新确认；并未证明 WebSocket 对应这个 PID、当前游戏已经加载指定隔离包，或屏幕真正归还控制。原生句柄只证明本地实例身份，磁盘元数据只证明文件前提。运行隔离仍依赖人工核对和上游读回。自动调用官方启动器、为外部游戏修改窗口/配置的模式没有新增；若需要，应先明确启动器契约与产品取舍。

## Demo 运镜试播

先配好 GSI 与 OBS，通过 MulNX 打开 CS2 并加载 Demo。在“MulNX 游戏交接”检查实例，点击“运镜试播”，即可使用临时比赛资料进入工作台，无需创建测试赛或准备正式比赛。

进入后连接 MulNX、确认隔离包，手动试播已有预设中的开场和回合镜头。连接、试播、接管、跳过与断开沿用同一原生租约；预设编辑和自动恢复在正式准备流程完成。试播仅要求新鲜的地图与选手数据，不要求正式系列赛地图绑定；自动运镜在控制器和 HTTP 入口均保持禁用。试播期间正式资料、检查点、采集和在线输出保持隔离。退出先切 OBS 等待画面并恢复资料，再解除借用，游戏继续运行；异常重启也只清理这次外部试播的数据隔离。界面进入试播及 GSI 就绪不作为已加载某个指定 Demo 文件的证明。

此路径的 Windows / CS2 / MulNX 实机效果需使用包含本变更的候选验收；旧 alpha.1 不包含该入口。

## 最小上游协作接口（待协作，尚未实现）

2026-10-17 再次核对 main 与发行接口未变。本轮未联系上游作者。以下为后续协作所需语义，不向现有 MulNX 假发这些命令：

| 必需语义       | 最小数据与判定                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 就绪与实际实例 | 协议版本、服务器会话随机标识、真实游戏实例标识（PID/创建时间）、当前地图执行标识；明确数据是否仍有效。Mizar 必须能关联 Host 所选实例，端口相同不够 |
| 实际调度归属   | 活动包名、**已加载到内存**的包修订/摘要、自动回合列表及当前控制方；切包、列表或控制方变化须推送失效。仅磁盘文件或 Apply 的入队回执不够             |
| 关联执行回执   | 每条命令带唯一请求 ID、服务器/地图代际、截止期限；分开返回 received/queued 与 started/completed/failed，包含宏不存在、实例不符、过期等失败原因     |
| 停止与撤销屏障 | 接管/取消须清除对应代际的待执行与运行镜头，返回实际停止屏障；游戏线程恢复时先拒绝过期/旧代际命令，再处理新任务。清空请求的入队不能替代屏障         |
| 断连与人工让渡 | 控制租约或等价失效规则；断连、换图、人工接管使旧自动意图无效，旧请求不因重连复活。上游自身 `OnNewRound` 也应服从同一控制归属                       |

这些能力到位并实测前，状态保持 `execution: unconfirmed`；实际镜头同步、可靠停止与旧队列撤销仍是缺口。命令排序、拒绝迟到任务必须在最终执行方实现，Mizar 不能用新的本地计时器伪造。

## 2.0.0-alpha.1 游戏内验收交接

以下均为 **待实机验收**。在主会话审查 PR 后，为指定提交构建首轮运镜试用包 `2.0.0-alpha.1`（不是完整 2.0 RC）；不把云端单测、浏览器或 WebSocket 模拟标成 Windows/CS2/OBS PASS，不在此任务发布版本。

1. 记录 Mizar commit/试用包摘要、MulNX 发行版本/文件摘要、CS2/Windows/OBS 版本、地图、实际包名及录制时间。使用受支持的 MulNX 启动方式；按上节先准备专用隔离包，启动 Mizar 配好 GSI/OBS，再通过 MulNX 启动 CS2；准备真实比赛与数据源后，从“MulNX 游戏交接”检查并借用所选实例，进入原生工作台；备用浏览器路径也从准备中心进入（直接只打开 `/workspace` 不会开始制作）。记录原始窗口、画质/帧率与配置摘要，核对借用前后未被修改。
2. 在 MulNX 手动选刚加载的唯一隔离包，记录其磁盘元数据、实际包名；在人工模式跨至少两个回合确认原 `OnNewRound: [begin]` 没有播放。使用原 Mtp 名、缺失根目录或修改隔离元数据时，Mizar 必须禁止启用/试播。随后核对可用宏；在设置添加空白地图条目，填写自己选出的候选，保存。试播开场和回合候选，逐个核对镜头/时限/停止后的正常观察；不合适的删除或修改。测试不存在的宏时，Mizar 最多显示入队/执行未确认，不能显示播放成功。
3. 导入自有或合成音频，配置七组阶段音乐及本图开场音效。录制实际 OBS 开场 Take，检查音效只发生一次，BGM、游戏声和麦克风混音不被改变。不能因只有镜头 ACK 就起音；对照节目阶段与镜头真实开始的差异。
4. 在热身先连接并确认活动包、启用自动；按实际比赛进入首回合开场、后续冻结期、战术/技术暂停、中场、图终/赛终。镜头未结束时，从冻结期进入战术暂停、从旧阶段切入实际开场 Take，核对各自只触发一次新镜头；延迟清空回执超过一秒时不补播。重复遥测/界面刷新不重触发；记录每个阶段实际宏、声音和网关状态。在冻结末段启动后进入实战，核对同回合镜头持续到所选时限；已经进入实战后才启用自动时不补发冻结期镜头。
5. 镜头期间点接管，确认全部槽清空并能正常观察；保持期间后续回合不抢控制。显式恢复只等下一边界。另测跳过只结束本次、试播后保持人工、Program 人工保持时停止自动镜头。无上游手动接管事件时必须按按钮。
6. 分别注入 MulNX 断联、晚回复、不回复、错误回包、GSI 过期/恢复、同图重开、换地图及 Companion 重启。确认本地不补播、旧回复不解除人工状态；在新图手动选包并重新确认。游戏线程停顿后排队命令的实际行为另记，无法可靠撤销则为联调缺口，不能勾选通过。
7. 检查过期实例选择、不同安装、多个 CS2、已有恢复事务和活动 Demo 均拒绝借用；正常退出工作台及退出 Host 后外部游戏仍存活、设置不变且没有游戏停机/回收资格。模拟 OBS 收尾失败，确认先保持人工、未解除借用且可重试。原实例退出/另开实例后检查借用失效与旧连接断开，不自动选择新进程；Host 异常关闭而 Companion 存活、GSI 持续新鲜时，记录最后续约及失效时刻，核对六秒期限后不再发新镜头；先不重启 Host，在设置尝试重连/启用/试播均应拒绝。再重启 Host，旧原生会话应在显示界面前锁定，必须先结束制作再重新借用，不创建受管恢复记录。实例不唯一后的重连同样拒绝；延迟旧心跳/清空回执不能解锁。成功结束制作后显式切浏览器模式，确认其正常编排不受 Host 重启或旧原生消息影响。核对原生面板、“返回游戏”、隐藏/退出，以及不同权限、DPI/全屏下的实际表现；不把句柄检查当作 OBS 捕获成功。
8. 导出候选 JSON，重启核对；再导入回草稿，确认保存前无影响；损坏 JSON、缺失音频和错误地图保持原预设。将通过的候选与游戏/OBS 录制、诊断包一起交回，未验证内容不设默认。

尚需上游/后续工作：关联执行/完成/失败/停止事件、活动包与资源查询、能力与可信游戏实例身份、队列期限/撤销、可靠控制让渡，以及官方启动器的自动启动契约（本轮仅显式借用已启动游戏）。安装器、注入、HSI 正式事件归一化和运镜引擎均不在本次范围。

默认启动方式可在设置 → 游戏连接 → CS2 启动设置选择并保存。新安装默认 MulNX，已有配置保留原选择。选择 MulNX 后，“进入工作台”准备游戏路径、GSI、原始控制台与官方工具，调用支持 `launch-protocol.txt: 1` 的 `--launch-result` 入口。官方启动器在实际启动前检查环境，成功路径不显示 MulNX 页面；Host 核对返回的 PID、创建时间与游戏路径，沿用原生借用及运镜租约进入同一次工作台操作，不再跳到设置页要求人工交接。游戏主线程恢复不等于游戏内网关或地图就绪，实际运镜仍须单独连接与验收。

未支持该入口的官方版本明确提示更新，不使用旧 `autoLaunch` 跳过检查，也不退回手动页面冒充一键成功。冲突提示由官方结果给出，用户正常退出对应程序后重试；Mizar 不自动终止其他游戏。启动失败、超时、不完整结果、进程身份变化均不进入制作、不自动重放启动请求；失败回执必须明确给出布尔型收尾状态，缺失时不能声称游戏已收尾。已有游戏和恢复事务沿用原门禁；独立启动的外部游戏仍须从原交接入口显式选择。借用保持外部设置和生命周期，退出工作台不会关闭外部 CS2。

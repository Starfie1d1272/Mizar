# 技术诊断回传

本入口负责技术诊断的回传同意、可靠待传队列及云端容量边界；本机证据主体、脱敏与人工导出仍由[架构中的诊断规则](architecture.md)负责。自动回传不修复或证明任何现场 HUD 根因。

## 当前实现阶段

Companion 待传队列已接入生产启动；高级设置默认只展示自动发送状态和操作，数据类别、维护者管理的 Cloudflare 接收方、七天正文保留及退出方式在首次启用时说明，预算与批次放进详情。未配置接收端时不能保存启用同意，仍可导出本机报告。现场底栏及设置可标记问题时间并保存当前性能上下文。正式桌面产品默认使用维护者接收地址 `https://mizar-diagnostics.duxinyu475.workers.dev`，使用者明确开启自动发送后才建立回传。开发与资格验收不设置默认地址；`MIZAR_DIAGNOSTICS_ENDPOINT` 可覆盖地址，空值关闭接收地址配置。云端接收开关与免费额度独立管理。任务关联、异常输入窗口与受管控制台各自按真实生产者和读取链验收，不能因队列或设置测试通过就宣称全部采集完成。

## 同意、暂停与撤回

桌面准备中心在接收端可用、尚未开启时提供一次说明弹窗，发送选项默认勾选；只有用户看到说明并点击「确认并继续」后才提交启用同意，此前不发送。取消勾选后确认或直接关闭弹窗都保持关闭，并在本机网页存储记住选择；清理该存储后可能再次出现，不能以此记录代替回传同意。已开启、制作中或接收端不可用时不显示，其他弹窗或正在输入时延后。高级设置始终保留手动入口。

使用者必须明确获知上传的是技术诊断而非匿名数据，可能包含机器、路径、赛事和选手标识；密码、令牌、Cookie、推流密钥等凭据精确脱敏，保留排障所需上下文。不得补传同意前的记录，不上传音视频或私人聊天。未知聊天与队内/私聊不能默认上传。当前待传副本排除聊天字段和聊天阶段；本机人工导出与云副本范围不同，不得据此声称原日志完整上云。

开启同意持久保存后，立即采集当前制作、节目、运行、HUD、比赛绑定及 OBS 配置基线，进入同意后的正常日志与待传队列；不补传启动时的旧快照。基线落盘失败时该次请求报告失败，重新提交开启操作会重采当前状态，不能仅凭同意已保存跳过采集。

暂停只停止网络传输，保留同意、待传副本和本机记录，跨重启保持暂停状态；恢复发送须先持久保存设置，失败回到已保存状态，旧请求不能覆盖更新的暂停意图。恢复后继续使用原批次身份。撤回与暂停是两个明确操作。

关闭先使内存同意失效并中止进行中的请求，立即写入独立且同步的撤回标记，再按串行事务持久化撤回意图并清除待传正文。状态文件写入失败时保留标记，重启先强制关闭旧同意并恢复删除意图；不能仅因内存已关闭就报告落盘成功。并发开关按请求顺序处理，旧启用请求不能擦除后续撤回标记。从未尝试登记的本地身份不创建无意义的云端删除请求。网络已经送出的字节不能收回；云端删除只有在收到相同安装身份的完整删除确认后才算完成。断网时保留删除意图，界面应显示待同步，不能显示已经删除。再次同意使用新的随机安装身份；旧身份删除按各自持久退避继续重试，未确认状态仍保留，但不阻止新同意后的登记与发送。暂停只限制当前发送，旧删除请求仍可同步；两者的超时和退避分别处理。旧状态只有明确记录为删除阶段的失败，才把原全局退避转给对应撤回身份；登记、许可和上传失败仍保持原退避。未同步撤回最多八份，达到上限时先同步，不能无限积累身份。

## 本地可靠性

队列从已提交的固定 Host、Companion 与文档来源生成集中技术投影，保留真实 producerKind/producerRunId；不把 Host 正文再包进 Companion。每个获准进程会话保留同意起点和源游标，重启只补入仍有安全来源且在同意范围内的记录，不读取任意私人文件。游标达到上限时保留未完成恢复并报告容量阻塞，不把未登记的新生产者当作已扫描；已有游标不会仅为腾位被遗忘，源日志仍可能按原预算轮转。日志已轮转、过期、损坏、超载或过大事件分别标记缺口，不能把采集器零丢帧或上传成功当成全链完整。

收集先固定来源游标的连续前缀，再按真实生产者分组，避免同一载体内文档与 Companion 交错时生成单事件小包。该前缀的全部 gzip 文件先同步，再一次提交队列引用和源游标；提交失败不推进任何来源，只清理本次新建且未提交的文件，已有批次保持原字节。未被队列引用不等于没有独有证据，重启不能仅凭“孤立”删除原包。网络失败、错误身份/摘要、拒收或确认丢失都保留批次，重试使用相同 SHA-256 身份。封装写入中断或文件已同步而队列引用尚未提交时，重启按原始批次和同一接收许可重新生成预期字节。有界核对全部字节一致后复用；若只留下精确前缀，则在核验过的同一普通文件句柄上仅补齐缺失后缀并同步，失败仍保留可核验前缀。非前缀冲突保留原始包与冲突文件，该批明确转为仅供人工导出，不增加确认数，也不阻止后续批次。状态提交失败保留已存在的原件，不将文件存在当作确认。接收确认持久后，逐项核对当前 event/2 批次的源事件、生产者、序号和技术投影覆盖；覆盖成立才释放精确传输副本，不另写 migrated 正文。原始来源缺失或覆盖无法核实则保留已确认 wire 并报告原因，不将它假装成新的本机原文。旧 event/1 队列和孤立旧包只作有界格式识别，不接纳为当前证据、不迁移或自动删除；确认属于旧格式的队列引用移出当前计账，正文原地保留，不能占满当前版本的入队额度。云 ACK 本身不授权清除本机唯一证据。

单批展开不超过四 MiB、压缩不超过 512 KiB、最多 4096 个事件；不合尺寸先拆小批，单条仍超限时标记云副本缺失，原始本机日志保持原有保留规则。内存待处理不超过 8 MiB，持久待传正文不超过六十四 MiB，最多 2048 批且状态文件最多两 MiB；队列满时不静默淘汰未确认批次，而是停止新增副本并显示积压，源日志仍按其既有预算轮转。重启恢复若因满队列暂停，保留恢复状态，确认释放容量后继续读取仍在保留范围内的源记录；不能将扫描提前停止当作恢复完成。批数、内存或 manifest 预算阻塞也保留未完成恢复及源游标；只有完整扫描并接纳来源前缀后才清除恢复状态，不能仅凭源序号/提交时钟稳定推断完成。后台补读可暂存在既有内存缓冲中，按正常收集周期封存；持久游标只随批次提交推进，重启仍从原日志恢复。manifest 超限的新包回滚后仍允许发送已持久包，确认释放空间后继续恢复。恢复期间实时提交不越过磁盘快照中的旧记录；同时观察序号分配和持久提交通知，扫描前已分配但扫描后才落盘的尾部记录在后续有界扫描中补齐，避免误报序号缺口或漏掉尾部。活跃文件尚未换行的尾部保留恢复状态等待写入完成；已经轮转封存的段不会再补写，其截断尾部按 `truncated_sealed_journal_record` 报告损坏并继续恢复后续健康段，原段字节不修改。该原因计数表示恢复时遇到的损坏观测，不声称唯一事件数；持久状态与后续批次 coverage 保留该证据。维护读取器也限制实际解压大小，不能信任上传端声明。服务端明确告知旧批次已超过保留期时，客户端持久标记该批本机保留、云端范围不可用；不能伪造确认、丢弃正文、悄悄延长服务端保留时钟或让这一旧批永久挡住新记录。跨重启仍保留这一状态与具体缺失计数。

已确认 wire 每轮最多核对四份，共用一次生产者固定范围；下一轮从尚未尝试的候选继续并循环回到前面的保留项。只以原 SessionJournal、性能 owner 和 DesktopLog 已提交的 delivery pin 所保护的源证明覆盖，直到传输副本删除及队列状态持久化结束才释放；未取得保护、已过准入期限、取消或覆盖不足时保留 wire，不阻挡以后有完整证明的批次。运行中的持有不因准入期限经过而失效；Host 通过固定 UUID 请求文件核验请求进程的系统创建身份，重启后仍保护同一存活请求，撤请求或进程结束后由原 owner 清理。释放失败记录 ack_pin_release_pending，下轮先重试同一释放，不能不断积累新 pin；关闭时未完成也明确报告。每轮各 owner 仅准备和提交一次，canonical 仅扫描一次；Host 先在原 owner 中登记最多四个临时保护范围，再离锁核验全文，提交回执后才移交保护；公开请求不能通过改传 kind 释放内部 delivery pin。Host 的原 owner 与跨进程回执仍各自核验原件，最多五遍逻辑读取，不代表实测耗时倍率。未确认、无 canonical 覆盖或不同正文的 wire 不删除，不恢复旧迁移或复制原文。

Host 启动前只恢复完整且身份、来源范围及 prepare→commit 转换一致的临时 pin 元数据；发布失败保留已完整同步的替代记录。截断、不一致或无法读取的记录原地保留，保护范围未知时暂停原件删除，仍可在既有一百 MiB 普通预算内记录后续操作；预算不足按既有丢失状态公开缺口，不继续增长。诊断保留或首次写入失败不阻止桌面启动，不将损坏记录等同已释放。元数据协议与进程实例核验是 DesktopLog 的私有模块，正文、保留和固定范围仍由同一所有者与锁管理。

请求仅向配置的 HTTPS 固定源发送，禁止重定向；仅测试允许回环 HTTP。使用每安装随机登记身份与随机登记证明，不在产品中嵌入共享服务密钥。登记和上传的令牌只保存在受控队列状态中，不能纳入诊断正文。正常记录按二十分钟收集一次，接近内存预算时提早持久化；每次收集只处理开始时已接纳的记录前缀，压缩或同步期间新到达的完整记录留给下一次收集，避免持续输入被滚动拆成大量小包；主动问题标记提前至十五秒内收集；错误保留完整正文随正常批次发送，异常高流量则由内存阈值提早持久化。每五秒后台轮询最多串行发送四批已经持久的副本，未取得新确认即停止本轮；不新增队列或定时器，也不为每次补读制造小包。重启与关闭会补存尚未打包的记录。临时网络失败退避最小三十秒、最高十五分钟并跨重启保存；新会话或明确恢复允许一次受限探测。服务器 Retry-After、额度、永久拒收、暂停与撤回独立处理，不被该探测绕过；过期批次变为仅供人工导出，不堵住后续合规新批。关闭同意不等待退避。该批次与预算设置仍须以包含最终采集器的容量模型复核，不代表已批准云端额度。

本机持久保留接收端的额度、短时限流、接收暂停与身份拒绝原因，设置页分别说明，并按服务端 Retry-After 显示重试时间；这些状态不能解释为使用者未同意。旧接收端的 `permit_budget` 仍显示为发送额度暂不可用，缺少重置时间时沿用有界退避，保留未确认批次。

## 任务与操作关联

打开工作台、返回设置、隐藏工作区、结束制作，HUD 另存为/保存/启用，以及恢复处理入口创建明确根任务。浏览器文档、Companion 进程会话、Host 进程会话、根任务与每个子操作分别保留身份；并发操作显式传递上下文，不依赖浏览器全局的“当前任务”。HTTP 与原生子操作均连接同一根任务，原始请求身份、参数、前后状态和错误链继续保留。入口已知时区分 user/system；未声明任务的旧边界明确记为 unattributed，不把未知触发来源猜成用户或系统。

观察链路与运镜会话的内部 `pulse` 仍逐次执行业务续期。同一路由、Host／租约、制作／节目／HUD／比赛绑定及响应事实不变且已确认成功时，复用五秒摘要保留首末时间、次数及请求引用；首个完整操作链保存前后状态，后续摘要关联同一组而不重复正文。身份、上下文、响应变化或失败立即保留完整证据；显式用户／任务关联及非 `pulse` 命令不聚合，执行前进入既有日志写入链。新同意持久化后切断旧摘要组；延后补记的接收／起始事实保留各自来源时间，完成结果按实际发生时间记录。导出冻结水位前及关机时刷出剩余次数；聚合来源区间与次数进入统一覆盖证据，不把异步未提交尾部当作逐次持久回执。CS2 等只读原生状态继续使用现有快照变化记录与重复观测汇总；运行遥测仍由运行与性能记录保存。

预检受阻为 blocked，导航撤回进入意图为 cancelled；故障保留原始 cause。原生命令返回只证明其合同确认的阶段，恢复入口另读 Host 状态：仍有游戏、恢复、观战、试播清理或窗口待处理事项时不能确认完成；读回失败为 unconfirmed。HUD 成功以校验后的资源/编辑版本/播出版本响应为证据，不把草稿保存说成已经启用。

Host 在线程实际执行的范围内绑定任务与操作身份，退出每个阶段及每五秒等待记录均可关联；同步作用域不会泄漏到其他线程或系统工作。诊断字段只作关联，不影响资格、安全、身份与制作控制门禁。WebView 消失时根任务终态可能缺失，须结合 Host 结果判断，不能补造成功。原始 Host 文件继续由完整人工包保留；自动副本的读取范围、待处理量和缺口见下节，不能把局部成功或队列确认说成整个工作区已经完成退出。

任务合同验证复用 HUD 生产浏览器验收：操作、落盘、服务重启、启用、实际完整包导出，再通过生产读取器恢复根任务与子操作；独立覆盖并发任务、导航取消、失败 cause、恢复未完成及读回失败。原生日志模块的线程隔离测试与 Windows Host 实机证据分别记录，不能互相替代。

## 独立生产者与稳定身份

Host 自己写不可复用分段与提交水位，Companion 不再将整份 Host 正文转存到 SessionJournal。文档事件通过受限 IPC 批量交接，保持原文档 UUID、序号与 eventId；最多 64 条/256 KiB，收到持久回执后移出有界内存。业务动作不等待交接，交接前文档结束仍是未知；纯浏览器使用既有 HTTP 单一路径，不双投。

技术投影集中在一个适配器，只保留允许的技术字段、原时间、版本及源引用，排除聊天、同意前和时间未知记录并记明计数；不递归上传未知 payload。新事件为 `mizar-diagnostic-event/2`，wire 外壳仍为 `mizar-technical-diagnostics/1`，permit/ACK 合同不变。每批使用真实生产者 UUID；无法证明当前来源身份时拒绝封存并记录缺口，不读取旧版本日志补造身份。接收器先兼容版本/producer 元数据并核对正文，客户端通过 permit 响应能力标记确认后才网络提交 v2，当前 event/2 的不可变 /1 批次按原字节继续处理；旧 event/1 批次仅作有界格式识别并原地保留，不迁移、发送或自动删除。

来源身份包含文件/进程代际和序号或偏移，重放保持 ID；相同文本的两个真实事件不合并。恢复、转发与 carrier reference 不复制同一正文。截断、重写、源消失、非法编码、写盘失败与未提交尾部分别报告；没有新证据时不补造成功或全局因果顺序。Producer pin、源保留与人工 ZIP 的统一规则见[架构](architecture.md#诊断证据历史与导出)。

## 受管 CS2 技术控制台

本机播出另从同一已核验受管来源识别明确 `[ALL]` 文本，作为独立 `program_all_chat` 原生记录提交，并经 ProgramChat 自己的固定文件输入适配器交给有界临时 Program 展示，不依赖诊断 journal ACK。输入适配器逐条交付有界聊天记录，不建立诊断批次或额外记录身份；消息去重与新鲜度由 ProgramChat 按原生消息身份处理。TEAM、私聊和技术报错不进入此记录；ALL 记录服务本机短时节目输入；人工诊断和云副本均排除聊天正文，保留来源范围与排除原因。展示仅接纳写入区间完全晚于当前 Program 边界、且最近五秒内捕获的消息，不回放积压历史；本机技术采集关闭时该来源也停止。跨地图和断流清理及展示契约见[协议](protocol.md#公开实时输出)。

Companion 的聊天输入按 Host 实际保留的固定分段保存文件身份、偏移和邻接摘要，不假定最多四个文件。游标检查点读写共用 256 KiB、1024 个身份的独立预算；该预算容纳常态分段和短进程碎片，但不是 Host 保留文件数的上限。新增身份在读取正文前检查容量，超限保留已有游标并报告，已登记来源仍可推进。仅在本轮来源身份均已核验或明确不存在时回收已消失的游标；路径权限错误或身份未确认不能当作文件已删除。旧版写出的超预算检查点保持原件并暂停这一输入，不以较小快照覆盖或反复从头重读；来源原件与主制播流程不受修改。现有文件安全核验、单次有界读取及 Program 新鲜度守卫继续有效。

启用本机控制台采集后，每次受管启动 CS2 前先将已有非空 `console.log` 逐字节保存到状态目录的 `console-history/<SHA-256>.log`，同内容只保存一份。它包含原始游戏文本和可能的聊天，仅留本机，不进入支持导出、云上传或公开节目。副本独立于普通诊断日志轮转；下一次游戏重建源文件不覆盖旧副本。源文件不被 Mizar 清空或删除。每份最多 512 MiB、最多十六份、合计两 GiB，不自动淘汰旧场次；保存失败或预算不足时保留原件与具体原因，仅停用本次原始采集，不为本次启动添加写日志参数；普通游戏准备、工作台和本机显示仍可继续。提交前同时核对 Steam 保存启动项与 MulNX 原有参数；若用户参数仍会写入或清空旧日志，则保留恢复责任并提示移除该参数或先归档，不能假称原件安全后启动。采集或回执不可用时，仅跳过依赖该回执的自动隐藏游戏原生 HUD 操作并提示，不因这项失败停用 GoTV 连接、提前提示接收或本机 HUD；进程身份与连接资格仍须核实。外部自行启动游戏、关闭采集、磁盘损坏及尚未保存的进程崩溃不在这一跨启动保证内。

桌面权限仅允许准备中心更改此项同意；准备中心与运行诊断窗口可读取状态。原生命令须同时登记到构建命令清单和已启用的能力声明，避免界面存在但调用被 ACL 拒绝。

默认开启，由「游戏与观战」中的聊天上屏设置统一控制；旧设置首次升级自动开启，此后用户关闭会持久保留。只对本次由 Mizar 启动、以 PID／创建时间／程序路径核验并持有进程句柄的游戏观察固定 `game/csgo/console.log`，不接受调用者路径，不采集手动启动或无法证明身份的游戏。程序目录须为 `game/bin/win64/cs2.exe`，所有父目录与源文件拒绝链接／重解析点／硬链接，Windows 还核对实际打开句柄的最终路径。读取放在独立有界后台线程，复用既有进程证明与 DesktopLog 的独立持久分段；Companion 不再经 NativeSource 或 SessionJournal 镜像原生正文，不占用工作台生命周期／窗口跟随锁。

确认后仅在正常与保留设置的受管启动参数中增加 `-condebug`，实际参数仍逐次记录；不改 Steam 长期启动项，不加清空日志参数。游戏原始文件可能含聊天并持续增长，它不受 Mizar 自有归档预算控制；设置说明此点。Mizar 不清空、截断或删除该游戏文件。关闭立即阻止 Mizar 后续提交，独立持久关闭标记优先于旧启用文档；过时启用请求被版本条件拒绝，丢失确认后重试不重置读取起点。已发出的游戏日志开关只能在下次启动时移除，不能把停止 Mizar 读取说成原始游戏文件已停止增长。

启动前从 EOF 建立边界，不补采旧内容；同一游戏的 Host 重启按已持久游标恢复，重新同意从新的 EOF 开始，跳过关闭区间。每轮最多读取 256 KiB 源字节、接纳 256 条技术行和 128 KiB 序列化证据，未读积压留在原文件继续读；原始单行最多 16 KiB，超长、非法编码、聊天与未知行分别计数。识别引擎日志的 `MM/DD HH:MM:SS` 前缀后，按技术通道和消息前缀分类，保留原行与独立观察时间；纳入 `[Client]` 的两类 `CSVCMsg_UserCommands_t` 缺基线/无指令数据警告。支持 UTF-8／UTF-16 LE／BE 和跨读取半行；这不是对所有引擎输出的覆盖承诺。凭据精确替换，稳定记录身份仅散列脱敏文本，不能成为原凭据的指纹。完整技术行按稳定分片保存并由生产读取器重组，故障类别仅作索引。

Client 通道明确报告 Demo 网络版本不兼容时保留原始拒绝原因，并归类为引擎失败；可选技术日志不承担试播生命周期判定。

Host 使用约 1 MiB 的不可复用普通分段，合计 100 MiB、十四天的有界保留；活动关键证据、现场标记与导出 pin 在同一 owner 中保护，预算不足时明确拒绝新增持久承诺，不覆盖已封存段。技术分段先完成持久写入，再原子更新游标，失败保留原游标供重试；确认与游标提交之间中断允许按稳定身份去重，不能声称恰好一次。进程证明在读取／提交边界失效时停止，本次尾部未读范围明确标记；游戏已结束后不借旧 PID 继续读文件。按文件身份、长度与游标邻接摘要识别可观察的替换／截断；相同身份与摘要的隐蔽重写不能保证检测。未知、重复轮转、预算耗尽和断电未落盘均不能包装成完整。

引擎文本没有可靠事件 UTC 时保留“上次观测 EOF 后”至“本次读取完成”的写入区间；读取时刻只是上界。替换／截断后旧内容下界未知，新的已观测 EOF 后才恢复可证明下界。人工时间范围按区间重叠保守附上完整技术分组，未知区间仍附带并说明；混合 Host 分组逐条检查原始时间，任一普通操作或控制台区间匹配、或时间未知时保留完整组，不能用同组控制台时间代替普通 Host 故障时间；不拿 Host 轮询时间冒充游戏错误发生时间。云副本只接纳整个已知写入区间都在云同意之后的行，排除同意前、未知或时钟倒置的区间并保留计数，完整本机证据不因此裁剪。

控制台验证使用仓库已有原生/Companion 验证入口与公开合成输入，分别核对真实读取器、DesktopLog、ProgramChat 输入隔离、持久回执、接收器和支持包读取器。以实际执行报告为准，不保留不存在的资格命令，也不把代码或合成日志当作实际 CS2 格式、现场 HUD 根因或 Windows 实机通过。导出中的当前控制台设置/健康快照标明读取、超时或失败。

## 性能异常前后证据

既有十五秒运行时与浏览器聚合继续作为索引。Companion 另在内存保留最多三十秒、每二百五十毫秒一份的技术输入窗口：GSI 接收序号、地图/回合/炸弹计时、最多十六名选手的位置与状态，以及当前原始输入处理前的归一化、运行时和发布游标。字段按固定技术集合选择，不复制 auth、名字、聊天、武器清单或未知字段；字符串最多一百二十八字符，额外选手有省略计数。完整原始 GSI 仍在既有本机采集，不声称这一选集能够替代完整采集文件。

观察处理失败或超过五十毫秒、运行时拒绝观察、遥测诊断、输入静默/恢复、浏览器异常或主动问题标记触发持久保存。重复触发各自保留原因和关联，共享同一窗口，延长后续观察至最多三十秒；默认后续观察十秒。输入静默可能只是菜单或正常游戏行为，记录事实而不宣判卡死。主动标记只取得收到标记时尚在内存的窗口，不能补造此前未触发且已经丢弃的历史。

内存环最多一 MiB，单样本十二 KiB，异步待写两 MiB，分段最多一百二十八 KiB。窗口直接形成最终压缩正文并使用稳定来源身份，普通 journal 只保存引用，不先把 gzip/Base64 再搬进 Session。性能正文最多六十四 MiB 压缩、二百五十六 MiB 展开、四千零九十六文件，每包展开上限一 MiB；活动、导出、问题标记等 pin 由该 producer 串行确认。已覆盖且无 pin 的历史按有界策略回收，ACK 不等于可删所有本机证据。

窗口记录实际前后跨度、最近样本年龄、样本数量、省略和关闭中断。仅在内存的记录为 memory-only，已经提交的引用必须能找到正文；坏包逐份隔离、空间和 I/O 不足保留缺口，不能将后续恢复悄悄改成先前标记成功。原始 UTC 用于范围与云同意检查。人工导出固定各来源水位/句柄和 pin 后逐条读取，新版待传独有正文只解码一次，carrier、唯一事件和聚合次数分别计数；不同来源的取值时刻不同，不声称跨进程原子快照。

窗口可能在同意后才触发但含有同意前的内存样本。云副本逐样本检查原始 UTC 接收时间，只保留本次同意起点之后且时间有效的样本，保留云副本排除计数与本机范围说明；不得仅凭窗口写盘时间补传同意前样本。本机完整窗口不因此删减。

浏览器保留 Mizar 文档自身的未处理错误与原始 cause，排除可识别的外部脚本来源。雷达完成 Canvas 绘制后才推进独立绘制序号，按秒观察最多八块自身画布。页面可见、实时通道仍接收较新输入且非主动暂停时，绘制序号三秒不变才记录绘制未推进；静态预览、隐藏和主动暂停单独标记。页面 RAF、网络接收和绘制完成分别举证，均不证明 GPU、OBS 捕获或观众端画面正常。

验证包含实际 GSI 入口、浏览器异常、前后不同输入状态、落盘关闭、进程重启、完整支持包导出及分卷摘要验证；另外覆盖文档 RAF 继续但雷达不推进、暂停排除和关闭时后置未完成。Windows/OBS/CEF 的真实表现仍需实机证据。

窗口自身的同步交接成本可用 `pnpm --filter @mizar/companion exec tsx test/support/measure-performance-window.ts` 复测：公开合成十六人数据，两小时二十 Hz 输入与一百二十次异常窗口，通过现有 PerformanceWindow 与有界持久正文 writer 实际写盘；输出同步耗时分位数与丢失、内存、写入健康。该加速工具只测窗口交接，不代表适配器、Core、渲染或 Windows 游戏延迟，也不替代最终集成后的上传容量模型。

## 云端存储与费用边界

实际资源、权限和 secret 配置见[诊断接收器部署](../development/diagnostics-cloud-deployment.md)。各版本的部署状态以部署回执、实际能力和经同意的批次确认为准。新客户端须取得接收器的 v2 能力确认后才封存/发送新事件批次；未升级时保留来源并显示 receiver_upgrade_required，已有新版 event/2 的不可变 /1 批次不重编码或重签；旧版本来源不进入当前投递路径。

源码中的接收器配置默认拒收、预算为零；客户端正式默认地址、实际部署和线上配额是不同事实。经使用者确认，私有 R2 保存完整脱敏 gzip 正文，D1 保存检索索引。每批创建后最多九十天自动发送，安装身份有效期同为九十天；客户端到期自动换新随机身份，旧未确认批次保持原字节和摘要，只供手动导出，不能重新签名或冒充已收到确认。新身份不重新签发已有批次；之后入队的记录仍按原始来源时间和同意边界检查。同意修订为 `technical-diagnostics-v3`；旧同意启动时先以独立策略标记持久关闭，须重新明确确认；未确认原包保持原字节供手动导出。策略标记跨重启不等于用户主动关闭并删除副本，之后重新同意也不自动发送这些旧包。

正文从首次签名许可起最多七天，且不超过原包创建后九十天；重试不续期。可识别的会话索引自最后一次接收保留九十天。原始 gzip 的 RFC 1952 MTIME 在首次持久化前一次写定并纳入 SHA，许可绑定该时间；同一原包的最小接收围栏在该时间后九十天删除。围栏清除后，同一旧原包仍因超出自动发送窗口而拒收。重写 MTIME 会改变原包摘要，属于不同包，不能说成原摘要续期。时间缺失、超出五分钟未来容差或过期均保留明确原因和本机副本。

接收端先核对压缩字节摘要、签名许可、登记绑定和撤回状态；同字节且规范化索引一致的已确认重试直接返回原确认。确认重试沿用原预留；索引冲突的副本保留在本地并停止自动重试。需要存储的新 event/2 正文才解压并核对索引。

全局批数预算保护请求、D1 行写入及 R2 操作成本；全局与单安装字节预算保护正文容量，不再限制单安装每日批数。正文批数和字节预算在首次预留时原子计入。已有 `pending`／`failed` 批次重试复用原预留，不重复扣款，即使当日新批额度耗尽也允许恢复这份原证据；仍检查身份撤回、过期和并发写入者上限，保留 IP 请求限流。许可、正文和已确认索引计数分别表达其阶段，不能把预留数量称为成功接收数量；旧版本已重复计入的历史预算不会被自动追溯退还。日批数、全局日字节和单安装日字节耗尽分别返回明确原因，Retry-After 指向下一 UTC 日；短时 IP 限流等待六十秒。既有持久退避跨重启遵守该时间，预算停收与用户暂停分开显示。

安装采用含创建时间的随机 UUIDv7，无机器/MAC 标识；服务端按固定创建时间拒绝过期身份再登记，短期令牌不跨过该身份的九十天期限。安装登记和撤回记录在身份到期且相关正文、会话索引均清除后删除，正常最迟约创建后一百八十天（最后一刻接收的索引仍需满九十天），随分批 Cron 清理推进；没有正常永久围栏。客户端最多保留八份待关闭/旧身份所有权，确保轮换后仍可撤回旧数据；旧索引最长寿命到期后向服务器确认关闭，收到真实关闭确认前不丢弃删除证明。达到预算则暂停续期/发送并明确保留本机记录。确有未结束写入者的客观不确定记录只保留必要隔离信息，受分配预算硬停止保护，状态仍为待处理，不能冒充正常到期清理完成。实际资源、清理证据与费用统一见部署审查入口。

正常使用预算须依据新版实际事件量和压缩量实测，再给单场、每日多场和多用户容量预测。旧支持包和跨比赛 OBS 日志只能说明既有材料体积，不能当作新版每场上传量。预算保护与异常滥用保护分别设计；不能通过删掉失败、重试、原始 cause、状态转移或性能停顿上下文来缩小流量。

R2 免费额度是账户共享资源，应用限流、费用告警和应用自身容量统计不构成全账户零元硬封顶；不承诺其他应用使用量可被实时感知。不升级账户或购买付费能力，接近获批预算时暂停接收并明确显示本机积压与未上传范围。维护操作限于诊断接收器的绑定、密钥和数据，正文按既定保留规则清理，不修改或删除其他桶及生产数据。

Companion 的同一串行日志写入器将关键证据与普通观察分别写入不可变分段，共用事件身份、提交顺序与普通保留预算，不复制正文。关键段继续受活动 pin 保护，普通段可按既有预算回收；导出与问题标记先封存两类分段再固定范围。恢复按原日志序号归并两个物理流，并以扫描开始时已提交的水位为截止，不能按单个文件的高序号越过另一文件的旧记录。关键证据本身耗尽预算、写入失败或未提交尾部仍明确报告，不因关闭而释放保护或宣称完整。

问题标记在启动时恢复已有持久 reservation，成功确认解除相应来源当前阻塞并保留历史失败原因。新标记先取得各 producer 串行区内的 prepare 回执，共享协调器按最多八份、共同引用的唯一正文合计六十四 MiB 预留预算，再确认 commit；Host 的实际回执来自固定受控文件而非前端自报。现场标记保存范围、事件/窗口引用和持久 pin，不重新压缩全部日志。部分来源没有回执、预算不足或写盘失败时明确未完整标记，并保留原证据，不把单条 marker 当完整现场保存。

导出、取消和失败释放对应短期 pin；现场标记以其持久语义保留，不因普通轮转、云 ACK 或服务重启自动消失。坏源逐个报告，其他来源继续可用。标记前已经丢失或标记后尚未发生的证据无法补造；Demo 中标记只观察诊断，不获得正式比赛或自动编排权限。

进程身份读取失败先保存失败 API 的原始 Windows 错误码，再记录目标 PID、已取得的创建标识和同一持有句柄的即时等待结果。宿主记录的 PID 与被查询目标分开；退出观察不是权限结论，也不作为新的关闭或配置恢复授权，不记录原始窗口句柄或凭据。

## 验证职责

队列负责测试默认关闭、同意起点、脱敏、断网、进程重启补入、丢失确认与幂等、假确认、中途撤回、离线删除同步、不安全文件与解压上限；另覆盖并发同意开关、批次 fsync / 状态提交中撤回、回执提交失败回滚、撤回提交失败重启、完成游标回收和有界响应读取。真实 Worker/R2/D1 配额、Windows CS2 控制台、OBS/CEF 和实际网络的证据独立记录；合成服务测试不能冒充这些实机结果。

人工支持包的 `snapshot.diagnosticDelivery` 单独记录诊断回传是否可用、配置、同意及暂停状态、队列与阻塞数量、字节数、确认与失败次数、受控错误码和下次尝试时间；初始化不可用时未知字段为 `null`，不将未知当作关闭。错误文本不原样导出，未列入允许集合的错误标为 `other`。接收器返回的有限失败阶段可随传输状态保留，便于区分登记、许可、预留、对象写入、索引确认和清理。原有 `snapshot.delivery` 仍表示投影消费者状态。

状态保留关闭原因、最近实际网络请求尝试时间和最近经校验并持久化的批次确认时间；旧状态缺少这些字段时为未知，不由累计确认数推算。旧政策或无法解析安装身份创建时间导致的关闭需重新同意，用户关闭与此区分。支持包投影同意时间、关闭原因、遗漏原因、待同步删除和上述时间；初始化失败时这些字段为 `null`。确认只覆盖对应批次，不证明整场完整。

经 Mizar 打开官方 MulNX 前，仅在本次原始控制台已保全且采集准备成功时为启动器添加 -condebug；自行启动的外部游戏不属于接入路径，Mizar 不读取其控制台或事后拦截历史覆写。

传输失败区分连接超时、连接失败、请求超时、HTTP 拒绝及无效回执，保留实际阶段；连接超时不解释为接收端拒收。每次实际登记请求在本机记录独立关联号、端点的协议/主机/端口及默认或环境覆盖来源、Node 版本和代理配置是否存在；不记录代理地址、凭据、请求正文或完整请求 URL。代理开关只代表配置，实际网络路线仍为未验证。登记响应和失败沿用该关联号及单调时钟耗时，中断及迟到响应保留中断标记；收到 HTTP 响应不代表回执有效或批次持久确认。端点和网络上下文只留本机，不扩展云端字段范围。登记确认成功即解除该阶段的旧失败与退避，即使尚无可发送批次；它不清除上传失败，也不增加批次确认数或最近确认时间。

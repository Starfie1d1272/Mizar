# 技术诊断回传

本入口负责技术诊断的回传同意、可靠待传队列及云端容量边界；本机证据主体、脱敏与人工导出仍由[架构中的诊断规则](architecture.md)负责。自动回传不修复或证明任何现场 HUD 根因。

## 当前实现阶段

Companion 待传队列已接入生产启动；高级设置默认只展示自动发送状态和操作，数据类别、维护者管理的 Cloudflare 接收方、七天正文保留及退出方式在首次启用时说明，预算与批次放进详情。未配置接收端时不能保存启用同意，仍可导出本机报告。现场底栏及设置可标记问题时间并保存当前性能上下文。正式桌面产品默认使用维护者接收地址 `https://mizar-diagnostics.duxinyu475.workers.dev`，使用者明确开启自动发送后才建立回传。开发与资格验收不设置默认地址；`MIZAR_DIAGNOSTICS_ENDPOINT` 可覆盖地址，空值关闭接收地址配置。云端接收开关与免费额度独立管理。任务关联、异常输入窗口与受管控制台各自按真实生产者和读取链验收，不能因队列或设置测试通过就宣称全部采集完成。

## 同意、暂停与撤回

桌面准备中心在接收端可用、尚未开启时提供一次说明弹窗，发送选项默认勾选；只有用户看到说明并点击「确认并继续」后才提交启用同意，此前不发送。取消勾选后确认或直接关闭弹窗都保持关闭，并在本机网页存储记住选择；清理该存储后可能再次出现，不能以此记录代替回传同意。已开启、制作中或接收端不可用时不显示，其他弹窗或正在输入时延后。高级设置始终保留手动入口。

使用者必须明确获知上传的是技术诊断而非匿名数据，可能包含机器、路径、赛事和选手标识；密码、令牌、Cookie、推流密钥等凭据精确脱敏，保留排障所需上下文。不得补传同意前的记录，不上传音视频或私人聊天。未知聊天与队内/私聊不能默认上传。当前待传副本排除聊天字段和聊天阶段；本机人工导出与云副本范围不同，不得据此声称原日志完整上云。

暂停只停止网络传输，保留同意、待传副本和本机记录，跨重启保持暂停状态；恢复发送须先持久保存设置，失败回到已保存状态，旧请求不能覆盖更新的暂停意图。恢复后继续使用原批次身份。撤回与暂停是两个明确操作。

关闭先使内存同意失效并中止进行中的请求，立即写入独立且同步的撤回标记，再按串行事务持久化撤回意图并清除待传正文。状态文件写入失败时保留标记，重启先强制关闭旧同意并恢复删除意图；不能仅因内存已关闭就报告落盘成功。并发开关按请求顺序处理，旧启用请求不能擦除后续撤回标记。从未尝试登记的本地身份不创建无意义的云端删除请求。网络已经送出的字节不能收回；云端删除只有在收到相同安装身份的完整删除确认后才算完成。断网时保留删除意图，界面应显示待同步，不能显示已经删除。再次同意使用新的随机安装身份；未同步撤回最多八份，达到上限时先同步，不能无限积累身份。

## 本地可靠性

队列只观察既有 SessionJournal 持久提交。每个允许采集的进程会话保存同意起点和已入队序号；重启只从固定的会话日志段补入该范围，不读取任意私人文件。日志已轮转、过期、损坏、超载或过大事件分别标记缺口，不能把采集器零丢帧或上传成功当成全链完整。

gzip 批次先写入独立文件并同步；队列引用和源游标写入同一原子状态文件后才允许上传。重启删除未被该状态引用的孤立批次。网络失败、错误身份/摘要的确认、服务端拒收不移除批次；确认丢失后以相同 SHA-256 批次身份重试，服务端必须幂等。收到确认后先原子更新队列；提交失败必须恢复内存队列供相同批次重试，再删除正文，删除失败留下的孤立文件可在初始化清理。

单批展开不超过四 MiB、压缩不超过 512 KiB、最多 4096 个事件；不合尺寸先拆小批，单条仍超限时标记云副本缺失，原始本机日志保持原有保留规则。内存待处理不超过 8 MiB，持久待传正文不超过六十四 MiB，最多 2048 批且状态文件最多两 MiB；队列满时不静默淘汰未确认批次，而是停止新增副本并显示积压，源日志仍按其既有预算轮转。重启恢复若因满队列暂停，保留恢复状态，确认释放容量后继续读取仍在保留范围内的源记录；不能将扫描提前停止当作恢复完成。批数、内存或 manifest 预算阻塞也保留未完成恢复及源游标；只有扫描与待处理前缀持久化都完成才清除恢复状态，不能仅凭源序号/提交时钟稳定推断完成。manifest 超限的新包回滚后仍允许发送已持久包，确认释放空间后继续恢复。恢复期间实时提交不越过磁盘快照中的旧记录；同时观察序号分配和持久提交通知，扫描前已分配但扫描后才落盘的尾部记录在后续有界扫描中补齐，避免误报序号缺口或漏掉尾部。活跃文件尚未换行的尾部保留恢复状态等待写入完成；已经轮转封存的段不会再补写，其截断尾部按 `truncated_sealed_journal_record` 报告损坏并继续恢复后续健康段，原段字节不修改。该原因计数表示恢复时遇到的损坏观测，不声称唯一事件数；持久状态与后续批次 coverage 保留该证据。维护读取器也限制实际解压大小，不能信任上传端声明。服务端明确告知旧批次已超过保留期时，客户端持久标记该批本机保留、云端范围不可用；不能伪造确认、丢弃正文、悄悄延长服务端保留时钟或让这一旧批永久挡住新记录。跨重启仍保留这一状态与具体缺失计数。

请求仅向配置的 HTTPS 固定源发送，禁止重定向；仅测试允许回环 HTTP。使用每安装随机登记身份与随机登记证明，不在产品中嵌入共享服务密钥。登记和上传的令牌只保存在受控队列状态中，不能纳入诊断正文。正常记录按二十分钟收集一次，接近内存预算时提早持久化；每次收集只处理开始时已接纳的记录前缀，压缩或同步期间新到达的完整记录留给下一次收集，避免持续输入被滚动拆成大量小包；主动问题标记提前至十五秒内收集；错误保留完整正文随正常批次发送，异常高流量则由内存阈值提早持久化。五秒后台轮询逐批发送已经持久的副本，不为每次轮询制造小包。重启与关闭会补存尚未打包的记录。退避由 30 秒增长到最多约六小时并加抖动；关闭同意不等待退避。该批次与预算设置仍须以包含最终采集器的容量模型复核，不代表已批准云端额度。

## 任务与操作关联

进入、隐藏、退出工作台，HUD 另存为/保存/启用，以及恢复处理入口创建明确根任务。浏览器文档、Companion 进程会话、Host 进程会话、根任务与每个子操作分别保留身份；并发操作显式传递上下文，不依赖浏览器全局的“当前任务”。HTTP 与原生子操作均连接同一根任务，原始请求身份、参数、前后状态和错误链继续保留。入口已知时区分 user/system；未声明任务的旧边界明确记为 unattributed，不把未知触发来源猜成用户或系统。

预检受阻为 blocked，导航撤回进入意图为 cancelled；故障保留原始 cause。原生命令返回只证明其合同确认的阶段，恢复入口另读 Host 状态：仍有游戏、恢复、观战、试播清理或窗口待处理事项时不能确认完成；读回失败为 unconfirmed。HUD 成功以校验后的资源/编辑版本/播出版本响应为证据，不把草稿保存说成已经启用。

Host 在线程实际执行的范围内绑定任务与操作身份，退出每个阶段及每五秒等待记录均可关联；同步作用域不会泄漏到其他线程或系统工作。诊断字段只作关联，不影响资格、安全、身份与制作控制门禁。WebView 消失时根任务终态可能缺失，须结合 Host 结果判断，不能补造成功。原始 Host 文件继续由完整人工包保留；自动副本的读取范围、待处理量和缺口见下节，不能把局部成功或队列确认说成整个工作区已经完成退出。

任务合同验证复用 HUD 生产浏览器验收：操作、落盘、服务重启、启用、实际完整包导出，再通过生产读取器恢复根任务与子操作；独立覆盖并发任务、导航取消、失败 cause、恢复未完成及读回失败。原生日志模块的线程隔离测试与 Windows Host 实机证据分别记录，不能互相替代。

## 固定 Host 日志增量读取

Companion 在后台读取同一 Mizar 日志目录中的 `desktop.ndjson`、`desktop.1.ndjson` 至 `.3.ndjson`，不接受浏览器提供的路径，也不遍历其他软件。固定来源依然拒绝符号链接、硬链接、非普通文件、变化的文件身份及超过 Host 二十五 MiB 单文件预算的来源。每秒每文件至多读取二百五十六 KiB；逐组等待既有 SessionJournal 持久确认，单组不超过一百九十二 KiB。不会在 GSI 接收回调中读文件或等待同步。单个来源失败不会反复回退其他可信文件的游标。后台采集清除恰好触发刷新请求的上下文，不能把整组原生记录误挂到导出请求的用户任务；每条内部仍保留原始任务身份。

每条保留原始 Host 会话、UTC 时间、阶段、参数、原始错误、任务和操作身份，另附源文件身份、字节偏移及稳定 `sourceRecordId`。复用旧 Companion 的新 Host 也按其原始身份保存，不按旧 Companion 启动时的 Host 编号过滤。原始凭据继续精确脱敏，可选 CS2 技术控制台使用下述独立同意和来源边界，不等于采集完整游戏控制台。

有界游标文件在日志组持久确认后才原子写入；确认失败回滚源游标。日志已持久但游标写入失败或进程在两者之间中断时允许重放，重放带相同源编号供维护读取去重，原始会话仍保留重放，不能声称恰好一次。轮转文件身份继续跟踪，截断/重写、源被删除、游标损坏、非法 JSON/UTF-8 或超预算行均标明可能缺失；坏行只保存原因、偏移、大小和摘要，完整原字节仍以 Host 原文件为准。未结束的普通半行等待补齐，待处理字节与采集健康进入诊断；读完当前有界轮次不代表全部积压已经读完。

自动副本按每条原始 Host UTC 时间检查同意边界，排除同意前、时间未知及聊天阶段，保留排除计数。延迟读到旧 Host 日志不构成上传旧记录的授权。断电可能丢失 Host 或会话日志尚未落盘的内容，不能凭游标补造。真实 Windows 文件身份、CS2 及退出流程的现场证据与合成日志/自动化分开记录。

## 受管 CS2 技术控制台

本机播出另从同一已核验受管来源识别明确 `[ALL]` 文本，作为独立 `program_all_chat` 原生记录提交，并经 NativeSource 交给有界临时 Program 展示。TEAM、私聊和技术报错不进入此记录；ALL 记录仅保存在本机普通日志中，云诊断继续排除聊天阶段。展示仅接纳写入区间完全晚于当前 Program 边界、且最近五秒内捕获的消息，不回放积压历史；本机技术采集关闭时该来源也停止。跨地图和断流清理及展示契约见[协议](protocol.md#公开实时输出)。

启用本机控制台采集后，每次受管启动 CS2 前先将已有非空 `console.log` 逐字节保存到状态目录的 `console-history/<SHA-256>.log`，同内容只保存一份。它包含原始游戏文本和可能的聊天，仅留本机，不进入支持导出、云上传或公开节目。副本独立于普通诊断日志轮转；下一次游戏重建源文件不覆盖旧副本。源文件不被 Mizar 清空或删除。每份最多 512 MiB、最多十六份、合计两 GiB，不自动淘汰旧场次；保存失败或预算不足时停止本次受管启动，保留原件与恢复记录，归档历史或修复磁盘后重试。外部自行启动游戏、关闭采集、磁盘损坏及尚未保存的进程崩溃不在这一跨启动保证内。

桌面权限仅允许准备中心更改此项同意；准备中心与运行诊断窗口可读取状态。原生命令须同时登记到构建命令清单和已启用的能力声明，避免界面存在但调用被 ACL 拒绝。

默认开启，由「游戏与观战」中的聊天上屏设置统一控制；旧设置首次升级自动开启，此后用户关闭会持久保留。只对本次由 Mizar 启动、以 PID／创建时间／程序路径核验并持有进程句柄的游戏观察固定 `game/csgo/console.log`，不接受调用者路径，不采集手动启动或无法证明身份的游戏。程序目录须为 `game/bin/win64/cs2.exe`，所有父目录与源文件拒绝链接／重解析点／硬链接，Windows 还核对实际打开句柄的最终路径。读取放在独立有界后台线程，复用既有进程证明、DesktopLog、NativeSource、SessionJournal 和压缩归档，不占用工作台生命周期／窗口跟随锁。

确认后仅在正常与保留设置的受管启动参数中增加 `-condebug`，实际参数仍逐次记录；不改 Steam 长期启动项，不加清空日志参数。游戏原始文件可能含聊天并持续增长，它不受 Mizar 自有归档预算控制；设置说明此点。Mizar 不清空、截断或删除该游戏文件。关闭立即阻止 Mizar 后续提交，独立持久关闭标记优先于旧启用文档；过时启用请求被版本条件拒绝，丢失确认后重试不重置读取起点。已发出的游戏日志开关只能在下次启动时移除，不能把停止 Mizar 读取说成原始游戏文件已停止增长。

启动前从 EOF 建立边界，不补采旧内容；同一游戏的 Host 重启按已持久游标恢复，重新同意从新的 EOF 开始，跳过关闭区间。每轮最多读取 256 KiB 源字节、接纳 256 条技术行和 128 KiB 序列化证据，未读积压留在原文件继续读；原始单行最多 16 KiB，超长、非法编码、聊天与未知行分别计数。识别引擎日志的 `MM/DD HH:MM:SS` 前缀后，按技术通道和消息前缀分类，保留原行与独立观察时间；纳入 `[Client]` 的两类 `CSVCMsg_UserCommands_t` 缺基线/无指令数据警告。支持 UTF-8／UTF-16 LE／BE 和跨读取半行；这不是对所有引擎输出的覆盖承诺。凭据精确替换，稳定记录身份仅散列脱敏文本，不能成为原凭据的指纹。完整技术行按稳定分片保存并由生产读取器重组，故障类别仅作索引。

复用 Host 四个各最多 25 MiB 的轮转文件及现有会话／待传预算，不另建无界日志。技术分段先完成持久写入，再原子更新游标，失败保留原游标供重试；确认与游标提交之间中断允许按稳定身份去重，不能声称恰好一次。进程证明在读取／提交边界失效时停止，本次尾部未读范围明确标记；游戏已结束后不借旧 PID 继续读文件。按文件身份、长度与游标邻接摘要识别可观察的替换／截断；相同身份与摘要的隐蔽重写不能保证检测。未知、重复轮转、预算耗尽和断电未落盘均不能包装成完整。

引擎文本没有可靠事件 UTC 时保留“上次观测 EOF 后”至“本次读取完成”的写入区间；读取时刻只是上界。替换／截断后旧内容下界未知，新的已观测 EOF 后才恢复可证明下界。人工时间范围按区间重叠保守附上完整技术分组，未知区间仍附带并说明；混合 Host 分组逐条检查原始时间，任一普通操作或控制台区间匹配、或时间未知时保留完整组，不能用同组控制台时间代替普通 Host 故障时间；不拿 Host 轮询时间冒充游戏错误发生时间。云副本只接纳整个已知写入区间都在云同意之后的行，排除同意前、未知或时钟倒置的区间并保留计数，完整本机证据不因此裁剪。

`pnpm diagnostics:console:qualify` 在 Windows 原生门禁调用真实 Rust 读取器与 DesktopLog，再经过实际 NativeSource、落盘、双端重启、HTTP Worker/R2/D1、生产 HTTP 支持包和读取器验证正常行、原始错误、丢失 ACK、时间区间与隐私排除；使用公开合成控制台，不读取用户抓包、不访问 Cloudflare 账户。真实 Windows 进程身份测试与解析／端到端各自判定；合成日志不能证明实际 CS2 版本必然生成该格式或解释现场 HUD 根因。生产支持包主动读取当前控制台设置／健康快照，超时和失败单独记录。

## 性能异常前后证据

既有十五秒运行时与浏览器聚合继续作为索引。Companion 另在内存保留最多三十秒、每二百五十毫秒一份的技术输入窗口：GSI 接收序号、地图/回合/炸弹计时、最多十六名选手的位置与状态，以及当前原始输入处理前的归一化、运行时和发布游标。字段按固定技术集合选择，不复制 auth、名字、聊天、武器清单或未知字段；字符串最多一百二十八字符，额外选手有省略计数。完整原始 GSI 仍在既有本机采集，不声称这一选集能够替代完整采集文件。

观察处理失败或超过五十毫秒、运行时拒绝观察、遥测诊断、输入静默/恢复、浏览器异常或主动问题标记触发持久保存。重复触发各自保留原因和关联，共享同一窗口，延长后续观察至最多三十秒；默认后续观察十秒。输入静默可能只是菜单或正常游戏行为，记录事实而不宣判卡死。主动标记只取得收到标记时尚在内存的窗口，不能补造此前未触发且已经丢弃的历史。

内存环最多一 MiB，单样本十二 KiB，异步待写两 MiB，分段最多一百二十八 KiB；历史序列化和脱敏让出输入执行后异步进入既有 SessionJournal，不逐帧同步磁盘。窗口明确记录实际前置跨度、最近样本年龄、后置样本数量与实际跨度、超预算/缺失计数和关闭中断；窗口内没有后续输入不能冒充十秒完整采样。窗口以后台批次先进入专用压缩暂存区，再等待既有 SessionJournal 对每条记录的持久确认；确认后才移除暂存副本。暂存区最多六十四 MiB 压缩文件、二百五十六 MiB 展开数据和四千零九十六个文件，每包展开不超过一 MiB，不淘汰未确认窗口；满额时保留已有证据并明确计数未接纳的内存交接。主日志或暂存写入失败保留完整原始异常链，独立定时重试，重启自动恢复；单个坏包隔离并标记缺失，不能阻止健康包恢复。普通会话记录的可恢复写入失败也在既有两 MiB 内存预算内重试，部分追加先回滚再重试；回滚使用单独可写句柄并再次验证固定文件身份与链接数，兼容 Windows 追加句柄不允许截断的权限边界；要求回执的调用仍收到实际失败，由其所有者决定重试，不能把失败的主动标记稍后悄悄变成成功。

暂存记录在创建时保存原始会话、UTC、单调时钟、源序号及稳定记录身份；恢复后的落盘时间单独保留，不把旧窗口伪装成重启后的新操作。确认与删除之间中断允许重放，生产读取器按稳定身份去重，不能声称恰好一次。导出固定暂存副本直至包组装完成，避免主日志快照与后台迁移之间丢失证据；包含范围内完整暂存正文，仍只在内存的正文标记 memory-only，不可读取的文件明确列出。原始 UTC 用于时间范围和云同意检查。断电尚未落盘、持续 I/O 故障后的内存预算耗尽、磁盘预算满及来源损坏仍可能缺失，状态必须如实保留。已确认的主日志继续沿用会话轮转及压缩分卷规则。人工导出还包含普通会话尚未确认落盘的完整内存记录（memory-only）及持久待传队列的完整脱敏技术副本（durable-outbox），不附带登记凭据或队列状态文件。读取器优先保留范围更广的原始本机记录，按源身份或会话序号去重；待传副本不能冒充原始本机采集范围。队列副本在串行事务内复制有界压缩字节，读取与逐包解压异步让出执行；损坏副本保留具体错误。固定产品日志先打开只读句柄并固定初始长度，再逐文件处理；轮转重命名或删除不丢失已打开的旧文件，后续追加不进入这次快照，截断/改写保留可读内容并标明 incomplete_snapshot。各文件快照时刻不同，不声称跨进程原子快照。

窗口可能在同意后才触发但含有同意前的内存样本。云副本逐样本检查原始 UTC 接收时间，只保留本次同意起点之后且时间有效的样本，保留云副本排除计数与本机范围说明；不得仅凭窗口写盘时间补传同意前样本。本机完整窗口不因此删减。

浏览器保留 Mizar 文档自身的未处理错误与原始 cause，排除可识别的外部脚本来源。雷达完成 Canvas 绘制后才推进独立绘制序号，按秒观察最多八块自身画布。页面可见、实时通道仍接收较新输入且非主动暂停时，绘制序号三秒不变才记录绘制未推进；静态预览、隐藏和主动暂停单独标记。页面 RAF、网络接收和绘制完成分别举证，均不证明 GPU、OBS 捕获或观众端画面正常。

验证包含实际 GSI 入口、浏览器异常、前后不同输入状态、落盘关闭、进程重启、完整支持包导出及分卷摘要验证；另外覆盖文档 RAF 继续但雷达不推进、暂停排除和关闭时后置未完成。Windows/OBS/CEF 的真实表现仍需实机证据。

窗口自身的同步交接成本可用 `pnpm --filter @mizar/companion exec tsx test/support/measure-performance-window.ts` 复测：公开合成十六人数据，两小时二十 Hz 输入与一百二十次异常窗口，真实 SessionJournal 写盘；输出同步耗时分位数与丢失、内存、写入健康。该加速工具只测窗口交接，不代表适配器、Core、渲染或 Windows 游戏延迟，也不替代最终集成后的上传容量模型。

## 云端存储与费用边界

实际资源、权限、secret 名称、验证与批准动作统一在[诊断接收器部署审查](../development/diagnostics-cloud-deployment.md)维护；当前尚未部署。代码和本地全链验证就绪后才提交准确 head 的执行记录，不将客户端队列或设置完成视作遥测交付。

当前基础队列没有云端端点，不执行部署，生产配置默认拒收、预算均为零。经使用者确认，私有 R2 保存完整脱敏 gzip 正文，D1 保存检索索引。每批创建后最多九十天自动发送，安装身份有效期同为九十天；客户端到期自动换新随机身份，旧未确认批次保持原字节和摘要，只供手动导出，不能重新签名或冒充已收到确认。新身份不重新签发已有批次；之后入队的记录仍按原始来源时间和同意边界检查。同意修订为 `technical-diagnostics-v3`；旧同意启动时先以独立策略标记持久关闭，须重新明确确认；未确认原包保持原字节供手动导出。策略标记跨重启不等于用户主动关闭并删除副本，之后重新同意也不自动发送这些旧包。

正文从首次签名许可起最多七天，且不超过原包创建后九十天；重试不续期。可识别的会话索引自最后一次接收保留九十天。原始 gzip 的 RFC 1952 MTIME 在首次持久化前一次写定并纳入 SHA，许可绑定该时间；同一原包的最小接收围栏在该时间后九十天删除。围栏清除后，同一旧原包仍因超出自动发送窗口而拒收。重写 MTIME 会改变原包摘要，属于不同包，不能说成原摘要续期。时间缺失、超出五分钟未来容差或过期均保留明确原因和本机副本。

安装采用含创建时间的随机 UUIDv7，无机器/MAC 标识；服务端按固定创建时间拒绝过期身份再登记，短期令牌不跨过该身份的九十天期限。安装登记和撤回记录在身份到期且相关正文、会话索引均清除后删除，正常最迟约创建后一百八十天（最后一刻接收的索引仍需满九十天），随分批 Cron 清理推进；没有正常永久围栏。客户端最多保留八份待关闭/旧身份所有权，确保轮换后仍可撤回旧数据；旧索引最长寿命到期后向服务器确认关闭，收到真实关闭确认前不丢弃删除证明。达到预算则暂停续期/发送并明确保留本机记录。确有未结束写入者的客观不确定记录只保留必要隔离信息，受分配预算硬停止保护，状态仍为待处理，不能冒充正常到期清理完成。实际资源、清理证据与费用统一见部署审查入口。

正常使用预算须依据新版实际事件量和压缩量实测，再给单场、每日多场和多用户容量预测。旧支持包和跨比赛 OBS 日志只能说明既有材料体积，不能当作新版每场上传量。预算保护与异常滥用保护分别设计；不能通过删掉失败、重试、原始 cause、状态转移或性能停顿上下文来缩小流量。

R2 免费额度是账户共享资源，应用限流、费用告警和应用自身容量统计不构成全账户零元硬封顶；不承诺其他应用使用量可被实时感知。不升级账户或购买付费能力，接近获批预算时暂停接收并明确显示本机积压与未上传范围。真实绑定、密钥、部署和七天正文永久清理需父会话确认；不修改或删除其他桶及生产数据。

问题标记等待该记录自身的写入与同步确认，并将收到标记时仍可读取的产品日志固定为本机现场副本，沿用完整日志的压缩分卷与摘要。普通日志轮转、后续高频事件和服务重启不淘汰该副本；较晚导出在同一 `fullLogs.files` 中附上原始正文，并复核分卷和整文件摘要，时间范围仍按原始记录过滤。副本不是第二份比赛状态，也不进入自动云上传。已轮转的历史及标记后尚未产生的记录无法由该副本补造。

现场副本最多八份、每份八 MiB、合计六十四 MiB，不自动淘汰旧标记；达到预算或写入失败时返回失败并提示立即手动导出，不把已写入的单条标记当现场完整保存。使用者保存诊断后可自行归档本机 `logs/marked-incidents` 中的副本以释放空间。损坏副本逐份报告，不阻止其他健康证据导出。Demo 试播允许这一仅记录本机诊断的操作，仍禁止正式比赛修改和自动编排。

成功响应返回源序号和已持久现场副本身份；不能仅以全局失败计数未变化作为成功证据。关闭后的日志拒绝确认新标记；已接纳的请求在服务关闭前完成，写入失败保留原始异常链并在操作附近反馈。普通高频记录仍使用既有异步写入，不为每条事件增加磁盘同步。

进程身份读取失败先保存失败 API 的原始 Windows 错误码，再记录目标 PID、已取得的创建标识和同一持有句柄的即时等待结果。宿主记录的 PID 与被查询目标分开；退出观察不是权限结论，也不作为新的关闭或配置恢复授权，不记录原始窗口句柄或凭据。

## 验证职责

队列负责测试默认关闭、同意起点、脱敏、断网、进程重启补入、丢失确认与幂等、假确认、中途撤回、离线删除同步、不安全文件与解压上限；另覆盖并发同意开关、批次 fsync / 状态提交中撤回、回执提交失败回滚、撤回提交失败重启、完成游标回收和有界响应读取。真实 Worker/R2/D1 配额、Windows CS2 控制台、OBS/CEF 和实际网络的证据独立记录；合成服务测试不能冒充这些实机结果。

明确交接的外部 CS2 使用同一已验证 PID、创建时间和进程句柄建立仅内存的控制台来源边界，从交接时的文件末尾开始读取。该边界不写受管恢复事务，不授予关停权；解除借用、实例退出或不唯一时停止。经 Mizar 打开官方 MulNX 前，同意开启本机采集时先保留上一份原始控制台，并为该独立启动器添加 -condebug；直接从外部启动器自行启动的历史覆写无法由 Mizar 事后拦截。

人工支持包的 `snapshot.diagnosticDelivery` 单独记录诊断回传是否可用、配置、同意及暂停状态、队列与阻塞数量、字节数、确认与失败次数、受控错误码和下次尝试时间；初始化不可用时未知字段为 `null`，不将未知当作关闭。错误文本不原样导出，未列入允许集合的错误标为 `other`。原有 `snapshot.delivery` 仍表示投影消费者状态。
